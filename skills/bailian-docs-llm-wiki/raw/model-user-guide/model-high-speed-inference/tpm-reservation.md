# 吞吐预留概述

吞吐预留为指定模型锁定专属推理容量，确保业务高峰期不受公共限流影响。本文介绍产品概念、推理模式、付费周期与价格、支持的模型、方案选型与生命周期。

<a id="什么是吞吐预留"></a>

## 什么是吞吐预留

您可以为指定模型购买**专属推理容量**。购买后系统生成一个**专属模型 code**，将 API 请求中的 `model` 参数替换为该 code，请求即消耗预留容量，不受公共资源限流影响。

一个吞吐预留对应一个专属模型 code，在该预留上追加的所有容量（含叠加容量包）共用同一 code，API 调用无需任何改动。为不同模型创建的吞吐预留各自生成独立的 code；预留创建后不支持更换基础模型，需要其他模型的容量时请为该模型新建预留。

预留容量内的调用不额外收取 Token 费用；超出部分按溢出策略处理：**自动溢出**（默认，转按量计费）或**仅使用预留容量**（超出时返回 429 限流错误）。

<a id="推理模式与支持的模型"></a>

## 推理模式与支持的模型

创建时选择一种推理模式：

-   **标准模式**：推理速度与标准 API 相同（TPS，每秒 Token 处理量），价格低于高速模式。
-   **高速模式**：推理速度相比标准模式提升 **1.5~2 倍**，适合高吞吐、低延迟场景；价格高于标准模式。

## 付费周期与价格

| 付费周期 | 适用模式 | 计费方式 |
| --- | --- | --- |
| **预付费/按天** | 标准模式、高速模式 | 按自然日一次性支付；当日购买按 1 天计费 |
| **预付费/按 8 小时时段** | 仅标准模式 | 购买连续 8 小时容量；仅当日 22:00–次日 00:00 可下单，购买后立即生效（起点为下单时刻所在整点，如 23:40 下单 → 23:00 生效至次日 07:00） |
| **后付费/按小时** | 仅高速模式 | 按实际使用时长计费，精确到分钟；删除实例或容量归零即停止计费 |

容量按 **kTPM**（1 kTPM = 1,000 Tokens/分钟）购买，分输入与输出两项：输入起步 **200 kTPM**、步长 **10 kTPM**，输出起步 **20 kTPM**、步长 **1 kTPM**。

按天费用 = `输入单价 × 输入 kTPM + 输出单价 × 输出 kTPM`。以 Qwen3.8-Max（华北2（北京）、标准模式）为例：200 输入 + 100 输出 kTPM 的按天费用 = `12.10 × 200 + 36.29 × 100 = 6049 元`。

<a id="方案选型"></a>

## 方案选型

| 方案 | 推理性能 | 付费方式 | 容量保障 | 适用场景 |
| --- | --- | --- | --- | --- |
| 按量付费 | 共享公共池 | 按 token 用量 | 无 | 流量波动大、短期使用 |
| 资源包/节省计划 | 共享公共池 | 预付费折扣 | 承诺折扣（非专属） | 费用优化 |
| **吞吐预留·标准模式** | **与标准 API 相同 TPS** | 按天 / 按 8 小时时段 | **专属容量，购买容量即为可用容量** | 流量可预估、不能接受限流 |
| **吞吐预留·高速模式** | **1.5~2 倍 TPS** | 按天 / 按小时后付费 | **专属容量，购买容量即为可用容量** | 高吞吐、高性能要求 |

准备购买时，创建与接入的完整步骤参阅[创建、接入与管理](tpm-reservation-index/tpm-reservation-create.md)。

<a id="生命周期"></a>

## 生命周期

三种付费周期各自的到期与停止行为：

| 付费周期 | 到期/停止行为 | 续费 |
| --- | --- | --- |
| **按天** | 到期后立即停机（不可调用），停机 **2 小时后释放**、不可恢复 | 停机后 0~2 小时内可续费；可开启**到期自动续费**（到期前 1 天自动扣款） |
| **按 8 小时时段** | 时段到期后容量自动失效，无停机保留期 | 不支持续费 |
| **按小时后付费** | 无到期概念：删除实例或容量归零即停止计费 | 不适用 |

<a id="常见问题"></a>

## 常见问题

<a id="accordion-q-超出预留容量时会怎样"></a>

Q: 超出预留容量时会怎样？

取决于溢出策略：**自动溢出**（默认）下超出部分自动转按量计费，业务不中断；**仅使用预留容量**下超出部分返回 429 限流错误，不产生额外费用。无论哪种策略，频繁触发都表示容量不足，建议扩容。

<a id="accordion-q-如何获取专属模型-code"></a>

Q: 如何获取专属模型 code？

创建吞吐预留后系统自动生成，在列表卡片详情区的概览页签可复制。调用时把 API 请求的 `model` 参数替换为该 code。

<a id="accordion-q-旧称-ptu-tpm-预留与现名称如何对应"></a>

Q: 旧称 PTU、TPM 预留与现名称如何对应？

产品已统一命名为吞吐预留，旧称对照如下：

| 旧称 | 现称 |
| --- | --- |
| PTU / 预置吞吐 / 高速容量 | 吞吐预留·高速模式 |
| TPM 预留 | 吞吐预留·标准模式 |
