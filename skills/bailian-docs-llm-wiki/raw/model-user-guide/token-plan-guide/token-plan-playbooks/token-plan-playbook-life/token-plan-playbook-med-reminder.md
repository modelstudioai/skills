把真实困境连同界面要求一起写进提示词，模型产出一个能长期用的用药管家网页。

**说明**

**免责声明**：本页展示内容均为 AI 模型生成，仅供参考，不构成任何效果承诺；实际产出效果与 Credits 消耗以控制台「用量详情」为准。

给父母管药最难的不是「按时吃」，而是每种药能开多久各不相同——有的医保单次只开两周、有的三周，子女得记住每种药哪天见底、赶在断药前跑医院。把真实困境连同想要的界面样子一起写进提示词，模型直接产出一个能长期用的单文件网页程序：打卡自动扣库存、算准断药日、把相近的开药日合并成一趟医院，再导出 .ics 到手机日历到点就响。

调用链：`qwen3.8-max` → 单文件 HTML 应用（药品管理 + 服药打卡 + 余量预警 + 行程合并 + .ics 导出）。关键分工：日期与库存全部由确定性 JS 计算，模型只负责把程序写出来，不让大模型直接算医疗相关日期。

## 步骤：功能需求 + 想要的界面样子一起给

把功能需求发给 `qwen3.8-max`：

```
帮我做一个「父母用药管家」网页应用，单个 HTML 文件，双击就能用，给我自己和我爸用。

背景：我爸同时吃好几种慢性病药，经常忘吃；更麻烦的是每种药医保单次能开的量不一样（有的两周、有的三周），我得记住每种药什么时候快没了、赶在断药前去医院开，经常算不清楚要么断药要么白跑。

## 功能要求
1. 药品管理：药名、每次剂量、每日次数、服用时段（早/中/晚/睡前）、餐前餐后、剩余片数、医保单次最多可开片数；localStorage 存本地。
2. 自动计算（必须用精确 JS 计算，不要估算）：可吃天数 = 剩余片数 ÷（每次剂量 × 每日次数）向下取整；预计断药日 = 今天 + 可吃天数；建议开药日 = 断药日往前推 3 天。
3. 合并行程：建议开药日相差 3 天以内合并为一条、取最早日期，例如「8月25日 建议一次去医院开：氨氯地平、二甲双胍」。
4. 每日打卡：按时段分组，勾选后自动扣减剩余片数，同一天不重复扣减。
5. 双视图：「长辈视图」只显示今天吃什么、字号大；「家属视图」显示剩余天数、断药日、开药行程。
6. 导出日历：分成两份 .ics——「给长辈的服药提醒」只含每日重复的服药事件，「我的开药提醒」只含开药行程；符合 RFC5545，时区 Asia/Shanghai，中文不乱码。开药事件的 UID 不要包含日期，这样开药日变化后重新导入时日历会更新同一条提醒，而不是新增一条。

## 其它
- 纯前端单文件、不引用任何外部资源、手机上也好用、数据只存本地不上传
- 页面上要写明：本工具仅做时间提醒，不提供任何用药建议，以医生处方和说明书为准
```

## 说明

-   **消耗**：本玩法涉及文本生成 + 深度思考（`qwen3.8-max`），产出 37 KB 完整应用。生成完整程序是长输出任务，思考与输出占消耗主体，明显高于普通问答；后续改细节时把现有代码带进上下文做定点修正，比整篇重写省不少，也不会把调好的部分改坏。
-   **医疗边界**：本玩法只做服药与开药的时间提醒，不提供任何用药建议；药名、剂量、服法一律以医生处方与药品说明书为准，录入结果需家属人工复核。数据只保存在浏览器本地，不上传任何服务器。
-   **确定性计算**：断药日算错会导致真断药，所以提示词里明确要求「用精确 JS 计算」，让模型产出确定性代码而非直接给答案——上面所有日期都由生成的程序计算，经独立验算逐项吻合。
-   **日历怎么导进手机**：把 .ics 用邮件发到手机后点开即可添加（iPhone 系统原生支持；安卓建议用邮箱 App 打开附件——直接在微信里点常常打不开）。
-   **界面好不好看取决于你有没有说**：第一版只给了功能需求，产出的界面深绿标题栏配点阵背景、七八种颜色混用；把配色、字体、层级、留白规则写进提示词后重新生成，同样的功能就拿到了上图的样子。
