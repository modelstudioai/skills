# Wiki 与本体知识图谱

在旗舰版文档知识库中开启 Wiki，将文档整理为可阅读、可检索的主题知识页面（Wiki Page），并通过本体知识图谱浏览页面关联。

**说明**Wiki 仅在旗舰版知识库中提供，标准版不包含 Wiki 与本体知识图谱能力。当前 Wiki 与本体知识图谱共用能力开关，开启后一次解析同时生成两类内容，并在知识库详情页分别展示。

## 功能概述

Wiki 是旗舰版文档知识库提供的知识组织能力。开启后，系统使用大模型从文档中提取摘要、实体和概念，生成结构化的 Wiki 页面（Wiki Page），并构建独立索引参与知识检索与问答。

Wiki Page 既可作为检索结果提供给应用，也可在控制台直接阅读和修订。自动生成的 Page 可通过来源文档追溯原始内容。

开启后，系统会在一次解析中同时生成：

-   **Wiki Page**：按主题组织的知识页面，可阅读、修订并参与检索召回。
-   **本体知识图谱**：基于 Wiki Page 之间的关联生成关系视图，用于知识浏览与关系展示。

Wiki Page 会构建独立索引参与检索召回；图谱数据本身不参与检索，主要用于展示。知识库详情页分别提供 **Wiki** 和 **本体知识图谱** 页签。

## Wiki 与切片检索的区别

Wiki 不替代原有的切片与向量索引。两者组织知识的方式不同，可以结合使用：

对比项

切片检索

Wiki 检索

知识单元

文档切片（Chunk）

主题知识页面（Wiki Page）

内容来源

保留文档原始片段

由模型从文档中提取、组织和生成

内容形态

标题、段落、表格等原文片段

摘要、实体、概念等主题化内容

适用问题

精确条款、原文定位、局部事实查询

主题理解、实体查询、概念解释与关联知识召回

溯源方式

返回来源文档及切片

返回 Wiki Page，并可查看来源文档

**警告**对于合同条款、错误码、精确数值等需要严格核对原文的问题，建议同时使用切片检索并查看来源文档，不要仅依赖模型生成内容。

## 开启并配置 Wiki

### 进入知识库编辑页

登录百炼控制台，进入[**数据接入 → 知识管理**](https://bailian.console.aliyun.com/cn-beijing/rag/knowledge/list)，点击目标知识库卡片的**查看详情**，进入详情页后点击右上角**编辑**。

如果尚未创建知识库，请先创建旗舰版知识库，并在创建时开启 Wiki 与本体知识图谱。

### 开启 Wiki 与本体知识图谱

展开 **Wiki 与本体知识图谱**，打开能力开关。开启后，系统会在一次解析中同时生成 Wiki Page 和本体知识图谱。

### 配置生成参数

配置项

说明

抽取模型

用于 Wiki 内容提取与生成，支持 qwen3.8-max（默认）、qwen3.8-flash、qwen3.7-plus，按所选模型的输入/输出 Token 计费

提取粒度

控制每篇文档抽取的 Wiki 实体/概念数量。**聚焦**：只抽取文档主角，最干净但可能漏掉次要实体；**标准**：抽取主角及被详细描述的次要实体/概念，适合大多数场景；**详尽**：抽取所有可识别的命名实体与概念，适合当作术语表使用

Wiki 内容生成要求

控制摘要、页面和首页的表达重点，最多 4000 字。例如面向法务审阅时优先展示责任主体、时间线和风险提示。引用、合并与防幻觉规则由系统固定维护

Wiki 提取重点

指定需要重点识别的领域实体和概念，最多 4000 字。例如产品、版本、组织、负责人和关键技术概念。不会替换系统的 JSON 与引用协议

更新方式

当前为自动更新，文档新增或修改后自动重新生成，始终保持最新，会按 Token 计费产生消耗

多数场景建议先使用标准粒度，再根据 Page 数量、内容质量和检索效果调整。

**说明**修改 Wiki 内容生成要求等配置后，需要重新解析才能影响已有内容，不会在保存后立即重写全部历史 Page。

### 保存配置

点击**保存并返回**。后续导入或更新文档时，系统按照当前配置生成 Wiki 内容。

### 费用估算与查看

Wiki 抽取模型费用可按下式估算：

```
Wiki 抽取模型费用 ≈ 输入 Token × 输入单价 + 输出 Token × 输出单价
```

实际消耗受文档长度、提取粒度、模型输出、任务重试和平台排队情况影响，最终费用以账单为准。

-   在控制台编辑知识库时，可在右侧**费用**面板实时查看当前所选抽取模型及各关联服务的参考单价。
-   查看知识库规格费用与模型 Token 明细，请参见[查看账单与用量](https://help.aliyun.com/zh/model-studio/billing-for-knowledge-base#h-ragbilling-view-bill)和[查询明细账单的 Token 消耗量与对应金额](https://help.aliyun.com/zh/model-studio/billing-for-knowledge-base#h-ragbilling-view-token)。

### 成本控制建议

-   **先小批验证**：历史文档迁移或大规模上线前，先用少量代表性文档验证生成效果、耗时与 Token 费用。
-   **分批导入**：控制导入并发，避免一次集中导入过多文档或在多个知识库中同时提交大批量文件，减少排队和重复重试。
-   **谨慎全量重新生成**：修改配置后重新解析、关闭 Wiki 后再次开启，都会触发批量或全量生成，请提前评估费用。
-   **评估自动更新频率**：频繁新增或修改文档会持续触发重新生成，请结合业务更新节奏和成本预算配置。
-   **停止规格费用**：仅删除知识库内文件不会停止规格费用。如需彻底停止知识库规格费用，需删除整个知识库实例，详见[如何彻底停止知识库的计费](https://help.aliyun.com/zh/model-studio/billing-for-knowledge-base#h-ragbilling-faq-stop-billing)。

**警告**关闭 Wiki 不是临时暂停，会删除全部 Wiki Page 与本体知识图谱，包含人工编辑内容和版本历史，且无法恢复。再次开启需要对全部文档完整生成，并再次产生 Token 费用。

## 导入文档并查看生成进度

文档导入方式与常规知识库一致，支持上传文件、选择类目和选择文件。具体格式、大小及操作说明见[文档管理](raw/application-user-guide/agent-context/knowledge-base/data-connection-overview/documents.md)。

1.  **导入文档**：在知识库详情的**文档列表**中点击**上传数据**，选择数据来源并完成导入。
2.  **检查文档解析状态**：在文档列表中查看解析状态。文档解析失败或导入索引失败时，请先根据错误信息处理文档解析或索引问题。
3.  **查看 Wiki 生成进度**：切换到 **Wiki** 页签，查看已处理、处理中和失败数量。Wiki 生成为异步任务，文档解析完成后仍需等待 Wiki 生成完成。
4.  **确认生成结果**：文档列表中的 **Wiki 生成状态**变为**已生成**后，进入 **Wiki** 页签检查 Page 内容和来源文档。

**说明**参考压测数据，在任务不拥堵的情况下，500 个文档的 Wiki 生成大约需要 2 小时左右；实际耗时会受到文档大小、所选模型以及平台流量与任务排队情况的影响，高峰期可能更久，不构成处理时效承诺。大批量导入建议参见[批量导入与并发](#h-ragwiki-batch)。

## 取消生成的影响

生成过程中可点击**取消生成**停止当前任务。取消不会删除原始文档和既有 Page，后续可重新触发生成：

-   原始文档及已完成的文档解析结果保留。
-   已经生成的 Wiki Page 保留，未完成的任务会回到**待提交**。
-   重新导入文档可再次触发待提交任务的生成；仅在文件选择器中重复选择同一文档，不一定会再次触发。
-   不要通过关闭再开启 Wiki 来恢复任务。关闭会删除全部既有 Page 和本体知识图谱。

如需继续处理待提交文档，请通过重新导入文档触发生成，不要通过关闭 Wiki 来恢复任务。

## 查看和管理 Wiki Page

知识库详情页的 **Wiki** 页签提供知识库整体索引摘要，以及以下内容类型：

内容类型

说明

摘要

文档或主题的概括性内容，帮助快速了解主要信息

实体

文档中涉及的产品、组织、人物、项目等具体对象

概念

领域术语、技术方法、业务机制等概念性知识

综合 / 对比

控制台提供的内容类型入口，实际生成结果取决于文档内容和抽取结果

点击 Page 标题可查看 Page 摘要、完整正文、来源文档和被链接信息。实际生成的 Page 数量和类型取决于源文档、提取粒度及模型处理结果；相同概念可能跨文档合并，Page 数量不一定随文档数量线性增长。

### 新建 Page

进入 **Wiki → 知识**，点击列表右上方的**新建 Wiki 页面**图标，创建并保存 Page。

### 编辑 Page

打开目标 Page 后点击**编辑**，修改摘要或正文并保存。保存后会生成一个新版本，例如从 V1 升级为 V2，并更新在线 Wiki 检索索引。

### 查看历史版本并回滚

在 Page 的**历史版本**中选择目标版本并执行回滚。回滚不是简单地把版本号改回旧值，而是以旧版本内容生成一个新版本。例如，从 V2 回滚到 V1 后会生成 V3。

### 删除 Page

在 **Wiki → 知识**列表中找到目标 Page，点击其右侧 **...**，选择**删除**。也可以在 Page 详情操作区执行删除。

删除前请确认影响范围。删除确认提示为不可恢复，删除后该 Page 不再参与后续 Wiki 检索。若后续重新执行全量生成，系统可能根据源文档再次生成相同主题的 Page。

**说明**Page 既可根据文档自动生成，也可根据业务需要手动新建，并在控制台持续维护。

## 本体知识图谱

在知识库详情页切换到**本体知识图谱**页签，查看基于 Wiki Page 关联生成的关系视图。图谱按内容类型展示图例和节点数量，并统计节点总数与孤立节点数。

本体知识图谱主要用于知识浏览与关系展示，图谱数据本身不参与检索。参与检索召回的是 Wiki Page 独立索引。

## 使用 Wiki 检索与问答

### 知识检索

开启 Wiki 的知识库可使用独立的 Wiki 检索服务，与向量检索服务并列。

1.  普通创建知识库并开启 Wiki 后，系统会自动提供 **Chunk 检索**和 **Wiki 检索**两种知识检索服务：Chunk 检索服务随知识库创建，Wiki 检索服务随 Wiki 开启链路创建。进入[**知识服务 → 知识检索**](raw/application-user-guide/agent-context/knowledge-base/service/rag-knowledge-retrieval.md)，打开知识库对应的 Wiki 检索服务。两类服务创建后即为已发布状态，可直接使用；如未查询到 Wiki 检索服务，可通过服务列表接口按知识库 ID 复核后再创建并发布。
2.  确认服务已绑定已开启 Wiki 的知识库；如需多知识库联合检索，可继续添加其他知识库。单个服务最多绑定 15 个知识库，且须位于同一业务空间。
3.  按需配置 Query 改写、初步向量/关键词检索 TopK、排序模型、相似度阈值和最大召回数量。
4.  在调试窗口输入典型业务问题，检查返回的 Wiki Page 及来源信息。
5.  确认服务处于**已发布**状态。自动创建的服务可直接使用；如修改了服务配置，请重新发布。通过[服务渠道](raw/application-user-guide/agent-context/knowledge-base/integration/channels.md)查看 API、SDK 等接入方式。

Wiki 检索结果包含 `wiki_page_id`、标题、类型、路径、别名、版本和摘要等元数据。返回文本可能是 Page 摘要或检索片段，不保证是完整正文；关键内容请继续阅读 Page 或核对来源文档。

### 知识问答

知识问答服务可关联带有 Wiki 能力的知识库，在检索 Wiki 内容的基础上生成自然语言回答。

1.  进入[**知识服务 → 知识问答**](raw/application-user-guide/agent-context/knowledge-base/service/rag-knowledge-qa.md)，创建或打开问答服务。
2.  添加目标知识库，单个服务最多绑定 15 个知识库。
3.  根据业务需要配置模型、提示词、引用、拒答和防泄漏等能力。
4.  使用典型问题调试，并核对回答引用的 Wiki Page 与来源文档。
5.  发布后通过[服务渠道](raw/application-user-guide/agent-context/knowledge-base/integration/channels.md)集成到业务应用或 Agent。

当前知识问答链路会同时使用普通知识检索和 Wiki 检索。应用不应假设答案只来自 Wiki Page，应同时核对原文切片、Wiki Page 和最终引用。

通过 API 接入知识检索或知识问答时，请参见[服务渠道](raw/application-user-guide/agent-context/knowledge-base/integration/channels.md)。

## API 接入注意事项

请从对应服务的**发布渠道 → API 调试**获取当前环境的请求地址、服务 ID 和最新请求示例，不要复用其他环境的域名或服务 ID。

-   知识检索 API（`POST /api/v1/indices/knowledge/search`）中的 `agent_id` 是已发布知识检索服务的唯一标识，只是接口沿用字段名；调用知识检索服务不需要创建 Agent 应用。
-   可通过 `POST /api/v1/indices/rag/app/list` 按 `pipeline_id` 查询知识库关联的检索服务；`agent_scene` 传 `search`，可选 `search_type=chunk/wiki` 过滤类型，返回结果中包含 `search_type`。服务详情接口 `/api/v1/indices/rag/app/get` 也会返回该字段。
-   Wiki 检索通过服务 ID 调用，返回 Page 列表及相关元数据。
-   知识问答采用流式响应时，响应中可能包含工具调用、工具返回和中间消息，调用方需按事件及消息类型解析，不能简单拼接全部内容作为最终答案。
-   外层 HTTP 200 不代表内部检索一定成功。请同时检查流式事件中的工具状态、错误码和最终答案。
-   API Key 仅在创建时展示明文，请妥善保管；测试完成后及时删除不再使用的 Key。

**警告**Wiki Page 和问答回答均包含模型生成内容。用于合同、财务、医疗、合规等高风险业务时，应结合来源文档进行人工复核，不要将生成结果作为唯一决策依据。

## 批量导入与并发

单次上传或选择文件最多 50 个，详见[容量与限制](raw/application-user-guide/agent-context/knowledge-base/reference/rag-knowledge-base-specifications.md)。

Wiki 生成会同时占用文档解析、索引构建与大模型生成资源，请控制导入并发，不要一次集中导入过多文档，也避免在多个知识库中同时提交大批量文件，否则容易导致任务排队时间明显拉长甚至控制台卡顿。

-   **分批导入**：建议按业务批次提交，例如每批约 100 个文档，通过控制台分两次提交，待当前批次任务完成、状态稳定后再提交下一批。
-   **耗时参考**：在不拥堵的情况下，500 个文档的 Wiki 生成大约需要 2 小时；实际耗时受文档大小、所选模型及平台流量排队影响，高峰期可能更久，不构成处理时效承诺。
-   **先小批验证**：历史文档迁移或大规模上线前，建议先用少量代表性文档验证生成效果、耗时与 Token 费用。
-   **异常止损**：如出现持续排队或失败，请暂停新增任务并联系技术支持，避免短时间内反复重试。

## 自动更新、关闭与删除

### 新增或修改文档

系统自动重新生成相关 Wiki 内容，并产生模型 Token 调用费用。生成期间，既有 Page 可继续保留和检索。频繁更新文档前，请评估生成任务量和成本。

### 删除文档

删除原文档后，关联 Wiki Page 和索引会异步清理，不会在文档删除的同一时刻全部消失。清理期间，Wiki 页签和检索结果可能暂时保留旧内容，请等待清理完成后再验证。

如果等待后仍长期保留已删除文档的 Page 或检索结果，请记录知识库 ID、文档 ID、删除时间和 Page ID，并联系技术支持。

### 关闭 Wiki

关闭不是临时暂停。二次确认会明确提示：

-   删除本知识库已生成的全部 Wiki Page 与本体知识图谱，包含人工编辑内容和版本历史，删除后无法恢复。
-   Wiki 索引不再参与召回，本体知识图谱关系视图不再可用；向量检索与关键词检索不受影响。
-   再次开启时需要对全部文档完整生成，并再次产生 Token 费用。

关闭过程中，Wiki 检索 API 可能返回 `WikiNotEnabled`。重新生成后，Page 会使用新的 Page ID，并从 V1 开始，不会恢复关闭前的版本历史。

### 删除知识库

删除知识库会清理知识库及其 Wiki 数据。若存在知识检索或知识问答服务，控制台会提示关联关系。

删除知识库后，请检查其关联的知识检索和知识问答服务，并按需解绑或删除不再使用的服务与 API Key。若在知识库删除后继续调用原问答服务，流式响应中的检索工具可能返回 `PipelineNotExist`，表示原知识库已不存在。

**警告**删除文档、关闭 Wiki 或删除知识库前，请确认影响范围。不要将这些操作视为可随意恢复的配置变更。

## 使用建议

1.  **按领域划分知识库**：将业务相近的文档放入同一知识库，减少无关主题对知识组织和检索的干扰。
2.  **保证源文档质量**：优先使用内容完整、标题清晰、解析效果良好的文档，先检查解析结果再评估 Wiki 效果。
3.  **从标准粒度开始**：先使用默认配置验证，再根据实体/概念覆盖情况调整提取粒度，避免一开始生成过多低价值 Page。
4.  **明确领域提取重点**：在 Wiki 提取重点中列出核心业务实体和概念，但不要写入与领域无关的通用要求。
5.  **结合切片检索验证**：对精确事实和关键条款，同时检查 Wiki Page、原文切片和来源文档。
6.  **使用真实问题评测**：通过企业典型问题对比开启 Wiki 前后的召回与回答效果，再决定是否扩大文档范围。
7.  **上线前验证异常路径**：除正常生成链路外，同时验证取消生成、删除文档、服务解绑和 API 错误处理，并建立必要的监控与告警。
