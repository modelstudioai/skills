# 常见问题

Connector 使用过程中的常见问题与处理方式。

## 连接与权限

### RAM 用户无法使用 Connector

RAM 用户需要主账号先授权。由主账号在 RAM 控制台为该用户补齐数据连接相关权限后重试。

### 报错缺少该模块的权限

当前账号缺少对应模块的操作权限。RAM 用户请联系主账号补齐授权；主账号出现该提示时，确认是否已开通相关服务。

### OSS Bucket 不出现在下拉列表中

按顺序确认：

1.  服务关联角色是否已初始化，在连接对话框中单击 **立即授权** 完成。
2.  Bucket 标签是否正确。需要 `bailian-datahub-access`，值为 `read`。
3.  当前账号是否具备该 Bucket 的读取权限。

### 把保密文件上传到连接器是否有安全风险

导入的文件仅供当前业务空间的用户使用，平台不会将其用于商业用途或对外公开。涉密数据建议：

-   使用独立的业务空间隔离，不与其他团队共用。
-   严格控制业务空间成员与 API Key 的分发范围。

## 身份验证配置

### 连接对话框里只有一个下拉框

这个 App 需要先有身份验证配置。展开 **选择身份验证配置** 下拉框，如果显示暂无配置，单击下方的 **创建身份验证配置** 先建一个。流程见[创建身份验证配置](raw/application-user-guide/overview/auth-guide/create-config.md)。

### 下拉框里看不到已建好的配置

身份验证配置与 App 绑定，为语雀建的配置不会出现在 Salesforce 的下拉框里。需要为当前 App 单独建一个。

### 一个配置能给多个连接用吗

可以。同一个 App 下的多个连接可以共用一个身份验证配置。两个账号凭证不同时，才需要各建一个配置。

### 删除连接会删掉身份验证配置吗

不会。配置仍留在 **身份验证配置** 列表中，可以给新连接复用。

### 对方系统换了密钥怎么办

新建一个身份验证配置填入新凭证，用新配置重建连接，确认可用后删除旧连接。不要在对方系统直接删除仍在使用的 OAuth 应用，那会让所有相关连接立刻中断。

## MCP 接入

### 返回 401

鉴权请求头缺失，或 API Key 无效、已过期。确认请求头格式为 `Bearer <API-Key>`，并在控制台核对 Key 状态。更换 Key 后需要重启客户端。

### 返回 404

MCP 地址路径填写有误。确认路径为 `/api/v2/connector/mcp`，注意版本号是 `v2`。

### 客户端显示已连接但工具列表为空

当前业务空间下还没有任何已连接的 App。先在 **Apps** 页面创建一个连接器。也要确认配置中的业务空间 ID 与创建连接器的空间一致。

### 工具调用突然失败

对应连接器的凭证可能已过期。在 App 详情页确认连接器状态，显示已过期时需要重新授权。

## 文件解析

### 解析耗时较长或偶现超时

在请求高峰时段，解析可能需要数小时。并发较高时还会因资源排队进一步延长。

处理方式：耐心等待或稍后重试，不要反复重复提交同一批文件。大批量导入尽量安排在非高峰时段。

### 导入的文件看不到了

仅支持查看最近 90 天内导入的文件。超过该时间范围后文件不再展示，但不会被删除。

### JSON、CSV、YAML 文件无法导入

目前不支持直接导入这三种格式。请先用相应工具转换为 XLSX 或 XLS 格式，再通过[表格连接器](raw/application-user-guide/overview/apps-guide/table.md)导入。

### 扫描件解析效果不好

导入时选择自定义解析设置，改用面向扫描件与图片型文档的解析方式。

## OSS 导入

### 导入 OSS 文件报错 10041495

通常是授权或路径问题。确认服务关联角色已初始化、Bucket 已添加 `bailian-datahub-access=read` 标签、对象路径包含 Bucket 名称。

### 为什么会产生 OSS 下行流量费

从 OSS 读取数据会产生 OSS 侧的下行流量费用，由 OSS 按其计费规则收取，与 Connector 的用量分开计算。同一 Bucket 被频繁读取时这部分费用会比较明显。

需要控制费用时，考虑把数据一次性导入平台托管存储，而不是每次从 OSS 实时读取。

路径必须包含 Bucket 名称：

## 数据库连接

### 提示数据库配置校验不通过，表数据量较大

目标表的数据量超出校验阈值。缩小范围，例如只选择必要的表，或对大表做分区、限定时间范围。

### 报 CHECK\_BINLOG\_FORMAT、CHECK\_ENFORCE\_GTID\_MODE 或 CHECK\_GTID\_CONSISTENCY

MySQL 实例的 binlog 相关参数不满足要求。按报错指向的参数逐项调整实例配置后重试。

### 私网数据源支持哪些地域

私网访问对 RDS 与 ECS 实例所在地域有要求。连接前确认实例地域在支持范围内，否则改用公网访问。

### RAM 用户如何开通 EventBridge 服务关联角色

RAM 用户需要主账号预先授予相应权限。由主账号在 RAM 控制台为该用户补齐权限后重试。

## 迁移

### 旧版数据连接必须迁移吗

一键迁移入口开放至 2026 年 9 月 30 日。届时未迁移的连接需要在新版中手动重建，成本明显更高。详见[数据连接迁移](raw/application-user-guide/overview/overview/migration.md)。

### 迁移页面显示不支持迁移

部分连接器无法通过一键入口处理，例如系统默认创建的连接器。这类情况需要在 Connector 中新建同类型连接器，然后重新导入数据或重新配置同步规则。

### 迁移会影响已有的智能体吗

迁移不改变数据本身。完成后建议打开引用该连接器的智能体和工作流，确认技能列表与节点配置仍指向正确的连接器与工具。

**重要**问题没有覆盖到时，记录操作步骤与完整报错信息（含 `requestId`）后提交工单，排查会快很多。
