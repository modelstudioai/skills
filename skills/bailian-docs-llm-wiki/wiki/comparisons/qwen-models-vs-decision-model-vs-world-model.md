# 通义大模型、决策模型与世界模型定位对比

为帮助开发者在百炼平台中快速识别不同模型能力的边界与适用范围，本文对三类核心模型能力——**通义大模型（Qwen 系列）**、**决策模型（`decision-model-preview`）** 和 **世界模型（HappyOyster 系列）** 进行系统性定位对比。该对比聚焦于技术本质、接口契约、运行约束与工程落地特征，不涉及性能基准或私有部署细节，旨在为 API 层面的技术选型提供清晰、可操作的判断依据。

---

## 关键维度对比

| 维度 | 通义大模型（Qwen 系列） | 决策模型（`decision-model-preview`） | 世界模型（HappyOyster 系列） |
|------|--------------------------|----------------------------------------|------------------------------|
| **核心定位** | 通用文本生成与对话智能体基座，支持多轮推理、工具调用与内容创作 | 结构化决策引擎：一次前向计算输出分类/是非/评分及其完整概率分布，**不生成自然语言** | 多模态世界建模与动态推演引擎：面向具身智能与开放环境交互，建模状态演化、目标分解与动作规划 |
| **输入格式** | `messages` 数组（role/content），支持 system/user/assistant 角色；`state` 字段非标准，需封装于 content 中 | `state`（任意结构：string/object/array） + `questions`（定义问题类型与判定标准的 JSON 对象） | `input` 对象，严格结构化：必含 `scene`（场景快照）、`goal`（目标描述），可选 `history`；各子模型 schema 不同 |
| **输出格式** | 自然语言文本（`content` 字段），支持流式 `delta`；含 `tool_calls`（Anthropic/DashScope 接口）、搜索摘要等中间产物 | 纯结构化 JSON：含 `choices`（选项名+概率）、`noul`（yes 概率）、`score`（期望等级+各级概率+置信度）等字段；无文本生成字段 | 结构化 JSON：含 `steps`（推演步骤）、`instructions`（调度指令序列）、`actions`（动作参数）等，依子模型而异；无自由文本 content 字段 |
| **支持模型** | `qwen-max`、`qwen-plus`、`qwen-turbo` 等多档位通用大模型 | 仅 `decision-model-preview`（预览版，GA 待发布） | `happyoyster-adventure`（探索推演）、`happyoyster-directing`（策略调度）、`happyoyster-acting`（邀测中，动作生成） |
| **API 端点** | • OpenAI 兼容：`/compatible-mode/v1/chat/completions`<br>• DashScope 原生：`/api/v1/services/aigc/text-generation/generation` | `/compatible-mode/v1/systemone`（TypeSafe System One 协议） | `/api/v1/services/aigc/world-model/invoke` |
| **计费方式** | 按 **输入 token + 输出 token** 总和计费（统一 token 计价规则），所有接口共享配额 | 按 **单次请求** 计费（无论 `questions` 数量或 `state` 长度），独立于文本模型配额体系 | 按 **单次请求** 计费（Adventure/Directing 同价，Acting 另计），独立配额，不与 token 消耗挂钩 |
| **流式响应** | ✅ 支持（OpenAI/DashScope 接口均支持 SSE 流式） | ❌ 不支持（返回即完整结构化结果） | ❌ 不支持（`stream: true` 被忽略，强制同步返回） |
| **上下文管理** | 依赖 `messages` 显式传入历史；`OpenAI Responses` 接口隐式维护但不可控；**不支持跨模型 session 共享** | ❌ 无上下文概念；每次请求为独立决策事件，`state` 即全部输入 | ⚠️ 有限支持：`input.history` 可传入简要历史，但非长程记忆，推演深度受 `max_step` 限制（默认 5–10） |
| **典型场景** | 客服对话、代码生成、报告撰写、联网问答、多工具协同执行 | 工单自动分派（选团队）、内容安全审核（是否违规）、任务完成度打分（1–5 分）、A/B 测试分流判断 | 游戏 NPC 行为推演、工业仿真流程调度、机器人任务规划（Goal → Sub-goals → Actions）、数字人场景交互逻辑生成 |

## 各方案适用场景建议

### ✅ 选择通义大模型（Qwen）当：
- 需要生成自然语言（回答、摘要、文案、代码等）；
- 业务逻辑依赖多轮对话状态、外部工具调用（如搜索、计算器、网页提取）；
- 已有 OpenAI/Anthropic 技术栈，追求平滑迁移；
- 场景对输出形式灵活性要求高（如混合文本+JSON+工具调用）。

> ⚠️ 注意：若仅需结构化判断（如“是/否”或“选 A/B/C”），使用 Qwen 属过度设计——成本高、延迟高、结果不可控（需正则/LLM 解析）。

### ✅ 选择决策模型（`decision-model-preview`）当：
- 核心需求是**高频、低延迟、强确定性**的结构化输出（分类/打分/二元判断）；
- 需要概率分布与置信度用于下游阈值控制（如“置信度 < 0.85 则转人工”）；
- 输入数据已结构化（如工单 JSON、用户行为日志、审核样本）；
- 对 token 成本敏感，且无需任何文本生成能力。

> ⚠️ 注意：不适用于需要解释性文本（如“为什么判为高危？”）、长文本理解（>64K token）或复杂推理链的场景。

### ✅ 选择世界模型（HappyOyster）当：
- 构建具身智能体（Agent）、数字人或仿真系统，需建模**环境状态变化**与**目标驱动的行为演化**；
- 任务本质是“从目标出发，推演出可行路径/指令序列/物理动作”；
- 场景具备明确时空结构（如地图、流程图、3D 场景快照）；
- 已具备场景建模能力（能将现实抽象为 `scene` + `goal` 格式）。

> ⚠️ 注意：不适用于纯文本处理、简单分类或静态知识问答；当前 Acting 子模型仅限邀测，生产环境需评估准入周期。

## 技术选型参考（面向开发者）

| 你的需求 | 推荐模型 | 理由 |
|----------|-----------|------|
| “根据用户提问生成一段产品介绍文案” | ✅ 通义大模型 | 文本生成是其核心能力，支持多模板、风格控制与[流式输出](../concepts/streaming-output.md) |
| “审核一条评论是否含辱骂，返回 yes/no 及置信度” | ✅ 决策模型 | 专为 `noul` 类型优化，毫秒级响应，概率输出开箱即用，成本仅为 Qwen 的 ~1/10 |
| “游戏里 NPC 看到玩家靠近后，决定是逃跑、攻击还是对话，并推演后续 3 步行为” | ✅ 世界模型（Adventure） | 唯一支持因果链推演与多步状态建模的模型，`scene`+`goal` 输入天然匹配游戏状态 |
| “把用户上传的合同 PDF 提取关键条款并生成摘要” | ✅ 通义大模型（配合文件解析预处理） | 需文本理解+生成能力；决策模型无法处理长文本，世界模型不支持文档解析 |
| “将客服会话实时打分（1–5），并判断是否需升级主管” | ✅ **组合使用**：<br>• 打分 → 决策模型（`score` 类型）<br>• 升级判断 → 决策模型（`noul` 类型） | 两类结构化输出可并行请求，低延迟、高精度、低成本；避免用 Qwen 两次调用解析再判断 |
| “构建一个能操作网页的 AI Agent，自动完成注册流程” | ✅ 通义大模型（Anthropic Messages 接口） + 工具调用 | 当前唯一支持 `tool_use` 与可控推理链的接口；世界模型 Acting 尚未开放，且不面向网页 DOM 操作 |

> 💡 **选型黄金法则**：  
> - **要文本？→ 选 Qwen**  
> - **要结构化答案（且不要文本）？→ 选决策模型**  
> - **要状态推演/动作规划？→ 选世界模型**  
> - **要两者以上？→ 组合调用，而非强行让单一模型越界承担**
