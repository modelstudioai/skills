# 模型评估 vs 应用评估

百炼平台同时提供模型评估和应用评估两套评测体系，分别面向不同的评测目标。模型评估聚焦于大模型本身的推理能力，帮助开发者完成模型选型与调优验证；应用评估聚焦于智能体或工作流应用的端到端输出质量，帮助开发者在 RAG 等复合系统中定位问题环节并持续优化。理解两者的定位差异，是构建有效评测策略的前提。

## 关键维度对比

| 维度 | 模型评估 | 应用评估 |
|------|----------|----------|
| 评测对象 | 文本生成类大模型 | 智能体应用、工作流应用 |
| 核心目标 | 模型选型、调优验证、能力基准测试 | 应用输出质量监控、RAG 链路归因优化 |
| 评测方式 | 自定义评测（AI/规则/人工）、基线评测 | 自动评测（单应用/多应用横评）、手动评测 |
| 数据集格式 | EvaluationSet（Prompt + Completion 两列） | 旧版：xls/jsonl；新版：按应用出入参定义或自定义表结构 |
| 数据集来源 | 手动上传 | 自动生成（基于知识库）、手动上传、应用观测导入 |
| 评分机制 | 评测维度（5 种类型：大模型数值/分类、规则相似度/匹配、人工分类） | 评估器（LLM 评估器 + Code 评估器 + 预置模板）+ 标签体系 |
| 评分方式数量上限 | 无明确限制 | 每个任务最多 10 个评估器 |
| 归因分析 | 不支持 | 支持（定位到模型理解/重排/检索/切片/知识缺失） |
| 排行榜 | 支持（相同维度下横向对比多模型） | 通过多应用横向评测实现 |
| 基线评测 | 支持（C-Eval、MMLU、ARC 等公开数据集） | 不支持 |
| API/SDK | 不支持，仅控制台操作 | 不支持公开 API，控制台操作 |
| 前提条件 | 无特殊要求 | 应用须已发布、配置知识库、开通应用观测 |
| 版本管理 | 不支持 | 新版评测集支持版本管理 |
| 多轮对话 | 不支持 | 旧版对话分析类型支持多轮对话 |
| 计费构成 | 被评测模型推理费用 + 裁判模型评分费用 | 应用调用产生的 [Token](../concepts/token.md) 费用 + 评估器模型费用（当前限时免费） |
| 地域限制 | 基线评测仅北京地域可用 | 无明确地域限制 |

## 适用场景建议

### 选择模型评估的场景

- **模型选型阶段**：需要在多个候选大模型之间进行能力对比，选出最适合业务场景的基座模型。
- **模型调优验证**：微调后需要量化评估调优效果是否达到预期（如准确率、BLEU 分数等）。
- **基础能力基准测试**：使用公开标准数据集快速了解模型在通用任务上的基础水平。
- **确定性指标评测**：翻译、摘要、Function Calling 等有明确参考答案的场景，适合用规则评估降低成本。

### 选择应用评估的场景

- **RAG 应用上线前验证**：端到端评测智能体应用在知识问答场景的回答质量。
- **多版本迭代对比**：同一应用调整 Prompt、检索策略或模型后，需要量化对比改进效果。
- **问题归因与调优**：评测发现 BadCase 后，需要定位问题出在模型理解、检索、重排还是知识库。
- **持续质量监控**：定期回归验证应用质量不因知识库更新或模型升级而退化。
- **工作流应用评测**：评估复杂工作流的端到端输出质量。

## 技术选型参考

在实际项目中，模型评估和应用评估通常是互补而非互斥的。推荐的组合策略：

1. **先用模型评估选模型**：通过基线评测和自定义评测筛选出满足业务需求的基座模型。
2. **再用应用评估验应用**：将选定模型集成到智能体或工作流后，用应用评估验证端到端效果。
3. **持续用应用评估做回归**：上线后定期执行应用评估，结合归因分析持续优化。

如果评测目标是纯粹的模型能力（不涉及知识库和检索链路），选择模型评估；如果评测目标是包含检索增强、多步编排在内的完整应用链路效果，选择应用评估。
