# 模型评测 vs 模型监控对比

百炼平台同时提供"模型评测"和"模型监控"两大能力，二者都围绕模型质量展开，但解决的问题和使用时机截然不同。模型评测侧重于**上线前的质量验证**，通过测试数据集和评分标准量化模型能力；模型监控侧重于**上线后的运行观测**，通过实时指标和告警保障服务稳定性。本文从多个维度对比两者差异，帮助开发者在不同阶段选择合适的工具。

## 核心定位对比

| 维度 | 模型评测 | 模型监控 |
|------|---------|---------|
| 核心目标 | 量化评估模型在特定场景下的表现质量 | 观测模型在生产环境中的运行状态和稳定性 |
| 使用阶段 | 上线前选型、调优后验证、定期回归 | 上线后持续运行、日常运维 |
| 关注焦点 | 回答质量、准确率、通过率 | 调用成功率、延迟、吞吐量、成本 |
| 数据来源 | 预先准备的测试数据集 | 生产环境的真实调用数据 |
| 评判方式 | AI 裁判打分 / 规则算法 / 人工标注 | 系统自动采集指标 + 阈值告警 |

## 功能维度详细对比

| 维度 | 模型评测 | 模型监控 |
|------|---------|---------|
| 支持的模型范围 | 预置模型（千问系列、第三方文本生成模型等）及调优后模型 | 模型列表中的所有模型及调优后模型（高级监控/告警/日志有地域限制） |
| 输入 | 评测数据集（Excel，含 Prompt + Completion）或推理结果集 | 无需额外输入，自动采集生产调用数据 |
| 输出 | 评测报告：综合得分、通过率、数据明细、排行榜 | 监控看板：调用次数、失败率、延迟、Token 消耗等指标图表 |
| 评测/监控模式 | 自定义评测（业务场景）+ 基线评测（标准数据集） | 普通监控（免费，小时级延迟）+ 高级监控（收费，分钟级延迟） |
| 评分/指标类型 | 大模型评估（数值型/分类型）、规则评估（相似度/字符串匹配）、人工评估 | 安全指标、成本指标、性能指标（延迟/RPM/TPM）、错误指标 |
| 告警能力 | 无内置告警 | 支持多级告警（INFO/WARNING/ERROR/CRITICAL），多渠道通知 |
| 日志/溯源 | 可查看评测任务中每条数据的输入输出和评分 | 开通推理日志后可查看每次真实调用的输入输出 |
| 外部集成 | 无 | 支持 Grafana、Prometheus HTTP API、自建应用接入 |
| 计费 | 被评测模型推理费用 + 裁判模型费用（当前限时免费） | 普通监控免费；高级监控产生云监控 CMS 费用；推理日志产生 SLS 费用 |

## 典型场景

### 适合使用模型评测的场景

- **模型选型决策**：在多个候选模型之间做横向对比，选择业务场景下表现最优的模型。
- **调优效果验证**：微调后使用基线评测验证通用能力是否退化，使用自定义评测验证业务指标是否提升。
- **质量基准建立**：用标准数据集（C-Eval、MMLU、GSM8K 等）建立模型能力基线，便于后续追踪。
- **上线前回归**：每次 Prompt 调整或模型升级前，用固定评测集验证不出现质量回退。

### 适合使用模型监控的场景

- **生产环境运维**：实时掌握模型调用的成功率、延迟和错误率，及时发现异常。
- **成本管控**：通过 Token 消耗统计和用量趋势分析，优化模型使用成本。
- **故障排查**：通过推理日志查看具体调用的输入输出，定位问题根因。
- **容量规划**：基于 RPM/TPM 等吞吐指标，合理规划资源和限流策略。
- **合规审计**：通过历史对话日志满足内容审计和合规要求。

## 协同使用建议

模型评测和模型监控并非二选一，而是覆盖模型生命周期不同阶段的互补工具：

1. **上线前**：使用模型评测进行选型和质量验证，确保模型能力达标。
2. **上线后**：开启模型监控，持续观测运行状态，配置告警规则。
3. **迭代优化**：当监控发现质量异常（如失败率上升、用户反馈变差），回到评测环节重新验证和调优。
4. **成本与质量平衡**：结合监控的 Token 消耗数据和评测的质量得分，在不同模型间找到性价比最优解。
