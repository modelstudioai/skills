# 应用评测 vs 应用监控对比

应用评测和应用监控是阿里云百炼平台中两个紧密关联但定位不同的质量保障功能。应用评测侧重于在应用迭代过程中系统化评估输出质量，帮助开发者发现和修复问题；应用监控（应用观测）则侧重于对线上运行中的应用进行实时调用链路追踪和性能指标采集。两者在应用质量管理的不同阶段发挥各自作用，理解它们的差异有助于开发者构建完整的质量闭环。

## 核心定位对比

| 维度 | 应用评测 | 应用监控（应用观测） |
|------|----------|----------------------|
| 核心目标 | 系统化评估应用输出质量，发现 BadCase 并驱动迭代优化 | 端到端追踪应用调用链路，监控运行时性能与状态 |
| 使用阶段 | 开发与迭代阶段（上线前验证、版本对比） | 线上运行阶段（实时监控、问题排查） |
| 数据来源 | 评测集（人工构建或基于知识库自动生成） | 真实线上调用数据（自动采集） |
| 输出产物 | 评测报告（正确率、BadCase 分析、调优建议） | 调用链路详情、性能统计图表、Trace/Span 数据 |
| 技术基础 | 大模型评分 + 人工标注 | OpenTelemetry 链路追踪 |

## 支持的应用类型

| 应用类型 | 应用评测 | 应用监控 |
|----------|----------|----------|
| 智能体应用 | 支持（需已发布） | 支持（完整调用链路追踪） |
| 工作流应用 | 支持（新版评测任务） | 支持（含工作流特有节点） |
| 高代码应用 | 不支持 | 支持（仅根节点，不支持内部链路追踪） |
| Assistant API 创建的应用 | 不涉及 | 不支持 |

## 功能维度对比

| 功能维度 | 应用评测 | 应用监控 |
|----------|----------|----------|
| 评测集管理 | 支持旧版（对话分析/知识问答）和新版（智能体/工作流/自定义）两套体系 | 无独立评测集，但可将 Span 数据导入评测集 |
| 自动评估 | 支持 LLM 评估器和 Code 评估器，可自动评分 | 不提供自动评估，专注于数据采集和展示 |
| 人工标注 | 支持通过标签进行多维度人工标注（分类/布尔值/数字/文本） | 支持对 Span 数据添加自定义标签（与评测共享标签体系） |
| 多应用对比 | 支持最多 8 个应用的横向对比评测 | 不支持多应用对比，按单应用维度查看 |
| 归因分析 | 支持自动归因（模型理解、重排、检索、切片等环节定位） | 通过调用链路节点手动定位问题环节 |
| 调优建议 | 自动生成针对 Prompt、检索配置、知识库切片的优化建议 | 不提供调优建议，需开发者自行分析 |
| 性能监控 | 不涉及 | 支持调用次数、失败率、Token 量、首 Token 耗时、平均调用时长等指标 |
| 数据导出 | 评测报告在线查看 | 支持导出为 JSONL 或 EXCEL 格式 |

## 前提条件与计费

| 维度 | 应用评测 | 应用监控 |
|------|----------|----------|
| 前提条件 | 应用需已发布；自动评测需配置知识库并开通应用观测 | 需授权并开通 OpenTelemetry 服务，初始化 LogStore |
| 计费方式 | 评测过程消耗的 Token 计入用量（分步计费，失败步骤已消耗的 Token 仍计费） | 功能本身不收费，底层 OpenTelemetry 服务产生存储费用 |
| 权限要求 | 子账号需 `管理员` 或 `应用评测-操作` 权限 | 子账号需 `AliyunBailianFullAccess`、`应用观测-操作` 页面权限及 `ram:CreateServiceLinkedRole` 策略 |

## 数据联动

应用评测与应用监控之间存在重要的数据流转关系：

- **监控数据反哺评测**：应用监控采集的真实线上 Span 数据可批量导入评测集，使评测样本更贴近真实用户场景。支持追加数据和全量覆盖两种导入方式，每个评测集最多支持 50 个字段映射。
- **评测依赖监控**：自动评测功能要求应用已开通应用观测，评测期间不可关闭观测功能。
- **标签体系共享**：两者共享同一套标签管理体系（布尔值、分类、数字、文本四种类型），在监控中标注的数据可在评测中复用。

## 适用场景建议

**选择应用评测的场景：**

- 应用版本迭代后需要验证输出质量是否提升
- 调整 Prompt、更换模型或修改检索策略后需要对比效果
- 需要系统化识别 BadCase 并获取自动调优建议
- 需要多个应用版本之间的横向对比评测
- 定期回归测试（每周或每月）

**选择应用监控的场景：**

- 需要实时追踪线上应用的调用链路和运行状态
- 排查单次请求的性能瓶颈或错误原因
- 监控应用的整体性能趋势（调用量、失败率、延时等）
- 需要查看模型推理过程中的思考链和中间结果
- 积累真实线上数据用于后续构建评测集

**建议的协同使用方式：**

1. 先通过应用监控采集线上真实调用数据
2. 将有代表性的 Span 数据导入评测集
3. 基于真实数据运行评测任务，获取质量评分和调优建议
4. 根据建议优化应用配置，发布新版本
5. 通过应用监控持续观察新版本的运行表现
