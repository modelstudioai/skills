# 知识库、记忆库与[长期记忆](../concepts/long-term-memory.md)能力对比

本文旨在帮助开发者清晰区分百炼平台中三种核心状态管理与信息增强能力：**知识库（Knowledge Base）**、**记忆库（Memory Library）** 和 **[长期记忆](../concepts/long-term-memory.md)（新）（Long Term Memory, 新版）**。三者虽均涉及“记忆”“检索”“持久化”等关键词，但在设计目标、技术定位、数据生命周期、集成方式及适用边界上存在本质差异。本对比聚焦实际工程选型需求，从输入输出、模型支持、API 能力、计费逻辑到典型场景逐项分析，避免概念混淆，助力高效构建可靠、可扩展的智能应用。

## 关键维度对比

| 维度 | 知识库（Knowledge Base） | 记忆库（Memory Library） | [长期记忆](../concepts/long-term-memory.md)（新）（Long Term Memory, 新版） |
|------|--------------------------|---------------------------|------------------------------------------|
| **核心定位** | **面向领域知识的 RAG 基础设施**：注入结构化/非结构化私有业务数据，提升模型回答的专业性与事实准确性 | **面向用户个体的语义化长期记忆中枢**：跨会话持续建模用户偏好、事件、画像等动态行为信息，解决上下文遗忘问题 | **面向对话流程的轻量级状态持久化能力**：在 `chat` 接口内嵌式管理结构化对话状态，替代临时 session_state，降低集成门槛 |
| **输入格式** | 支持多模态原始文件：<br>• 文档类：PDF/DOCX/PPTX/TXT/MD（≤150 MB，≤1000页）<br>• 视觉类：JPG/PNG/WEBP（VL 模型支持）<br>• 音视频：MP4/MOV/MP3/WAV（需转文本或帧提取）<br>• 结构化数据：CSV/Excel（首行字段名，禁用合并单元格） | 支持语义化文本输入：<br>• `messages`：标准对话历史数组（含 role/content）<br>• `custom_content`：任意字符串（如日志摘要、系统事件）<br>• `meta_data`：自定义 KV 标签（用于过滤） | 仅支持结构化 schema 定义下的对话内容提取：<br>• 输入为 `messages` 数组（含 system [prompt](../guides/prompt.md) 中声明的 `memory_schema`）<br>• 不接受原始文件、二进制流或独立文本块 |
| **输出格式** | • 检索：返回带 `score`、`content`、`source`（引用溯源）、`meta` 的切片列表<br>• 问答：返回生成答案 + 可选引用标记（如 `[1][2]`）+ 溯源详情 | • `SearchMemory`：返回 `id`、`content`、`created_at`、`meta_data`、`score` 的记忆片段数组<br>• `GetUserProfile`：返回按 schema 填充的 JSON 对象（如 `{"age": 28, "hobby": [" hiking", "AI"]}`） | • 响应体顶层新增 `retrieved_memory` 字段，值为 JSON 数组：<br> `[{"city": "杭州", "language": "zh-CN", "updated_at": "2025-04-01T10:20:00Z"}]`<br>• **不自动注入 messages**，需开发者手动拼接至 [prompt](../guides/prompt.md) |
| **支持模型** | • **广泛兼容**：Qwen 全系列（QwQ/Long/Max/Plus/Turbo/Coder/Deep-Research/VL-Max/OCR/开源 Qwen3/Qwen2.5/Qwen2）、DeepSeek-R1、Llama3.1、Yi-Large 等<br>• 支持自定义调优模型（基于 Qwen-Plus/Turbo/VL-Max 等） | • **模型无关**：作为独立 API 服务，与下游大模型解耦<br>• 可与任意模型（包括非百炼托管模型）组合使用 | • **严格限定**：仅对 `qwen-max`、`qwen-plus`、`qwen-turbo` 的 `chat` 接口生效<br>• 不支持 VL/Audio 模型、`completion`、`function_calling` 模式 |
| **API 端点** | • 控制台集成：工作流节点 / 智能体配置页<br>• SDK/API：`bailian.cn-beijing.aliyuncs.com`（中国站）<br> `bailian.ap-southeast-1.aliyuncs.com`（国际站新加坡）<br>• 关键接口：`CreateKnowledgeBase`, `UploadFile`, `Search`, `ChatWithKB` | • 统一 API 域名：`dashscope.aliyuncs.com`（与 DashScope 模型 API 同域）<br>• 关键接口：<br> `AddMemory` / `SearchMemory` / `ListMemory` / `UpdateMemory` / `DeleteMemory`<br> `CreateProfileSchema` / `GetUserProfile` | • 复用 `chat` 接口（如 `https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation`）<br>• 通过请求体参数启用：<br> `long_term_memory: true` / `memory_schema: {...}` / `retrieve_memory: {...}` |
| **计费方式** | • **双重计费**：<br> – **规格费**：按小时计费（标准版 ¥0.03/小时；旗舰版 ¥0.2/RCU/小时）<br> – **调用费**：向量化、Rerank、路由、问答生成等各环节**独立按 Token 计费** | • **按次计费（商业化后）**：<br> – `AddMemory`：¥0.03/次（pro）、¥0.018/次（lite）<br> – `SearchMemory`：¥0.001/次（pro）、¥0.00002/次（lite）<br> – 免费试用期至 2026-08-20 | • **零额外计费**：完全包含在对应 `qwen-*` 模型的 `chat` 接口 Token 费用中<br>• 无独立规格费、存储费或调用次数费 |
| **数据生命周期** | • 文件级持久化：上传即存储，**无自动过期机制**<br>• 删除知识库 → **永久清除所有数据（不可恢复）**<br>• 同步规则导入的文件为独立副本，源端删除不影响 | • **可配置过期策略**：创建 `MemoryProject` 时指定 `expired_in_days`（默认永不过期）<br>• 支持显式 `DeleteMemory` 或批量清理<br>• 用户画像同样遵循该生命周期 | • **LRU 自动淘汰**：单 `user_id` 下最多存 1000 条，超限时按最后访问时间自动清理最旧记录<br>• 无显式过期设置，不支持手动删除单条（仅支持清空整个 user_id） |
| **典型场景** | • 企业内部知识问答（制度/产品文档/FAQ）<br>• 客服工单辅助（历史案例库+产品手册）<br>• 多模态内容检索（PPT 图表问答、培训视频关键帧搜索）<br>• 合规审计（合同条款溯源、政策依据引用） | • 个性化助手（记住用户饮食禁忌、会议偏好、常用联系人）<br>• 智能导购（持续追踪浏览/加购/反馈行为）<br>• 任务型 Agent（“帮我订下周三的会议室” → 后续自动关联“周三”“会议室”上下文）<br>• 用户画像构建（多轮渐进填充职业、兴趣、设备偏好） | • 客服对话状态保持（“您刚咨询的是订单 #12345，当前物流是…”）<br>• 多步骤表单填写（分轮收集地址、支付方式、发票信息）<br>• 简易个性化（记住本次对话中用户指定的“简洁回答”风格）<br>• 快速原型验证（无需额外服务依赖，5 分钟接入） |

## 各方案的适用场景建议

- **选择知识库，当你的需求是：**  
  ✅ 需要将大量静态或半静态的**业务文档、产品资料、音视频素材、外部数据库导出内容**注入模型；  
  ✅ 要求回答具备**强事实依据与可追溯性**（如“请引用第3份合同中的付款条款”）；  
  ✅ 场景涉及**多模态检索**（看图问答、听音频找原文）；  
  ❌ 不适合高频更新的用户行为数据、细粒度对话状态、或需要跨模型复用的记忆。

- **选择记忆库，当你的需求是：**  
  ✅ 需要构建**高精度、可扩展、模型无关的用户长期记忆系统**；  
  ✅ 要求支持**复杂语义检索**（如“找出我上周提过的所有待办事项”）、**结构化画像抽取**（自动归纳“用户是 iOS 开发者，常用工具是 VS Code”）；  
  ✅ 应用已集成 OpenClaw 等框架，追求**零侵入式自动捕获与召回**；  
  ✅ 需要精细控制成本（通过 `lite/pro` 策略平衡效果与预算）；  
  ❌ 不适合直接处理原始 PDF/图片，也不适用于仅需几轮对话内状态保持的轻量场景。

- **选择长期记忆（新），当你的需求是：**  
  ✅ 正在快速开发一个基于 `qwen-max/plus/turbo` 的 `chat` 应用，**希望最小改造即获得基础状态记忆能力**；  
  ✅ 记忆需求高度结构化且字段明确（如固定提取 `order_id`, `delivery_address`）；  
  ✅ 对数据规模要求不高（≤1000 条/user），且可接受 LRU 淘汰机制；  
  ✅ 团队希望**规避额外运维成本与计费复杂度**，优先保障开发效率；  
  ❌ 不适合需要跨模型复用、多模态输入、用户画像建模、或高保真语义检索的场景。

## 面向开发者的技术选型参考

| 选型决策点 | 推荐方案 | 理由说明 |
|------------|----------|----------|
| **是否必须支持 PDF/图片/音视频等原始文件？** | ✅ 知识库 | 记忆库与长期记忆（新）均不接收原始文件，仅处理文本化内容。知识库是唯一原生支持多模态文件上传、解析与检索的方案。 |
| **是否需要记忆在多个不同大模型间共享？** | ✅ 记忆库 | 知识库绑定特定 RAG 流程，长期记忆（新）深度耦合 `qwen-*` 模型。只有记忆库以独立 API 形式存在，可被任意模型（甚至非百炼模型）调用 `SearchMemory` 获取结果。 |
| **是否追求最低接入成本与零额外费用？** | ✅ 长期记忆（新） | 无需申请新权限、无需配置新域名、无需额外计费项，仅需在现有 `chat` 请求中添加几个参数即可启用。适合 MVP 验证或成本敏感型项目。 |
| **是否需要严格的数据隔离与精细化生命周期管理？** | ✅ 记忆库 | 提供 `user_id` + `memory_library_id` + `project_id` 三级隔离；支持显式过期时间、批量删除、元数据过滤；审计与运维能力最强。知识库以“知识库”为单位隔离，长期记忆（新）仅靠 `user_id`，粒度较粗。 |
| **是否需在回答中自动插入引用标记并溯源原文？** | ✅ 知识库 | 知识问答模式原生支持 `[1][2]` 式引用与 `source` 字段返回，满足合规、审计、可信生成等强需求。其他两者仅返回记忆内容，无溯源能力。 |
| **是否已有 OpenClaw 框架且希望自动记忆？** | ✅ 记忆库（配合 OpenClaw 插件） | `@modelstudio/modelstudio-memory-for-openclaw` 插件可实现 `before_agent_start` 自动写入、`agent_end` 自动召回，真正零代码侵入。知识库与长期记忆（新）均需手动编码集成。 |

> **最终建议**：  
> - **企业级知识中枢** → 选 **知识库**；  
> - **用户中心化智能体底座** → 选 **记忆库**；  
> - **轻量级对话状态快启方案** → 选 **长期记忆（新）**。  
> 三者并非互斥，而是可分层协同：用**知识库**承载公司级知识资产，用**记忆库**管理用户级长期关系，用**长期记忆（新）** 处理单次会话内的临时状态——合理组合，方能构建兼具专业性、个性化与敏捷性的下一代 AI 应用。
