# 知识库、记忆库与[长期记忆](../concepts/long-term-memory.md)能力对比

本文旨在帮助开发者清晰区分百炼平台中三类核心数据增强能力：**知识库（Knowledge Base）**、**记忆库（Memory Library）** 和 **[长期记忆](../concepts/long-term-memory.md)（Long-Term Memory，新）**。尽管三者均支持“检索+增强生成”，但其设计目标、数据来源、生命周期、适用范式存在本质差异。本对比聚焦技术选型关键维度，避免概念混淆，助力您在智能体构建、RAG 应用或个性化服务中做出精准决策。

| 维度 | 知识库（Knowledge Base） | 记忆库（Memory Library） | [长期记忆](../concepts/long-term-memory.md)（Long-Term Memory，新） |
|------|--------------------------|---------------------------|----------------------------------|
| **核心定位** | **外部私有知识注入**：为模型提供领域专属、静态/半静态的权威信息源，解决“不知道”问题 | **跨会话用户状态建模**：自动从对话中提取用户行为、偏好、承诺等事件性信息，解决“记不住”问题 | **结构化长期状态存储与语义召回**：统一 API 提供记忆全生命周期管理，强调可编程性与多规则融合，是记忆库能力的标准化演进 |
| **输入格式** | 多模态原始文件（PDF/DOCX/CSV/PNG/MP4 等）或结构化文本；需预处理（上传→切片→向量化） | 对话消息数组（`messages`）或纯文本（`custom_content`）；支持元数据（`meta_data`）和画像模板（`profile_schema`） | 同记忆库：`messages`（≤50 条）或 `custom_content`（≤512 字符）；`messages.content` 为数组时仅文本部分参与抽取；`meta_data` 全链路透传 |
| **输出格式** | 检索结果为带来源引用的文本切片（`chunks`），含 `content`、`source`、`score`；问答结果为自然语言响应（由指定 LLM 生成） | 检索结果为结构化 `memory_nodes` 数组，含 `id`、`content`、`score`、`meta_data`、`created_at`；支持分页与完整画像对象（`UserProfile`） | 同记忆库：标准 `memory_nodes` 列表；`SearchMemory` 响应含 `total_count`、`next_token` 等分页字段；`AddMemory` 返回 `memory_node_id` |
| **支持模型** | **作为 RAG 的生成模型**：Qwen3/Qwen2.5/Max/Plus/Turbo/Coder/DeepSeek-R1/Llama3.1/Yi-Large 等数十种预置与自定义文本模型；VL 模型用于图片/音视频向量化 | **不依赖外部 LLM 生成**：内置专用记忆抽取模型（隐式调用）；`pro`/`lite` 策略决定抽象质量，**无需开发者指定模型名称** | 同记忆库：无显式模型选择；`plan_version=pro` 触发更高质量的抽取与重排序，底层模型由平台托管 |
| **API 端点** | `POST /v2/knowledge_bases/{kb_id}/search`（检索）<br>`POST /v2/knowledge_bases/{kb_id}/query`（问答）<br>地域限定：华北2（北京）、新加坡 | `POST /v2/apps/memory/add`<br>`POST /v2/apps/memory/memory_nodes/search`<br>`GET /v2/apps/memory/memory_nodes`（List）<br>全域可用（DashScope 公共 endpoint） | `POST /v2/apps/memory/add`<br>`POST /v2/apps/memory/memory_nodes/search`<br>`GET /v2/apps/memory/memory_nodes`<br>同记忆库，**接口路径与参数完全兼容**，是其正式 API 标准化版本 |
| **计费方式** | • **规格费**：按小时（标准版 0.03 元/小时，旗舰版 0.2 元/RCU/小时）<br>• **模型费**：向量化（按 Token）、Rerank（按召回切片数×平均 Token）、多库线性叠加<br>• **免费额度**：720 小时标准版规格费 | • **商业化起始日**：2026-08-20 10:00（北京时间）<br>• **按次计费**：`AddMemory` 与 `SearchMemory` 调用独立计费，区分 `pro`/`lite` 版本<br>• **无规格费**：无需预购计算资源 | 同记忆库：计费模型、生效时间、`pro`/`lite` 分档完全一致；**二者实为同一计费体系下的同一能力** |
| **典型场景** | • 客服知识库问答（产品文档/PDF）<br>• 表格数据分析（NL2SQL 查询 Excel 销售数据）<br>• 图文报告解读（上传财报截图问关键指标）<br>• 音视频内容检索（会议录像中定位“项目风险讨论”片段） | • 智能助手跨会话提醒（“上次说每天9点吃药” → 主动提醒）<br>• 用户画像渐进构建（多轮对话后自动填充“职业：医生”“兴趣：登山”）<br>• 电商客服记忆历史订单与投诉点 | • 构建可审计的记忆管理后台（List/Delete/Update 全覆盖）<br>• 多业务线共享记忆库（如 CRM + 客服系统共用 `user_id`）<br>• 混合规则检索（同时查询“健康提醒”+“旅行计划”两类记忆） |

## 各方案的适用场景建议

- **选择知识库，当您需要：**  
  ✅ 将大量**静态、权威、非个人化**的业务资料（如产品手册、合同模板、行业法规、内部 Wiki）赋能给大模型；  
  ✅ 支持**多模态内容**（PDF 图文混排、Excel 表格、会议录像）的深度理解与检索；  
  ✅ 要求**精确溯源**（每个回答必须标注来自哪份文档第几页）；  
  ❌ 不适合存储用户私密对话、临时偏好或需频繁更新的个人状态。

- **选择记忆库 / 长期记忆（新），当您需要：**  
  ✅ 实现**真正的跨会话个性化**（用户离开再回来，AI 仍记得其姓名、习惯、未完成事项）；  
  ✅ 自动从**自然对话流**中提炼结构化事件（“设置明天下午3点会议” → 记忆节点）与用户属性（“我35岁，在阿里云工作” → 画像字段）；  
  ✅ 构建**可编程、可治理**的用户状态中心（支持按 `user_id` + `meta_data` 精准筛选、批量更新、设置过期策略）；  
  ✅ 开发 OpenClaw 等低代码平台应用，通过插件（如 `modelstudio-memory-for-openclaw`）实现零配置记忆捕获；  
  ❌ 不适合替代数据库存储强事务性数据（如订单支付状态），也不用于索引超大规模公开知识。

> **重要说明**：`记忆库（Memory Library）` 与 `长期记忆（Long-Term Memory，新）` **并非并列方案，而是同一能力的演进关系**。后者是前者的正式 API 标准化、功能增强与文档统一版本。开发者应优先使用 `长期记忆（新）` 的接口（路径 `/v2/apps/memory/...`），它具备更严谨的参数校验、完整的 SDK 支持（`agentscope-runtime`）、明确的多规则混合检索能力，并代表百炼长期记忆能力的未来方向。现有 `记忆库` 文档将逐步归档，新项目请直接集成 `长期记忆（新）`。

## 面向开发者的技术选型参考

| 选型决策树 | 推荐方案 | 关键依据 |
|------------|----------|----------|
| **我的数据是公司级文档/报表/音视频，需提升模型在专业领域的回答准确率** | ✅ 知识库 | 唯一支持多模态原始文件直传、NL2SQL、视觉理解、语音转写等 RAG 原生能力；地域限制需提前规划部署。 |
| **我的应用需记住每个用户的个性化信息（如偏好、待办、历史交互），且用户会多次回访** | ✅ 长期记忆（新） | `user_id` 隔离、自动抽取、`pro`/`lite` 策略可控、全生命周期 API；避免自行维护 Redis/DB 存储对话状态的复杂性。 |
| **我正在使用 OpenClaw 或 Model Studio 构建智能体，希望开箱即用记忆能力** | ✅ 长期记忆（新） + `modelstudio-memory-for-openclaw` 插件 | 插件已适配新 API，支持 `autoCapture`/`autoRecall` 钩子，5 分钟接入，无需手写 API 调用逻辑。 |
| **我需要同时利用公司知识库 *和* 用户个人记忆** | ⚡️ **组合使用**：知识库（`/v2/knowledge_bases/...`） + 长期记忆（`/v2/apps/memory/...`） | 在智能体工作流中，先调用知识库获取领域答案，再调用长期记忆注入用户上下文，最后交由大模型融合生成；二者数据域、权限模型、计费完全解耦。 |
| **我已有旧版记忆库集成，是否需要迁移？** | ✅ 建议迁移至长期记忆（新） | 接口兼容（路径/参数/认证一致），但新版本修复了文档歧义（如 `messages` 数组处理）、增强稳定性，并获得长期官方支持；旧版文档将不再更新。 |

**最后建议**：  
- **起步验证**：优先使用控制台快速创建知识库（文档搜索）或调用 `SearchMemory` API 测试效果，避免过早陷入架构设计；  
- **成本监控**：知识库的 Rerank 费用易被低估（与召回数而非返回数相关），长期记忆的 `pro` 调用成本高于 `lite`，务必在压测阶段开启配额告警；  
- **地域合规**：知识库功能受地域严格限制（仅北京/新加坡），而长期记忆全球可用，若您的用户分布广泛，此点可能成为关键约束。
