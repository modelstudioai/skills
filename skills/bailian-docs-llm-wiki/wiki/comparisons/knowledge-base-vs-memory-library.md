# 知识库与记忆库对比

阿里云百炼平台提供两种为大模型补充"外部信息"的能力：**知识库（Knowledge Base）** 与 **记忆库（Memory Library）**。二者名字相近、都涉及"检索后注入 Prompt"，但解决的问题、数据形态和使用方式截然不同。本文从技术选型角度对两者做系统对比，帮助开发者在 RAG 问答与跨会话记忆两类场景中做出正确取舍。

## 核心定位差异

- **知识库**：面向"**静态领域知识**"。基于 RAG（检索增强生成）为大模型补充**私有文档、结构化数据、图片、音视频**等企业资料，解决"模型不知道我的业务数据"的问题。知识由开发者主动导入、批量建索引。
- **记忆库**：面向"**动态用户记忆**"。通过长期记忆 API 自动从**对话流**中提取用户偏好、习惯、画像并持久化，解决"模型跨会话上下文丢失"的问题。记忆由系统在对话中自动沉淀、按用户隔离。

一句话概括：知识库让模型"懂业务"，记忆库让模型"记得你"。

## 关键维度对比

| 维度 | 知识库（Knowledge Base） | 记忆库（Memory Library） |
| --- | --- | --- |
| 解决的问题 | 补充私有/领域知识，提升特定领域问答准确性 | 跨会话上下文持久化，记住用户偏好与历史 |
| 数据来源 | 开发者主动导入的文档、Excel/CSV、图片、音视频 | 从对话消息自动提取，或 `custom_content` 直写 |
| 数据形态 | 非结构化文档、结构化表格、[多模态](../concepts/multimodal.md)资源 | 记忆片段（关键事件）+ 用户画像（结构化属性） |
| 检索方式 | 向量 + 关键词混合检索 → Rerank 排序 | 语义向量检索（`SearchMemory`，`top_k` 控制条数） |
| 数据隔离维度 | 按知识库（pipeline_id）/ 业务空间 | 按 `user_id` 命名空间完全隔离 |
| API 端点 | `bailian.cn-beijing.aliyuncs.com`（阿里云 SDK） | `https://dashscope.aliyuncs.com/api/v2/apps/memory/*`（HTTP） |
| 鉴权方式 | AccessKey ID/Secret + WORKSPACE_ID + RAM 策略 | `DASHSCOPE_API_KEY`（`sk-` 开头） |
| 地域限制 | 仅中国站华北2（北京）可开通使用 | 通过 DashScope 公网端点，无强地域绑定 |
| 典型入口 | 控制台可视化 + 开放 API | 控制台管理 + HTTP API + OpenClaw 插件（零侵入） |
| 有效期 | 索引长期存在，随知识库存续 | 片段/画像可配 7/30/180 天或永不过期（默认 180 天） |
| 计费方式 | 按规格计费：标准版 0.03 元/小时；旗舰版 0.2 元/RCU/小时 + 存储 | 随长期记忆 API 调用计费（DashScope） |
| 典型场景 | 企业文档问答、产品手册、NL2SQL、图文/音视频检索 | 智能体记住用户习惯、个性化助手、跨会话连续对话 |

## 能力细节补充

### 知识库
- **类型创建时固定**：文档搜索类、数据查询类（NL2SQL）、图片问答类、音视频搜索类，创建后不可更改。
- **规格分级**：标准版（1 QPS，≤100 GB）与旗舰版（50–10,000 QPS，按 RCU 计费，≤9,999 GB）。
- **解析多样**：电子文档解析、文档智能解析、大模型文档解析、Qwen VL 解析、音视频解析。
- **两条服务线**：知识检索服务（仅返回切片）与知识问答服务（检索 + 生成，含极速/多轮智能模式），均可绑定最多 15 个知识库。
- 注意：**开放 API 指南仅适用于文档搜索类知识库**。

### 记忆库
- **两类记忆内容**：记忆片段（自动提取、去重、动态更新）与用户画像（基于模板提取的结构化属性）。
- **三种接入**：API 直连（`AddMemory` / `SearchMemory`）、Python `agentscope-runtime`、OpenClaw 记忆插件。
- **零侵入接入**：OpenClaw 插件通过 `before_agent_start`（自动召回）与 `agent_end`（自动捕获）钩子工作；但全 Agent 共享同一记忆，且不支持 Coding Plan 的 API Key。

## 适用场景建议

**优先选择知识库**：
- 需要基于企业内部文档、产品手册、FAQ 做精准问答。
- 有结构化数据（Excel/CSV）需要自然语言查询（NL2SQL）。
- 涉及图片、富文本、音视频等[多模态](../concepts/multimodal.md)资料的检索与理解。
- 知识内容相对稳定、由团队集中维护和更新。

**优先选择记忆库**：
- 构建长期陪伴型智能体，需要跨会话记住用户偏好、习惯、画像。
- 希望对话上下文自动沉淀，无需手动维护数据集。
- 使用 OpenClaw Agent，期望以零侵入方式为其加装长期记忆。
- 记忆按用户强隔离、需要按用户 ID 独立命名空间。

## 技术选型参考

1. **数据是否随对话增长？** 是则用记忆库（自动提取），否则用知识库（批量导入）。
2. **需要[多模态](../concepts/multimodal.md)或结构化检索吗？** 需要则选知识库；记忆库聚焦文本对话记忆。
3. **鉴权与部署约束**：知识库依赖阿里云 AccessKey 且限华北2地域；记忆库用 DashScope API Key，接入更轻量。
4. **成本模型**：知识库按存储/QPS 规格持续计费，适合稳定的大规模知识资产；记忆库随 API 调用计费，适合按用户量弹性增长的记忆场景。
5. **二者并非互斥**：在个性化企业助手中，可同时用知识库回答业务问题、用记忆库记住用户偏好，两条链路的检索结果一并注入 Prompt，实现"既懂业务又记得你"的智能体。
