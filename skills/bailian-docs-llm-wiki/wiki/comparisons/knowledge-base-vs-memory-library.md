# 知识库与记忆库功能对比

本文旨在帮助开发者清晰区分百炼平台中**知识库（Knowledge Base）** 与**记忆库（Memory Library）** 两大核心能力的定位、技术实现与适用边界。二者虽均通过“检索 + 注入上下文”增强大模型能力，但设计目标、数据来源、生命周期及集成范式存在本质差异。正确选型可显著降低开发成本、避免资源浪费，并提升智能体的专业性与拟人性。

---

## 关键维度对比

| 维度 | 知识库（Knowledge Base） | 记忆库（Memory Library） |
|------|---------------------------|---------------------------|
| **核心定位** | 面向**领域知识增强**：注入静态/半静态、结构化或非结构化的**外部私有数据**（如产品文档、合同、数据库、音视频），解决“不知道”的问题。 | 面向**用户状态延续**：持久化存储动态生成的**对话衍生信息**（如用户偏好、待办事项、身份特征），解决“记不住”的问题。 |
| **数据来源** | 主动导入：OSS、飞书、钉钉、本地文件（PDF/Word/Excel/MP4等）、RDS 表；支持定时同步与 API 批量上传。 | 被动提取：从**当前会话对话消息**（`messages`）中自动解析，或通过 `custom_content` 显式写入；用户画像需绑定预定义模板（`ProfileSchema`）。 |
| **数据生命周期** | 长期稳定：内容由人工/系统维护，更新频率低（分钟级至天级）；支持版本管理与历史回溯（需自建机制）。 | 动态演进：事实记忆可设过期时间（规则配置），用户画像默认永续；支持 `Update`/`Delete` 操作，但删除不可逆。 |
| **输入格式** | [多模态](../concepts/multimodal.md)原始文件（文档、表格、图片、音视频）→ 自动解析 → 切片 → 向量化；支持 Meta 标签与结构化字段注入。 | 结构化请求体：`user_id` + `messages`（含 `role`/`content`）或 `custom_content`（纯文本）；用户画像需显式传入 `profile_schema_id`。 |
| **输出格式** | 检索结果为**语义相关文本切片列表**（含原文片段、来源位置、相似度分），格式统一为 `retrieved_chunks: [{content, source, score, ...}]`；支持多库联合返回。 | 检索结果为**结构化记忆对象列表**：事实记忆返回 `memory_nodes: [{id, content, timestamp, score, ...}]`；用户画像返回 `user_profile: {field1: value, field2: value, ...}`。 |
| **支持模型** | **分阶段调用**：<br>• 向量模型：`text-embedding-v4`、`qwen3-vl-embedding`<br>• 排序模型：`qwen3-rerank`、`qwen3-vl-rerank`<br>• 生成模型：全系千问（QwQ/Long/Max/Turbo/Coder/Deep-Research/VL/Qwen3/Qwen2.5/Qwen2）、DeepSeek-R1、Llama3.1、Yi-Large 等。 | **专用记忆模型**：<br>• 抽取模型（Add）：内置 `Pro`（高质量）与 `Lite`（轻量）两档<br>• 检索模型（Search）：底层复用向量+Rerank（`Pro`启用，`Lite`跳过），不暴露具体模型名；无第三方模型接入能力。 |
| **API 端点** | 百炼专属 SDK（`bailian20231229`）：<br>• `CreateIndex` / `SubmitIndexJob`（建库）<br>• `Retrieve` / `RetrieveWithRerank`（检索）<br>• `ListKnowledgeBases`（管理）<br>鉴权使用 `BAI_LIAN_API_KEY`。 | DashScope 统一网关（RESTful）：<br>• `POST /add` / `POST /memory_nodes/search` / `GET /profile_schemas/{id}/user_profile`<br>• 全路径：`https://dashscope.aliyuncs.com/api/v2/apps/memory/`<br>鉴权使用 `DASHSCOPE_API_KEY`。 |
| **计费方式** | **复合计费**：<br>• **规格费**：按知识库类型（标准版 0.03 元/小时；旗舰版按 RCU）<br>• **模型费**：向量化、Rerank、问答生成三阶段独立计费（[Token](../concepts/token.md) 实际用量）<br>• 多库并行时费用线性叠加。 | **按调用次数 + 存储量计费**（2026年8月20日起）：<br>• `AddMemory`：按次计费（`Pro`/`Lite` 单价不同）<br>• `SearchMemory`：按次计费（`Pro`启用 Rerank，单价更高）<br>• 存储：按长期有效记忆条数计费（免费额度内 10,000 条）<br>• 无模型 [Token](../concepts/token.md) 费用。 |
| **典型场景** | • 客服知识问答（基于产品手册/FAQ）<br>• 合同条款智能审查（PDF+表格）<br>• 视频会议纪要检索（MP4→字幕→切片）<br>• 数据库自然语言查询（SQL 表结构+样例数据） | • 智能助手记住用户习惯（“每天9点提醒喝水”）<br>• 销售 Bot 持续追踪客户意向（“关注价格，预算5万”）<br>• 教育 Bot 记录学生薄弱知识点（“三角函数恒等变换易错”）<br>• 多轮对话中自动补全用户身份（“张医生，您上次提到的患者李XX…”） |
| **地域支持** | 仅限 **中国站华北2（北京）**、**国际站新加坡**。其他地域（如法兰克福）不可用。 | **全地域可用**（与 DashScope 服务地域一致），无地域限制。 |
| **隔离粒度** | 知识库级隔离：每个知识库为独立索引空间；支持标签/Meta 过滤，但跨库检索需显式指定。 | `user_id` 级隔离：同一 `user_id` 下所有记忆（事实+画像）自动聚合；支持多应用共享同一 `user_id` 空间。 |
| **高级能力** | • 多轮对话 Query 改写（自动补全）<br>• 标签过滤 / Meta 字段精准召回<br>• [多模态](../concepts/multimodal.md)联合检索（图文音视）<br>• 知识检索服务（多库融合） | • `plan_version` 可控质量/成本权衡（Pro/Lite）<br>• 用户画像模板驱动结构化提取<br>• `autoCapture`/`autoRecall` 插件式零侵入集成<br>• 异步画像提取（约3秒延迟） |

## 适用场景建议

### ✅ 选择知识库，当您需要：
- 将**企业私有资料**（如内部Wiki、技术文档、法律条文、产品说明书）转化为可被大模型精准引用的知识源；
- 支持**复杂格式内容理解**（扫描PDF、Excel公式、会议视频字幕、产品图片标注）；
- 构建**面向业务系统的专业问答能力**，要求答案强事实性、可溯源、高一致性；
- 需要**跨用户共享知识**（如客服知识库供全体坐席调用）；
- 对检索精度要求极高，且愿意为 Rerank 和高质量向量模型支付额外成本。

### ✅ 选择记忆库，当您需要：
- 构建**具备“人格感”和“连续性”的智能体**，使其在多次对话中主动识别并响应用户个性化需求；
- 快速沉淀**对话中涌现的关键事实**（如预约时间、投诉诉求、偏好设置），无需人工标注或建库；
- 基于**预定义用户属性框架**（如CRM字段）自动构建结构化用户画像，用于个性化推荐或风控判断；
- 在**多应用/多渠道**（App、小程序、Web）间统一维护同一用户的[长期记忆](../concepts/memory.md)；
- 追求**低代码集成与快速验证**，利用 `autoCapture`/`autoRecall` 插件实现开箱即用的记忆闭环。

### ⚠️ 避免混淆的典型误区：
- ❌ 用记忆库存储产品手册——内容静态、非对话生成、需多人共享，应属知识库范畴；  
- ❌ 用知识库记录“用户昨天说想买MacBook”——该信息时效性强、高度个性化、源于对话，是典型事实记忆；  
- ❌ 在无 `user_id` 场景下强行使用记忆库——`user_id` 是强制必填项，缺失将导致数据污染或无法隔离；  
- ❌ 期望记忆库支持 PDF 解析或表格查询——其输入仅为文本消息或字符串，不处理原始文件。

## 技术选型参考（面向开发者）

| 选型考量点 | 推荐方案 | 说明 |
|------------|----------|------|
| **是否需要处理原始文件（PDF/Excel/MP4）？** | → 知识库 | 记忆库仅接受文本输入，无解析能力。 |
| **数据是否来自用户实时对话？** | → 记忆库 | 知识库数据需预先导入，无法自动捕获对话流。 |
| **是否要求跨会话、跨用户共享同一份知识？** | → 知识库 | 记忆库天然按 `user_id` 隔离，共享需额外设计（如固定 `user_id` 或导出再导入）。 |
| **是否需严格控制答案出处（如标注页码/章节）？** | → 知识库 | 其检索结果携带完整来源元信息（`source` 字段），记忆库仅返回抽象内容。 |
| **是否追求最低延迟 & 最高 QPS？** | → 记忆库（`Lite` 模式） | `Lite` 检索跳过 Rerank，延迟更低；知识库 Rerank 为必选环节（除非禁用，但影响精度）。 |
| **是否已有成熟向量数据库/ES集群，希望复用？** | → 知识库（自定义向量库接入） | 百炼知识库支持对接用户自有向量库（需配置），记忆库为全托管服务，不可替换底层。 |
| **是否需与工作流引擎（如 OpenClaw）深度集成？** | → 两者皆可，但路径不同 | 知识库通过「文档知识库节点」嵌入工作流；记忆库通过「[长期记忆](../concepts/memory.md)插件」（如 `modelstudio-memory-for-openclaw`）无缝注入。 |

> **最佳实践提示**：在复杂智能体中，**知识库与记忆库常协同使用**。例如：客服 Bot 先用知识库回答“退货政策”，再用记忆库记住“该用户本次申请的是iPhone 15 Pro退换”，最后在后续对话中主动关联：“您之前咨询的iPhone 15 Pro退换，物流单号已更新为SF123456789”。
