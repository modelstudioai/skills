# 模型微调、压缩与部署对比

百炼平台围绕模型的全生命周期提供了微调（Fine-Tuning）、压缩（Compression）和部署（Deployment）三项核心能力。三者在工作流中通常按顺序衔接——先通过微调让模型适配特定业务，再通过压缩降低推理成本，最后通过部署上线对外服务。本文从多个维度横向对比三者的定位、输入输出、支持范围和计费方式，帮助开发者快速做出技术选型。

## 核心维度对比

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
|------|---------|---------|---------|
| **核心目标** | 提升模型在特定场景下的表现 | 降低推理显存占用与部署成本 | 将模型上线为可调用的推理服务 |
| **输入** | 训练数据集（JSONL/ZIP）+ 基础模型 | 全精度自定义微调模型 + 校准数据（可选） | 预置模型或微调/压缩后的模型 |
| **输出** | 微调后的自定义模型（参数快照） | 量化后的低精度模型 | 可调用的在线推理服务（API 端点） |
| **操作方式** | 控制台 + API | 控制台（+ OpenAPI） | 控制台 + API |
| **支持的模型范围** | Qwen3/2.5 文本、千问VL、万相视频/图像、CosyVoice 语音 | 仅部分全精度微调模型（如 qwen3.5-flash） | 预置模型（千问、DeepSeek、GLM 等）及自定义微调/压缩模型 |
| **调优/处理方法** | CPT、SFT（全参/高效）、DPO（全参/高效） | 量化模板（指定目标部署规格） | PTU / 模型单元（MU）/ 按 Token 用量 |
| **计费方式** | 按训练消耗 Token 数计费 + 部署费用 | 当前限时免费（部署后按 MU 规格计费） | PTU 按吞吐时长、MU 按单元时长、按 Token 按用量 |
| **典型耗时** | 视数据量和模型大小，数小时至数天 | 通常较短，视模型大小而定 | 部署上线后即可调用 |
| **可逆性** | 可基于同一基础模型反复训练 | 不可逆，不支持二次压缩或继续训练 | 可随时下线并重新部署 |
| **地域限制** | 仅华北2（北京） | 仅华北2（北京） | 仅华北2（北京） |

## 数据格式对比

| 功能 | 数据格式 | 格式说明 |
|------|---------|---------|
| 微调-SFT | JSONL（ChatML） | 每行一条多轮对话样本，含 system/user/assistant 角色 |
| 微调-DPO | JSONL | 在 messages 基础上增加 chosen/rejected 字段 |
| 微调-CPT | JSONL | 纯文本格式，每行 `{"text": "..."}` |
| 微调-视频/图像 | ZIP | 训练素材 + data.jsonl 标注文件打包 |
| 压缩 | 校准数据集 | 从已发布数据集中选择，用于量化校准 |
| 部署 | 无需额外数据 | 直接选择已有模型进行部署 |

## 计费方式详细对比

| 计费维度 | 模型微调 | 模型压缩 | 模型部署 |
|---------|---------|---------|---------|
| **训练/处理费用** | 按 Token 计费，单价因模型而异（如 Qwen3-8B 为 0.006 元/千Token） | 当前限时免费 | 不涉及 |
| **运行时费用** | 部署后按 MU 计费 | 部署后按压缩目标规格的 MU 计费 | PTU 按吞吐时长；MU 按单元数×时长；按 Token 按实际用量 |
| **成本优化效果** | 通过高效训练（LoRA）降低训练成本 | 压缩后可部署到更小 MU 规格，显著降低运行成本 | PTU 保障吞吐、MU 资源独占、按 Token 按需付费 |

## 适用场景建议

- **模型微调**：当现有模型在特定业务场景下表现不佳，且 [Prompt 工程](../concepts/prompt-engineering.md)等轻量方法无法满足需求时使用。适合客服对话、代码助手、垂直领域知识注入、安全合规对齐等场景。推荐从 SFT 高效训练开始验证，效果不满意再考虑全参训练或 DPO。

- **模型压缩**：当微调后的模型部署成本过高，希望在可接受的精度损失范围内降低推理资源消耗时使用。适合已经完成微调、模型效果达标但部署预算有限的场景。需注意压缩不可逆，建议保留原始全精度模型。

- **模型部署**：所有需要将模型上线为在线服务的场景都需要部署。根据业务特点选择计费方式——流量稳定选 PTU 保障吞吐，需要资源独占和灵活配置选 MU，流量波动大或初期验证选按 Token 计费。

## 典型工作流

对于大多数业务场景，推荐的完整工作流为：

1. **微调阶段**：选择合适的基础模型，准备训练数据，通过 SFT/DPO 微调模型
2. **压缩阶段**（可选）：对全精度微调模型进行量化压缩，降低部署规格需求
3. **部署阶段**：选择合适的计费方式，将模型部署上线，通过 API 对外提供服务

三个环节各司其职又紧密衔接，开发者应根据业务需求、预算和性能要求，灵活组合使用。
