# 知识库 vs 记忆库 vs 数据接入对比

阿里云百炼平台提供了三种核心数据管理机制：**知识库**（基于 RAG 的文档[检索增强生成](../concepts/rag.md)）、**记忆库**（跨会话长期记忆）和**数据连接**（外部数据源实时接入）。三者解决的问题域不同，但在实际应用架构中经常需要组合使用。本文从技术定位、数据特征、接入方式、计费模式等维度进行系统对比，帮助开发者在不同场景下做出合理选型。

## 核心定位对比

| 维度 | 知识库 | 记忆库 | 数据连接 |
|------|--------|--------|----------|
| 核心目标 | 为大模型补充私有文档和最新信息，提升回答准确性 | 让智能体具备跨会话的长期记忆能力，实现个性化对话 | 安全接入企业外部数据源，实时查询和引用数据 |
| 技术原理 | RAG（[检索增强生成](../concepts/rag.md)）：先检索再生成 | 自动提取对话关键信息，语义检索后注入上下文 | 连接器模式，数据留在原位或托管于平台 |
| 数据来源 | 用户上传的文档（PDF、Word、Markdown 等） | 对话过程中自动提取或手动写入 | 外部数据库、文件系统、对象存储等 |
| 数据流向 | 单向：文档 -> 向量化 -> 检索 -> 注入上下文 | 双向：对话 -> 提取记忆 / 记忆 -> 注入对话 | 实时：应用 -> 连接器 -> 外部数据源 |

## 数据类型与格式对比

| 维度 | 知识库 | 记忆库 | 数据连接 |
|------|--------|--------|----------|
| 输入格式 | PDF、DOCX、TXT、MD、HTML、Excel、CSV、图片、音视频 | 对话消息（messages）或自定义文本（custom_content） | 取决于连接器类型：文件、表格、SQL 数据库、语雀文档、OSS |
| 数据结构 | 非结构化文档 + 结构化表格 | 记忆片段（非结构化）+ 用户画像（结构化） | 结构化（数据库）+ 非结构化（文件） |
| 存储方式 | 平台存储或自购 ADB-PG | 平台托管 | 平台托管或数据留在原数据源 |
| 数据持久性 | 持久存储，手动管理生命周期 | 可配置过期时间（7/30/180 天或永不过期） | 流处理类数据留在原库；托管类持久存储 |

## 知识库类型与数据连接器类型

知识库按检索场景分为四种类型：

| 知识库类型 | 适用数据 | 核心能力 |
|-----------|---------|---------|
| 文档搜索 | 企业文档、产品手册等非结构化数据 | 语义检索，支持基础问答、图文回复、视觉理解、极速问答 |
| 数据查询 | 单个 Excel 或 CSV 文件 | 结构化数据查询 |
| 图片问答 | 图片文件 | multimodal-embedding-v1 模型支持 |
| 音视频搜索 | 音视频文件 | 语音识别、视频帧提取、剧情解析 |

数据连接器按访问方式分为两大类：

| 连接器类别 | 类型 | 数据位置 |
|-----------|------|---------|
| 平台托管 | 文件、表格 | 百炼平台或自有 OSS |
| 流处理 | MySQL、PostgreSQL、PolarDB-X 2.0、语雀、OSS | 数据留在原数据源 |

## API 与集成方式对比

| 维度 | 知识库 | 记忆库 | 数据连接 |
|------|--------|--------|----------|
| 主要 API | Retrieve API（检索）、文件管理 API（上传/索引） | AddMemory、SearchMemory、ListMemory、UpdateMemory、DeleteMemory | 通过连接器配置后由应用自动调用 |
| SDK 支持 | 百炼 SDK（Python/Java） | agentscope-runtime（Python）、cURL | 控制台配置为主 |
| 集成方式 | 关联到智能体应用、工作流应用或通过 SDK 集成 | API 直接调用 或 OpenClaw 插件零代码集成 | 控制台创建连接器，应用中引用 |
| 认证方式 | AccessKey + 业务空间 ID | DASHSCOPE_API_KEY | 控制台 RAM 权限 + 数据源账密 |
| 权限要求 | AliyunBailianDataFullAccess（子账号） | 无特殊权限要求 | 主账号或数据连接管理权限的 RAM 用户 |

## 性能与配额对比

| 维度 | 知识库 | 记忆库 | 数据连接 |
|------|--------|--------|----------|
| 并发能力 | 标准版 1 QPS；旗舰版 50-10,000 QPS | AddMemory 120 次/分钟；SearchMemory 300 次/分钟；合计 3000 次/分钟 | 取决于底层数据源性能 |
| 存储上限 | 标准版 100 GB；旗舰版 9,999 GB；文件数 100,000/业务空间 | 无明确存储上限 | 文件连接器：100,000 文件 / 1 TB |
| 单次检索限制 | 最多召回 20 个切片 | 建议 top_k 设为 3-10 | 无统一限制 |
| 延迟参考 | 取决于规格和检索参数 | SearchMemory 200-500ms；AddMemory 500-1000ms | 取决于数据源网络和查询复杂度 |

## 计费模式对比

| 维度 | 知识库 | 记忆库 | 数据连接 |
|------|--------|--------|----------|
| 基础费用 | 标准版 0.03 元/小时；旗舰版 0.2 元/RCU/小时 | 限时免费 | 平台存储 1 TB 免费额度（文件/表格连接器） |
| 模型调用费用 | 向量化 + 排序模型按 Token 计费 | 暂无 | 无独立模型费用 |
| 免费额度 | 新用户 720 小时标准版（30 天内有效） | 全功能限时免费 | 平台存储限时免费 |
| 费用优化手段 | 关闭排序、降低初步召回参数、购买资源包 | 不适用 | 使用自有 OSS 避免平台存储费用 |

## 适用场景建议

### 选择知识库的场景

- 需要基于企业内部文档（产品手册、技术文档、FAQ）进行问答
- 数据以非结构化文档为主，需要语义检索能力
- 对检索精度有较高要求，需要调优切片策略、相似度阈值等参数
- 需要高并发生产级部署（旗舰版）

### 选择记忆库的场景

- 需要智能体记住用户的个人偏好、历史交互信息
- 构建个性化助手，要求跨会话连续对话体验
- 需要自动从对话中提取和积累用户画像
- 希望零代码集成长期记忆能力（通过 OpenClaw 插件）

### 选择数据连接的场景

- 需要实时查询企业数据库（MySQL、PostgreSQL、PolarDB-X 2.0）中的业务数据
- 数据分散在多个系统中（数据库、语雀、OSS），需要统一接入
- 数据需要留在原位，不希望复制到百炼平台
- 需要对结构化数据执行 SQL 查询

### 组合使用建议

在实际应用中，三者往往组合使用以构建完整的数据增强方案：

- **知识库 + 记忆库**：智能体既能检索企业知识文档回答专业问题，又能记住用户偏好提供个性化服务
- **知识库 + 数据连接**：文档知识与实时业务数据互补，适合需要同时查阅文档和查询数据库的场景
- **三者结合**：构建具有知识检索、实时数据查询和个性化记忆能力的全功能智能体
