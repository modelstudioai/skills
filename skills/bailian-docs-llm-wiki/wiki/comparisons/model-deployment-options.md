# 模型部署方式对比：托管服务 vs 自定义部署

本文旨在帮助开发者在百炼平台上进行技术选型时，清晰理解「托管服务」与「自定义部署」两类模型部署范式的本质差异、能力边界与适用约束。随着模型应用从实验验证走向生产落地，部署方式的选择直接影响系统稳定性、成本效率、运维复杂度及功能可扩展性。本文基于当前平台（2025年Q3）最新能力，结合计费模型、API 行为、模型支持范围与生命周期管理等维度，提供结构化对比与实操建议。

> ⚠️ 说明：本文中  
> - **“托管服务”** 指百炼平台统一纳管、开箱即用的标准化部署能力，包括 **PTU（预置吞吐）、MU/DTU（独占算力）、[Token](../concepts/token.md) 按量（LoRA 共享）及智能路由**；  
> - **“自定义部署”** 特指通过 **自定义模型导入 + MU/DTU 部署** 实现的私有化模型上线路径（含全参微调、LoRA 微调、量化压缩模型），**不包含用户自行搭建的 Kubernetes / Triton 等外部推理服务**（该类方案不在百炼平台 SLA 保障范围内，亦不纳入本文对比）。

---

## 关键维度对比表

| 维度 | 托管服务（PTU / MU / DTU / [Token](../concepts/token.md) 按量 / 智能路由） | 自定义部署（OSS 导入 + MU/DTU 部署） |
|------|--------------------------------------------------|----------------------------------------|
| **输入格式** | 支持标准文本、多轮对话（`messages`）、图片（Base64 或 URL）、文件引用（PDF/TXT/DOCX 等）；智能路由仅限文本 `chat.completions` 格式 | 同托管服务（依赖所导入模型的 tokenizer 与 `chat_template` 兼容性）；**需严格满足 OSS 导入规范**（如 LoRA 的 `rank`、`lora_alpha`、`target_modules` 校验） |
| **输出格式** | 完全兼容 DashScope/OpenAI 接口规范（`choices[0].message.content` / `delta.content` 流式）；支持 `enable_thinking` 返回思考过程 | 完全一致；但若自定义模型未实现 `thinking` token 解析逻辑，`enable_thinking=true` 可能导致解析异常或计费偏差 |
| **支持模型** | ✅ 预置主流模型（Qwen、DeepSeek、GLM、Qwen-VL 等）<br>✅ 智能路由支持动态模型集（`qwen3.8-max`, `deepseek-v4-flash-0731`）<br>❌ 不支持用户自训练/自优化模型 | ✅ LoRA 微调模型（百炼调优产出或符合 OSS 规范导入）<br>✅ 全参微调模型（需白名单开通）<br>✅ 量化压缩模型（仅限 `qwen3.5-flash-2026-02-23` 全参模型）<br>❌ 不支持原始 HuggingFace 模型直接部署（必须经百炼校验与封装） |
| **API 端点** | 统一使用 `https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation`（DashScope）或 `https://api.maaS.aliyuncs.com/v1/chat/completions`（OpenAI 兼容）；智能路由强制使用 `maas.aliyuncs.com` 域名 | **完全相同端点** —— 部署后生成唯一 `model-code`，调用方式、Header、Body 结构与托管服务完全一致，无额外适配成本 |
| **计费方式** | • PTU：按保底吞吐量（kTPM）预付费，阶梯容量系数影响实际可用量<br>• MU/DTU：MU 按模型单元（MU1/MU5）数量计费；DTU 按输入/输出 TPM 计费<br>• [Token](../concepts/token.md) 按量：仅对 LoRA 模型按实际调用 Token 计费，闲置 30 天自动释放<br>• 智能路由：按实际路由到的模型计费（效果优先策略可能触发高价模型） | **与所选部署模式完全一致**：导入后部署为 MU 即按 MU 计费，部署为 DTU 即按 DTU 计费，部署为 Token 按量即按 Token 计费；**无额外“导入费”或“模型管理费”** |
| **典型场景** | • PTU：内容审核、长文档摘要（1M token）、高并发客服机器人<br>• MU/DTU：新模型灰度发布、敏感业务专属算力隔离、需强 SLA 保障的金融/政务场景<br>• Token 按量：A/B 测试、POC 验证、低频内部工具<br>• 智能路由：效果敏感型应用（如搜索问答），需自动 fallback | • 私有知识增强：基于企业私有数据微调的 LoRA 模型<br>• 合规要求：模型权重不出域、推理链路全可控<br>• 性能定制：通过量化压缩降低显存占用、提升吞吐<br>• [多模态](../concepts/multimodal.md)扩展：自定义图像/视频生成模型（需匹配 `aigc_config`） |
| **部署时效性** | • PTU/MU/DTU：控制台提交后约 2–5 分钟就绪（资源充足时）<br>• Token 按量：秒级创建<br>• 智能路由：配置后即时生效 | • 模型导入：OSS 文件校验约 30–120 秒（取决于模型大小与网络）<br>• 部署：同 MU/DTU/Token 按量时效（导入成功后即可部署） |
| **扩缩容能力** | • PTU：支持自助增减 `input_tpm`/`output_tpm`（实时生效）<br>• MU/DTU：支持调整副本数或规格（如 MU1→MU5），需重启服务<br>• Token 按量：不支持自助扩缩，需人工申请 | **完全继承所选部署模式的能力**：导入后的模型可自由选择 MU/DTU/Token 按量任一方式部署，并享受对应扩缩容能力 |
| **生命周期管理** | • PTU/DIU：支持续订、退订（已用部分按 1.2 倍结算）<br>• Token 按量：30 天无调用自动释放<br>• 智能路由：`model-code` 删除后不可复用 | **完全一致**：导入模型本身长期保留在「我的模型」中心；部署实例的生命周期规则与托管服务完全相同 |

## 适用场景建议

### ✅ 推荐选择「托管服务」当：
- **快速验证 MVP**：无需训练/微调，直接调用 Qwen-Max、DeepSeek-VL 等预置模型完成原型开发；
- **高并发、稳延迟需求明确**：如日均百万请求的智能客服，选用 PTU 可规避资源争抢，保障 `p99 < 2s`；
- **成本敏感且负载波动大**：Token 按量模式下，测试期零调用=零费用，避免资源闲置浪费；
- **需多模型动态协同**：例如搜索结果需先用 `qwen-turbo` 快速初筛，再用 `qwen-max` 深度精排，智能路由可自动调度。

### ✅ 推荐选择「自定义部署」当：
- **业务强依赖私有知识**：如法律合同审查、医疗报告生成，必须基于行业语料微调，且需确保模型权重与推理环境自主可控；
- **已有成熟微调 pipeline**：团队具备 LoRA 全流程能力（数据清洗 → 训练 → 评估 → 导出），希望将百炼作为生产推理层而非训练平台；
- **性能/成本深度优化需求**：通过量化压缩将 `qwen3.5-flash` 显存占用降低 40%，在 MU1 上实现原 MU3 的吞吐，显著降本；
- **合规审计要求严格**：需提供模型来源证明、训练数据清单、推理日志留存等，自定义部署便于构建完整溯源链。

### ⚠️ 不建议混合使用的场景：
- 将同一业务同时接入托管服务（如 `qwen-plus`）与自定义部署（如 `my-qwen-plus-finetuned`）并做简单负载均衡 —— 因两者 Token 计费逻辑、上下文长度限制、采样参数支持度（如 `top_p` 在智能路由中不可用）存在差异，易引发结果不一致与计费异常。

## 开发者技术选型 checklist

请在决策前逐项确认：

- [ ] **模型是否已在百炼预置列表中？**  
  → 是 → 优先尝试托管服务（PTU/MU）；  
  → 否 → 进入自定义部署流程（需确认是否支持 LoRA/全参导入）。

- [ ] **是否需要微调？**  
  → 否 → 托管服务全覆盖；  
  → 是 → 检查微调类型：文本生成（支持 SFT/DPO）、图像/语音（仅 LoRA）→ 对应选择百炼微调 API 或 OSS 导入。

- [ ] **SLA 要求是否明确？**  
  → 需要 99.9% 可用性 + p95 < 1.5s → 选择 MU/DTU（独占算力）；  
  → 可接受弹性延迟（如后台批处理）→ PTU 或 Token 按量更经济。

- [ ] **月均预估 Token 消耗量？**  
  → < 100 万 → Token 按量成本最低；  
  → > 500 万 → 对比 PTU 保底价与 DTU 实际用量价，通常 PTU 更优；  
  → 波动剧烈（如促销期激增 10 倍）→ PTU 扩容更平滑。

- [ ] **是否需跨地域部署？**  
  → 是 → 注意：微调/导入/常规部署 API **仅北京地域可用**；吞吐预留（PTU）支持多地域，但需切换 Endpoint 与 API Key。

- [ ] **是否有[长期记忆](../concepts/memory.md)、工具调用等 Agent 能力需求？**  
  → 是 → 直接使用 **Managed Agents API**（托管服务），其底层自动绑定 `qwen-max` 等托管模型，**不支持挂载自定义模型**。

---

> 💡 提示：所有部署服务（无论托管或自定义）均通过统一 `model-code` 调用，开发者可利用此特性实现灰度发布 —— 例如先将 5% 流量切至新导入的 LoRA 模型，其余走 `qwen-plus` 托管服务，通过 A/B 测试指标（响应时长、准确率、Token 成本）决策全量节奏。
