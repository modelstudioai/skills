# 模型部署方式对比：高并发推理、模型压缩与模型监控

为帮助开发者在百炼平台高效构建稳定、低成本、可观测的 AI 服务，本文系统对比三大核心部署支撑能力：**高并发推理（High-Speed Inference）**、**模型压缩（Model Compression）** 和 **模型监控（Model Monitoring）**。三者定位不同——高并发推理解决“如何更快更稳地跑模型”，模型压缩解决“如何在资源受限时轻量运行模型”，模型监控解决“模型上线后是否健康、是否可控”。本对比聚焦技术选型关键维度，不替代具体操作文档，旨在提供清晰、可落地的决策依据。

## 关键维度对比表

| 维度 | 高并发推理 | 模型压缩 | 模型监控 |
|------|-------------|------------|-------------|
| **核心目标** | 提升吞吐量、降低首字延迟、保障服务确定性 | 减小模型体积与显存占用，适配边缘/高密部署场景 | 实现生产环境模型可观测性，支持故障排查、成本治理与 SLA 保障 |
| **输入格式** | 标准 API 请求（JSON），含 `model`、`messages`、`stream` 等字段；Batch 场景需 JSONL 文件 | 压缩任务请求（JSON），含 `model_id`、`compression_type`、`calibration_dataset` 等；源模型需已注册为 Hugging Face 格式 | 无主动输入；自动采集所有调用请求的元数据（Request ID、状态码、Token 数、延时等）；推理日志需手动开启并投递至 SLS |
| **输出格式** | 实时响应（JSON/Stream）、异步结果文件（Batch）、或路由解析头（`x-dashscope-resolved-model`） | 压缩任务状态（`pending`/`running`/`success`/`failed`）；成功后生成新模型 ID（如 `qwen2-1.5b-chat-awq-int4`）及部署就绪通知 | 图表化监控指标（失败率、首 Token 延迟、TPM、限流次数等）、告警通知（邮件）、结构化日志（审计日志含元数据；推理日志含完整 Prompt/Response，≤128KB） |
| **支持模型** | 全量百炼托管模型（Qwen/GLM/DeepSeek 等）及专属部署模型；Prime/PTU/DTU/Batch/智能路由均有明确支持列表 | 仅限开源模型：`Qwen2-1.5B`、`Qwen2-7B`、`Phi-3-mini-4k-instruct`；不支持 LoRA 微调模型直接压缩，需先合并权重 | 所有可调用模型均支持**用量统计**；但**监控告警**功能不支持语音/图片/视频生成类及三方直连模型（需控制台实时确认） |
| **API 端点** | 主调用端点统一为 `/v1/chat/completions` 或 `/v1/completions`，但需配合专用域名（如 Prime 模式用 `cn-beijing.maas.aliyuncs.com`）或专属 `model` ID（如 `ptu-xxx`、`auto-model-xxxx`） | 专用管理端点：<br>`POST /api/v1/model-compression`（提交任务）<br>`GET /api/v1/model-compression/{task_id}`（查询状态） | 无直接调用 API；全部通过控制台访问：<br>用量页 → `costing-balance/usage-statistics`<br>监控页 → `model/telemetry`<br>告警页 → `model/alert`<br>日志页 → 监控详情页内跳转 |
| **计费方式** | 按实际消耗 Token 计费（标准价）；<br>• Prime/PTU/DTU：额外收取容量预留费（按 kTPM/月或 GPU 小时）；<br>• Batch：单价约为实时推理的 50%；<br>• 智能路由：按实际执行模型计费 | **不产生推理费用**；压缩任务本身免费，但需消耗平台算力配额（超时任务不计费但不返还配额）；压缩后模型部署与调用按标准 Token 计费 | **完全免费**（基础用量统计与监控）；<br>• 推理日志投递至 SLS 后，按 SLS 实际用量计费；<br>• 告警依赖云监控服务角色授权，开通后可能产生 Prometheus/SLS 基础资源费用（按量付费） |
| **典型场景** | • 秒级响应的 C 端对话应用（客服机器人、AI 助手）<br>• 大促期间流量洪峰保障（电商搜索推荐）<br>• 多模型 A/B 测试与自动选优（智能路由）<br>• 非实时批量处理（日志分析、报告生成） | • 边缘设备部署（车载终端、IoT 设备）<br>• 高并发低延迟微服务（千节点级 API 网关后端）<br>• 显存受限环境（单卡 A10/A100 运行多实例）<br>• 快速验证模型轻量化效果（POC 阶段） | • 生产环境 SLA 巡检（失败率 >1% 自动告警）<br>• 成本异常检测（TotalToken 突增 300% 触发通知）<br>• 故障根因分析（结合首 Token 延迟 + 限流错误 + 日志上下文）<br>• 合规审计（保留 Request ID 与 Token 用量记录） |

## 各方案适用场景建议

| 方案 | 推荐采用场景 | 不建议采用场景 | 关键提醒 |
|------|----------------|------------------|-----------|
| **高并发推理** | ✅ 流量可预测且峰谷比高（如工作日 9–18 点集中调用）<br>✅ 对首 Token 延迟（P99 < 800ms）或 TPS 稳定性有强 SLA 要求<br>✅ 需要模型能力不变前提下的极致性能提升（如 Prime 模式）<br>✅ 需平衡效果与成本（智能路由）或处理非实时大批量任务（Batch） | ❌ 流量极低频、偶发性调用（预留资源闲置成本高）<br>❌ 模型尚未完成效果验证，需频繁迭代（PTU/DTU 部署周期长）<br>❌ 客户端无法适配流式解析（`delta.reasoning_content` 字段）或专属域名 | • Prime 模式必须使用专属域名，否则降级为标准 API<br>• Batch 不返回 `reasoning_content`，且不支持纯文本 `qwen3.8-max`<br>• 智能路由禁用 `temperature`/`top_p` 等 12 个参数，仅支持 OpenAI 协议 |
| **模型压缩** | ✅ 部署环境显存紧张（如单卡 A10 8GB 运行 Qwen2-7B）<br>✅ 需在边缘设备（Jetson Orin、RK3588）本地运行模型<br>✅ 快速验证量化/剪枝对业务指标（如 QA 准确率）影响<br>✅ 已完成[模型微调](../concepts/model-fine-tuning.md)并合并权重，进入轻量化交付阶段 | ❌ 使用闭源或自定义结构模型（非标准 HF 格式）<br>❌ 需要 `embedding`/`rerank` 等非生成类能力（压缩后模型不支持）<br>❌ 对精度损失极度敏感（INT4 可能导致 1–3% 下降，需校准验证）<br>❌ 需要在线动态压缩（仅支持离线任务） | • `awq_int4` 必须指定 `calibration_dataset`，否则任务失败<br>• 压缩后模型 ID 为 `{model_id}-{compression_type}`，需在 API 中显式调用<br>• 剪枝比例 `pruning_ratio=0.3` 表示保留 30% 注意力头（非剪掉 30%） |
| **模型监控** | ✅ 模型已上线生产，需建立运维闭环（监控→告警→日志→复盘）<br>✅ 多团队共用业务空间，需按 API-Key 追踪用量与问题归属<br>✅ 需满足内部合规要求（保留审计日志 ≥30 天）<br>✅ 成本敏感型项目，需实时感知 Token 消耗趋势 | ❌ 模型处于开发调试阶段（无真实流量，监控价值低）<br>❌ 使用不支持告警的模型类型（如 `wan3.0-video-prime`）且无需用量统计<br>❌ 未完成云监控服务角色授权（告警创建按钮置灰）<br>❌ 部署地域非北京/新加坡（推理日志不可用） | • 用量数据延迟约 1 小时，监控指标为分钟级延迟<br>• “免费额度用完即停”开关**仅能在额度未耗尽时开启**<br>• 关闭审计日志投递将**永久丢失**推理日志能力，且无法补录 |

## 技术选型参考（面向开发者）

作为开发者，在设计模型服务架构时，请按以下逻辑分层决策：

1. **先定“观测底线”**：  
   无论选择何种部署方式，**模型监控是生产环境的必备基础设施**。请在模型首次上线前，完成云监控服务角色授权，并至少配置两项基础告警：`调用失败率 > 1%` 和 `TotalToken 数环比突增 200%`。用量统计应作为每日巡检项，避免账单异常。

2. **再选“运行形态”**：  
   - 若流量稳定、SLA 要求严苛（如金融风控对话），优先评估 **PTU/DTU 预留** 或 **Prime 模式**；  
   - 若流量波动大、成本敏感，且可接受秒级延迟，选用 **智能路由**；  
   - 若任务天然批量、非实时（如每日 10 万条用户评论情感分析），**Batch 推理** 是性价比最优解；  
   - 若需在边缘设备或低配 GPU 上运行，且模型在支持列表中，**模型压缩** 是必选项，建议从 `rtn_int8` 开始验证，再尝试 `awq_int4`。

3. **最后做“组合优化”**：  
   - ✅ **高并发推理 + 模型监控**：标准黄金组合，适用于绝大多数线上服务；  
   - ✅ **模型压缩 + 高并发推理（PTU/DTU）**：在压缩后模型上启用 PTU，兼顾轻量与确定性；  
   - ⚠️ **模型压缩 + 智能路由**：暂不支持（智能路由仅匹配全精度模型）；  
   - ❌ **模型压缩 + Batch 推理**：Batch 本身已针对成本优化，压缩收益有限，且 Batch 不支持压缩模型（当前未开放）。

> **重要提示**：所有方案均以**模型在百炼平台注册成功并状态为 `ready`** 为前提。部署前请务必在控制台核对模型地域支持性（如 `qwen3.7-flash-2026-07-15` 仅在北京可用）、开通状态及最新文档说明。技术演进快速，本文所列能力与限制以百炼控制台实时信息为准。
