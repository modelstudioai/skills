# 模型微调、压缩与部署对比

百炼平台提供了完整的模型生产链路：模型微调（Fine-tuning）、模型压缩（Quantization）和模型部署（Deployment）。这三个环节各自承担不同职责，微调负责让模型学会特定领域的知识和指令遵循能力，压缩负责在保持模型能力的前提下降低推理资源需求，部署则将模型上线为可调用的推理服务。理解三者的定位、输入输出和适用场景，有助于开发者根据业务需求设计高效的模型生产流程。

## 关键维度对比

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
|------|---------|---------|---------|
| **核心目标** | 基于自有数据定制模型能力，提升特定场景表现 | 通过量化降低模型参数精度，减少部署资源需求 | 将模型上线为可调用的推理服务 |
| **在链路中的位置** | 第一步（模型生产起点） | 第二步（可选，位于微调与部署之间） | 第三步（模型上线） |
| **输入** | 基础模型 + 训练数据集（JSONL / ZIP） | 微调产出的自定义模型 | 预置模型、微调模型或压缩后模型 |
| **输出** | 自定义微调模型 | 低精度量化模型 | 在线推理服务（API endpoint） |
| **支持的模型范围** | Qwen3.6/3.5/3/2.5 系列、Qwen-VL、Wan 图像/视频、CosyVoice 语音等 | 仅百炼平台微调产出的自定义模型（以控制台展示为准） | 预置模型（Qwen、DeepSeek、GLM 等）及微调/压缩后的自定义模型 |
| **支持的模态** | 文本生成、视觉理解、图像生成、视频生成、语音合成 | 文本生成（当前已知） | 文本生成、[多模态](../concepts/multimodal.md)、语音合成等 |
| **操作方式** | 控制台 + DashScope API | 仅控制台 | 控制台 + DashScope API |
| **训练/处理方法** | CPT（继续预训练）、SFT（监督微调）、DPO（偏好优化）；全参或 LoRA | 量化模板（MU 编号越大精度损失越大、成本越低） | PTU（预置吞吐）、MU（模型单元）、[Token](../concepts/token.md) 用量三种计费模式 |
| **数据要求** | CPT: 1000 万+ [Token](../concepts/token.md)；SFT: 1000+ 条；DPO: 100+ 组 | 可选校准数据集（最多 5 个，提升量化精度） | 无额外数据要求 |
| **可逆性** | 可基于同一基础模型反复微调 | 不可逆，压缩后不可继续微调或二次压缩 | 可随时上线/下线，删除后不可恢复 |
| **计费方式** | 按训练 [Token](../concepts/token.md) 用量计费（Token 数 x 循环次数 x 单价） | 压缩任务本身限时免费 | PTU 按 TPM 时长计费；MU 按单元数时长计费；Token 用量按调用量计费 |
| **地域限制** | 无特殊限制 | 仅华北2（北京） | 无特殊限制 |

## 典型链路与场景选择

### 链路一：微调后直接部署

适用于对推理成本不敏感、追求最优模型效果的场景。微调完成后直接以全精度模型部署，获得最高精度表现。

- 典型场景：企业核心业务（如金融风控、医疗问诊）对准确率要求极高
- 部署方式建议：MU 模型单元（资源独占，性能可控）

### 链路二：微调后压缩再部署

适用于需要平衡模型效果与部署成本的场景。压缩可将部署规格从高配 MU 降至低配 MU，成本节省可达 56% 以上。

- 典型场景：流量规模较大的在线服务（如智能客服、内容审核），需要长期运行且对成本敏感
- 部署方式建议：MU 模型单元（压缩后规格更低，单价更优）
- 注意事项：压缩不可逆，建议在免费期内用业务测试集验证多个量化模板的推理效果后再正式上线

### 链路三：仅部署预置模型

适用于不需要定制化能力、直接使用平台预置模型的场景。跳过微调和压缩环节，快速上线。

- 典型场景：通用问答、内容生成、快速原型验证
- 部署方式建议：PTU 预置吞吐（高并发保障）或 Token 用量（按需付费、低流量场景）

## 技术选型参考

开发者在选择链路时，建议按以下决策顺序评估：

1. **是否需要定制模型能力？** 如果预置模型已满足业务需求，直接部署即可，无需微调。
2. **选择哪种微调方法？** 数据量充足且需要注入领域知识时用 CPT；指令遵循和任务适配用 SFT；安全合规和偏好对齐用 DPO。数据量少或需快速验证时优先选择 LoRA 高效训练。
3. **是否需要压缩？** 当微调模型的全精度部署成本超出预算时，考虑压缩。注意压缩会带来一定精度损失，且操作不可逆，务必在压缩前保留全精度模型。
4. **选择哪种部署计费方式？** 流量稳定且需要吞吐保障选 PTU；需要资源独占和灵活配置选 MU；流量波动大或处于验证阶段选 Token 用量按需计费。

## 成本优化建议

| 优化手段 | 说明 |
|---------|------|
| 高效训练（LoRA） | 微调阶段选择 LoRA 而非全参训练，训练成本更低、收敛更快 |
| 模型压缩 | 对微调模型进行量化，降低部署 MU 规格，长期运行成本显著下降 |
| PTU 前缀缓存 | 多轮对话或重复前缀场景下，命中缓存的 Token 按折扣系数消耗额度 |
| PTU 溢出机制 | 超出额度时自动转按量计费，避免业务中断 |
| Token 用量计费 | 低流量或验证阶段使用，不调用不计费，避免资源闲置浪费 |
