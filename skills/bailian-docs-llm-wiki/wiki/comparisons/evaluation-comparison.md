# 模型评测与应用评测对比

百炼平台提供两套独立的评测体系：**模型评测**和**应用评测**。前者聚焦于大语言模型本身的能力验证与横向比较，后者聚焦于[智能体应用](../concepts/agent-application.md)、工作流应用的端到端输出质量评估。两者在评测对象、数据格式、评分机制和适用场景上存在显著差异，开发者需要根据当前所处的开发阶段和具体目标选择合适的评测方式。

## 关键维度对比

| 对比维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| **评测对象** | 大语言模型（预置模型、调优模型） | [智能体应用](../concepts/agent-application.md)、工作流应用 |
| **核心目标** | 量化模型能力，辅助模型选型与调优验证 | 验证应用端到端输出质量，指导应用优化 |
| **评测模式** | 自定义评测、基线评测 | 自动评测（基于知识库）、手动评测（人工构建评测集） |
| **评测集格式** | Excel（Prompt + Completion 列） | 旧版：Excel（对话分析）或 JSONL（知识问答）；新版：按应用出入参自动生成模板 |
| **评测集来源** | 手动上传；基线评测使用系统预置标准数据集（C-Eval、MMLU、GSM8K 等） | 自动生成（仅知识问答类型，需 qwen-max 或 qwen-plus）或手动上传 |
| **评分机制** | 5 种评测维度类型（大模型评估-数值型/分类型、规则评估-文本相似度/字符串匹配、人工评估-分类型） | 评估器体系：预置模板 + 自定义 LLM 评估器 + Code 评估器 + 基于历史任务创建 |
| **评估器数量** | 一个任务可组合多个评测维度 | 每个任务最多 10 个评估器，建议 3-5 个覆盖不同维度 |
| **评分范围** | 大模型评估-数值型为 1-5 分；规则评估为相似度/匹配结果 | 灵活配置：0-100（精细评估）、0-1 或 1-5（快速分类） |
| **结果报告** | 综合得分、通过率、分数分布；基线评测还含能力雷达图与行业对比 | 综合得分、评测进度、各评估器通过率；自动评测额外提供 BadCase 分析、归因分析和调优建议 |
| **人工标注** | 人工评估-分类型维度（打标签） | 标签管理系统（分类/布尔值/数字/文本四种标签类型），支持快速标注模式 |
| **前置条件** | 无特殊要求；基线评测仅支持调优后模型 | 自动评测要求应用已发布且配置知识库，并开通应用观测 |
| **横向对比能力** | 排行榜（创建任务时选择参与） | 自动评测支持最多 8 个应用横向评测 |
| **费用构成** | 被评测模型推理费用 + 裁判模型评分费用（大模型评估类型） | 应用调用产生的 [Token](../concepts/token.md) 费用 + LLM 评估器产生的 [Token](../concepts/token.md) 费用 |
| **版本状态** | 单一版本 | 存在旧版与新版两套界面，功能和评测集类型有差异 |

## 评分机制详细对比

模型评测和应用评测在"如何评分"上采用了不同的设计理念：

- **模型评测**采用"评测维度"概念，每种维度类型有固定的评分方式。大模型评估类型需要配置评分器 Prompt，由裁判模型按 Prompt 指令评分；规则评估类型通过算法自动计算；人工评估类型由人工打标。系统预置综合评测、语义相似度、自定义评测三种评分器模板。

- **应用评测**采用"评估器"概念，设计更为灵活。LLM 评估器适合需要语义理解的场景（相关性、有害性、幻觉检测），Code 评估器适合确定性判断（格式校验、数值计算），两者可自由组合。评估器还可从历史评测任务中自动抽象生成，形成评测能力的复用与积累。

## 适用场景建议

**选择模型评测的场景：**

- 需要在多个候选模型之间做技术选型，横向对比模型在特定业务场景的表现
- 模型调优后需要量化验证调优效果，与调优前或基线模型对比
- 需要使用标准学科/数学/推理榜单评估模型通用能力（基线评测）
- 关注模型层面的能力边界，尚未进入应用集成阶段

**选择应用评测的场景：**

- [智能体应用](../concepts/agent-application.md)或工作流应用已搭建完成，需要端到端验证输出质量
- 需要自动化评测流程并获得 BadCase 归因分析与调优建议（自动评测）
- 需要领域专家介入、对应用输出做细粒度人工标注和质量判断（手动评测）
- 需要多维度标签体系对线上真实数据做持续质量监控（结合应用观测）
- 需要灵活组合 LLM 语义评估与代码规则评估，覆盖复杂业务评分逻辑

**典型开发阶段对应关系：**

在百炼平台的开发流程中，模型评测通常用于前期的模型选型与调优验证阶段，帮助开发者确定最适合业务需求的基础模型；应用评测则用于后期的应用集成与上线验证阶段，确保整个应用链路（包括 Prompt 工程、知识库检索、工具调用等）的综合输出质量达标。两者互补而非替代，建议在项目全生命周期中结合使用。
