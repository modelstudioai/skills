# 模型评测与应用评测对比

百炼平台同时提供"模型评测"和"应用评测"两项质量验证能力，二者虽然都以评分和报告为产出，但评测对象、数据来源、评分机制和适用阶段截然不同。理解它们的差异有助于开发者在正确的环节选择正确的工具，避免重复劳动或评测盲区。

## 关键维度对比

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **评测对象** | 单个大语言模型（预置或调优后的模型） | 智能体应用或工作流应用（含 RAG、Prompt、检索等完整链路） |
| **核心目标** | 量化模型本身的生成能力，辅助选型和调优验证 | 量化端到端应用输出质量，辅助应用上线和持续优化 |
| **评测模式** | 自定义评测（开发者定义数据和维度）、基线评测（预置行业标准数据集） | 自动评测（大模型自动生成评测集并打分）、手动评测（人工标注）、新版评测任务（评估器 + 标签组合） |
| **评测数据来源** | 开发者手动准备 Excel 格式的评测数据集或推理结果集；基线评测使用预置数据集（C-Eval、MMLU 等） | 自动评测从关联知识库自动生成；手动评测人工上传；新版支持从应用观测导入 |
| **评分机制** | 5 种维度类型：大模型数值型（1-5 分）、文本相似度、大模型分类型（Pass/Fail）、字符串匹配、人工评估 | 评估器体系：LLM 评估器（语义理解）、Code 评估器（Python 规则）、基于历史标注的评估器；另有人工标签（分类/布尔值/数字/文本） |
| **支持的被评测对象** | 千问系列、千问开源版、通义法睿及部分第三方文本生成模型（含基于预置模型调优后的版本） | 已发布的智能体应用和工作流应用 |
| **归因分析** | 不提供（仅输出得分和通过率） | 自动评测对低分样本提供 RAG 链路归因（模型理解有误、重排不佳、检索无效、切片不完整、未获取知识） |
| **多对象对比** | 通过排行榜对比多个模型在同一评测维度上的表现 | 多应用横向评测，最多 8 个应用在同一基准下对比 |
| **计费方式** | 被评测模型推理费用 + 裁判模型评分费用（大模型评估类型） | 评测 Token 费用（自动评测仅支持 qwen-max 和 qwen-plus） |
| **前提条件** | 模型已部署；基线评测要求模型已调优 | 应用已发布、已配置知识库、已开通应用观测 |

## 评测数据格式对比

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **数据格式** | Excel（评测数据集或推理结果集） | 旧版：`.xls`/`.xlsx`（对话分析）、`.jsonl`（知识问答）；新版：按应用类型定义 |
| **数据集类型限制** | 仅支持评测集类型，不支持训练集 | 旧版分对话分析和知识问答；新版分智能体、工作流、自定义三类 |
| **建议数据规模** | 小规模 50-100 条，正式 200-500 条，全面 500+ 条 | 单次上传最多 10 个文件，单文件不超过 20MB |
| **版本管理** | 不涉及 | 新版评测集支持版本管理，每次发布生成新版本 |

## 适用阶段与场景

### 模型评测适用场景

- **模型选型阶段**：用相同测试数据横向对比多个候选模型，通过得分和通过率选出最优模型。
- **模型调优后验证**：量化调优前后的效果差异，判断调优方向是否正确。
- **通用能力基准检验**：使用基线评测（C-Eval、MMLU、GSM8K 等）快速验证调优模型的通用能力。
- **能力量化汇报**：生成包含综合得分、通过率和分数分布的评测报告，为团队决策提供数据支撑。

### 应用评测适用场景

- **应用上线前验收**：评估智能体或工作流的端到端输出质量，确保达到上线标准。
- **知识库更新后回归**：知识库变更后重新评测，验证变更未引入质量回退。
- **Prompt 调整后验证**：修改 Prompt 后用同一评测集对比新旧版本效果。
- **RAG 链路问题定位**：通过归因分析定位低分样本的具体问题环节（检索、重排、模型理解等），实施针对性优化。
- **多版本/多应用选型**：横向对比最多 8 个应用版本，选择最优方案。

## 技术选型建议

1. **先模型评测，后应用评测**：在模型选型和调优阶段使用模型评测确定最优模型，在应用集成后使用应用评测验证端到端效果。
2. **模型评测关注"模型能力"，应用评测关注"系统效果"**：如果问题出在模型本身的生成能力，用模型评测定位；如果问题可能出在检索、切片、Prompt 等应用层，用应用评测的归因分析定位。
3. **持续监控建议结合使用**：模型评测用于追踪模型版本迭代的能力变化，应用评测用于追踪应用整体质量趋势。
4. **成本考量**：模型评测的基线评测和规则评估维度成本较低；应用评测的自动评测依赖 qwen-max/qwen-plus，需关注 Token 消耗。
