# 应用评测与模型评测对比

百炼平台提供了两套独立的评测体系：**应用评测**和**模型评测**。两者虽然都用于质量验证，但评测对象、数据流和适用阶段截然不同。应用评测面向已部署的智能体或工作流应用，关注端到端的回答质量与知识库检索效果；模型评测面向大语言模型本身，关注模型的基础能力和推理质量。理解两者的差异有助于开发者在不同阶段选择合适的评测手段。

## 关键维度对比

| 维度 | 应用评测 | 模型评测 |
|------|---------|---------|
| **评测对象** | 智能体应用、工作流应用 | 大语言模型（预置模型或调优后模型） |
| **核心目标** | 评估应用端到端的回答质量，含知识库检索与重排效果 | 评估模型本身的推理能力与生成质量 |
| **评测模式** | 自动评测（大模型生成评测集）、手动评测（人工构建评测集）、新版评测任务（评估器 + 标签） | 自定义评测（业务场景）、基线评测（标准数据集） |
| **数据来源** | 自动生成评测集、手动上传（xls/xlsx）、应用观测导入 | 手动上传 Excel（Prompt + Completion）、系统预置标准数据集（C-Eval、MMLU 等） |
| **评分机制** | 大模型打分（1-5 分，4 分及以上为正确）、评估器（预置模板 / LLM / Code）、人工标签 | 评测维度：大模型评估（数值型/分类型）、规则评估（文本相似度/字符串匹配）、人工评估 |
| **归因分析** | 支持 BadCase 自动归因（模型理解有误、重排不佳、检索无效、切片不完整、未获取知识） | 不提供归因分析，仅给出评分和通过率 |
| **排行榜** | 支持多应用横向评测（最多 8 个应用） | 支持排行榜，可在同一维度上对比多个模型 |
| **前提条件** | 应用需已发布且配置知识库，需开通应用观测 | 自定义评测支持预置和调优模型；基线评测仅支持调优后部署的模型 |
| **计费方式** | 调用 qwen-max 或 qwen-plus 产生 Token 费用；Code 评估器无额外费用 | 大模型评估类型消耗裁判模型 Token；规则评估和人工评估无额外模型费用 |
| **产出物** | 评测报告（正确率、BadCase 分析、归因、调优建议） | 评测报告（综合得分、通过率、数据明细；基线评测含雷达图和学科得分） |

## 评测数据结构对比

| 项目 | 应用评测 | 模型评测 |
|------|---------|---------|
| **旧版格式** | 对话分析（xls/xlsx）、知识问答（jsonl） | -- |
| **新版格式** | 智能体型 / 工作流型 / 自定义型评测集（xls/xlsx，20MB 以内） | Excel：Prompt + Completion（评测数据集）或 Prompt + Completion + Output（推理结果集） |
| **推荐数据量** | 由评测集生成工具自动决定 | 小规模 50-100 条，正式 200-500 条，全面 500+ 条 |
| **版本管理** | 评测集发布后支持版本管理 | 无内置版本管理 |

## 适用场景建议

### 选择应用评测

- 已经构建好智能体或工作流应用，需要验证端到端回答质量。
- 需要定位回答错误是出在模型、检索、重排还是知识切片环节（归因分析）。
- 希望在知识库更新、Prompt 调整、模型更换后做回归验证。
- 需要对线上真实流量进行持续观测和人工标注。

### 选择模型评测

- 处于模型选型阶段，需要在多个候选模型之间做横向对比。
- 完成模型调优（Fine-tuning）后，需要量化调优前后的能力差异。
- 需要使用行业标准基准（C-Eval、MMLU、GSM8K 等）验证模型通用能力。
- 希望建立定期评测机制，追踪模型能力随版本变化的趋势。

### 推荐组合使用

在完整的开发周期中，建议先用**模型评测**完成底层模型的选型和调优验证，再用**应用评测**验证上层应用的端到端效果。两者结合可以覆盖从模型基础能力到应用交付质量的全链路质量保障。
