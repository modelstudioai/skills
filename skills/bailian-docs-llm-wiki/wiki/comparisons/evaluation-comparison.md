# 评测体系对比（应用评测 vs 模型评测）

百炼平台提供两套独立但互补的评测体系：**应用评测**面向智能体应用/工作流应用的端到端输出质量评估，**模型评测**面向大语言模型本身的能力量化。两者共享"评测集 + 评估器 + 评测任务 + 评测报告"的整体框架，但在被测对象、输入输出格式、评估器机制、[计费](../concepts/billing.md)方式与典型场景上存在显著差异。本页面向开发者做技术选型参考，帮助在"评应用"与"评模型"之间做出正确选择，并在需要时组合使用。

## 关键维度对比

| 对比维度 | 应用评测 | 模型评测 |
| --- | --- | --- |
| 被测对象 | 智能体应用、工作流应用（已发布且配置知识库） | 大语言模型本身（千问系列、开源版、第三方文本生成模型） |
| 评测目标 | 应用端到端输出质量（含知识库检索、编排、回复） | 模型通用能力与业务场景表现（学科、数学、推理、问答等） |
| 评测范式 | 自动评测（LLM 生成评测集并评分）+ 手动评测（人工打标） | 自动评测（系统自动完成）+ 人工评测（手动标注） |
| 评测集类型 | 旧版：对话分析（.xls/.xlsx）、知识问答（.jsonl）；新版：智能体/工作流/自定义（按应用出入参自动生成模板） | 自定义评测：评测数据集（Prompt+Completion）、推理结果集（含 Output）；基线评测：系统预置标准榜单数据集 |
| 数据格式 | .xls/.xlsx/.jsonl，单文件 ≤ 20MB，单次最多 10 个文件 | Excel 格式（评测集类型，不支持训练集） |
| 评估器机制 | 预置模板（通用质量/智能体/文本匹配/文本相似度/格式校验）+ 自定义（LLM 评估器、Code 评估器、基于评测任务创建）；单任务最多 10 个评估器 | 5 种评测维度：大模型评估-数值型、规则评估-文本相似度、大模型评估-分类型、规则评估-字符串匹配、人工评估-分类型；可组合多维度 |
| 评分尺度 | 1-5 分、0-100、0-1、1-5（由评估器配置）；自动评测 1-5 分，4 分以下触发归因 | 1-5 分（数值型）、Pass/Fail（分类型）、相似度/匹配率（规则型）、人工标签 |
| 裁判变量 | query、reference_response、context 等映射到评测集字段或应用输出 | `${prompt}`、`${output}`、`${completion}` 三变量（仅大模型评估类型） |
| API/界面入口 | 控制台「应用评测」模块，区分旧版/新版界面 | 控制台「模型评测」模块 |
| 基线/榜单能力 | 无内置标准榜单，依赖自动生成的知识问答评测集 | 提供预置基线数据集（C-Eval、MMLU、ARC、GSM8K、HellaSwag、BBH）及行业对比、能力雷达图 |
| 排行榜 | 单次最多 8 个应用横向评测 | 可选参与排行榜，对比多模型在同一维度上的表现 |
| [计费](../concepts/billing.md)方式 | 评测任务调用大模型产生 Token 费用；Code 评估器无额外费用；知识问答自动生成仅支持 qwen-max/qwen-plus | System Prompt 产生被评测模型推理费用；评分器 Prompt 产生裁判模型评分费用；规则评估/人工评估无裁判费用 |
| 报告内容 | 总正确率、BadCase 分析、归因分析、调优建议；数据明细 + 指标统计 | 综合得分、通过率、分数分布；数据明细 + 指标统计；基线评测含分学科明细、能力雷达图、行业对比 |
| 模型支持范围 | 自动生成仅 qwen-max/qwen-plus；评估器 LLM 建议 32B 以上 | 千问系列（QwQ/Max/Plus/Turbo/Coder/Math）、千问开源版（Qwen3/Qwen2.5/Qwen2/Qwen1.5）、通义法睿及部分第三方模型；基线评测仅支持调优模型 |
| 版本/状态约束 | 评测任务发起后配置不可修改；评测集发布后才能用于任务 | 任务状态：待执行/进行中/评测完成/评测失败/评测终止；基线评测需先完成模型调优与部署 |

## 适用场景建议

### 选择应用评测

- 已构建智能体应用或工作流应用，需要评估**端到端**输出质量（含知识库检索、工具调用、编排逻辑）。
- 需要自动生成评测集并获取 BadCase 归因与调优建议，驱动应用迭代。
- 需要对线上真实数据通过应用观测 Span 进行标签标注与质量评估。
- 需要用 Code 评估器做精确格式校验、数值计算，或用 LLM 评估器做相关性、有害性、幻觉检测。
- 典型场景：智能客服 QA 质量评估、RAG 应用回答准确性验证、多应用横向对比选型。

### 选择模型评测

- 需要量化评估**模型本身**的通用能力（学科、数学、推理），无需自备评测数据，直接使用基线榜单。
- 需要在多个候选模型之间做选型对比，参与排行榜横向比较。
- 需要验证调优后模型相对基线模型的能力提升。
- 需要自定义业务评分标准，组合数值型/分类型/规则型/人工型多维度评测。
- 典型场景：[模型选型](../concepts/model-selection.md) benchmark、调优效果验证、Function Calling/NL2SQL 精确匹配率评估、内容安全 Pass/Fail 判定。

### 组合使用

当应用表现不达预期时，可先用**模型评测**验证底层模型在相关任务上的基线能力，再用**应用评测**定位是模型能力不足还是应用编排/知识库检索问题，从而分离变量、精准调优。

## 技术选型小结

- 评**应用**（含知识库与编排）→ 应用评测；评**模型**（裸能力）→ 模型评测。
- 需要标准榜单与行业对比 → 模型评测基线评测；需要 BadCase 归因与调优建议 → 应用评测自动评测。
- 关注成本：优先规则评估/Code 评估器（无裁判费用），语义判断再上 LLM 评估器/大模型评估。
- 数据量建议：应用评测自动生成受限于知识库内容，模型评测自定义建议小规模 50–100 条、正式 200–500 条、全面 500+ 条。
