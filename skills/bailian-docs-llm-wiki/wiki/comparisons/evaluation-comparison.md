# 应用评测与模型评测对比

百炼平台同时提供「应用评测」与「模型评测」两套评测能力。前者面向已编排完成的智能体应用/工作流应用，验证端到端输出质量；后者面向底层大语言模型本身，量化模型在指定数据集上的能力表现。两者在评测对象、数据形态、评估器机制和计费方式上均存在显著差异，开发者在技术选型时应根据评测目标选择对应工具，避免混淆。

## 关键维度对比

| 对比维度 | 应用评测 | 模型评测 |
| --- | --- | --- |
| 评测对象 | 智能体应用、工作流应用（已发布且配置知识库） | 大语言模型本身（千问系列、开源版、第三方文本生成模型） |
| 评测目标 | 端到端验证应用输出质量，含知识库召回与编排链路 | 量化模型在指定数据集上的能力，支持模型选型、调优验证 |
| 评测模式 | 自动评测、手动评测两种范式 | 自动评测、人工评测两种模式 |
| 输入数据格式 | 对话分析 `.xls`/`.xlsx`；知识问答 `.jsonl`；新版支持智能体/工作流/自定义模板，`.xls`/`.xlsx`，单文件 ≤20MB | Excel 格式；分「评测数据集」（Prompt+Completion）与「推理结果集」（含 Output）两种来源 |
| 预置标准数据集 | 无，需自动生成或手动上传 | 基线评测提供 C-Eval、MMLU、ARC、GSM8K、HellaSwag、BBH 等标准榜单 |
| 评估器/评测维度 | 预置模板（通用质量/智能体/文本匹配/文本相似度/格式校验）+ 自定义 LLM 评估器 + Code 评估器 + 基于历史任务创建；每任务最多 10 个 | 5 种评测维度：大模型评估-数值型、规则评估-文本相似度、大模型评估-分类型、规则评估-字符串匹配、人工评估-分类型 |
| 评分方式 | LLM 语义评分（1-5 或 0-100）、Code 规则评分、人工标注（较差/一般/较好 或 1-5） | AI 裁判打分（1-5）、相似度算法、字符串精确匹配、人工打标 |
| 关键变量映射 | 评估器参数需映射到评测集字段或应用输出 | 裁判模型接收 `${prompt}`、`${output}`、`${completion}` 三个变量 |
| 标签管理 | 分类/布尔值/数字/文本四类标签，评测与应用观测共用 | 不单独提供标签体系，人工评估以分类型维度承载 |
| API 端点 | 控制台应用评测界面（新版/旧版切换） | 控制台模型评测界面 |
| 计费方式 | 评测任务调用大模型产生 Token 费用；Code 评估器无额外费用；自动评测限单次最多 8 个应用 | System Prompt 产生被评测模型推理费用；评分器 Prompt 产生裁判模型评分费用；基线评测仅支持调优模型 |
| 报告内容 | 评分、BadCase 分析、归因分析、调优建议；数据明细 + 指标统计双视图 | 综合得分、通过率、分数分布；基线评测含分学科明细、能力雷达图、行业对比 |
| 版本/约束 | 区分新版与旧版界面；评测集类型不可修改；任务发起后配置不可修改 | 基线评测仅支持调优模型，不支持预置模型；自定义评测仅支持评测集，不支持训练集 |
| 典型场景 | 智能体应用回归测试、知识库召回质量验证、应用调优迭代 | 模型选型对比、调优前后能力量化、通用能力榜单验证 |

## 适用场景建议

### 何时选择应用评测

- 已完成智能体应用或工作流应用的编排，需要验证端到端输出质量。
- 需要评估知识库召回与编排链路的协同效果，关注 BadCase 与归因分析。
- 希望通过 LLM + Code 组合评估器，从相关性、格式校验、幻觉检测等多维度量化应用表现。
- 需要与应用观测联动，对线上真实 Span 标注标签，实现持续质量监控。

### 何时选择模型评测

- 处于模型选型阶段，需要对比千问系列、开源版本或第三方文本生成模型在业务数据集上的能力。
- 需要使用标准榜单（C-Eval、MMLU、GSM8K 等）验证模型的通用学科、数学、推理能力。
- 模型经过调优后，需要量化调优前后能力变化，作为发布依据。
- 关注 Function Calling、NL2SQL 等需要精确字符串匹配的场景，且希望使用成本极低的规则评估。

### 组合使用

应用评测与模型评测并非互斥。典型实践是：先用模型评测筛选出业务数据集上表现最佳的底层模型，再基于该模型构建智能体应用，最后用应用评测验证端到端输出质量与知识库召回效果，形成「模型选型 → 应用编排 → 应用验证」的闭环。
