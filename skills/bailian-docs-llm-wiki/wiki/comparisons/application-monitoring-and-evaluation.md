# 应用可观测性对比：应用监控、模型监控与应用评估

在大模型应用的全生命周期中，可观测性是保障稳定性、可维护性与持续迭代能力的关键基础设施。随着百炼平台能力演进，开发者面临三类核心可观测能力的选择：**应用监控（Application Monitoring）** 侧重运行时链路追踪与性能诊断，**模型监控（Model Monitoring）** 聚焦 API 层面的模型服务指标聚合，而 **应用评估（Application Evaluation）** 则面向质量保障，提供前摄性、可复现的效果验证。本页旨在从技术定位、能力边界与工程实践角度，系统对比三者差异，帮助开发者在不同阶段精准选型，避免能力错配或重复建设。

---

## 关键维度对比

| 维度 | 应用监控（Application Monitoring） | 模型监控（Model Monitoring） | 应用评估（Application Evaluation） |
|------|-----------------------------------|-----------------------------|-----------------------------------|
| **核心目标** | 运行时链路追踪、延迟拆解、异常根因定位 | 模型服务级资源消耗与稳定性统计（QPS/错误率/[Token](../concepts/token.md)） | 应用效果质量验证（准确性、安全性、鲁棒性等） |
| **输入格式** | 实时请求流量（HTTP/SDK 调用），自动注入 trace context；支持自定义 `X-Bailian-Trace-ID` | 模型 API 调用日志（由百炼网关统一采集），需绑定 `app_id` 和可选 `model_id` | 结构化评测集（CSV/JSONL），含 `input`、`expected_output`、`category` 等字段 |
| **输出格式** | <ul><li>Trace 数据（OpenTelemetry 兼容 JSON）</li><li>实时 metrics（延迟分布、[Token](../concepts/token.md) 数、错误码）</li><li>可视化仪表盘（含 span 级耗时下钻）</li></ul> | <ul><li>时间序列指标（JSON 格式，含 `request_count`, `p99_latency_ms`, `error_rate` 等）</li><li>聚合报表图表（控制台渲染）</li><li>告警通知（钉钉/邮件）</li></ul> | <ul><li>评测报告（JSON + 控制台可视化）</li><li>明细结果（每条样本的 `actual_output`, `accuracy_score`, `latency_ms`, `safety_flag` 等）</li><li>人工标注记录（仅人工评测模式）</li></ul> |
| **支持模型** | ✅ 所有百炼托管模型（Qwen 系列、Qwen-VL、Qwen-Audio、第三方接入模型）<br>✅ 多跳 RAG 各环节（检索/重排/生成）<br>✅ 自定义工具调用链路 | ✅ 所有通过百炼控制台部署的 API 模型（如 `qwen-max`, `text-embedding-v1`）<br>❌ 不支持直接调用 [OpenAI 兼容接口](../concepts/openai-compatibility.md)的第三方代理模型 | ✅ 所有已发布状态的应用（无论底层模型类型）<br>✅ 支持跨模型架构对比（如 v1 vs v2 版本）<br>✅ 支持带工具调用、RAG 等复杂流程的端到端效果评估 |
| **API 端点** | `GET /v1/monitoring/traces`（按 trace ID 或时间范围导出）<br>`POST /v1/applications/{id}/traces`（调试用） | `GET /v1/monitor/metrics`（指标查询）<br>`POST /v1/monitor/alerts`（告警配置） | `POST /v1/evaluations`（发起评测）<br>`GET /v1/evaluations/{id}`（获取结果）<br>`POST /v1/datasets`（管理评测集） |
| **计费方式** | ✅ 按 trace 数据量计费（采样率直接影响成本）<br>⚠️ `trace_tool_inputs: true` 显著增加体积与费用<br>❌ metrics 数据不额外计费 | ✅ 按监控数据点（metric point）计费<br>（1 个指标 × 1 分钟粒度 × 1 维度 = 1 point）<br>⚠️ 多维下钻（如按 `env=prod` & `model_id=qwen-plus`）会增加点数 | ✅ 按评测任务执行次数 + 样本量计费<br>（10,000 样本以内为单次任务）<br>⚠️ 人工评测不计费，但占用团队协作工时 |
| **数据时效性** | ⏱️ Trace 实时上报（秒级可见）<br>📊 Metrics 延迟 ≤ 30 秒 | ⏱️ 指标最大延迟 2 分钟（非流式）<br>📊 不适用于毫秒级故障定位 | ⏱️ 异步执行（分钟级完成，取决于样本量与应用响应速度）<br>📊 结果为快照式，无实时性要求 |
| **数据保留期** | 📅 Trace：7 天<br>📊 Metrics：30 天 | 📅 原始指标：30 天<br>📊 聚合报表：90 天 | 📅 评测结果缓存：30 天（过期需重跑）<br>📁 评测集永久存储（版本快照） |
| **典型场景** | <ul><li>排查某次请求超时：发现「重排模块耗时 2.1s」</li><li>分析工具调用失败原因：查看入参是否含非法字符</li><li>压测期间观察 token 消耗突增与错误率关联性</li></ul> | <ul><li>每日巡检：确认 `qwen-plus` P99 延迟未突破 SLO（2s）</li><li>容量规划：基于过去 7 天 QPS 趋势扩容实例</li><li>灰度发布监控：对比 `staging` 与 `prod` 环境错误率差异</li></ul> | <ul><li>上线前验收：验证新版本在「金融问答」评测集上准确率 ≥ 92%</li><li>迭代对比：v2.1 相比 v2.0 在「多轮对话连贯性」指标提升 15%</li><li>SLO 审计：每月生成《安全合规评测报告》供法务审核</li></ul> |

## 各方案适用场景建议

| 场景描述 | 推荐方案 | 理由说明 |
|----------|-----------|-----------|
| **需要定位一次具体请求为何返回空结果或超时** | ✅ 应用监控 | 只有应用监控能提供完整 span 链路（从 API 入口 → RAG 检索 → 工具调用 → 模型生成），支持逐环节耗时与状态检查；模型监控仅知“该请求失败”，无法定位在哪一跳出错。 |
| **想了解过去 24 小时 `text-embedding-v1` 的整体错误率和平均延迟趋势** | ✅ 模型监控 | 模型监控专为聚合统计设计，支持多维下钻与历史趋势图，且数据保留更久（90 天报表）；应用监控的 metrics 缺乏长期趋势分析能力，trace 数据又过于离散。 |
| **准备将新版客服机器人上线，需证明其回答准确率达标且无敏感信息泄露** | ✅ 应用评估 | 应用评估是唯一支持结构化比对（`expected_output` vs `actual_output`）与安全规则扫描的能力；应用监控和模型监控均不涉及语义正确性判断。 |
| **发现线上应用错误率突然升高，需快速确认是模型层问题还是应用逻辑缺陷** | ⚖️ **组合使用**：<br>• 先查**模型监控**：若所有调用该模型的应用错误率同步上升 → 模型侧问题<br>• 再查**应用监控**：若仅某应用错误率飙升，且 trace 中大量失败发生在工具调用环节 → 应用逻辑或工具配置问题 | 单一能力无法覆盖归因分析全链路，需交叉验证。模型监控提供横向对比视角，应用监控提供纵向深度。 |
| **日常运维值班，需设置阈值告警防止服务降级** | ✅ 模型监控（主） + ✅ 应用监控（辅） | 模型监控支持基于 P99 延迟、错误率的稳定告警；应用监控的 trace 采样率低且不可靠，不适合作为告警源，但可作为告警触发后的根因分析入口。 |

## 面向开发者的选型参考

- **选应用监控，当您需要：**  
  ✅ 深度调试单次请求行为（尤其含 RAG、Function Calling 的复杂流程）  
  ✅ 追踪跨组件调用链（如应用 → 向量库 → LLM → 工具 API）  
  ✅ 对接外部 APM（如 Jaeger、Datadog）进行统一可观测体系建设  
  ❌ 不适合用于长期趋势分析、SLO 达标审计或质量验收  

- **选模型监控，当您需要：**  
  ✅ 监控模型服务 SLA（如 P99 < 2s，错误率 < 0.5%）  
  ✅ 基于用量做成本优化与弹性扩缩容决策  
  ✅ 快速识别环境差异（如 staging 错误率显著高于 prod）  
  ❌ 不适合分析应用层逻辑错误（如提示词失效、工具参数构造错误）  

- **选应用评估，当您需要：**  
  ✅ 在发布前/后进行可复现的质量验证（非临时抽查）  
  ✅ 构建自动化 CI/CD 流水线中的质量门禁（如 `accuracy < 90%` 则阻断发布）  
  ✅ 满足合规审计要求（如生成《月度安全评测报告》）  
  ❌ 不适合实时故障响应（它是批处理，非流式）  

> **最佳实践提示：**  
> - **不要用应用评估替代监控**：它不提供实时性，无法支撑故障应急。  
> - **不要用模型监控替代应用监控**：它丢失了应用内部逻辑细节，无法定位 RAG 或工具链问题。  
> - **三者可协同**：将应用评估的基线指标（如“平均响应时长”）设为模型监控的 SLO 目标；将应用监控发现的高频错误模式，沉淀为应用评估的新测试用例。  
> - **权限注意**：`monitoring:read` 权限仅开放 trace/metrics 查询；`evaluation:run` 权限需单独申请，且人工评测涉及敏感内容审核，建议最小权限分配。
