# RAG API 与知识库功能对比

本文档面向百炼平台开发者，旨在清晰区分 **RAG API**（即 `api/rag-api.md` 所述的底层服务接口）与 **知识库（Knowledge Base）**（即 `guides/knowledge-base.md` 所述的完整 RAG 能力载体）在技术定位、能力边界与集成路径上的本质差异。二者并非互斥替代关系，而是**分层协作、面向不同抽象层级的设计产物**：RAG API 是原子化、可编程的基础设施接口；知识库是封装了数据治理、检索策略、模型编排与服务发布的一站式 RAG 应用单元。正确理解其差异，是构建稳定、可维护、可扩展 RAG 系统的关键前提。

## 关键维度对比

| 维度 | RAG API | 知识库（Knowledge Base） |
|------|---------|---------------------------|
| **本质定位** | **底层能力接口集合**：提供知识库生命周期、文档处理、同步任务、检索问答等细粒度 RESTful 操作，强调控制力与可组合性 | **端到端 RAG 应用单元**：以“知识库”为实体，预集成数据接入、[向量化](../concepts/embedding.md)、混合检索、重排、生成、服务发布等全链路能力，强调开箱即用与体验一致性 |
| **输入格式** | 高度结构化 JSON 请求体，需显式传入 `knowledge_id`、`query`、`top_k` 等参数；文档上传需 multipart/form-data 或 base64 编码 | 支持多源异构输入：<br>• 控制台：拖拽上传 PDF/Word/Excel/Markdown/图片/音视频<br>• API：支持 `POST /api/v1/indices/rag/index/retrieve`（底层检索）或 `POST /api/v2/apps/knowledge/chat`（流式问答）<br>• CLI：`bl knowledge upload --file xxx.pdf`<br>• 元数据与标签可通过 CSV 或 API 批量注入 |
| **输出格式** | 同步响应，JSON 格式，含 `answer`、`references`（切片 ID + 内容片段 + 文档来源）、`usage`（token 消耗）等字段；**不支持流式（SSE）** | 多形态输出：<br>• Playground：带高亮引用的富文本答案 + 可展开切片详情面板<br>• API：`/search` 返回结构化召回结果；`/chat` 支持 **SSE 流式响应**（含 `delta`、`references`、`finish_reason`）<br>• CLI：格式化终端输出，含引用溯源标记 |
| **支持模型** | 问答阶段支持指定生成模型（如 `qwen-max`, `qwen-plus`），由 `model` 参数控制；嵌入与重排模型由知识库创建时绑定，**不可在 API 调用中动态切换** | **模型解耦且灵活配置**：<br>• 嵌入模型：默认 `text-embedding-v4`（创建后不可改）<br>• 重排模型：支持 `qwen3-rerank` / `qwen3-vl-rerank`，可在知识库设置中启用/关闭<br>• 生成模型：问答服务中可自由切换 `qwen3.6-plus` 等，并支持 `temperature`、`enable_thinking` 等 LLM 参数 |
| **API 端点** | 统一前缀 `/v1/knowledge/`：<br>• `POST /v1/knowledge/query`（核心问答）<br>• `POST /v1/knowledge_bases`（创建 KB）<br>• `POST /v1/documents`（上传文档）<br>• `GET /v1/sync_jobs/{job_id}`（查同步状态） | 多层级端点，按使用场景划分：<br>• 底层索引检索：`POST /api/v1/indices/rag/index/retrieve`（需 `index_id`）<br>• 应用级联合检索：`POST /api/v1/indices/knowledge/search`（需 `agent_id`）<br>• 流式问答服务：`POST /api/v2/apps/knowledge/chat`（需 `agent_id` + 消息历史）<br>• 控制台服务调用统一走 `/api/v2/apps/knowledge/` 前缀 |
| **计费方式** | **纯按调用量计费**：<br>• 每次 `/v1/knowledge/query` 调用计 1 次<br>• 文档解析、切片、同步任务均独立计费<br>• 无规格费（如 QPS 预留），免费额度仅限调用量 | **混合计费模式**：<br>• **规格费**：标准版（0.03 元/小时）、旗舰版（按 RCU，1 RCU ≈ 50 QPS）<br>• **模型费**：嵌入、重排、生成模型调用单独计费<br>• **免费额度**：720 小时标准版规格费（有效期至 2026-02-03），**不覆盖模型调用费** |
| **典型场景** | • 需精细控制文档解析流程（如自定义切片逻辑后批量导入）<br>• 构建私有 Agent 工作流，将 RAG 作为子模块嵌入<br>• 自动化运维脚本（如定时同步知识库、批量清理失效文档）<br>• 与非百炼生态系统深度集成（需完全掌控 HTTP 层） | • 快速验证 RAG 效果（Playground 交互调试）<br>• 对接第三方低代码平台（Dify、AgentScope）<br>• 面向终端用户发布稳定问答服务（通过 `agent_id` 绑定服务）<br>• 多模态内容管理（图文/音视频混合检索）<br>• 需要流式响应、多轮上下文保持的对话应用 |
| **核心限制** | • 单次 `query` ≤ 2048 字符<br>• 单知识库最多 100 万切片<br>• `/v1/knowledge/query` 仅同步模式，无流式<br>• 错误响应统一为 `code`+`message`，需自行解析 | • 地域限制：仅华北2（北京）、新加坡可用<br>• 并发限制：标准版 1 QPS，旗舰版按 RCU 弹性扩容<br>• 文件大小：文档 ≤ 150 MB，音视频 ≤ 512 MB<br>• 单知识库最多 100,000 文档<br>• 切片策略创建后不可修改 |

## 适用场景建议

### ✅ 选择 **RAG API** 当：
- 你正在构建一个**高度定制化的 RAG 管道**，需要绕过默认切片逻辑，对文档进行预处理（如按业务规则提取关键段落）后再注入；
- 你的应用已具备成熟的任务调度与状态管理框架（如 Airflow、Celery），希望将文档同步、索引重建等作为后台作业统一管控；
- 你需要将百炼 RAG 能力**无缝嵌入自有 Agent 框架**，并与其他工具（数据库查询、API 调用）在同一工作流中编排；
- 你追求极致的**成本透明性与调用粒度控制**，明确知道每一次 `query`、每一次 `sync_job` 的消耗，并据此做精细化预算。

### ✅ 选择 **知识库（Knowledge Base）** 当：
- 你希望**在 5 分钟内完成一个可演示的 RAG Demo**：上传文档 → Playground 测试 → 发布服务 → 前端调用，全程无需写一行代码；
- 你需要交付一个**面向业务人员的自助式知识管理平台**，支持标签分类、权限隔离、版本回溯、效果 A/B 测试（通过 Playground 对比不同切片策略）；
- 你的应用场景要求**实时流式响应**（如客服对话机器人），或依赖**多轮上下文感知**（如 `agent_id` 绑定的会话状态）；
- 你计划对接 **Dify、AgentScope、Qoder 等主流 AI 工具链**，知识库提供的标准化 `agent_id` 和 `MCP Server` 接口能显著降低集成复杂度；
- 你重视**生产环境可观测性**：知识库自动投递 SLS 日志，包含 `pipeline_id`、`latency`、`response_code` 等关键诊断字段，便于根因分析。

## 技术选型参考（致开发者）

| 选型考量 | 推荐方案 | 理由说明 |
|----------|----------|----------|
| **快速原型验证（PoC）** | 知识库（Playground） | 零配置启动，支持实时高亮溯源、多参数在线调整（TopK/重排开关/模型切换），迭代效率远超 API 调试 |
| **企业级知识中台建设** | **知识库 + RAG API 混合使用** | 用知识库承载核心业务知识服务（对外 API），用 RAG API 实现后台自动化治理（如每日增量同步、异常文档自动归档） |
| **嵌入式 Agent 开发** | RAG API | 更轻量、更可控；可精确指定 `knowledge_id` 和 `top_k`，避免知识库服务层的额外路由开销与策略干扰 |
| **多租户 SaaS 应用** | 知识库（旗舰版 + RCU 弹性） | 规格费按 RCU 计费，天然支持并发弹性伸缩；每个租户分配独立 `agent_id`，天然隔离资源与配额 |
| **合规敏感型场景（如金融、医疗）** | RAG API（配合私有 VPC 部署） | 完全掌控数据流向，所有请求经由客户 VPC 内网直连，规避公网传输风险；切片与检索逻辑可审计、可加固 |

> **重要提醒**：知识库的底层能力实际由 RAG API 提供支撑。二者不是平行关系，而是「服务封装」与「能力基座」的关系。选择知识库，本质是选择百炼团队为你预置的最佳实践组合；选择 RAG API，则意味着你主动承担起架构设计、错误处理、限流熔断、监控告警等工程责任。请根据团队技术成熟度、项目交付周期与长期运维成本综合决策。
