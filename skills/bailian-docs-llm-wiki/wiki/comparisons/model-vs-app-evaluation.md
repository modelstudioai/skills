# 模型评测与应用评测对比

百炼平台同时提供模型评测和应用评测两套评测体系，分别面向不同的评测对象和使用场景。模型评测聚焦于对大语言模型本身的能力进行量化评估，而应用评测则着眼于对构建在模型之上的智能体应用和工作流应用的端到端输出质量进行验证。理解二者的差异有助于开发者在正确的环节选择正确的评测工具，避免重复劳动或遗漏关键质量风险。

## 关键维度对比

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **评测对象** | 大语言模型（预置模型、调优模型） | 智能体应用、工作流应用 |
| **核心目标** | 量化模型在特定任务上的生成能力 | 评估应用端到端的输出质量与 RAG 效果 |
| **评测模式** | 自定义评测、基线评测 | 自动评测（单应用/多应用横向）、手动评测、新版评测任务 |
| **评测数据来源** | 评测数据集（含 [prompt](../guides/prompt.md) + completion）或推理结果集 | 知识问答数据集（自动生成或手动上传）、对话分析数据集、新版评测集（智能体/工作流/自定义） |
| **数据格式** | Excel（.xls/.xlsx） | .xls/.xlsx（对话分析）、.jsonl（知识问答）、新版评测集多种格式 |
| **评分机制** | 大模型评估（数值型/分类型）、规则评估（相似度/字符串匹配）、人工评估 | 评估器（LLM 评估器/Code 评估器/基于历史标注）、人工标签（分类/布尔/数字/文本） |
| **单任务评分维度上限** | 可组合多个评测维度（无明确上限） | 最多 10 个评估器 |
| **支持的模型** | 千问系列、千问开源版、通义法睿及部分第三方文本生成模型 | 自动评测仅支持 qwen-max 和 qwen-plus 生成评测集和执行评测 |
| **归因分析** | 无内置归因；需开发者自行分析低分样本 | 自动归因分析（模型理解有误、重排不佳、检索无效、切片不完整、未获取知识） |
| **排行榜** | 支持多模型排行榜对比 | 支持多应用横向评测对比（最多 8 个应用） |
| **前提条件** | 模型已部署；基线评测需先完成模型调优 | 应用已发布、已配置知识库、已开通应用观测 |
| **费用构成** | 被评测模型推理费用 + 裁判模型评分费用 | 评测产生的 Tokens × 模型调用单价 |
| **典型输出** | 综合得分、通过率、分数分布、数据明细、排行榜 | 评测报告、归因分析、调优建议、版本对比 |

## 评测类型详细对比

| 特性 | 模型评测 - 自定义评测 | 模型评测 - 基线评测 | 应用评测 - 自动评测 | 应用评测 - 手动评测 |
|------|----------------------|---------------------|---------------------|---------------------|
| 是否需要准备数据 | 是 | 否（使用预置数据集） | 否（基于知识库自动生成） | 是 |
| 评分方式 | AI + 规则 + 人工 | 标准基准自动评分 | AI 自动评分 | 人工标注 |
| 灵活度 | 高 | 低 | 中 | 高 |
| 适用阶段 | 模型选型、调优验证 | 调优后通用能力验证 | 应用上线前后持续监控 | 需要专家主观判断 |

## 适用场景建议

### 选择模型评测的场景

- **模型选型阶段**：需要在多个候选模型之间做横向对比，选出最适合业务的基础模型。
- **模型调优验证**：完成微调后需要量化调优效果（如对比调优前后的得分变化）。
- **通用能力基准测试**：使用基线评测验证调优模型在学科知识、数学、推理等通用维度上的表现。
- **评分标准高度定制**：需要自定义评分器 Prompt，精细控制裁判模型的打分逻辑。

### 选择应用评测的场景

- **RAG 应用质量把控**：应用依赖知识库[检索增强生成](../concepts/rag.md)，需要评估从检索到生成的全链路效果。
- **问题定位与归因**：希望系统自动分析低分样本的原因（检索无效、切片不完整、模型理解有误等），而非仅获得分数。
- **多版本迭代验证**：应用迭代后使用同一评测集对比新旧版本，验证优化效果。
- **工作流应用评测**：需要评估工作流类型应用的端到端输出质量。
- **持续质量监控**：在知识库更新、Prompt 调整、模型切换后触发回归评测。

### 组合使用建议

在实际开发流程中，两种评测通常配合使用：先通过模型评测完成基础模型的选型和调优，再通过应用评测验证集成到应用后的端到端效果。当应用评测归因分析指向"模型理解有误"时，可回到模型评测环节进一步排查模型自身的能力短板。

## 技术选型参考

1. **评测粒度**：如果关注的是模型对单个 [prompt](../guides/prompt.md) 的生成质量，使用模型评测；如果关注的是应用整体的回答效果（包含检索、重排、生成等多环节），使用应用评测。
2. **数据准备成本**：模型评测的自定义评测需要人工准备评测集，基线评测则无需准备数据；应用评测的自动评测可基于知识库自动生成评测集，降低数据准备成本。
3. **问题定位能力**：应用评测提供自动归因分析，能快速定位问题出在 RAG 的哪个环节；模型评测更侧重于给出分数，问题定位需开发者自行分析。
4. **迭代效率**：应用评测支持新旧版本报告直接对比，适合快速迭代；模型评测通过排行榜实现多模型对比，适合选型决策。
