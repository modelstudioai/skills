# 微调指南 vs 微调任务 API

阿里云百炼的模型调优能力可以从两个视角切入：面向初次接入、希望零代码完成全流程的"微调指南"，以及面向自动化流水线、希望用代码驱动任务生命周期的"微调任务 API"。两者并不互斥，而是同一套底层训练能力在不同使用场景下的两种暴露形式。本文从定位、能力边界、接入方式到选型建议做一次系统对比，帮助开发者在"什么时候用控制台、什么时候写代码"这件事上做出判断。

## 核心定位对比

| 维度 | 微调指南（控制台 + 全流程视角） | 微调任务 API（Jobs API） |
| --- | --- | --- |
| 定位 | 端到端的方法论与操作指南，覆盖训练方式选型、数据准备、控制台操作、评测部署全链路 | 围绕"训练任务"对象的编程接口，聚焦任务的创建、查询、列举、取消 |
| 目标用户 | 初次接触模型调优的产品 / 算法 / 业务人员，以及希望获得全流程参考的开发者 | 已经把调优集成进 CI / CD、自动化实验、批量管理的工程团队 |
| 能力覆盖 | 训练方式（CPT / SFT / DPO）选型、训练模式（全参 / LoRA）对比、支持模型矩阵、数据格式规范、控制台操作步骤、评测与部署衔接 | 任务生命周期管理：创建、列举、详情、取消；文件 ID、超参、后缀等字段级控制 |
| 交互形态 | 控制台可视化界面 + API 参考段落，偏教程与说明 | 纯 HTTP 接口 + 状态机，偏契约与自动化 |
| 状态可见性 | 控制台以页面刷新 + 状态标签呈现 | 通过 `GET /api-v1/fine-tunes/<job_id>` 与列举接口轮询状态字段 |

## 关键维度对比

| 维度 | 微调指南 | 微调任务 API |
| --- | --- | --- |
| 入口方式 | 百炼控制台"模型调优"页面；同时指引 API 入口 | DashScope HTTP API：`/api/v1/fine-tunes`、`/api/v1/files`、`/api/v1/deployments` |
| 前置条件 | 开通百炼服务、准备训练数据、了解训练方式概念 | 开通服务、获取 API-KEY；子账号需授予调用、训练、部署权限 |
| 训练方式支持 | 完整覆盖 CPT / SFT（全参+高效）/ DPO（全参+高效），并给出 `CPT → SFT → DPO` 的递进建议 | 在 `training_type` 字段中传入 `cpt` / `sft` / `efficient_sft` / `dpo_full` / `dpo_lora` 等枚举值 |
| 训练文件 | 控制台直接上传；API 路径为 `POST /api/v1/files`（`purpose=fine-tune`），单文件 ≤300MB，总配额 5GB / 100 个 | 通过文件接口上传后把 `file_id` 传入 `training_file_ids` / `validation_file_ids` |
| 数据格式 | ChatML（SFT）、带 chosen/rejected 的 ChatML（DPO）、纯文本 `{\"text\":...}`（CPT）、多模态 content 数组（VL） | 同样要求上述格式，API 侧会在数据校验阶段按 schema 拦截不合规样本 |
| 任务状态 | 控制台以中文标签呈现（排队中 / 运行中 / 成功 / 失败 等） | 标准状态机：`PENDING` / `QUEUING` / `RUNNING` / `CANCELING` / `SUCCEEDED` / `FAILED` / `CANCELED` |
| Checkpoint 管理 | 控制台配置 Checkpoint 保存参数，可视化查看中间快照 | 仅 `efficient_sft` / `sft` 支持中间 Checkpoint 的保存与发布；通过快照列表 API 轮询发布状态 |
| 部署衔接 | 训练成功后在"模型部署"页面一键部署，再去"模型评测"评估效果 | 训练成功后从 `finetuned_output` 字段拿到定制模型 ID，调 `POST /api/v1/deployments` 部署 |
| 计费方式 | 控制台支持按 Token 用量（`plan=lora`）或按模型单元使用时长（`plan=mu`，含预/后付费） | 通过 API 创建的任务**仅支持按 Token 计费**；如需模型训练单元必须在控制台创建 |
| 模型覆盖 | 列出 Qwen 文本、Qwen-VL 视觉、CosyVoice 语音、Wan 视频 / 图像等全家族支持矩阵 | 由 `model` 字段传入，具体可微调模型与指南中列出的矩阵一致 |
| 取消任务 | 控制台点击取消按钮 | `POST /api/v1/fine-tunes/<job_id>/cancel`，对 running 任务尽快终止，不保证立刻生效 |

## 适用场景建议

### 适合用"微调指南"（控制台为主）

- 第一次接触模型调优，需要先理解 CPT / SFT / DPO 三种方式的差异与递进关系。
- 训练数据规模较小、迭代次数有限，希望可视化地查看 Checkpoint、部署、评测。
- 需要使用**模型训练单元（MU）计费**，包括预付费 / 后付费包年包月等形态。
- 团队协作场景，希望非工程角色（算法、产品）也能参与训练任务的管理与评估。
- 涉及 CosyVoice、Wan 视频 / 图像等特殊模态，需要在控制台确认当前地域与接口限制。

### 适合用"微调任务 API"

- 已经把调优嵌入到 MLOps / CI 流水线，需要以代码驱动"上传文件 → 创建任务 → 轮询状态 → 部署 → 调用"的完整闭环。
- 需要批量创建、列举、取消任务，或在多个环境（开发 / 预发 / 生产）间复制同一套训练配置。
- 对任务状态、超参、后缀名需要字段级精细控制，希望把训练配置纳入 Git 管理。
- 接受按 Token 计费，且不需要预付费 MU 资源池。
- 需要对 `validation_file_ids`、`hyperparameters`、`suffix` 等字段做参数化实验。

### 混合使用

实际项目中，两种方式常常并存：用指南中的方法论完成**训练方式选型、数据准备、评测标准制定**；用 API 完成**日常的任务提交与批量管理**。典型组合是——

1. 首次接入时跟着指南在控制台跑通一次 SFT + 高效训练，建立对数据格式、状态流转、部署调用的直觉。
2. 稳定后把相同配置沉淀成脚本，通过 API 在流水线中重复执行。
3. 遇到新模态（VL / CosyVoice / Wan）或新训练方式（CPT / DPO）时，再回到指南查阅限制与推荐超参。

## 技术选型参考

给开发者的几条决策建议：

- **先问计费模式**：如果业务侧强制要求 MU 预付费，只能走控制台；如果按 Token 后付费即可满足，API 完全可替代。
- **再看自动化程度**：一次性实验用控制台足够；超过 3 次以上的重复训练，强烈建议切到 API，并把超参配置外置到文件。
- **关注状态机语义**：API 的状态字段是下游自动化判断的唯一依据，注意 `CANCELING` 与 `CANCELED` 的区分，以及取消操作对已终态任务无效。
- **Checkpoint 可用性**：只有 `sft` / `efficient_sft` 提供中间 Checkpoint 的保存与发布能力，CPT / DPO 任务只能等终态。
- **多模态训练**：VL、CosyVoice、Wan 系列的训练入口、地域限制、调用约束在指南中有详细说明，API 侧的字段本身并不做区分，需要在调用前确认当前模型的能力边界。
- **版本管理**：通过 API 的 `suffix` 字段 + 训练文件版本 + 超参配置文件，可以构建可复现的训练版本体系；控制台侧则依赖任务列表与 Checkpoint 快照做版本回溯。

总体来说，"微调指南"提供的是**方法论与入口**，"微调任务 API"提供的是**可编程的任务生命周期接口**。两者共享同一套底层训练能力与模型矩阵，差异主要体现在交互形态、计费方式、自动化友好度上。选对入口，能让调优工作既不走弯路，也方便后续规模化。
