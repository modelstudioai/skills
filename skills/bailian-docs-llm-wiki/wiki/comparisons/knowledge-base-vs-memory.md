# 知识库与记忆库对比

百炼平台同时提供**知识库**和**记忆库**两种数据增强方案，分别解决不同层面的信息补充需求。知识库基于 RAG 技术为大模型注入私有文档和结构化数据，侧重于"让模型知道组织的知识"；记忆库则聚焦于跨会话的长期记忆管理，侧重于"让模型记住用户的偏好和历史"。本文从多个维度对二者进行对比，帮助开发者在技术选型时做出合理判断。

## 核心维度对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **定位** | 为大模型补充私有数据与最新信息，回答特定领域问题 | 跨会话持久化用户偏好和历史信息，实现个性化交互 |
| **底层技术** | RAG（[检索增强生成](../concepts/rag.md)）：文件解析 → 切分 → 向量化 → 语义召回 | 自动记忆提取 + 语义检索：从对话中抽取关键事件并持久化存储 |
| **数据来源** | PDF、Word、Markdown、图片、Excel、RDS、音视频等文件与数据源 | 对话消息（自动提取）或自定义内容（手动写入） |
| **数据粒度** | 文档切片（单切片上限 6000 Token） | 记忆片段（关键事件信息）和用户画像（结构化属性） |
| **存储类型** | 文档搜索、数据查询(NL2SQL)、图片问答、音视频搜索 四种类型（创建后不可更改） | 记忆片段 + 用户画像 两种内容类型 |
| **检索方式** | 向量语义检索 + Rerank 排序模型（支持 hybrid 语义+BM25） | 语义检索（SearchMemory），支持 top_k 参数控制返回条数 |
| **向量模型** | text-embedding-v4/v3（512 维）、multimodal-embedding-v1（1024 维）、qwen3-vl-embedding | gte-rerank-v2（排序模型） |
| **主要 API** | ApplyFileUploadLease → AddFile → SubmitIndexJob → Retrieve | AddMemory、SearchMemory、ListMemory、UpdateMemory、DeleteMemory |
| **API 端点** | 百炼 SDK 知识库检索接口 | `https://dashscope.aliyuncs.com/api/v2/apps/memory/*` |
| **集成方式** | 智能体应用挂载、工作流节点绑定、SDK 外部调用 | API 直接调用、插件集成（如 OpenClaw 生命周期钩子） |
| **资源级别** | 工作空间级别 | 账号级别（每账号自带默认记忆库，不可删除） |

## 性能与配额对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **检索延迟** | 取决于知识库规模和排序模型配置 | SearchMemory 200–500ms；AddMemory 500–1000ms |
| **速率限制** | 按应用并发配额 | AddMemory 120 次/分钟；SearchMemory 300 次/分钟；合计 3000 次/分钟 |
| **计费** | 向量存储（内置免费 / ADB-PG 自购）+ 向量化 + Rerank 调用费用 | 限时免费 |
| **版本规格** | 标准版 / 旗舰版（可互转，每日限变配 1 次） | 无版本区分 |
| **存储上限** | 旗舰版降标准版需存储低于 80 GB | 无明确存储上限文档说明 |
| **规则配额** | 无限制（取决于切片数和文件数配额） | 每库最多 50 条记忆片段规则 + 50 条用户画像规则 |

## 配置与管理对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **创建后可变参数** | 名称、描述、相似度阈值（向量模型、切片方式等创建后不可改） | 记忆规则（名称、指令、自动更新、过期时间） |
| **数据更新** | 文档类支持 OSS+FC 自动更新；数据类支持 RDS 自动同步；音视频仅支持删除 | 通过 AddMemory 持续写入，支持 UpdateMemory 修改、DeleteMemory 删除 |
| **过期机制** | 无过期（手动管理生命周期） | 可配置 7 天 / 30 天 / 180 天 / 永不过期 |
| **调试工具** | 命中测试（模拟提问验证召回质量） | 控制台查看和检索记忆 |
| **多应用共享** | 可挂载到多个应用，但权重仅在同类型知识库间生效 | 支持多应用共享同一记忆库 |
| **用户隔离** | 无内置用户隔离 | 通过 user_id 天然实现用户级隔离 |

## 适用场景建议

**选择知识库的场景：**

- 需要让大模型基于企业内部文档（产品手册、技术文档、FAQ）回答问题
- 数据源为文件（PDF、Word、Excel）或数据库，需要结构化检索
- 需要图片问答、音视频搜索等多模态检索能力
- 需要精细控制切片粒度、排序策略和召回阈值
- 面向所有用户提供统一的知识问答服务

**选择记忆库的场景：**

- 需要智能体记住每位用户的个人偏好、历史请求和上下文
- 需要跨会话保持对话连贯性（如定时提醒、个人习惯）
- 需要构建用户画像并基于画像提供个性化服务
- 希望零成本快速接入（当前限时免费）
- 需要通过 user_id 实现多租户记忆隔离

**组合使用：**

知识库和记忆库并不互斥。推荐的最佳实践是将二者结合：用知识库提供领域知识支撑，用记忆库记录用户个性化信息。例如，一个客服智能体可以通过知识库检索产品文档解答技术问题，同时通过记忆库记住用户的产品型号和历史工单，在后续对话中提供更精准的个性化服务。

## 技术选型速查

| 需求 | 推荐方案 |
|------|----------|
| 企业知识问答 | 知识库 |
| 用户个性化助手 | 记忆库 |
| 多模态数据检索 | 知识库 |
| 跨会话上下文保持 | 记忆库 |
| 结构化数据查询（NL2SQL） | 知识库 |
| 用户画像管理 | 记忆库 |
| 个性化知识问答 | 知识库 + 记忆库 |
