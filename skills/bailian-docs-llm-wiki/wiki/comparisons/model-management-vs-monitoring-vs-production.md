# 模型管理、监控与生产部署能力对比

为帮助开发者在百炼平台中高效构建、运维和规模化落地 AI 应用，本文对平台三大核心能力模块——**模型管理（Model Management）**、**模型监控（Model Monitoring）** 和 **模型生产（Model Production）** 进行系统性对比分析。三者分别聚焦于**运行时策略管控**、**生产环境可观测性保障** 和 **模型全生命周期工程化交付**，虽目标协同，但在设计定位、技术边界、适用阶段与权限模型上存在本质差异。本对比面向企业级开发者与 MLOps 工程师，旨在提供清晰的技术选型依据，避免能力误用（如用监控替代限流、用管理接口替代训练部署）。

---

## 关键能力维度对比

| 维度 | 模型管理（Model Management） | 模型监控（Model Monitoring） | 模型生产（Model Production） |
|------|-----------------------------|-----------------------------|-----------------------------|
| **核心定位** | 运行时访问控制与配额治理（**Who can call what, and how much?**） | 生产调用可观测性与异常诊断（**How is it performing, and when does it break?**） | 模型训练、压缩、部署与容量编排（**How to build, optimize and serve a custom model?**） |
| **输入格式** | RESTful JSON 请求体（含 `model_id`, `rate_limit`, `permissions` 等结构化参数） | 无主动输入；数据自动采集自所有通过百炼 API 的模型调用请求（含标准 HTTP 头与请求体元信息） | RESTful JSON 请求体（含 `model_name`, `training_type`, `hyper_parameters`, `plan`, `capacity` 等强类型字段） |
| **输出格式** | 标准 HTTP 响应（200/403/404），返回策略快照或操作结果（如 `{"rate_limit": {"rps": 5}}`） | 可视化图表（控制台）、结构化指标（Prometheus/OpenMetrics）、日志事件（SLS JSON）、告警通知（邮件/钉钉/短信） | [异步任务](../concepts/asynchronous-task.md) ID（`job_id`）、部署 ID（`deployed_model`）、模型代码（`ModelCode`）、状态轮询端点（`GET /deployments/{id}`） |
| **支持模型范围** | ✅ 所有已上线的**推理模型**：通义千问系列（`qwen-max`, `qwen-plus`）、语音/多模态模型（`paraformer-realtime-v1`）、客户私有微调模型（需已完成部署）<br>❌ 不支持训练中模型、未部署模型、基础模型（如 `qwen3-14b`） | ✅ 全量内置模型 + 调优后模型（文本/视觉/语音/向量等）<br>⚠️ 部分模型功能受限：语音/图片/视频生成不支持全部监控项（如首 [Token](../concepts/token.md) 延时）；三方直连模型监控能力弱 | ✅ 文本生成、图像生成、视频生成、语音合成（CosyVoice）四类任务<br>⚠️ 地域严格受限：微调/导入/压缩仅支持**华北2（北京）**；部署方案地域支持不一（`ptu_v2`: 北京/新加坡；`dtu`/`mu`: 仅北京；图像/视频/语音部署仅开放北京） |
| **API 端点示例** | `GET /v1/models`<br>`PUT /v1/models/{model_id}/rate-limits`<br>`POST /v1/models/{model_id}/permissions` | 无直接调用型 API；监控数据通过控制台或云监控/Prometheus/SLS 接入；告警规则通过 `/api/v1/alert-rules`（需授权）管理 | `POST /api/v1/fine-tunes`（微调）<br>`POST /api/v1/deployments`（部署/PTU预留）<br>`GET /api/v1/fine-tunes/{job_id}`（状态查询） |
| **计费方式关联** | ❌ **不产生费用**；仅为策略配置接口，不影响账单 | ❌ **不作为计费依据**；用量统计与费用核对请以[模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)和账单为准 | ✅ **直接驱动计费**：<br>• `lora`: 按 [Token](../concepts/token.md) 计费<br>• `mu`/`dtu`: 按模型单元/吞吐容量预付费或后付费<br>• `ptu_v2`: 按预留吞吐量（kTPM）按小时计费 |
| **典型场景** | • 多租户工作空间中为不同业务线分配 `qwen-plus` 调用配额（RPS=10）<br>• 临时禁止某 RAM Role 调用敏感语音识别模型<br>• 为 A/B 测试组开通 `qwen-max` 的专属 [Token](../concepts/token.md) 配额（TPM=50k） | • 实时发现 `qwen-max` 失败率突增至 8%，触发钉钉告警并定位为内容安全拦截激增<br>• 分析图像生成模型首 Token 延时持续上升，判断 GPU 显存泄漏<br>• 投递推理日志至 SLS，审计用户 Prompt 合规性（需手动开启） | • 使用自有数据微调 `qwen3-14b`，产出 `qwen3-14b-ft-abc123`<br>• 将微调模型以 `mu` 方式部署为高隔离服务，绑定专属域名<br>• 为大促流量预留 `ptu_v2` 吞吐（input_tpm=200k, output_tpm=100k）并复用至多个模型 |

## 适用场景建议

| 场景描述 | 推荐能力模块 | 关键理由 | 注意事项 |
|----------|--------------|----------|----------|
| **需要为不同部门/项目组划分模型调用权限与速率上限** | ✅ 模型管理 | 提供基于 `model_id` 的细粒度 RBAC 控制，支持 RPS/TPM 双维度限流，变更秒级生效，且与 IAM 权限中心深度集成 | 必须具备工作空间管理员或模型管理员角色；非管理员调用更新接口将返回 `403 Forbidden` |
| **线上服务出现延迟升高、失败增多、成本异常，需快速定位根因** | ✅ 模型监控 | 提供分钟级延迟的实时指标（失败率、429 次数、首 Token 延时、TotalToken）、预置告警模板、审计/推理日志投递能力，覆盖“可观测性黄金信号” | 告警仅支持表中标记 ✅ 的指标；推理日志需手动开启且仅支持北京/新加坡地域；数据不用于计费 |
| **需基于自有数据定制模型（如行业知识增强、风格迁移），并稳定、高性能地对外提供服务** | ✅ 模型生产 | 提供端到端闭环：从数据准备 → 微调训练 → 模型压缩 → 多种部署模式（共享/独占/预留）→ 容量弹性伸缩，满足不同 SLA 与成本诉求 | 微调与部署强绑定，必须使用微调产出的有效 `model_id`；地域限制严格，务必提前验证控制台可选范围；HTTP 200 不代表操作成功，需检查响应体 `operation_status` |
| **仅需调用百炼现成模型（如 `qwen-max`）完成简单任务，无定制/治理/运维需求** | ⚠️ 无需上述任一模块 | 直接调用标准 `/v1/services/<model_id>/chat` 等 API 即可，三者均为进阶能力 | 若后续出现配额不足、性能波动或需审计，则需按需启用对应模块 |

## 开发者技术选型参考

- **优先确认阶段归属**：  
  - 若处于 **模型上线后运维期**（已部署模型在跑，但需控权、看数、告警）→ 首选 **模型监控** + **模型管理**；  
  - 若处于 **模型交付前工程期**（需训练、优化、部署新模型）→ 必选 **模型生产**；  
  - **模型管理** 是生产环境的“守门员”，应在模型部署后立即配置，而非等到问题发生。

- **警惕能力边界陷阱**：  
  - ❌ 不要用 `模型监控` 的“失败率”代替 `模型管理` 的“限流”来防雪崩——监控是观测，管理才是控制；  
  - ❌ 不要用 `模型管理` 的 `permissions` 接口替代 `模型生产` 的 `deployments` 接口来“部署模型”——前者管访问，后者管实例；  
  - ❌ 不要期望 `模型生产` 的微调 API 支持跨地域调用——所有训练类操作必须在北京 Region 发起。

- **关键依赖检查清单**：  
  - ✅ 调用 `模型管理` 前：确认账号具备工作空间 **管理员** 或 **模型管理员** 角色；  
  - ✅ 配置 `模型监控` 告警前：已在控制台完成 **云监控服务角色授权**；  
  - ✅ 启用 `模型监控` 推理日志前：已开启 **审计日志投递**，且 SLS 日志库位于 **北京或新加坡**；  
  - ✅ 执行 `模型生产` 微调前：确保训练数据已上传至 **华北2（北京）OSS**，且 API 请求 Endpoint 为 `https://dashscope.aliyuncs.com`（北京）；  
  - ✅ 部署 `模型生产` 模型后：立即通过 `模型管理` 设置合理限流，避免资源耗尽。

- **推荐组合实践**：  
  > **“生产即治理”工作流**：完成 `模型生产` 部署 → 立即调用 `模型管理` 接口设置初始 RPS/TPM 配额 → 在 `模型监控` 控制台配置失败率 & 429 告警 → 将监控指标投递至自有 Prometheus → 将审计日志投递至 SLS 归档。此闭环覆盖交付、防护、观测、归档全链路，是企业级 AI 服务的基线实践。
