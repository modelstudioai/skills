# 模型评估与应用评估对比

百炼平台同时提供「模型评测」和「应用评测」两套评估体系，分别面向不同的评估对象和使用阶段。模型评测聚焦于大语言模型本身的能力验证与选型，而应用评测则关注基于模型构建的智能体应用或工作流应用的端到端输出质量。理解两者的定位差异，有助于开发者在不同阶段选择正确的评测工具。

## 核心维度对比

| 对比维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| **评估对象** | 大语言模型（预置模型或调优后模型） | 智能体应用、工作流应用 |
| **评估目标** | 量化模型的语言能力、推理能力、生成质量 | 评估应用端到端的回答质量与知识检索效果 |
| **评测模式** | 自定义评测（自建标准）、基线评测（公开榜单） | 自动评测（大模型打分）、手动评测（人工标注）、新版评测任务（评估器+标签组合） |
| **数据来源** | 自备 Excel 评测数据集 / 推理结果集；基线评测使用预置标准数据集（C-Eval、MMLU 等） | 自动评测从知识库自动生成；手动评测需上传对话分析数据集；新版支持从应用观测导入 |
| **评分机制** | 5 种评测维度类型：大模型评估（数值型/分类型）、规则评估（相似度/字符串匹配）、人工评估 | 评估器（LLM 评估器、Code 评估器、基于历史标注）+ 人工标签（分类/布尔/数字/文本） |
| **裁判模型** | 自定义评测中可选千问-Max 等作为裁判模型 | 自动评测仅支持 qwen-max 和 qwen-plus |
| **归因分析** | 不提供归因分析 | 自动评测提供 BadCase 归因（模型理解有误、重排不佳、检索无效、切片不完整、未获取知识） |
| **多对象对比** | 可通过排行榜横向对比多个模型 | 支持多应用横向评测（最多 8 个应用） |
| **前提条件** | 基线评测要求模型已完成调优和部署 | 应用必须已发布、已配置知识库、已开通应用观测 |
| **计费方式** | 裁判模型按 Token 计费 + 被评测模型推理费用（分开归属） | 评测产生的 Token 按模型调用单价计费 |
| **结果输出** | 综合得分、通过率、分数分布、数据明细；基线评测含学科雷达图 | 评测报告、评分明细、归因分析、调优建议 |
| **评估器数量限制** | 单任务可组合多个评测维度（无明确上限） | 每个评测任务最多 10 个评估器 |

## 评测数据格式对比

| 对比维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| **文件格式** | Excel（`.xlsx`） | 旧版：`.xls`/`.xlsx`（对话分析）、`.jsonl`（知识问答）；新版：按应用类型定义 |
| **核心字段** | `Prompt`（问题）、`Completion`（参考答案）、可选 `Output`（推理结果） | 知识问答：query、referenceAnswer、关键词等；对话分析：对话轮次数据 |
| **数据生成** | 需人工准备 | 可自动生成（知识问答类型）或从应用观测导入 |
| **建议数据量** | 小规模 50-100 条，正式 200-500 条，全面 500+ 条 | 单文件不超过 20MB，单次上传最多 10 个文件 |

## 适用场景建议

**选择模型评测的场景：**

- 需要在多个候选模型之间做选型决策时，用相同测试集横向对比各模型的能力。
- 完成模型微调后，需要量化验证调优前后的效果提升（如得分从 75 提升到 85）。
- 需要对模型的通用能力（学科、数学、推理）进行标准化基准测试。
- 需要建立定期评测机制，持续监控模型在固定数据集上的表现趋势。

**选择应用评测的场景：**

- 已构建智能体或工作流应用，需要评估应用整体的回答质量而非底层模型能力。
- 需要定位回答质量问题的具体环节（检索、重排、切片、模型理解），利用归因分析快速优化。
- 需要对比多个应用版本（最多 8 个）在同一基准下的表现差异。
- 知识库更新、Prompt 调整、检索策略变更后，需要回归验证应用效果。
- 需要领域专家进行主观判断和人工标注打分。

**推荐组合使用：** 在项目初期用模型评测完成模型选型和调优验证，确定最优基座模型后，在应用构建阶段切换到应用评测进行端到端质量监控和持续优化。两者覆盖了从模型层到应用层的完整评估链路。
