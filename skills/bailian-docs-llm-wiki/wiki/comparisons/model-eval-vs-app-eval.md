# 模型评测 vs 应用评测

百炼平台同时提供「模型评测」和「应用评测」两套评测体系，分别面向大语言模型本身的质量验证和智能体/工作流应用的效果评估。本文从定位、评测对象、数据准备、评分机制、适用场景等维度进行对比，帮助开发者根据实际需求选择合适的评测方案。

## 核心定位对比

| 维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| 评测对象 | 大语言模型（千问、GPT、Claude 等） | 智能体应用、工作流应用 |
| 核心目标 | 量化模型本身的语言理解、推理、生成能力 | 评估应用端到端的回答质量与 RAG 链路效果 |
| 评测粒度 | 单条 Prompt → 单条 Output | 多轮对话、知识库检索、推理链路 |
| 典型使用者 | 模型调优人员、算法工程师 | 应用开发者、RAG 系统运维人员 |

## 评测模式对比

| 维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| 自定义评测/评测 | 自定义评测（自备数据集与评分标准） | 手动评测（人工构建评测集并标注打分） |
| 基线/自动评测 | 基线评测（使用 C-Eval、MMLU 等预置榜单） | 自动评测（大模型基于知识库自动生成评测集并打分） |
| 新增能力 | — | 新版评测任务：评估器 + 标签组合机制 |
| 横向对比 | 多模型排行榜 | 多应用横向评测（最多 8 个应用/版本） |
| 归因分析 | 无 | 内置 BadCase 归因（模型理解有误 / 重排不佳 / 检索无效 / 切片不完整 / 未获取知识） |

## 数据准备对比

| 维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| 数据格式 | Excel（.xlsx），列为 Prompt / Completion / Output | 旧版：对话分析（.xls/.xlsx）、知识问答（.jsonl）；新版：智能体 / 工作流 / 自定义表结构 |
| 数据来源 | 自备评测数据集或已有推理结果集 | 手动上传、自动生成（知识问答）、从应用观测导入 |
| 数据量建议 | 小规模 50-100 条；正式 200-500 条；全面 500+ 条 | 由评测集管理，支持版本管理 |
| 数据集类型限制 | 仅支持「评测集」类型，不支持训练集 | 旧版与新版为独立体系，需手动切换 |

## 评分机制对比

| 维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| 评分类型 | 数值型（1-5 分）、分类型（Pass/Fail）、文本相似度、字符串匹配、人工分类型 | LLM 评估器、Code 评估器、基于评测任务的评估器；标签支持分类 / 布尔 / 数字 / 文本 |
| 裁判/评估模型 | 可自选裁判模型（如千问-Max） | 自动评测固定使用 qwen-max / qwen-plus |
| 评分器模板 | 综合评测、语义相似度、自定义 Prompt | 预置模板：通用质量、智能体、文本匹配、文本相似度、格式校验 |
| 评分变量 | `${prompt}`、`${output}`、`${completion}` | 由评估器自动处理，无需手动配置变量 |
| 每任务评分器数量 | 可组合多个评测维度 | 最多 10 个评估器，建议 3-5 个组合 |

## 费用与限制对比

| 维度 | 模型评测 | 应用评测 |
| --- | --- | --- |
| 计费项 | 被评测模型推理费用 + 裁判模型评分费用（分开归属） | 评测产生的 Tokens x 模型调用单价 |
| 模型限制 | 自定义评测支持多种千问系列、开源版、第三方模型；基线评测仅支持调优后的模型 | 自动评测仅支持 qwen-max / qwen-plus |
| 前置条件 | 基线评测需先完成模型调优和部署 | 应用需已发布、已配置知识库、已开通应用观测 |
| 文件限制 | — | 单次最多上传 10 个文件，单文件不超过 20MB |

## 适用场景建议

### 选择模型评测

- **模型选型**：需要在多个候选大模型（千问、GPT、Claude 等）之间做客观对比。
- **调优验证**：量化模型微调前后的能力变化（如得分从 75 提升到 85）。
- **通用能力量化**：使用 C-Eval、MMLU、GSM8K 等公开榜单评估模型学科、数学、推理能力。
- **持续监控**：建立定期评测机制，追踪模型表现趋势。

### 选择应用评测

- **RAG 应用上线前验证**：评估智能体应用的知识库检索质量和回答准确性。
- **版本迭代对比**：对同一应用的不同版本进行横向评测，验证 Prompt 调整或检索策略优化的效果。
- **BadCase 定位**：利用自动归因分析定位 RAG 链路中具体问题（检索、重排、切片、知识库缺失）。
- **多应用选型**：在统一基准下对比最多 8 个应用或版本。

### 组合使用

对于「模型调优 + 应用落地」的完整链路，建议：

1. 先用**模型评测**验证底层模型能力，选择合适的基座模型。
2. 构建应用后，用**应用评测**评估端到端效果，特别是 RAG 链路质量。
3. 应用上线后，定期运行应用评测进行回归监控；若发现模型层面退化，再回到模型评测做定位。

## 技术选型参考

| 决策因素 | 推荐方案 |
| --- | --- |
| 评估纯大模型能力（推理、生成、学科知识） | 模型评测 |
| 评估 RAG 应用端到端效果 | 应用评测 |
| 需要与业界公开榜单对比 | 模型评测（基线评测） |
| 需要定位 RAG 链路问题环节 | 应用评测（自动评测归因） |
| 对比多个候选模型 | 模型评测（自定义评测 + 排行榜） |
| 对比多个应用版本 | 应用评测（多应用横向评测） |
| 预算有限、希望零额外评估费用 | 模型评测（规则评估-字符串匹配 / 文本相似度） |
| 需要人工专家主观判断 | 应用评测（手动评测 + 标签管理） |
