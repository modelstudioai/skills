# 模型微调、模型压缩与模型部署对比

百炼平台围绕模型的生产化使用提供了三项核心能力：模型微调（Fine-Tuning）、模型压缩和模型部署。三者在模型优化链路中各司其职、前后衔接——微调提升模型能力，压缩降低资源开销，部署将模型上线为可调用的推理服务。本文从功能定位、输入输出、支持模型、操作方式、计费等维度进行对比，帮助开发者根据实际需求选择合适的环节进行操作。

## 核心维度对比

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
|------|---------|---------|---------|
| **功能定位** | 通过训练数据调整模型参数，提升特定场景表现 | 通过量化算法降低模型精度，缩小部署规格 | 为模型创建独立推理服务，提供在线调用能力 |
| **输入** | 训练数据集（JSONL/ZIP 格式） | 已微调的全精度自定义模型 + 可选校准数据 | 预置模型或已微调/已压缩的自定义模型 |
| **输出** | 自定义微调模型 | 量化后的低精度模型 | 可调用的在线推理服务（返回 deployed_model ID） |
| **支持的模型类型** | 文本生成、视觉理解、语音合成、视频生成、图像生成 | 仅特定文本生成模型（如 qwen3.5-flash） | 文本生成、多模态、语音合成等（覆盖预置与自定义模型） |
| **调优/处理方法** | CPT、SFT（全参/LoRA）、DPO（全参/LoRA） | 量化模板（由平台预设） | 无（直接部署） |
| **操作方式** | 控制台 + API | 控制台 + OpenAPI | 控制台 + API |
| **核心 API 端点** | POST `/api/v1/fine-tunes` | OpenAPI 创建压缩任务 | POST `/api/v1/deployments` |
| **计费方式** | 按训练 Token 数 × 循环次数 × 单价 | 当前限时免费 | 预置吞吐（PTU）/ 模型单元（MU）/ Token 用量 |
| **典型耗时** | 数小时至数天（取决于数据量和模型规模） | 任务排队 + 运行时间 | 部署上线后持续运行 |
| **是否可逆** | 可基于同一基础模型多次训练 | 不可逆，不支持二次压缩或继续训练 | 可随时下线/删除服务 |
| **地域限制** | 无特殊限制 | 无特殊限制 | 仅支持中国内地（北京） |

## 数据格式对比

| 格式要求 | 模型微调 | 模型压缩 | 模型部署 |
|---------|---------|---------|---------|
| **数据格式** | SFT: ChatML JSONL; DPO: chosen/rejected JSONL; CPT: 纯文本 JSONL; VL: ZIP 包 | 校准数据集（从数据管理中选择已发布数据集） | 无需额外数据 |
| **最低数据量** | CPT: 1000 万 Token; SFT: 1000+ 条; DPO: 100+ 组 | 由量化模板决定是否需要校准数据 | 不适用 |

## 计费方式详细对比

| 计费项 | 模型微调 | 模型压缩 | 模型部署 |
|-------|---------|---------|---------|
| **训练/压缩费用** | Token 数 × epochs × 单价（如 Qwen3-8B: 0.006 元/千 Token） | 限时免费 | 不适用 |
| **部署费用** | 微调模型需另行部署，按部署计费方式收费 | 压缩模型需另行部署，按部署计费方式收费 | PTU: 按 TPM 量和时长; MU: 按单元数和时长; Token 用量: 按实际调用 |
| **付费方式** | 按量后付费 | 免费（限时） | 后付费（按小时）或预付费（按天/包月） |

## 流程关系与典型链路

三项能力在实际使用中构成一条线性链路：

1. **模型微调**：准备高质量训练数据，选择基础模型和调优方法（CPT/SFT/DPO），训练产出自定义模型。
2. **模型压缩**（可选）：对微调产出的全精度模型进行量化，降低部署规格和推理成本。
3. **模型部署**：将预置模型、微调模型或压缩模型部署为在线推理服务，供业务系统调用。

> 模型压缩并非必经步骤。如果对推理成本不敏感或模型不在压缩支持列表内，可直接从微调跳到部署。

## 适用场景建议

| 场景 | 推荐操作 |
|------|---------|
| 模型在特定行业/任务上表现不佳，需要注入领域知识 | 模型微调（CPT + SFT） |
| 模型输出不符合人类偏好，存在幻觉问题 | 模型微调（DPO） |
| 微调后模型部署成本过高，需要降低显存占用 | 模型压缩 → 模型部署 |
| 需要稳定、高并发的在线推理服务 | 模型部署（PTU 或 MU 计费） |
| 微调后模型效果验证，用量不稳定 | 模型部署（Token 用量计费） |
| 本地训练的 LoRA 模型需要上线 | 模型导入 → 模型部署 |
| 快速验证模型效果，不需要专属资源 | 直接使用预置模型 API，无需部署 |

## 技术选型参考

- **是否需要微调**：优先尝试 Prompt 工程和插件调用。只有当这些方式无法满足需求时，再考虑模型微调。微调的迭代周期较长，数据准备和训练成本不可忽视。
- **是否需要压缩**：当微调模型的部署规格（如 MU1 × 2）导致成本偏高，且基础模型在压缩支持列表内时，可通过压缩降低到更小规格（如 MU8 × 1）。需注意压缩不可逆，量化可能带来精度损失。
- **部署计费方式选择**：流量稳定选 PTU（预置吞吐），需要资源隔离和自定义配置选 MU（模型单元），调优模型效果验证或用量极低选 Token 用量计费。计费方式创建后不可更改，切换需重新部署。
