# 模型微调、压缩与部署对比

在百炼平台上，模型微调（Fine-tuning）、模型压缩（Model Compression）和[模型部署](../concepts/model-deployment.md)（Model Deployment）是将基础模型转化为生产可用服务的三个核心环节。它们分别解决"让模型更懂业务"、"让模型更轻量"和"让模型上线服务"的问题。本文从技术定位、适用场景、操作流程等关键维度进行系统对比，帮助开发者在不同业务需求下做出合理的技术选型。

## 核心定位对比

| 维度 | 模型微调 | 模型压缩 | [模型部署](../concepts/model-deployment.md) |
|------|---------|---------|---------|
| **核心目标** | 提升模型在特定领域/任务上的表现 | 降低模型显存占用，缩小部署规格 | 将模型上线为可调用的推理服务 |
| **输入** | 基础模型 + 标注训练数据 | 微调产出的全精度自定义模型 | 预置模型或微调/压缩后的模型 |
| **输出** | 自定义微调模型 | 量化后的低精度模型 | 可调用的在线推理服务（API 端点） |
| **是否必须** | 可选（[Prompt 工程](../concepts/prompt-engineering.md)满足需求时可跳过） | 可选（仅需降本时使用） | 必须（模型上线的最后一步） |
| **技术手段** | CPT / SFT / DPO（全参或 LoRA） | 量化算法（由量化模板决定） | 资源调度 + 推理引擎托管 |

## 支持模型范围对比

| 维度 | 模型微调 | 模型压缩 | [模型部署](../concepts/model-deployment.md) |
|------|---------|---------|---------|
| **模型类型** | 文本生成、视觉理解、视频生成、图像生成、语音合成 | 仅文本生成（当前仅 qwen3.5-flash 等少量模型） | 文本生成、多模态、语音合成等全类型 |
| **代表模型** | Qwen3/3.5/3.6、Qwen2.5 全系列，Qwen-VL，万相，CosyVoice | qwen3.5-flash-2026-02-23 | 千问全系列、DeepSeek、GLM、MiniMax、Kimi 等 |
| **模型来源** | 平台预置基础模型 | 仅限微调产出的自定义模型 | 预置模型 + 微调/压缩产出的自定义模型 |
| **覆盖广度** | 中等（需在支持调优列表内） | 极窄（当前仅少量模型可压缩） | 最广（预置模型 + 所有自定义模型） |

## 数据格式与输入要求

| 维度 | 模型微调 | 模型压缩 | [模型部署](../concepts/model-deployment.md) |
|------|---------|---------|---------|
| **训练/校准数据** | 必须提供（SFT: ChatML JSONL; DPO: 正负样本对; CPT: 纯文本） | 可选（部分量化模板需要校准数据集） | 不需要训练数据 |
| **数据量要求** | CPT: 1000万+ Token; SFT: 1000+ 条; DPO: 100+ 组 | 校准数据需在数据管理中已发布 | 无 |
| **特殊格式** | 视频/图像/语音需打包为 ZIP | 校准数据从数据管理选取 | 导入 LoRA 模型需 safetensors + config.json |

## 使用方式与 API 对比

| 维度 | 模型微调 | 模型压缩 | [模型部署](../concepts/model-deployment.md) |
|------|---------|---------|---------|
| **控制台操作** | 模型调优页面，可视化创建训练任务 | 模型训练 > 模型压缩页面 | [模型部署](../concepts/model-deployment.md)页面（仅北京地域） |
| **API 端点** | `POST /api/v1/fine-tunes` | OpenAPI（具体端点见文档） | `POST /api/v1/deployments` |
| **关键 API 参数** | model, training_file_ids, training_type, hyper_parameters | 源模型、量化模板、校准数据 | model_name, plan (ptu/mu/lora), capacity |
| **状态查询** | `GET /api/v1/fine-tunes/<job_id>` | 任务列表查看状态 | `GET /api/v1/deployments/<deployed_model>` |
| **任务终态** | SUCCEEDED / FAILED | 压缩成功 / 压缩失败 / 已取消 | RUNNING（部署完成）|

## 计费方式对比

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
|------|---------|---------|---------|
| **计费模型** | 按 Token 总数 x 循环次数 x 单价 | 当前限时免费 | PTU（按吞吐量时长）/ 模型单元（按小时）/ Token 用量（按量） |
| **费用示例** | qwen3-8b: 0.006 元/千Token; qwen2.5-72b: 0.15 元/千Token | 免费（以控制台公告为准） | PTU: 按 TPM 时长; 模型单元: 如 MU1x2=108元/小时 |
| **付费模式** | 后付费 | 免费 | 后付费（按小时）或预付费（按天/月） |
| **成本控制建议** | 先用 LoRA 高效训练验证，再考虑全参 | 通过压缩降低部署规格从而降低部署费用 | 按业务量选择合适的计费方式 |

## 流程衔接关系

三个功能在模型生产链路中呈线性递进关系：

1. **模型微调** -- 让基础模型学会特定任务，产出自定义模型
2. **模型压缩**（可选） -- 对微调产出的全精度模型做量化，降低部署成本
3. **模型部署** -- 将最终模型上线为推理服务，供业务调用

典型场景链路为：`基础模型 → SFT 微调 → (可选) 量化压缩 → 模型部署 → API 调用`。

## 适用场景建议

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| 模型在特定领域表现不佳 | 模型微调（SFT） | 使用领域问答对进行监督微调，快速提升领域准确率 |
| 需要注入大量领域知识 | 模型微调（CPT + SFT） | 先用 CPT 补充知识，再用 SFT 学会指令遵循 |
| 模型输出风格不符合预期 | 模型微调（DPO） | 通过正负样本对齐人类偏好 |
| 微调后模型部署成本过高 | 模型压缩 + 部署 | 先压缩降低规格（如 MU1x2 降至 MU8x1），再部署 |
| 快速验证微调效果 | Token 用量部署 | 成本最低，不使用不计费，适合效果验证阶段 |
| 生产环境稳定服务 | PTU 或模型单元部署 | PTU 适合流量稳定场景；模型单元适合需要自定义性能的大规模推理 |
| 本地训练的 LoRA 模型上线 | 模型导入 + 部署 | 从 OSS 导入 LoRA 权重，再通过部署上线 |

## 限制与注意事项

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
|------|---------|---------|---------|
| **地域限制** | 有（具体见文档） | 与部署一致 | 仅华北二（北京） |
| **不可逆性** | 可反复训练迭代 | 不可逆，压缩后不支持继续训练或二次压缩 | 删除后不可恢复 |
| **关键限制** | 模型需在支持调优列表内 | 仅支持列表内微调模型，不支持已量化模型 | 计费方式创建后不可更改 |
