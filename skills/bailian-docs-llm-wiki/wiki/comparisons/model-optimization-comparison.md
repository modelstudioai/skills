# 模型微调、压缩与高速推理对比

百炼平台围绕模型的"训练-优化-部署"链路提供了三项核心能力：**模型微调（Fine-tuning）**、**模型压缩（Model Compression）** 和 **TPM 预留高速推理**。三者分别解决不同阶段的问题——微调让模型学会新知识和新行为，压缩降低部署成本，TPM 预留保障线上推理吞吐。本文从多个关键维度对三者进行对比，帮助开发者在实际项目中做出合理的技术选型。

## 核心维度对比

| 维度 | 模型微调 | 模型压缩 | TPM 预留（高速推理） |
|------|---------|---------|-------------------|
| **核心目标** | 基于自有数据定制模型能力，提升特定场景表现 | 将全精度模型量化为低精度版本，降低部署成本 | 为推理提供专属容量保障，消除公共限流 |
| **作用阶段** | 训练阶段 | 训练后、部署前的优化阶段 | 部署与推理阶段 |
| **输入** | 标注数据集（JSONL/ZIP），格式因模态和方法而异 | 已完成微调的自定义全精度模型 + 可选校准数据 | 已部署的模型（官方模型或微调模型） |
| **输出** | 定制化微调模型 | 量化后的低精度模型 | 专属模型 code + 刚性容量保障 |
| **支持模型范围** | Qwen3.6/3.5/3/2.5 系列文本、VL 视觉、Wan 图像/视频、CosyVoice 语音等 | 当前仅支持 qwen3.5-flash-2026-02-23 对应的自定义微调模型 | qwen3.6-flash、qwen3.7-max/plus、glm-5.1/5.2、kimi-k2.6、deepseek-v4-flash/pro 等 |
| **操作方式** | 控制台可视化 + DashScope API | 控制台 + OpenAPI | 控制台创建预留 + API 调用时替换 model 参数 |
| **关键参数** | learning_rate、n_epochs、batch_size、max_length、lora_rank | 源模型、量化模板（决定目标部署规格）、校准数据 | 模型、输入/输出 kTPM、付费周期、购买时长 |
| **[计费](../concepts/billing.md)方式** | 按训练数据 [Token](../concepts/token.md) 总数 x 循环次数 x 训练单价 | 当前限时免费（部署按标准规格[计费](../concepts/billing.md)） | 按 kTPM 预付费（按天），超额部分自动降级为按量[计费](../concepts/billing.md) |
| **耗时量级** | 分钟到数小时（视数据量和模型规模） | 分钟到小时级（压缩任务） | 秒级（创建预留后即可调用） |
| **是否可逆** | 可基于同一基础模型重新微调 | 不可逆，压缩后不支持继续训练或二次压缩 | 可随时扩缩容、续费或退订 |

## 流程关系

三项能力在模型生命周期中构成串联关系，但并非每个环节都是必选：

```
基础模型 → [微调] → 微调模型 → [压缩(可选)] → 量化模型 → [部署] → [TPM 预留(可选)] → 线上推理
```

- **仅用微调**：适合需要定制模型能力但对部署成本和推理吞吐无特殊要求的场景。微调后直接部署即可。
- **微调 + 压缩**：适合微调模型过大、部署成本过高的场景。压缩可将模型部署到更小规格的部署单元（例如从 MU1x2 降至 MU8x1），显著降低每小时费用。
- **微调 + TPM 预留**：适合微调模型已部署但业务高峰期受限流影响的场景。TPM 预留锁定专属吞吐量，超额自动降级不中断。
- **三者组合**：对成本和性能都有严格要求的生产环境推荐全链路使用。

## 适用场景建议

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| 垂直领域知识注入（金融/医疗/法律） | 微调（CPT + SFT） | 先用 CPT 注入领域知识，再用 SFT 学习指令格式 |
| 客服/代码助手等指令跟随 | 微调（SFT） | 准备高质量问答对数据，SFT 即可满足 |
| 安全合规强化、降低幻觉 | 微调（DPO） | 用正负样本对对齐人类偏好 |
| 微调模型部署成本过高 | 压缩 | 量化后部署到更小规格，降低单位时间费用 |
| 业务高峰期不能接受限流 | TPM 预留 | 锁定专属容量，超额自动降级不中断服务 |
| 高吞吐高性能且需完全隔离 | PTU 专属部署 | TPM 预留的升级方案，提供专属部署实例 |
| 流量波动大、短期试用 | 按量付费（无需上述方案） | 无额外操作，按实际用量计费 |
| 大规模生产环境全链路优化 | 微调 + 压缩 + TPM 预留 | 定制能力 + 降低成本 + 保障吞吐的完整方案 |

## 技术选型决策要点

1. **是否需要改变模型能力？** 如果需要模型学习新知识、新格式或新行为，必须使用微调。压缩和 TPM 预留不改变模型能力本身。

2. **部署成本是否为瓶颈？** 如果微调后的模型部署费用过高，且所用基础模型在压缩支持列表中，可通过压缩降低部署规格和费用。注意压缩不可逆，后续迭代需从上游全精度模型重新训练。

3. **是否有明确的吞吐量要求？** 如果业务对推理吞吐有刚性保障需求（不能接受公共限流），应使用 TPM 预留。TPM 预留按 kTPM 预付费，建议结合控制台提供的容量计算器估算所需额度。

4. **快速验证 vs. 生产部署？** 快速验证阶段建议使用微调的高效训练（LoRA）模式 + 按量付费推理，成本低、周期短；进入生产阶段后再考虑全参训练、压缩和 TPM 预留的组合方案。
