# [模型微调](../concepts/fine-tuning.md) vs 模型压缩 vs 模型部署对比

在百炼平台上构建 AI 应用时，开发者常需要对模型进行定制化处理以满足业务需求。[模型微调](../concepts/fine-tuning.md)、模型压缩和模型部署是三个紧密关联但目标各异的环节：微调解决"模型能力不够"的问题，压缩解决"推理成本太高"的问题，部署解决"模型如何上线服务"的问题。本文从多个维度对比三者的定位、能力和适用场景，帮助开发者在技术选型时做出合理决策。

## 核心定位对比

| 维度 | [模型微调](../concepts/fine-tuning.md) | 模型压缩 | 模型部署 |
| --- | --- | --- | --- |
| **核心目标** | 提升模型在特定任务上的表现 | 降低推理成本、减少显存占用 | 将模型上线为可调用的推理服务 |
| **本质操作** | 在已有模型上继续训练（SFT/CPT/DPO） | 将全精度模型量化为低精度版本 | 分配计算资源、启动推理实例 |
| **输入** | 基础模型 + 标注数据集（JSONL/ZIP） | 自定义微调模型（全精度） | 预置模型或微调/压缩后模型 |
| **输出** | 微调后的自定义模型 | 量化后的低精度模型 | 可调用的推理服务端点 |
| **流程位置** | 上游（训练阶段） | 中游（优化阶段） | 下游（服务化阶段） |

## 支持的模型范围

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
| --- | --- | --- | --- |
| **文本生成模型** | Qwen3.6/3.5/3/2.5 等全系列 | 仅部分微调模型（如 qwen3.5-flash 微调产物） | 千问全系列、DeepSeek、GLM、MiniMax、Kimi 等 |
| **视觉理解模型** | Qwen3-VL、Qwen2.5-VL 等 | 暂不支持 | 千问 VL 系列 |
| **图像生成模型** | wan2.7-image-pro/image | 暂不支持 | 支持部署 |
| **视频生成模型** | wan2.5-i2v、wan2.2-i2v/kf2v | 暂不支持 | 支持部署 |
| **语音合成模型** | cosyvoice-v3-flash | 暂不支持 | 支持部署 |
| **外部导入模型** | 不适用 | 不适用 | 支持 LoRA 模型从 OSS 导入 |

## 操作方式与接口

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
| --- | --- | --- | --- |
| **控制台操作** | 支持（零代码可视化） | 支持 | 支持 |
| **API 操作** | 支持（/api/v1/fine-tunes） | 支持（OpenAPI） | 支持（/api/v1/deployments） |
| **核心 API 流程** | 上传数据 → 创建任务 → 轮询状态 → 部署 | 选择源模型 → 选量化模板 → 开始压缩 | 创建部署 → 等待运行中 → 推理调用 |
| **操作耗时** | 数小时至数天（取决于数据量和模型大小） | 数小时（取决于模型大小） | 数分钟（资源分配） |

## 计费方式

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
| --- | --- | --- | --- |
| **计费单元** | 按 Token 计费（API）或模型训练单元（控制台） | 当前限时免费 | PTU / 模型单元 / Token 用量 三选一 |
| **典型成本** | 与训练数据量和训练轮次正相关 | 免费（截至公告时间） | PTU 按吞吐额度计费；模型单元按小时计费；Token 按用量计费 |
| **计费特点** | API 创建的任务仅支持按 Token 计费，不支持训练单元 | 压缩免费，但产出模型部署后按部署规格计费 | 创建后不可切换计费方式，需下线重新部署 |

## 关键限制对比

| 维度 | 模型微调 | 模型压缩 | 模型部署 |
| --- | --- | --- | --- |
| **前置条件** | 需准备符合格式要求的训练数据 | 必须有支持压缩的自定义微调模型 | 需要可部署的模型（预置/微调/压缩后） |
| **可逆性** | 可在微调模型基础上继续训练 | 不可逆，不支持继续训练或二次压缩 | 可随时上下线 |
| **地域限制** | 无特殊限制 | 无特殊限制 | 仅支持华北二（北京）地域 |
| **数据要求** | SFT 需 ChatML 格式 JSONL；视觉/音频需 ZIP 打包 | 部分量化模板需要校准数据集 | 导入 LoRA 模型需满足 rank 和文件格式要求 |

## 三者的协作关系

模型微调、压缩和部署并非互斥选择，而是模型生产链路中的三个环节，典型的端到端流程为：

1. **微调**：基于业务数据对基础模型进行 SFT/CPT/DPO 训练，获得定制化模型
2. **压缩**（可选）：对微调产出的全精度模型进行量化，降低部署规格需求和推理成本
3. **部署**：将微调或压缩后的模型部署为在线推理服务，供业务系统调用

## 适用场景建议

**选择模型微调的场景**：
- 基础模型在特定业务领域表现不佳，需要通过训练提升能力
- 需要定制化输出风格、音色、视觉风格等
- 需要强化模型在安全合规方面的表现
- 有充足的高质量标注数据

**选择模型压缩的场景**：
- 微调后模型的部署成本过高，希望降低部署规格
- 对推理精度的轻微损失可接受，但对成本敏感
- 示例：qwen3.5-flash 微调模型从 MU1x2（108元/小时）压缩后降至 MU8x1（47元/小时）

**选择合适部署方式的场景**：
- **PTU（预置吞吐）**：生产环境、流量可预估、需要高并发保障（TPS 提升 1.5~2.0 倍）
- **模型单元**：需要资源独占、自定义性能指标、支持 PD 分离的大规模推理
- **Token 用量**：微调效果验证阶段、低频调用、不使用不计费
