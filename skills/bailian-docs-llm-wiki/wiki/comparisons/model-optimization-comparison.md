# 模型优化方案对比：微调、压缩与高速推理

在百炼平台上部署和使用大模型时，开发者经常面临三类优化需求：让模型更懂业务（微调）、让模型更省资源（压缩）、让模型更快响应（高速推理/TPM 预留）。三者目标不同、流程各异，但常常需要组合使用。本文从核心目标、前置条件、操作流程、成本模型等维度对三种方案做系统对比，帮助开发者快速完成技术选型。

## 核心维度对比

| 维度 | 微调（Fine-tuning） | 模型压缩（Model Compression） | 高速推理（TPM 预留） |
|------|---------------------|-------------------------------|----------------------|
| **核心目标** | 注入领域知识、学会遵循特定指令、对齐人类偏好 | 降低模型精度以减少显存占用，降低部署成本 | 锁定专属推理吞吐量，保障业务高峰不被限流 |
| **优化层面** | 模型能力（质量） | 模型体积（效率） | 推理资源（容量） |
| **前置条件** | 高质量训练数据集（SFT 1000+ 条，CPT 1000 万+ Token） | 已有支持压缩的自定义微调模型 | 无特殊前提，选定模型即可购买 |
| **输入** | JSONL 格式训练数据（ChatML / ZIP 包） | 自定义微调模型 + 可选校准数据集 | 业务流量预估（RPM、平均 Token 数） |
| **输出** | 微调后的自定义模型 | 量化后的低精度模型 | 专属模型 code（替换 API 中的 model 参数） |
| **操作方式** | 控制台可视化 + DashScope API | 控制台可视化 + OpenAPI | 控制台购买 + API 中替换 model 参数 |
| **代码改动** | 部署后替换 model 参数 | 部署后替换 model 参数 | 仅替换 model 参数为专属 code |
| **支持模型范围** | Qwen 全系列、千问VL、Wan 图像/视频、CosyVoice 语音 | 当前仅 qwen3.5-flash-2026-02-23 微调模型 | 千问3.7/3.6、GLM-5.x、DeepSeek-v4、Kimi-K2.6 等 |
| **支持模态** | 文本、视觉、图像生成、视频生成、语音合成 | 文本生成 | 文本生成 |
| **计费方式** | 按训练 Token 用量 x 循环次数 x 单价 | 压缩本身限时免费；部署按规格计费 | 预付费锁定容量；超额自动降级为按量计费 |
| **典型耗时** | 数小时至数天（取决于数据量和模型规模） | 任务排队后自动完成 | 即买即用（短暂预热） |
| **可逆性** | 可基于同一基座模型重新训练 | 不可逆：产出模型不支持继续训练或二次压缩 | 可随时扩缩容或退订 |

## 方案流程对比

### 微调流程

1. 准备训练数据（JSONL / ZIP），上传至百炼数据管理
2. 选择基座模型、训练方式（CPT / SFT / DPO）和超参数
3. 启动训练任务，观察 Loss 曲线
4. 训练完成后部署模型
5. 通过标准 API 调用微调后模型

### 压缩流程

1. 确认已有支持压缩的微调模型
2. 创建压缩任务，选择源模型和量化模板
3. 按需配置校准数据
4. 等待压缩完成
5. 将产出模型部署到更小规格的部署单元

### TPM 预留流程

1. 使用容量计算器估算所需 TPM（基于 RPM、平均 Token 数、缓存命中率）
2. 创建 TPM 预留，选择模型和容量
3. 支付预付费用，获取专属模型 code
4. 将 API 中 `model` 参数替换为专属 code
5. 通过监控面板跟踪使用率，按需扩缩容

## 适用场景建议

### 选择微调的场景

- 模型在特定领域（金融、医疗、法律）的回答质量不够，需要注入专业知识
- 需要模型学会特定的指令格式或工具调用方式（如 Agent 场景）
- 模型输出存在幻觉或安全合规问题，需要通过 DPO 对齐偏好
- 需要定制图像/视频生成风格或专属语音音色

### 选择压缩的场景

- 已有微调模型，希望降低部署成本（例如从 MU1x2 降至 MU8x1）
- 对推理延迟有一定容忍度，但对成本敏感
- 模型规模较大，需要部署到更小规格的计算单元

### 选择 TPM 预留的场景

- 业务流量可预估，高峰期不能接受限流或排队
- 需要稳定的推理吞吐保障（如生产环境的在线服务）
- 希望费用可控且可预测，避免按量计费的波动

## 组合使用建议

三种方案并非互斥，实际生产中常常组合使用：

1. **微调 + 压缩**：先通过 SFT 让模型掌握业务能力，再通过压缩降低部署成本。适合对模型质量有定制需求、同时关注成本的场景。注意压缩后不可再训练，建议在微调效果稳定后再压缩。

2. **微调 + TPM 预留**：先微调获得定制模型并部署，再通过 TPM 预留锁定推理吞吐。适合既需要定制能力、又需要稳定服务保障的生产场景。

3. **三者结合**：微调 → 压缩 → 以更低成本部署 → 对部署后的模型购买 TPM 预留。这是成本与性能兼顾的完整优化路径。

## 决策参考

| 你的核心诉求 | 推荐方案 |
|-------------|---------|
| 模型回答质量不够 / 需要领域适配 | 微调 |
| 部署成本太高 / 显存不够 | 压缩 |
| 高峰期被限流 / 需要稳定吞吐 | TPM 预留 |
| 质量 + 成本双优化 | 微调 → 压缩 |
| 质量 + 稳定性双保障 | 微调 → TPM 预留 |
| 全链路优化 | 微调 → 压缩 → TPM 预留 |
