# 模型优化方式对比：微调 / 压缩 / 高速推理

百炼平台为开发者提供三类模型优化手段：**模型微调（Fine-tuning）**、**模型压缩（Model Compression）** 与 **高速推理（TPM 预留 / PTU 部署）**。三者目标不同——微调解决"模型不贴合业务"，压缩解决"部署太贵/太慢"，高速推理解决"高峰期被限流"。它们互不冲突，常组合使用：微调 → 压缩 → 专属部署。本文从目标、输入输出、支持模型、API 端点、计费、典型场景等维度做横向对比，帮助开发者做技术选型。

## 关键维度对比

| 维度 | 模型微调（Fine-tuning） | 模型压缩（Model Compression） | 高速推理（TPM 预留 / PTU） |
| --- | --- | --- | --- |
| 核心目标 | 注入领域知识、对齐业务指令与偏好 | 降低推理显存与成本、提升吞吐 | 锁定专属推理容量、规避公共限流 |
| 输入（前置产物） | 自有训练数据（ChatML JSONL / ZIP 等） | 已存在的全精度自定义微调模型 | 已可调用的模型（公共或微调后均可） |
| 输出（产出） | 新的自定义微调模型 | 量化后的低精度模型 | 专属模型 code（容量预留实例） |
| 支持模型范围 | Qwen3/3.5/3.6、千问VL、wan2.7-image(pro)、wan2.5/2.2 视频、CosyVoice 等 | 仅"支持压缩的模型"列表中的自定义微调模型（如 qwen3.5-flash-2026-02-23）；已量化模型不可二次压缩 | 控制台展示的模型为准，含 Qwen3.7-Max/Plus、Qwen3.6-Flash、GLM-5.2/5.1、DeepSeek-v4-Pro/Flash、Kimi-K2.6 等 |
| 训练/压缩方法 | CPT、SFT、DPO；每种分全参与 LoRA | 量化（量化模板含目标部署规格 MU5/MU8 等） | 不涉及训练，仅容量预留 |
| 数据要求 | CPT 需 1000万+ Token 无标签文本；SFT 需 1000+ 条问答对；DPO 需 100+ 组正负样本对 | 部分模板要求校准数据集（"内部上传"且"已发布"），OpenAPI 用 `custom_calibration_file_ids` 传入 | 无训练数据；仅需填写输入/输出 TPM、购买时长等参数 |
| API 端点 | `POST /api/v1/files`（上传）、`POST /api/v1/fine-tunes`（建任务）、`GET /api/v1/fine-tunes/<job_id>`（轮询）、`POST /api/v1/deployments`（部署） | OpenAPI 创建压缩任务（控制台或 OpenAPI 调用） | 创建后获取"专属模型 code"，调用 `/compatible-mode/v1/chat/completions`，把 `model` 参数替换为该 code |
| 计费方式 | 按 Token 用量计费：`费用 = 训练数据 Token 总数 × 循环次数 × 训练单价` | 压缩功能**限时免费**；产出模型部署后按所选部署单元标准规格计费 | 预付费按 kTPM（按天），预留容量内调用不额外收费；超出自动降级按量计费，不中断；缩容退订按 1.5 倍系数结算 |
| 是否可逆/迭代 | 可多次微调迭代 | 产出模型**不支持**继续训练或二次压缩，需回上游重训 | 可续费、缩容、退订；到期 2 小时内可续费，14 小时后删除不可恢复 |
| 控制台入口 | 模型 → 模型调优 | 模型 → 模型训练 → 模型压缩 | 模型 → 高速推理 / TPM 预留 |
| 部署形态 | 部署为在线服务（`plan` 可选 `lora` 等） | 部署到更小规格单元（MU5、MU8 等） | 专属容量实例（TPM 预留）或专属部署实例（PTU） |

## 各方案适用场景建议

### 模型微调

- 业务有自有数据，通用模型在垂直行业（金融/医疗/法律）输出不达标；
- 需抑制幻觉、对齐安全合规偏好（DPO）；
- 客服、代码助手、Agent 工具调用等需遵循特定指令格式；
- 需多模态定制（视觉理解、图像/视频生成、专属音色）。

### 模型压缩

- 已有微调模型，但部署成本高、吞吐不足；
- 部署规格过大，希望迁到 MU5/MU8 等更小单元；
- 对延迟敏感的在线推理，希望降低显存占用；
- 注意：压缩后不可继续训练或二次压缩，迭代要回到上游全精度模型。

### 高速推理（TPM 预留 / PTU）

- 业务流量可预估，且**不能接受公共限流**；
- 营销活动、API 对外开放等高峰场景；
- 对极致性能与隔离有更高要求时选 PTU 专属部署；
- 仅需替换 `model` 参数为专属 code，接入零改动。

## 技术选型参考

| 业务诉求 | 推荐路径 |
| --- | --- |
| 模型答得不对/不懂行业知识 | 微调（CPT → SFT → DPO） |
| 微调后太贵、推理慢 | 先微调，再压缩到 MU5/MU8 |
| 高峰期被限流、要求稳定容量 | TPM 预留（或 PTU） |
| 既懂行业、又便宜、又稳 | 微调 → 压缩 → 专属部署（PTU）组合使用 |
| 只想降本不改模型 | 资源包/节省计划 或 压缩部署规格 |
| 流量波动大、短期试用 | 按量付费，无需微调或预留 |

三者并非互斥：微调产出更贴合业务的模型，压缩把该模型变便宜变快，高速推理为最终上线模型锁定稳定容量。建议按"**业务问题 → 微调；成本问题 → 压缩；容量问题 → 预留**"的顺序定位诉求，再决定是否组合使用。
