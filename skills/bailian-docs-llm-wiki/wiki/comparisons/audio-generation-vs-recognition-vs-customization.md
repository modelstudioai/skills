# 语音生成、语音识别与声音定制对比

本页旨在帮助开发者清晰区分百炼平台中三类核心音频能力：**语音生成（TTS）**、**语音识别（ASR）** 和 **声音定制（Voice Customization）**，明确其技术定位、能力边界与适用阶段。随着智能语音应用向个性化、场景化演进，准确理解三者在数据流中的角色（输入→处理→输出）、模型依赖、工程集成复杂度及成本结构，是构建高可用音频服务的关键前提。本文聚焦非实时批处理场景（实时流式能力请参阅[实时音频 API](../../raw/model-api-reference/realtime-audio-api-directory.md)），所有能力均通过 RESTful 接口调用，统一使用 API Key 鉴权。

## 关键维度对比

| 维度 | 语音识别（ASR） | 语音生成（TTS） | 声音定制（Voice Customization） |
|------|----------------|----------------|------------------------------|
| **核心目标** | 将**语音信号转换为文本** | 将**文本转换为自然语音** | **创建专属音色模型**（复刻或设计），供 TTS 调用 |
| **输入格式** | `audio_url`（公网可访问 MP3/WAV/M4A）或 `audio_bytes`（Base64 编码）；时长 ≤ 180 秒 | `text`（UTF-8 字符串）；支持多语种、标点停顿控制；可选 `voice` 参数指定预置音色 | • **音色复刻**：`audio_url` 或 Data URI（WAV/MP3，≤20 MB）<br>• **音色设计**：`voice_prompt`（文本描述） + `preview_text`（试听文本）<br>• 必须指定 `target_model`（如 `cosyvoice-v3.5-plus`） |
| **输出格式** | JSON 对象，含 `output.result`（识别文本）、`output.segments`（时间戳分段）等字段 | JSON 响应含 `output.audio_url`（OSS 公网直链）或 `output.audio_bytes`（Base64）；音频格式为 MP3/WAV，采样率可配 | • 创建成功返回 `voice_id`（唯一标识）<br>• 查询/详情返回音色元信息（名称、状态、创建时间、支持语种等）<br>• 不直接返回音频，需后续在 TTS 中引用该 `voice_id` |
| **支持模型** | `qwen-audio-asr-v1`（中英文混合） | `qwen-tts-v2-zh`（中文）、`qwen-tts-v2-en`（英文）、`cosyvoice-v3.5-plus` 等 | • **复刻**：Qwen-Audio-TTS、CosyVoice、Qwen-Omni、MiniMax 等<br>• **设计**：仅 Qwen-Audio-TTS、CosyVoice<br>• 模型需与后续 TTS 调用严格一致 |
| **API 端点** | `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/audio/speech_recognition` | `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/audio/speech_synthesis` | `POST https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/customization`（推荐地域域名）<br>或 `https://dashscope.aliyuncs.com/api/v1/services/audio/tts/customization`（兼容旧域名） |
| **计费方式** | 按**识别音频时长（秒）** 计费；支持包年包月套餐 | 按**合成音频时长（秒）** 计费；预置音色免费，定制音色调用按标准 TTS 计费 | • **复刻**：按调用次数或参考音频时长计费（Qwen-Omni/CosyVoice 按次，MiniMax 按时长+试听合成费）<br>• **设计**：按调用次数计费<br>• **注意**：音色本身不产生持续费用，仅创建/管理操作收费；后续使用该音色调用 TTS 时，仍按 TTS 标准计费 |
| **典型场景** | 会议录音转写、客服对话分析、视频字幕生成、语音笔记整理 | 智能播报（天气/新闻）、有声书生成、IVR 语音导航、短视频配音 | • 企业品牌音（复刻 CEO 声音）<br>• 游戏 NPC 个性化语音（设计“冷峻女剑客”音色）<br>• 教育 App 中教师音色复刻用于课件朗读<br>• 无障碍服务中为用户定制专属合成音 |
| **是否支持流式** | ❌ 不支持（非实时批处理） | ❌ 不支持（非实时批处理） | ❌ 不支持（音色创建为[异步任务](../concepts/asynchronous-task.md)，结果需轮询或回调获取） |
| **关键限制** | 单次请求 ≤ 180 秒；仅支持 MP3/WAV/M4A；单声道优先 | 单次请求 ≤ 180 秒；文本长度建议 ≤ 5000 字符；部分模型对语种/标点敏感 | • 复刻音频：Qwen-Omni ≤10 MB / ≤60 秒，MiniMax ≤20 MB<br>• 设计提示词：≤500 字符；试听文本：15–200 字符<br>• 音色 ID 命名受 `prefix`/`preferred_name` 规则约束 |

## 各方案的适用场景建议

- **选择语音识别（ASR）当且仅当**：  
  你的输入是**已录制的音频文件**，目标是提取其中的**文字内容**。例如：将客户投诉电话录音自动转为工单文本；为教育视频批量生成双语字幕；分析销售会议录音提取关键决策点。  
  ✅ 适用：需文本结果、无实时性要求、音频质量可控（信噪比高）。  
  ❌ 不适用：输入是文字、需要实时逐字上屏、音频为强噪音环境（需前端降噪预处理）。

- **选择语音生成（TTS）当且仅当**：  
  你的输入是**结构化文本**，目标是生成**标准、稳定、可复用的语音输出**。例如：每日新闻播报系统、智能硬件语音反馈、标准化客服应答语音。  
  ✅ 适用：使用平台预置音色即可满足需求、对音色一致性要求高、需快速上线。  
  ❌ 不适用：需完全匹配某位真人声音、需为不同角色设计差异化音色、文本内容高度动态且需毫秒级响应（此时应评估实时 TTS）。

- **选择声音定制（Voice Customization）当且仅当**：  
  你已明确需要**超越预置音色的个性化表达**，且愿意投入额外开发与管理成本。它**不是独立的“语音服务”，而是 TTS 的增强前置步骤**。  
  ✅ 适用：  
  - 品牌建设：需长期、统一使用 CEO 或吉祥物声音；  
  - 内容生产：为系列有声课程/播客打造专属主播音色；  
  - 用户体验：允许终端用户上传 30 秒语音，即时生成其个人语音助手。  
  ❌ 不适用：  
  - 仅需一次性的、临时的语音播报；  
  - 对音色相似度要求不高（预置音色已足够）；  
  - 无法提供合规的参考音频（复刻需用户授权）或缺乏音色描述能力（设计需精准 prompt 工程）。

## 技术选型参考（面向开发者）

作为开发者，在做技术决策时，请按以下逻辑链判断：

1. **明确数据流向起点**：  
   → 输入是**音频**？ → 选 **ASR**。  
   → 输入是**文本**？ → 进入第 2 步。

2. **评估音色需求层级**：  
   → 只需通用、高质量、多语种音色 → 直接调用 **TTS**（如 `qwen-tts-v2-zh`）。  
   → 必须使用特定人物声音或高度风格化音色 → 必须先执行 **声音定制**（复刻或设计），获得 `voice_id` 后，在 TTS 请求的 `parameters.voice` 中传入该 ID。

3. **验证工程可行性**：  
   - **ASR/TTS**：接入简单，单次 HTTP 请求 + 解析 JSON，适合快速验证。注意音频格式与 URL 可访问性。  
   - **声音定制**：  
     • 是**异步长任务**（复刻通常需数秒至数十秒），需实现状态轮询（`GET /voices/{voice_id}`）或订阅事件回调；  
     • **音色生命周期需自主管理**（创建→测试→发布→归档→删除），建议封装为服务层资源；  
     • **模型强绑定**：`target_model` 必须与后续 TTS 的 `model` 完全一致，否则调用失败——这是最常见的集成错误。

4. **成本与合规前置检查**：  
   - ASR/TTS：按量计费透明，可预估单次成本（例：1 分钟音频识别 ≈ X 元）。  
   - 声音定制：  
     • 复刻需确保参考音频**已获本人明确授权**（尤其商用场景），平台不承担版权风险；  
     • 设计音色虽无需音频，但 `voice_prompt` 描述需避免歧视性、违法或侵犯人格权表述；  
     • MiniMax 等第三方模型定制，需同步遵守其独立条款。

> **最佳实践提示**：  
> - 在 MVP 阶段，**始终优先使用预置 TTS 验证业务流程**，再迭代引入声音定制；  
> - 对于需复刻的场景，**务必用同一设备、同一环境录制 3–5 段 10–30 秒参考音频**（覆盖不同语调/语速），显著提升复刻质量；  
> - 所有音频类 API 均**不支持私有 OSS 签名 URL**，若音频存于私有 Bucket，请先配置 Bucket 公共读，或使用平台提供的预签名上传接口中转。
