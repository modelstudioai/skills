# 图像、视频与3D生成能力对比

为帮助开发者快速理解百炼平台在多模态生成领域的技术边界与工程适配性，本文系统对比图像生成（Image Generation）、视频生成（Video Generation）与3D生成（3D Generation）三大核心能力。对比基于当前（v2.4.x）平台正式发布的 API 能力，聚焦**可用性、可控性、集成成本与生产就绪度**，旨在支撑技术选型决策——例如：内容运营团队应优先选用图像API批量产出营销图；动画工作室需评估视频API的时长/分辨率灵活性；而工业设计团队则需关注3D生成对几何精度与格式兼容性的实际支持程度。

---

## 关键维度对比

| 维度 | 图像生成 | 视频生成 | 3D生成 |
|------|----------|----------|--------|
| **输入格式** | 文本（`prompt`）、Base64编码图像（图生图/局部重绘）、可选掩码（`mask`） | 文本（`input.prompt`）、公开可访问图像URL（图生视频）、人脸图像（人像驱动） | 文本（`prompt`）**或** 公开可访问图像URL（`image_url`）；不支持Base64图像上传 |
| **输出格式** | PNG/JPEG（直链URL，有效期1小时）；支持多图并行（`n=1~4`） | MP4（H.264编码，直链URL，有效期24小时）；固定分辨率（如Kling: 1024×576，Vidu: 1280×720） | GLB（glTF Binary，直链URL，有效期24小时）；仅单模型输出，无批量选项 |
| **支持模型** | 千问（Qwen-VL图像版）、万相（WanXiang）、Z-Image（已弃用图生图）、可灵（Kling）、Vidu（`vidu-image`专用）、创意工具（后处理） | 可灵（Kling）、Vidu、爱诗（PixVerse）、万相（图生视频）、人像驱动、HappyHorse、MiniMax（公测未开放） | Tripo-3D（唯一支持模型） |
| **API端点** | `POST https://dashscope.aliyuncs.com/api/v1/images/generations` | `POST https://dashscope.aliyuncs.com/api/v1/videos/generations` | `POST https://dashscope.aliyuncs.com/api/v1/3d/generation` |
| **调用模式** | 同步响应（小尺寸/简单[prompt](../guides/prompt.md)）+ 异步任务（推荐）；同步返回含`url`与`task_id` | 异步为主；所有模型均需轮询`/api/v1/tasks/{task_id}`获取最终`video_url` | 异步强制；必须轮询任务状态，无同步直出能力；最长等待180秒 |
| **计费方式** | 按**生成图片张数**计费（1次请求`n=4`计为4次）；Z-Image单价最低，万相/可灵中等，Vidu-image略高 | 按**生成视频条数**计费（与`duration`无关）；Kling/Vidu单价相近，人像驱动按“驱动时长秒数”阶梯计费 | 按**成功生成任务次数**计费（失败不扣费）；Tripo-3D为独立计费单元，价格显著高于图像单次调用 |
| **典型场景** | 社媒配图、电商主图生成、AIGC设计初稿、UI组件可视化、背景移除/抠图增强 | 短视频广告、产品动态演示、AI动画短片、虚拟人播报、教学过程可视化 | 游戏低多边形资产原型、3D打印概念模型、AR/VR场景快速建模、工业设计草模验证 |
| **核心限制** | • `prompt` ≤ 512字符<br>• Z-Image不支持`negative_prompt`与图生图<br>• 临时URL有效期仅1小时 | • `prompt` ≤ 512字符<br>• 输出分辨率/帧率/时长由模型硬编码，不可自定义<br>• 人像驱动要求正脸无遮挡 | • `prompt` ≤ 200字符（强建议）<br>• 仅支持HTTP(S) `image_url`，不支持Base64<br>• GLB无PBR材质贴图，仅基础网格 |

## 各方案适用场景建议

### ✅ 推荐图像生成（Image Generation）当：
- 需要**高频率、低成本、多样化视觉产出**（如每日生成100+张营销图）；
- 要求**精细风格控制**（万相的`style=anime`、可灵的ControlNet兼容）；
- 需结合**已有图像进行编辑**（局部重绘、背景替换、主体增强）；
- 对**延迟敏感**（Z-Image轻量模型适合实时预览，但功能受限）。

### ✅ 推荐视频生成（Video Generation）当：
- 目标是制作**2–8秒高质量短视频**（广告、教程、社交动态），且接受固定分辨率；
- 有**图像素材需动态化**（万相图生视频、人像驱动口型同步）；
- 需要**多模型横向对比**（如用Vidu做电影感运镜，Kling做强叙事连贯性）；
- 已具备**视频后处理管线**（因平台不提供剪辑、配音、字幕等能力）。

### ✅ 推荐3D生成（3D Generation）当：
- 需从**文本或单视角图快速获得可导入引擎的3D网格**（Unity/Unreal/Blender）；
- 应用场景对**几何拓扑容错率较高**（如概念验证、非精密装配）；
- 团队具备**后续手动优化能力**（补充材质、修复法线、重拓扑）；
- **无需实时交互或物理仿真**（Tripo不生成绑定、骨骼或物理属性）。

### ⚠️ 不建议跨域替代的情况：
- **勿用图像生成替代视频**：即使生成多帧图像，也无法保证时序一致性与运动连贯性；  
- **勿用视频生成替代3D**：视频是2D投影序列，无法提供视角自由旋转、碰撞检测等3D原生能力；  
- **勿用3D生成替代图像/视频**：Tripo不支持纹理细节渲染、光照模拟或动态效果，视觉表现力远低于图像/视频模型。

## 开发者技术选型参考

| 选型考量 | 推荐方案 | 理由说明 |
|----------|----------|----------|
| **最低接入门槛** | 图像生成 | 参数最简（仅`model`+`prompt`+`size`），同步响应快，调试周期短；文档示例丰富，错误反馈明确（如`prompt`截断静默） |
| **最高可控性** | 图像生成（万相/可灵） | 支持`style`、`seed`、`negative_prompt`、ControlNet扩展及图生图，参数组合空间大，复现性最佳 |
| **最长输出链路容忍度** | 视频生成 | 平均生成耗时45–120秒，需健壮的任务轮询与超时重试逻辑；建议搭配消息队列解耦前端请求 |
| **最严格式兼容性要求** | 3D生成 | GLB为工业标准，可直接拖入Three.js、Babylon.js等WebGL引擎；但需自行处理材质缺失问题（如加载外部PBR贴图） |
| **最高合规风险** | 3D生成 | 输入图像严禁含人脸/Logo/版权内容，审核策略比图像/视频更严格；建议预检服务前置校验`image_url`内容 |
| **最易规模化部署** | 图像生成 | 支持`n=4`批量生成，QPS上限高；Z-Image虽功能少，但适合灰度发布与AB测试流量分发 |

> **重要提醒**：所有生成类API均启用**统一内容安全网关**。无论图像、视频或3D，若输入含暴力、色情、政治敏感、侵权元素，请求将被拦截并返回`400 Bad Request`（错误码`ContentPolicyViolation`），**不产生计费**。建议在生产环境集成前，使用沙箱环境完成全量提示词安全扫描。
