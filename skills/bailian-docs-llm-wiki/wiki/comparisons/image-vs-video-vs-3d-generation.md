# 图像、视频与3D内容生成能力对比

为帮助开发者快速理解百炼平台在多模态AIGC领域的技术布局与能力边界，本文系统对比图像生成、视频生成与3D内容生成三大核心能力模块。对比聚焦于**工程可用性、接口一致性、模型特性及生产适配性**，旨在支撑技术选型决策——例如：当需为电商商品页生成高质感静态图时，应优先选用万相而非Vidu；当构建虚拟展厅需可交互3D资产时，Tripo-H3.1的几何精度与PBR贴图支持成为关键指标。所有结论均基于当前（2024年Q3）平台正式发布的API行为与文档规范。

## 关键维度对比

| 维度 | 图像生成（`/image-generation`） | 视频生成（`/video/generation`） | 3D内容生成（`/3d-generation`） |
|------|-------------------------------|--------------------------------|------------------------------|
| **输入格式** | 文本（prompt）、Base64图像、mask URL、reference image（支持文生图、图生图、inpainting等多任务） | 文本（prompt）、公网图像URL、语音/文本驱动信号（人像驱动）、结构化运镜指令（MiniMax） | 文本（prompt）、单张图像URL、4张视角图像数组（前/左/后/右），三者互斥 |
| **输出格式** | 同步返回：Base64编码图像 或 可下载URL（有效期24小时）；支持 `n=1–4` 批量生成 | 异步返回：`task_id` → 轮询 → `output.video_url`（直连MP4，有效期24小时）；部分模型支持帧序列导出 | 异步返回：`task_id` → 轮询 → `pbr_model_url`（GLB+PBR贴图）、`base_model_url`（无贴图GLB）、`rendered_image_url`（渲染预览图）；所有URL有效期2小时 |
| **核心支持模型** | 万相（WanX）、可灵（Kling）、Z-Image、Qwen-VL分支、Vidu（副产物）、Creative Tools（编辑类） | Vidu、可灵（Kling）、万相（WanXiang）、HappyHorse、爱诗、人像驱动、MiniMax（独立Endpoint） | Tripo/Tripo-H3.1（高精度）、Tripo/Tripo-P1.0（快速） |
| **API端点** | `POST /api/v1/services/aigc/image-generation/generation`（同步） | `POST /api/v1/video/generation`（异步创建）<br>`GET /api/v1/video/generation/tasks/{task_id}`（轮询） | `POST /api/v1/services/aigc/video-generation/3d-generation`（异步创建，**必须带`X-DashScope-Async: enable`头**）<br>`GET /api/v1/tasks/{task_id}`（统一任务查询） |
| **调用模式** | **同步阻塞式**（典型响应时间：0.8–4s，依模型与分辨率而定） | **强制异步**（任务创建后需轮询，典型生成耗时：文生视频 20–90s；图生视频 30–120s） | **强制异步**（任务创建后需轮询，典型耗时：文生3D 60–300s；单图生3D 90–400s；多图生3D 120–600s） |
| **计费方式** | 按**请求次数 × 质量因子**计费：<br>- `standard`：1单位<br>- `hd`：2单位（仅万相/可灵支持）<br>- 创意工具类操作（inpainting等）：3单位起 | 按**任务成功数 × 时长/分辨率因子**计费：<br>- 基础任务（4s/720p）：1单位<br>- 8s/Vidu高清：3单位<br>- 人像驱动/MiniMax：5单位起 | 按**任务成功数 × 几何/贴图质量因子**计费：<br>- `Tripo-P1.0` + `standard`：1单位<br>- `Tripo-H3.1` + `ultra` + `detailed`：6单位<br>- 无贴图模型（`texture=false & pbr=false`）：0.5单位（最低） |
| **地域约束** | 全地域可用（默认华东1/华南1） | 全地域可用 | **强绑定华北2（北京）**：Endpoint域名必须为 `cn-beijing.maas.aliyuncs.com`，其他地域调用失败 |
| **典型延迟敏感场景** | UI原型草图（Z-Image，512×512，<1s）、实时海报生成（万相，768×768，≈1.5s） | 无法满足毫秒级响应；最低延迟场景为“人像驱动”口型同步（端到端≈3s，含音频处理） | 不适用低延迟场景；最短任务周期≥60s，不支持流式响应 |
| **内容可控性** | 高：支持局部重绘（mask）、涂鸦引导、风格迁移、构图控制（可灵支持长宽比显式指定） | 中：Vidu/可灵支持运镜关键词（如“zoom in”, “pan left”），但稳定性弱于图像；人像驱动仅控制口型与微表情 | 高：Tripo-H3.1支持`geometry_quality=ultra`精确控制面数，`texture_quality=detailed`保障PBR材质精度；多图输入显著提升几何重建鲁棒性 |

## 各方案适用场景建议

| 场景类型 | 推荐方案 | 理由说明 |
|----------|-----------|-----------|
| **营销素材快速生产**（电商主图、社交媒体配图） | ✅ 图像生成（万相/WanX） | 中文提示词优化强，对“国风”“赛博朋克”等风格泛化好；支持`hd`质量与768×768以上分辨率；同步API便于集成CMS工作流 |
| **动态广告/短视频创意**（产品演示、概念动画） | ✅ 视频生成（Vidu 或 可灵） | Vidu在运动连贯性与光影一致性上表现最优；可灵对构图控制更佳；二者均支持4–8秒标准时长，符合信息流广告规格 |
| **虚拟人/数字分身构建** | ✅ 视频生成（人像驱动） + 3D生成（Tripo） | 人像驱动实现高保真口型同步；Tripo-P1.0可快速生成基础3D人脸网格，再通过纹理映射叠加驱动结果，形成“3D虚拟人+2D驱动层”混合管线 |
| **工业设计/游戏资产开发** | ✅ 3D生成（Tripo-H3.1） | 支持200万面高精度网格与PBR材质，输出标准GLB格式可直接导入Unity/Unreal；多图输入模式适配实物扫描建模流程 |
| **低代码原型工具集成** | ✅ 图像生成（Z-Image） | 固定512×512分辨率、无`negative_prompt`依赖、响应<1s，适合Figma插件、Notion AI Bot等轻量前端调用 |
| **合规敏感型应用**（教育、政务） | ⚠️ 图像生成（万相）或 3D生成（Tripo） | 万相与Tripo均未开放人脸生成能力（风控策略严格），规避肖像权风险；视频生成中“人像驱动”明确要求上传真实人脸，需额外签署授权协议 |

## 开发者技术选型参考

- **优先选择同步API的场景**：需实时反馈（如用户上传草图后即时生成效果图）、服务端渲染（SSR）集成、无后台任务队列能力的轻量应用 → **选图像生成**。
- **必须接受异步架构的场景**：涉及长时间计算（>5s）、需批量处理（如每日生成1000个商品3D模型）、需与现有Celery/Airflow任务流对接 → **视频或3D生成**，并务必实现健壮的轮询/回调机制。
- **模型能力交叉时的决策原则**：
  - Vidu虽能生成单帧图像，但其图像能力是视频模型的副产物，**生产环境禁止用于图像主任务**（文档明确提示稳定性与一致性低于万相/可灵）；
  - Creative Tools（局部重绘等）属于图像生成子集，不可跨域用于视频/3D编辑；
  - Tripo不支持任何形式的“3D转视频”，若需3D模型动效，须导出GLB后使用Three.js/Babylon.js自行实现动画。
- **成本敏感型项目**：  
  - 图像任务：避免滥用`hd`，Z-Image在512×512场景下成本仅为万相`standard`的1/3；  
  - 视频任务：优先选用4秒时长，避免Vidu 8秒档位（计费翻3倍）；  
  - 3D任务：用`Tripo-P1.0`替代`H3.1`可降本60%，若无需超精细曲面（如机械零件），`P1.0`完全满足需求。
- **地域与部署注意事项**：  
  - 若应用已部署在华北2（北京），3D生成可零改造接入；  
  - 若主力集群在华东1，调用3D API需额外配置北京地域Endpoint及独立API Key，增加运维复杂度 —— 此时应评估是否改用图像+视频组合方案模拟3D效果。

> **最后建议**：新项目启动前，务必在[百炼控制台](https://bailian.console.aliyun.com)申请对应模型的免费试用额度，并使用`curl`或Postman验证最小可行请求（MVP）。注意检查响应头中的`X-RateLimit-Remaining`与`X-Request-ID`，便于问题定位与配额监控。
