# 长期[记忆](../concepts/memory.md)、知识库与托管智能体方案对比

为帮助开发者在百炼平台中科学选型，本文对三种核心能力——**长期[记忆](../concepts/memory.md)（Long Term Memory）**、**知识库（Knowledge Base）** 和 **托管智能体（Managed Agents）** 进行系统性对比。三者均面向 AI 应用的“状态化”与“专业化”演进需求，但定位差异显著：  
- **长期[记忆](../concepts/memory.md)**聚焦**用户级、细粒度、动态演化的结构化事实与画像管理**，强调跨会话的个性化记忆沉淀与实时检索；  
- **知识库**专注**静态/半静态企业知识的规模化、可治理、多源 RAG 服务**，强调文档级语义理解与高精度召回；  
- **托管智能体**提供**长时运行、状态保持、工具自治的云端执行环境**，强调任务级闭环与复杂操作编排能力。  

本对比基于当前（2025 年 Q2）百炼平台正式版 API 与控制台能力，面向实际工程落地场景，不涉及概念性或实验性功能。

## 关键维度对比表

| 维度 | 长期记忆（Long Term Memory） | 知识库（Knowledge Base） | 托管智能体（Managed Agents） |
|------|------------------------------|---------------------------|-------------------------------|
| **核心定位** | 用户级结构化记忆管理（事实 + 画像） | 企业级文档知识检索增强（RAG 基础设施） | 任务级长时运行智能体托管（沙箱化执行环境） |
| **输入格式** | `messages[]`（含 `text`/`image_url`）、`user_id`、`profile_schema`（可选）、`extract_mode`；支持多模态文本+图片（仅启用多模态项目解析） | 文档文件（PDF/DOCX/CSV/XLSX/TXT/MD/PNG/JPG 等）、数据库连接、OSS/飞书/钉钉等第三方源；支持元数据标签、自定义切片策略 | 用户消息（`text`）、挂载资源（文件/记忆库存储）、初始事件（`initial_events`）；支持 `bash`/`web_search`/`read` 等工具调用指令 |
| **输出格式** | `memory_nodes[]`（含 `id`, `type`, `content`, `score`, `meta_data`）、`user_profile`（结构化 JSON）、`event_id`（异步任务标识） | 检索结果：`chunks[]`（含 `content`, `score`, `source`）；问答结果：`answer`（流式/非流式）、`references[]`；完整日志（SLS 投递） | 事件流（SSE）：`message`/`tool_call`/`tool_call_output`/`session_status`/`interrupted`；最终产出物（通过 `mark_artifacts` 标记） |
| **支持模型** | 无独立模型；底层由平台统一调度 `qwen3-*` 系列模型完成抽取与检索（`plan_version=pro` 启用高精度模型） | 嵌入模型（`text-embedding-v4` 等）、重排模型（`qwen3-rerank`/`qwen3-vl-rerank`）、生成模型（`qwen3.6-plus`, `deepseek-coder` 等，按问答服务配置） | 全系列百炼大模型（`qwen3-max`, `qwen3.8-plus`, `qwen2.5-72b` 等），通过 `model.id` 显式指定；模型变更即生成新 Agent 版本 |
| **API 端点（典型）** | `POST /v1/memory_nodes/add`<br>`POST /v1/memory_nodes/add-async`<br>`POST /v1/memory_nodes/search`<br>`GET /v1/user_profiles/{user_id}` | `POST /api/v1/indices/knowledge/search`（多库联合检索）<br>`POST /api/v2/apps/knowledge/chat`（流式问答）<br>`POST /api/v1/indices/rag/index/retrieve`（单库底层检索） | `POST /v1/sessions`（创建会话）<br>`POST /v1/sessions/{id}/events`（发送消息/审批/中断）<br>`GET /v1/sessions/{id}/events/stream`（SSE 事件流） |
| **计费方式** | **按调用次数 + 计划版本计费**：<br>- `add`/`search` 接口调用次数<br>- `plan_version=pro`（高精度抽取/重排） vs `lite`（基础语义）<br>▶️ 商业化起始时间：2026 年 8 月 20 日 | **按规格 + 模型调用 + 资源用量计费**：<br>- 知识库规格（标准版/旗舰版，RCU 单位）<br>- 嵌入/重排/生成模型 [Token](../concepts/token.md) 消耗<br>- 文件存储、SLS 日志投递等附加资源<br>▶️ 免费额度仅抵扣标准版规格费 | **按会话时长 + 工具调用 + 模型消耗计费**：<br>- 会话运行时长（秒级计费，含空闲等待）<br>- 内置工具调用（如 `web_search` 0.03 元/次）<br>- 大模型 [Token](../concepts/token.md) 消耗（按所选 `model.id` 计费）<br>- 文件上传/记忆库存储按量计费 |
| **数据隔离粒度** | `user_id`（主隔离） + `memory_library_id`（次隔离） + `project_id`（项目级） | `workspace`（业务空间） → `knowledge_base_id`（知识库） → `index_id`（索引） | `workspace` → `agent_id`（智能体） → `environment_id`（运行环境） → `session_id`（会话） |
| **状态持久性** | ✅ 记忆节点永久存储（除非显式删除）<br>✅ 用户画像异步更新并持久化 | ✅ 文档切片、索引、元数据全量持久化<br>✅ 定时同步副本独立于源系统 | ✅ 会话事件历史全量持久化<br>✅ 挂载的 `memory_store` 实时双向同步<br>❌ 临时沙箱文件（`/tmp`）随会话结束销毁 |
| **典型场景** | - 电商客服中持续记录用户偏好（“只买有机食品”）<br>- 办公助手自动归纳会议结论为 `skill` 并复用<br>- 教育应用动态构建学生知识掌握画像 | - 客服知识中心：从 1000+ 产品手册中精准召回故障解决方案<br>- 法务合规助手：基于合同模板库与最新法规 PDF 生成审查意见<br>- 内部 Wiki 智能搜索：支持标题/段落/表格混合检索 | - 自动化数据分析：上传 Excel → 清洗 → 建模 → 生成可视化报告<br>- 多步骤内容创作：调研竞品 → 撰写初稿 → 检索最新数据修订 → 导出 PDF<br>- IT 运维助手：诊断服务器日志 → 执行修复脚本 → 生成工单 |

## 适用场景建议（面向开发者）

| 场景描述 | 推荐方案 | 理由说明 |
|----------|----------|----------|
| **需要记住每个用户的独特行为、偏好、承诺或技能，并在后续对话中主动调用** | ✅ 长期记忆 | `user_id` 隔离 + `observation/skill/profile` 三类结构化类型 + 异步高精度抽取能力，专为个性化记忆设计；知识库无法按用户维度建模，托管智能体无跨会话记忆机制。 |
| **已有大量结构化/非结构化文档（PDF/Word/Excel/网页），需快速构建可检索、可审计、可集成的 RAG 服务** | ✅ 知识库 | 开箱即用的多源接入、智能切片、向量化、重排、混排、日志监控全链路；长期记忆不支持文档解析，托管智能体虽可读文件但无索引与召回能力。 |
| **任务需多轮工具调用（如查网络→读文件→写代码→运行→生成报告）、依赖沙箱环境、要求中断续接与状态保持** | ✅ 托管智能体 | 独立容器、内置 `bash`/`web_search`/`edit` 等 9 大工具、MCP/Skill 扩展、文件系统挂载、SSE 事件流，是唯一支持长时自治执行的方案；另两者均为无状态服务。 |
| **需将用户画像（如职业、兴趣）与企业知识（如产品文档）联合用于决策，但二者来源与更新频率不同** | ⚠️ **组合使用**：长期记忆（存用户画像） + 知识库（存产品文档） | 长期记忆擅长动态用户建模，知识库擅长静态知识管理；可通过 `search` 返回用户画像 + `knowledge/search` 返回文档切片，在应用层融合；托管智能体可作为编排层调用二者 API。 |
| **需让智能体“记住”自己在本次会话中生成的中间结果（如分析草稿、临时图表），供后续步骤使用** | ✅ 托管智能体（配合 `memory_store`） | 挂载的 `memory_store` 提供跨工具调用的持久化文件树，沙箱内路径 `/mnt/session/memory/` 可读写；长期记忆需手动 `add`，知识库不支持会话级临时数据。 |
| **轻量级、低延迟的关键词/语义检索（如 FAQ 匹配），且无需复杂 RAG 流程** | ✅ 长期记忆（`search` 接口） 或 ✅ 知识库（单库 `retrieve`） | 长期记忆 `search` 延迟更低（尤其 `lite` 模式），适合用户意图补全；知识库 `retrieve` 更适合文档片段匹配；托管智能体无原生检索能力。 |

## 技术选型参考（给开发者的行动指南）

- **第一步：明确核心诉求**  
  - 若目标是 **“让 AI 认得清、记得住、用得准每个用户”** → 优先评估 **长期记忆**；  
  - 若目标是 **“让 AI 看得懂、找得准、答得对全部企业文档”** → 优先评估 **知识库**；  
  - 若目标是 **“让 AI 做得到、做得完、做得稳复杂真实任务”** → 优先评估 **托管智能体**。

- **第二步：检查约束条件**  
  - **地域限制**：知识库仅支持华北2（北京）/新加坡；长期记忆与托管智能体无地域限制（以 DashScope 网关为准）。  
  - **数据敏感性**：三者均默认加密存储，但托管智能体沙箱支持 `unrestricted` 网络，需严格管控 `web_search`/`web_fetch` 使用；知识库支持私有向量库（ADB-PG）；长期记忆暂不支持 BYOV（Bring Your Own Vector）。  
  - **运维成本**：知识库与长期记忆为全托管服务，零运维；托管智能体需关注会话生命周期管理（超时、中断、失败重试）、工具审批策略配置（`always_allow` vs `always_ask`）。

- **第三步：验证最小可行集成（MVP）**  
  - ✅ **长期记忆**：用 `curl -X POST https://dashscope.aliyuncs.com/api/v1/memory_nodes/add-async` 发送一条带 `profile_schema` 的消息，轮询 `GetEvent` 确认画像抽取成功。  
  - ✅ **知识库**：在控制台 Playground 中上传一份 PDF，用「知识检索」模式测试召回相关段落，再切换「知识问答」验证生成质量。  
  - ✅ **托管智能体**：创建一个仅启用 `bash` 工具的智能体，发起会话后发送 `{"content":"ls -l /mnt/session/uploads/"}`，确认文件挂载可见。

- **第四步：考虑演进路径**  
  - 初期单点突破 → 后期能力融合：例如，先用 **知识库** 构建产品知识底座，再用 **长期记忆** 记录客户咨询中的个性化需求，最后用 **托管智能体** 编排“根据客户画像 + 产品知识 + 实时行情”生成定制化方案。

> 💡 **关键提醒**：三者并非互斥，而是百炼平台“记忆-知识-执行”三层架构的有机组成。生产级应用往往需组合使用——**长期记忆管“人”，知识库管“事”，托管智能体管“做”。** 请基于具体业务流程图，逐环节标注所需能力，再对照上表决策。
