# 模型监控 vs 应用监控

百炼平台提供两套互补的监控体系：**模型监控**聚焦于单个模型的调用量、Token 消耗、性能指标与费用管理；**应用监控**（应用观测）则面向由模型、检索、插件等多环节组成的完整应用，提供端到端的调用链路追踪与可观测能力。理解两者的定位差异，有助于开发者在不同场景下选择合适的监控手段，甚至组合使用以实现全方位的生产可观测性。

## 关键维度对比

| 维度 | 模型监控 | 应用监控（应用观测） |
|------|---------|-------------------|
| **监控粒度** | 单个模型维度 | 应用级端到端调用链路 |
| **核心能力** | 用量统计、性能指标、告警、推理日志 | 调用链路追踪（Trace/Span）、监控统计、数据标注与导出 |
| **支持对象** | 模型列表中的所有模型及调优后自定义模型 | 智能体应用、工作流应用、高代码应用 |
| **监控指标** | 调用次数、Token 消耗、首 Token 延时、调用时长、RPM、TPM、失败率、内容安全错误 | 调用次数、失败率、Token 总量（输入/输出）、平均首 Token 耗时、平均调用时长 |
| **链路追踪** | 不支持 | 支持完整调用链路（CHAIN → AGENT → LLM → RETRIEVER → TOOL 等多种节点类型） |
| **日志能力** | 推理日志（需开通，仅部分模型、北京/新加坡地域） | Trace 级调用记录，支持按 Request ID / Trace ID / Span ID 搜索 |
| **告警机制** | 费用告警 + 模型指标告警（需开启高级监控），支持短信/邮件/电话/钉钉/企微/Webhook | 不提供独立告警机制 |
| **数据导出** | 通过 Prometheus HTTP API 接入 Grafana 等外部系统 | 支持导出为 JSONL 或 EXCEL 格式 |
| **数据标注** | 不支持 | 支持自定义标签（布尔值、分类、数字、文本），可与评测集联动 |
| **外部系统集成** | 高级监控开启后支持 Prometheus API，可接入 Grafana | 基于可观测链路 OpenTelemetry 服务 |
| **API 支持** | 通过 Prometheus HTTP API 查询指标 | 暂无 API |
| **费用** | 高级监控需开通 Prometheus 实例（付费） | 功能本身免费，存储依赖 OpenTelemetry 服务需付费 |
| **地域限制** | 高级监控：北京、新加坡、弗吉尼亚；告警：北京、新加坡 | 无特殊地域限制说明 |

## 适用场景

### 模型监控适用场景

- **成本管控**：需要按[业务空间](../concepts/workspace.md)维度追踪各模型的 Token 消耗与费用，管理免费额度，设置费用告警。
- **模型性能基线**：关注单个模型的首 Token 延时、调用时长、RPM/TPM 等性能指标变化趋势。
- **异常告警**：需要在模型调用失败率上升、限流增加或 Token 消耗异常时主动通知运维人员。
- **外部监控系统集成**：已有 Grafana 等监控平台，希望将百炼模型指标接入统一看板。
- **内容安全审计**：需要监控模型调用中的违规内容事件。

### 应用监控适用场景

- **应用调试与故障排查**：智能体或工作流应用出现异常时，需要查看完整调用链路，定位是模型推理、知识检索、插件调用还是其他环节出了问题。
- **端到端性能分析**：需要了解从用户输入到最终输出的完整延时分布，而非仅关注模型推理本身。
- **数据质量管理**：需要对调用数据进行标注、筛选，并将高质量样本添加到评测集用于迭代优化。
- **多环节应用的可观测性**：应用涉及 RAG 检索、重排序、改写、内容安全检测等多个环节，需要逐环节观测。

### 组合使用建议

在生产环境中，建议同时开启两套监控：

- 使用**模型监控**管理成本、设置告警阈值、追踪长期用量趋势。
- 使用**应用监控**在出现问题时进行链路级排查，并持续优化应用的端到端体验。

两者协同可以覆盖从单模型性能到完整应用链路的全维度可观测需求。

## 技术选型参考

| 需求 | 推荐方案 |
|------|---------|
| 追踪某个模型的 Token 消耗趋势 | 模型监控 |
| 设置模型调用失败率告警 | 模型监控（高级监控） |
| 排查智能体应用某次对话为何超时 | 应用监控 |
| 查看工作流中检索节点返回了哪些文本切片 | 应用监控 |
| 将模型指标接入 Grafana 大盘 | 模型监控（Prometheus API） |
| 将调用记录导出用于离线分析 | 应用监控（JSONL/EXCEL 导出） |
| 管理免费额度、控制费用 | 模型监控（用量统计 + 费用告警） |
| 对调用数据打标签并构建评测集 | 应用监控 |
| 同时关注成本和应用质量 | 两者组合使用 |
