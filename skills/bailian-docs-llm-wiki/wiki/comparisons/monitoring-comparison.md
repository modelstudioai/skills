# 应用监控与模型监控对比

百炼平台围绕"应用"和"模型"两个层级提供了互补的可观测能力：**应用监控**（应用观测）面向智能体应用、工作流应用、高代码应用等已发布应用，追踪端到端的内部调用链路（CHAIN/Span/节点嵌套），用于优化业务运营效果与成本；**模型监控**面向主账号下所有业务空间内的模型调用，提供用量统计、运行指标、调用日志、Token 追踪与主动告警，用于成本核算与稳定性保障。两者关注层级、数据口径、适用范围与计费方式均不同，本页帮助开发者按场景做技术选型。

## 关键维度对比

| 维度 | 应用监控（应用观测） | 模型监控 |
| --- | --- | --- |
| 关注层级 | 应用层（智能体/工作流/高代码应用） | 模型层（主账号下所有业务空间的模型调用） |
| 核心能力 | 端到端调用链路追踪、节点级延时与 Token、Span 数据标注、加入评测集 | 用量统计、运行指标看板、Token 追踪、调用日志、主动告警 |
| 数据时效 | 分钟级 | 普通监控小时级；高级监控分钟级；用量数据延迟约 1 小时 |
| 数据保留 | 调用记录最长 30 天 | 用量统计最长 30 天；更早数据需到费用与成本页面查询 |
| 指标粒度 | CHAIN/AGENT/RETRIEVER/LLM/TOOL 等节点级，含 Prompt 内容、输出、延时、Token | 模型 + 业务空间维度，含调用次数、失败率、平均调用时长、首包时长、RPM/TPM 等 |
| 支持范围 | 智能体应用（不含 Assistant API 创建）、工作流应用、高代码应用（仅入口 CHAIN） | 普通监控支持所有地域所有模型；高级监控支持北京/新加坡/弗吉尼亚；告警仅北京/新加坡；日志仅北京部分模型 |
| 是否有 API | 无 API，仅控制台操作 | 控制台操作；告警规则可配置 |
| 输入/输出 | 自动追踪应用输入的 Prompt 及输出；可导出 JSONL/EXCEL | 记录模型调用的请求与响应（需开通推理日志）、Token 用量 |
| 计费方式 | 功能本身不收费；数据存储费用由可观测链路 OpenTelemetry 服务收取 | 功能本身不收费；底层存储/告警依赖对应云服务；模型调用按 Token/张/秒计费 |
| 权限要求 | 主账号开通；子账号需 AliyunBailianFullAccess + 应用观测操作权限 + ram:CreateServiceLinkedRole | 主账号或子账号开通高级监控/日志；默认业务空间成员可查所有空间，子空间成员仅当前空间 |
| 典型场景 | 排查应用内部链路瓶颈、定位节点级错误、将真实调用加入评测集 | 成本核算、稳定性告警、Token 异常消耗追踪、模型调用失败排查 |

## 适用场景建议

- **选择应用监控**：当你需要回答"我的智能体应用在某一轮对话中，到底是检索、重写、模型推理还是插件调用拖慢了响应、消耗了 Token、还是触发了错误"——也就是要追踪**应用内部端到端链路**时。它适合做应用运营效果分析、节点级延时优化、错误根因定位，以及把真实线上调用沉淀为评测样本。
- **选择模型监控**：当你关心的是"主账号下各业务空间调用了哪些模型、花了多少 Token、失败率多少、是否有突增或静默失败"——也就是要做**模型层的成本核算与稳定性保障**时。它适合做账单对账、免费额度管理、模型选型对比、告警配置（如超时、Token 突增）、以及北京地域部分模型的请求/响应内容审计。
- **二者配合使用**：应用监控看的是"一次应用调用"内部各节点的细节，模型监控看的是"大量模型调用"的聚合趋势与告警。若要同时做单次链路排障和长期成本/稳定性治理，建议先用模型监控定位异常模型与时间窗，再用应用监控下钻到具体应用的节点级 Span。

## 技术选型参考

- 若应用为 Assistant API 创建的智能体应用，或需要按账号维度统计 Token 总量，应用监控不适用，应转向模型监控与费用账单。
- 若需要分钟级运行指标与主动告警，且模型在北京/新加坡地域，应启用模型监控的**高级监控**与**告警规则**；应用监控不提供主动告警。
- 若需要审计单次模型调用的输入与输出内容，仅模型监控的**推理日志**（北京地域部分模型）支持，应用监控虽记录 Prompt/输出但聚焦应用链路而非模型级审计。
- 若需要将真实调用沉淀为评测样本，应用监控的"添加到评测集"能力更直接；模型监控无此能力。
- 若高代码应用需要观测内部链路，目前应用监控仅能看到入口 CHAIN 节点，需在代码中使用 AgentScope-AI 的 Tracing 模块并部署时加 `--telemetry enable` 才能上报。
