# 模型监控与应用监控对比

百炼平台提供两套互补的观测体系：**模型监控**聚焦单个模型的调用量、性能指标与成本核算，**应用监控**（应用观测）则面向完整应用的端到端调用链路追踪。两者在监控对象、数据粒度、告警能力和使用场景上各有侧重，开发者常需结合使用以兼顾"模型稳定性保障"与"应用链路可观测性"。本文从关键维度对比两套能力，帮助开发者快速定位适用方案。

## 核心维度对比

| 维度 | 模型监控 | 应用监控（应用观测） |
| --- | --- | --- |
| **监控对象** | 单个模型的调用运行状态 | [智能体应用](../concepts/agent-application.md)、工作流应用、高代码应用的完整调用链路 |
| **核心价值** | 成本核算 + 稳定性保障 | 端到端链路追踪 + 运营优化 |
| **数据粒度** | 普通监控：小时级；高级监控：分钟级 | 分钟级指标更新 |
| **统计维度** | 按"模型 + [业务空间](../concepts/workspace.md)"汇总 | 按应用维度，可展开至单次调用的各节点 |
| **支持地域** | 普通监控：全部地域；高级监控：北京、新加坡、弗吉尼亚；告警：北京、新加坡 | 当前[业务空间](../concepts/workspace.md)所在地域（需开通 OpenTelemetry 服务） |
| **开通方式** | 自动采集，高级监控需手动开启 | 需手动完成授权、开通 OpenTelemetry、初始化 LogStore |
| **关键指标** | 调用总量、失败量/失败率、平均调用时长、平均首包时长、[Token](../concepts/token.md) 消耗、RPM/TPM | 调用次数、失败率、[Token](../concepts/token.md) 总量（输入/输出）、平均首 [Token](../concepts/token.md) 耗时、平均调用时长 |
| **链路追踪** | 不支持，仅提供单模型维度指标 | 支持，可展开 CHAIN/AGENT/LLM/RETRIEVER 等节点的嵌套调用链 |
| **日志能力** | 推理日志（仅北京地域部分模型），记录每次输入与输出 | Trace/Span 列表，记录 Prompt、输出、延时、Token，支持按 Request/Trace/Span ID 检索 |
| **告警能力** | 支持（仅北京、新加坡），可按模型设置阈值告警，通知方式含短信/邮件/电话/钉钉/Webhook | 不支持独立告警配置 |
| **数据导出** | 不支持直接导出（需通过费用与成本页面导出账单） | 支持导出 JSONL / EXCEL |
| **数据标注** | 不支持 | 支持对 Span 添加标签（布尔/分类/数字/文本），与评测标签管理共享 |
| **评测集联动** | 不支持 | 支持将 Span 数据直接导入评测集作为评测样本 |
| **[计费](../concepts/billing.md)** | 功能本身不收费，用量按模型[计费](../concepts/billing.md)规则[计费](../concepts/billing.md) | 功能本身不收费，观测数据存储费由 OpenTelemetry 服务收取 |
| **数据保留** | 用量统计：30 天；更早数据需查费用与成本页面 | 调用记录：最长 30 天 |
| **API 支持** | 可接入 Grafana（通过 Prometheus 指标） | 无 API，仅控制台操作 |

## 监控指标详细对比

| 指标类别 | 模型监控 | 应用监控 |
| --- | --- | --- |
| 安全指标 | 内容安全错误次数 | 通过 GUARDRAIL 节点观测 |
| 成本指标 | 平均单次请求调用量、Token 消耗汇总 | Token 总量、平均单次请求 Token 量 |
| 性能指标 | 调用时长、首 Token 延时、RPM、TPM、非首 Token 延时 | 平均调用时长、平均首 Token 耗时 |
| 错误指标 | 失败次数、失败率、限流错误（429） | 调用失败次数、失败率（按状态"正常/错误"分类） |

## 适用场景建议

**选择模型监控的场景：**

- 需要按模型维度做成本核算和用量统计（按 Token/张/秒计费）
- 需要对单个模型设置性能告警（超时、Token 突增等）
- 需要查看模型推理日志以排查单次调用的输入输出问题
- 需要将监控数据接入 Grafana 等自建监控系统
- 关注模型级别的 RPM/TPM 限流情况

**选择应用监控的场景：**

- 需要端到端追踪智能体或工作流应用的完整调用链路
- 需要了解应用内部各节点（检索、重写、模型推理、插件调用）的耗时分布
- 需要将线上真实调用数据导入评测集，用于持续优化应用效果
- 需要对调用数据进行标注和分类管理
- 需要导出调用数据做离线分析

**建议结合使用的场景：**

- 生产环境中同时运行多个[智能体应用](../concepts/agent-application.md)：用应用监控追踪链路瓶颈，用模型监控对底层模型设置告警
- 成本优化：用模型监控掌握各模型 Token 消耗趋势，用应用监控定位具体哪个应用节点消耗最多
- 故障排查：用应用监控定位出错节点，再用模型监控的推理日志查看具体模型调用的输入输出
