# 模型监控与应用监控对比

阿里云百炼平台提供两套互补的可观测能力：**模型监控**聚焦于单个模型维度的调用量、性能与成本管控；**应用观测**则面向应用维度，追踪端到端调用链路与内部节点执行情况。两者在监控粒度、底层技术、告警能力等方面存在显著差异，开发者应根据运维目标选择合适的方案或组合使用。

## 关键维度对比

| 维度 | 模型监控 | 应用观测 |
|------|----------|----------|
| **监控对象** | 单个模型的调用行为与资源消耗 | 应用（智能体/工作流/高代码）的端到端调用链路 |
| **观测粒度** | 模型级（按模型名称、[业务空间](../concepts/workspace.md)聚合） | Span 级（可展开至 LLM、检索、插件等子节点） |
| **底层技术** | 私有 Prometheus 实例 | 可观测链路 OpenTelemetry 服务 |
| **数据更新频率** | 普通监控小时级；高级监控分钟级 | 分钟级 |
| **核心指标** | 调用次数、Token 消耗、延时（含首 Token）、RPM/TPM、失败率、内容安全错误 | 调用次数、失败率、Token 总量（输入/输出）、首 Token 耗时、平均调用时长 |
| **调用链路追踪** | 不支持 | 支持（CHAIN → AGENT → LLM/RETRIEVER/TOOL 等多级展开） |
| **日志能力** | 支持推理日志（记录每次调用的输入与输出），仅限部分地域和模型 | 通过 Span 详情查看输入输出，所有被观测应用均可用 |
| **告警能力** | 支持（短信、邮件、电话、钉钉、企业微信、Webhook），可配置告警等级 | 不支持 |
| **API 接口** | 支持 Prometheus HTTP API 查询指标 | 暂无 API |
| **外部集成** | 支持 Grafana、自建监控系统通过 Prometheus API 接入 | 不支持外部集成 |
| **数据导出** | 通过 Prometheus API 或阿里云账单导出 | 支持导出为 JSONL 或 EXCEL |
| **数据标注** | 不支持 | 支持自定义标签标注，可添加到评测集 |
| **免费额度管理** | 支持查看和控制免费额度用完即停 | 不涉及 |
| **计费** | 功能本身不收费（高级监控依赖 Prometheus 实例） | 功能本身不收费（存储依赖 OpenTelemetry 服务费用） |
| **支持范围** | 所有模型；高级监控/告警限北京、新加坡等地域 | 智能体应用、工作流应用、高代码应用（不含 Assistant API 创建的智能体） |

## 功能侧重对比

### 模型监控的独有优势

- **用量与成本管控**：提供免费额度管理、用量统计（按模型类型区分 Token/张/秒等单位），适合精细化成本控制。
- **告警通知**：支持多级告警（CRITICAL/ERROR/WARNING/INFO）和多渠道通知，适合生产环境异常响应。
- **Prometheus 生态集成**：数据可接入 Grafana 或自建监控平台，适合已有统一监控体系的团队。
- **推理日志审计**：可记录每次调用的完整输入输出，用于故障排查和内容合规审计。

### 应用观测的独有优势

- **调用链路可视化**：以 Span 树形式展示应用内部执行流程（LLM 推理 → 检索 → 重排 → 插件调用等），快速定位瓶颈节点。
- **多维度筛选**：支持按 Request ID/Trace ID/Span ID 搜索，按状态、延时、Token 量等条件组合过滤。
- **数据标注与评测集**：可对 Span 添加标签并批量导入评测集，打通从观测到评测的闭环。
- **节点级洞察**：可查看 RETRIEVER、RERANKER、EMBEDDING 等中间节点的执行详情，优化 RAG 管线。

## 适用场景建议

| 场景 | 推荐方案 |
|------|----------|
| 监控模型调用量与费用、管理免费额度 | 模型监控 |
| 对模型性能指标设置告警阈值 | 模型监控 |
| 接入 Grafana 构建统一运维大盘 | 模型监控 |
| 排查智能体/工作流应用中的慢节点或错误节点 | 应用观测 |
| 查看 RAG 检索与重排的中间结果 | 应用观测 |
| 将线上真实数据导出用于离线评测 | 应用观测 |
| 审计模型调用的输入输出内容 | 模型监控（推理日志） |
| 生产环境全方位可观测性 | 两者结合使用 |

## 技术选型建议

- **仅使用模型 API**（未构建百炼应用）：使用模型监控即可满足性能追踪和成本管控需求。
- **已构建智能体或工作流应用**：建议同时启用两者——模型监控负责成本告警与全局指标，应用观测负责链路级故障定位与优化。
- **需要对接外部监控平台**：优先启用模型监控的高级监控功能，通过 Prometheus API 接入现有体系。
- **需要评测闭环**：启用应用观测，利用数据标注和评测集功能，将线上表现反馈到模型与应用的迭代优化中。
