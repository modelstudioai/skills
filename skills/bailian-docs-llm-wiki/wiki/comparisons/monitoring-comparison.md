# 模型监控与应用监控对比

百炼平台提供两套互补的监控能力：**模型监控**和**应用监控（应用观测）**。模型监控聚焦于单个模型的调用性能、Token 消耗和费用管理；应用监控则面向完整的应用调用链路，提供端到端的可观测性。理解二者的差异有助于开发者根据实际需求选择合适的监控手段，或将两者结合使用以获得全面的生产可观测性。

## 关键维度对比

| 维度 | 模型监控 | 应用监控（应用观测） |
|------|---------|-------------------|
| **监控对象** | 单个模型的调用行为 | 应用级端到端调用链路 |
| **支持范围** | 模型列表中所有模型及调优后的自定义模型 | 智能体应用、工作流应用、高代码应用 |
| **核心指标** | 调用次数、Token 消耗、首 Token 延时、调用时长、RPM、TPM、失败率、内容安全错误 | 调用次数、失败率、Token 总量（输入/输出）、平均首 Token 耗时、平均调用时长 |
| **链路追踪** | 不支持；仅提供调用级日志 | 支持完整调用链路（CHAIN → AGENT → LLM → RETRIEVER 等节点） |
| **日志能力** | 推理日志（需开通，仅限部分模型和部分地域） | 自动追踪所有 Prompt 及响应数据 |
| **告警机制** | 费用告警 + 模型指标告警（需开启高级监控）；支持短信、邮件、电话、钉钉、企业微信、Webhook | 不提供独立告警功能 |
| **数据导出** | 通过 Prometheus HTTP API 接入 Grafana 等外部系统 | 支持导出为 JSONL 或 EXCEL 格式 |
| **数据标注** | 不支持 | 支持对 Span 数据添加自定义标签，并可批量添加到评测集 |
| **外部系统集成** | 高级监控支持 Prometheus + Grafana | 基于可观测链路 OpenTelemetry 服务 |
| **统计维度** | 按[业务空间](../concepts/workspace.md)、模型、API Key 等维度 | 按应用、Span 类型、Request/Trace/Span ID 等维度 |
| **计费** | 高级监控依赖 Prometheus 实例费用 | 功能免费，数据存储依赖 OpenTelemetry 服务费用 |
| **API 支持** | 高级监控提供 Prometheus HTTP API | 暂无 API |
| **地域限制** | 高级监控：北京、新加坡、弗吉尼亚；告警：北京、新加坡；日志：北京、新加坡部分模型 | 无特别地域限制说明 |

## 适用场景

### 适合使用模型监控的场景

- **模型选型与成本优化**：需要对比不同模型的 Token 消耗和调用延时，选择性价比最优的模型。
- **费用管控**：需要设置费用告警阈值，管理免费额度用量，避免超支。
- **模型性能基线监测**：持续跟踪单个模型的 RPM、TPM、首 Token 延时等指标变化趋势。
- **异常告警响应**：需要在模型调用失败率上升或限流时及时收到多渠道通知。
- **接入自建监控体系**：已有 Grafana/Prometheus 体系，希望将百炼模型指标纳入统一看板。

### 适合使用应用监控的场景

- **应用调试与排障**：需要查看智能体或工作流应用的完整调用链路，定位某个节点的延时或错误。
- **RAG 流程观测**：需要观测检索（RETRIEVER）、向量化（EMBEDDING）、重排（RERANKER）等环节的执行情况。
- **应用质量评估**：需要对模型响应进行数据标注，并将 Span 数据批量导入评测集进行系统化评测。
- **多节点应用的端到端可视化**：工作流包含 LLM、插件调用、条件分支等多个节点，需要全局链路视图。

### 建议组合使用的场景

- **生产环境全面可观测**：用模型监控管理成本和设置告警，用应用监控追踪调用链路和排查问题。
- **从开发到上线的全周期**：开发阶段用应用监控调试链路逻辑，上线后用模型监控持续跟踪性能和费用。

## 技术选型建议

1. **如果只使用模型 API 直接调用**（无智能体/工作流），模型监控即可满足需求。
2. **如果构建了智能体或工作流应用**，应用监控提供的链路追踪能力是排障和优化的必备工具。
3. **生产环境建议两者并用**：模型监控负责成本告警和性能基线，应用监控负责链路追踪和质量评估，形成互补。
4. **需要主动告警时优先配置模型监控**，因为应用监控目前不提供独立告警功能。
5. **需要接入外部可视化系统时**，模型监控（Prometheus）和应用监控（OpenTelemetry）分别对应不同的数据源，可根据团队技术栈选择。
