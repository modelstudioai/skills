# 应用监控与模型监控对比

百炼平台提供两套互补的监控体系：**应用观测**（Application Monitoring）和**模型监控**（Model Monitoring）。前者聚焦于应用内部的调用链路追踪与调试，后者聚焦于模型维度的用量统计、性能指标与告警。理解两者的定位差异，有助于开发者在不同场景下选择合适的监控手段，或将二者组合使用以实现端到端的可观测性。

## 核心维度对比

| 维度 | 应用观测 | 模型监控 |
|------|---------|---------|
| **监控粒度** | 应用级，追踪单次请求的完整内部调用链路（Trace / Span） | 模型级，统计某个模型在[业务空间](../concepts/workspace.md)下的整体调用指标 |
| **观测对象** | 智能体应用、工作流应用、高代码应用 | 模型列表中的所有模型及调优后的自定义模型 |
| **核心能力** | 调用链路追踪、Span 筛选与过滤、数据标注、导出到评测集 | 用量统计、性能指标监控、告警配置、推理日志、外部系统接入 |
| **关键指标** | 调用次数、失败率、Token 总量、首 Token 耗时、平均调用时长 | 调用次数、Token 消耗、调用时长、首 Token 延时、RPM、TPM、失败率、内容安全错误次数 |
| **数据更新频率** | 分钟级 | 用量数据约 1 小时延迟；监控指标分钟级 |
| **数据保留** | 取决于 OpenTelemetry 服务存储配置 | 用量数据仅支持最近 30 天查询 |
| **统计维度** | 按应用维度 | 按[业务空间](../concepts/workspace.md)维度 |
| **告警能力** | 不支持 | 支持费用告警和模型指标告警（短信、邮件、电话、钉钉、企业微信、Webhook） |
| **日志查看** | 通过 Trace/Span 查看每次调用的输入输出与思考过程 | 通过推理日志查看每次对话记录（仅部分模型、部分地域） |
| **API 支持** | 暂无 API | 高级监控提供标准 Prometheus HTTP API |
| **外部系统对接** | 不支持 | 支持 Grafana 等通过 Prometheus API 接入 |
| **依赖服务** | 可观测链路 OpenTelemetry 服务 | 高级监控依赖 Prometheus 实例 |
| **地域限制** | 无特殊限制 | 高级监控限北京、新加坡、弗吉尼亚；告警限北京、新加坡；日志限北京、新加坡的部分模型 |
| **计费** | 功能免费，存储费用由 OpenTelemetry 服务收取 | 功能免费，高级监控的 Prometheus 实例可能产生费用 |

## 功能侧重对比

| 功能 | 应用观测 | 模型监控 |
|------|---------|---------|
| 调用链路追踪 | 支持，细粒度到每个 Span（LLM / RETRIEVER / TOOL 等） | 不支持 |
| Token 消耗统计 | 支持（单次请求级别） | 支持（模型维度汇总 + 单次追踪） |
| 性能指标仪表盘 | 支持（按应用聚合，最长 30 天） | 支持（按模型聚合，含 RPM/TPM） |
| 数据导出 | 支持导出 JSONL / EXCEL | 不支持直接导出（可通过 Prometheus API 拉取） |
| 数据标注 | 支持（布尔、分类、数字、文本标签） | 不支持 |
| 评测集集成 | 支持直接添加 Span 到评测集 | 不支持 |
| 免费额度管理 | 不涉及 | 支持查看和管理免费额度用完即停开关 |
| 异常告警 | 不支持 | 支持多级别告警（CRITICAL / ERROR / WARNING / INFO） |

## 适用场景建议

### 应用观测适合

- **调试与排障**：需要定位某次应用调用中哪个环节（模型推理、检索、插件调用等）出现异常或耗时过长。
- **Prompt 优化**：通过查看模型的输入输出和思考过程，迭代改进 Prompt 设计。
- **质量标注与评测**：对线上流量进行标注，构建评测数据集，形成持续优化闭环。
- **应用级性能分析**：关注某个具体应用的整体调用质量和用户体验指标。

### 模型监控适合

- **成本管控**：需要按模型、按[业务空间](../concepts/workspace.md)统计 Token 消耗和费用，管理免费额度。
- **生产环境运维**：需要对模型服务的可用性、性能、错误率进行持续监控和告警。
- **容量规划**：通过 RPM/TPM 等指标了解模型调用负载，预判是否需要扩容或切换模型。
- **合规与审计**：通过推理日志记录每次对话内容，满足内容审计需求。
- **多系统集成**：需要将监控数据接入 Grafana 等已有可观测平台，实现统一运维视图。

### 组合使用建议

在生产环境中，建议同时启用两套监控：用**模型监控**建立全局视角，掌握各模型的用量趋势和健康状态，并配置告警及时发现异常；用**应用观测**进行深入排查，当告警触发或用户反馈问题时，通过调用链路追踪定位具体的故障环节。两者一宏观一微观，共同构成完整的可观测体系。
