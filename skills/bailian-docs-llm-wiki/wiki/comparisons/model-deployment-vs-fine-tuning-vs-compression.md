# 模型部署、微调与压缩方案对比

为帮助开发者在百炼平台上高效构建端到端大模型应用，本文系统对比三大核心能力模块：**模型部署**（服务化上线）、**微调（Fine Tuning）**（任务适配优化）与**模型压缩**（推理成本优化）。三者并非互斥，而是构成典型的「训练 → 压缩 → 部署」生产流水线。本对比聚焦技术可行性、资源约束、使用门槛与业务适配性，旨在为不同阶段的技术选型提供客观、可落地的决策依据。

---

## 关键维度对比表

| 维度 | 模型部署 | 微调（Fine Tuning） | 模型压缩 |
|------|----------|----------------------|-----------|
| **核心目标** | 将模型（基础/微调/压缩后）以 API 形式稳定、低延迟、可扩展地对外提供服务 | 利用自有数据对预训练模型进行有监督或强化学习优化，提升其在特定任务/领域上的效果 | 对已微调完成的模型执行后训练量化（PTQ），降低推理显存占用与计算开销，缩小部署规格（MU） |
| **输入格式** | `deployment_id`（非 `model_id`）、标准 OpenAI 格式请求体（含 `messages`, `temperature` 等） | JSONL 训练数据集（每行含 `prompt`/`completion` 或模态对应字段）、超参配置（learning_rate, epoch 等）、`model_id`（必须为平台可微调模型） | 已成功完成的微调模型（状态为 `SUCCEEDED`）、量化模板（如 `awq-mu8`）、可选校准数据集（最多 5 个） |
| **输出格式** | 标准 OpenAI 兼容响应（含 `choices[0].message.content`, `usage` 等字段）；流式响应支持 `stream: true` | 新生成的 `fine_tuned_model_id`（如 `ft-qwen-max-abc123`），可用于后续部署或推理；训练日志与评估指标（loss, accuracy） | 新模型 ID（格式为 `源模型名-后缀`，如 `my-qwen-ft-awq8`），状态为 `compressed`，仅支持部署与推理，不可导出、不可再微调 |
| **支持模型** | 所有平台内置模型（Qwen 系列、WanImage、TTS 等）及用户导入的 ONNX/Triton/PyTorch 模型（需满足兼容性要求） | 限定为平台明确标注“支持微调”的模型（如 `qwen-max-0428`、`wan-image-v2.1`、`tts-zh-cn-v3`）；不支持基础模型直接微调（需先启用） | **严格限定**：仅支持百炼平台内训练成功的微调模型（`fine-tuned` 状态）；不支持基础模型、第三方模型、未完成训练的 checkpoint |
| **API 端点** | `POST https://dashscope.aliyuncs.com/api/v1/deployments/{deployment_id}/chat/completions`（统一 `/v1/deployments` 路由） | `POST /v2/fine_tuning/jobs`（创建任务）<br>`GET /v2/fine_tuning/jobs/{job_id}`（查询状态）<br>`GET /v2/models/{fine_tuned_model_id}/chat/completions`（推理） | 控制台操作为主；无独立 RESTful API；任务提交后通过 `/v2/models/{compressed_model_id}` 进行部署与推理 |
| **计费方式** | 按部署类型差异化计费：<br>• `token`：按实际输入/输出 Token 数计费<br>• `ptu`：按预置 Token Unit（小时级结算，不累计）<br>• `dtu`：按预留 GPU 算力（DTU，分钟计费，最小 1 小时）<br>• `exclusive`：按实例规格与运行时长计费<br>• `routing`：按所路由的实际部署类型分别计费 | 按训练算力消耗计费（计入「训练算力配额」）：<br>• 文本类：按 GPU 小时 × 模型规模系数<br>• 多模态/RL/OPD 类：额外加收高级路径费用；免费额度不覆盖 | **任务本身限时免费**（以控制台公告为准）；<br>**但部署压缩后模型仍按 MU 规格正常计费**（如 MU5 比 MU1 成本显著降低） |
| **典型场景** | • A/B 测试多版本模型<br>• 生产环境高并发对话服务<br>• 合规敏感业务（专属部署+VPC）<br>• 流量波动大的 PoC 验证（Token 按量） | • 客服话术风格对齐（指令微调）<br>• 行业知识注入（法律/医疗问答）<br>• 图像生成定制（Logo 设计、产品图渲染）<br>• 决策策略优化（游戏 AI、交易引擎） | • 微调模型推理延迟超标需降规格<br>• 服务成本过高需压降 MU 占用<br>• 边缘/轻量级容器部署（如 MU5/MU8）<br>• 在免费期内快速验证多种量化效果 |

## 适用场景建议

### ✅ 推荐选择「模型部署」当：
- 您已有可用模型（内置、已微调或已压缩），只需快速上线服务；
- 业务对 SLA、延迟、隔离性或数据主权有明确要求（如金融、政务）；
- 流量模式清晰可预测（选 PTU），或高度不确定（选 Token 按量）；
- 需要灰度发布、多地域容灾或故障自动降级（启用智能路由）。

### ✅ 推荐选择「微调」当：
- 通用大模型在您的垂直任务上表现不足（如专业术语理解、固定格式输出）；
- 您拥有高质量、领域相关的标注数据（≥1000 条文本，或 ≥500 张图像）；
- 需要深度定制模型行为（如角色扮演、多轮对话一致性、图像风格迁移）；
- 可接受数小时至数天的训练周期，并具备算力配额。

### ✅ 推荐选择「模型压缩」当：
- 您已完成微调，但部署时发现 MU 规格过高（如 MU1×2）、成本或延迟不达标；
- 您处于模型优化迭代期，希望在华北2（北京）地域低成本试错多种量化方案；
- 您的目标部署环境资源受限（如轻量级 Kubernetes 集群、边缘节点）；
- **注意**：若尚未微调，或模型不在华北2，或需结构剪枝/蒸馏等高级压缩，请暂缓使用。

## 技术选型参考（面向开发者）

| 您的问题 | 推荐方案 | 关键原因 |
|----------|----------|----------|
| “我刚训练好一个客服微调模型，怎么让它被前端调用？” | **模型部署**（推荐 `token` 或 `dtu` 类型） | 部署是服务化的必经环节；微调产出的 `fine_tuned_model_id` 可直接用于创建部署。 |
| “通用 Qwen 回答太泛，如何让它学会我们公司的产品话术？” | **微调**（文本生成类 + 指令微调） | 微调是注入领域知识最直接、效果最可控的方式；需准备 [prompt](../guides/prompt.md)-completion 对齐数据。 |
| “微调后的模型部署要 MU1×2，太贵了，能变小吗？” | **模型压缩**（华北2 地域 + 选择 MU5/MU8 模板） | 压缩专为解决此问题设计；可将 MU 规格显著降低，且保持可用精度。 |
| “我只有原始模型 ID（如 `qwen3.5-flash`），想直接压缩？” | ❌ 不支持 | 压缩仅接受 `fine-tuned` 状态模型；请先完成微调（哪怕只训 1 epoch 做验证）。 |
| “我的业务在新加坡，能用压缩功能吗？” | ❌ 当前不可用 | 压缩服务仅限华北2（北京）地域；请确认控制台「模型压缩」页面是否可见。 |
| “需要同时支持中文问答和英文报告生成，怎么部署？” | **模型部署**（智能路由） | 创建多个部署（如 `zh-qa-deployment`, `en-report-deployment`），通过智能路由按请求内容动态分发。 |
| “微调训练失败，日志显示 ‘out of memory’” | 调整微调参数或换模型 | 降低 `batch_size`、减少 `epoch`、选用更小基座模型（如 `qwen-plus` 替代 `qwen-max`）；检查数据集大小是否超限（文本 ≤10 GB）。 |

> **重要提醒**：  
> - **流水线顺序不可逆**：微调 → 压缩 → 部署 是推荐路径；压缩后模型不可再微调，部署后不可修改模型权重。  
> - **地域强约束**：压缩仅限华北2；DTU 部署必须指定 `region` 且不跨地域共享；部署/微调/压缩均需确保模型在对应地域可用。  
> - **ID 体系清晰**：`model_id`（原始模型）→ `fine_tuned_model_id`（微调产出）→ `compressed_model_id`（压缩产出）→ `deployment_id`（部署实例），四者逻辑独立，调用时务必使用对应 ID。
