# 模型部署、微调与压缩技术路径对比

本文档面向百炼平台开发者，系统对比**模型部署（Deployment）**、**模型微调（Fine-tuning）** 和**模型压缩（Compression）** 三大核心技术路径。三者在模型生命周期中处于不同阶段、承担不同目标：  
- **部署**解决「如何稳定、高效、合规地对外提供服务」；  
- **微调**解决「如何让通用模型适配特定业务语义、风格或任务逻辑」；  
- **压缩**解决「如何在可接受精度损失下，显著降低微调后模型的推理成本与资源门槛」。  

明确三者的边界、能力边界、约束条件与协同关系，是构建高性价比、可演进、可运维AI应用的关键前提。本对比聚焦实际工程选型所需的核心维度，不涉及底层算法原理，强调平台级可用性、计费逻辑与落地可行性。

---

## 关键维度对比表

| 维度 | 模型部署（Deployment） | 模型微调（Fine-tuning） | 模型压缩（Compression） |
|------|--------------------------|---------------------------|-----------------------------|
| **核心目标** | 将模型（基础/微调/压缩后）转化为生产级API服务 | 提升模型在特定领域/任务/风格上的表现力与对齐度 | 降低已微调模型的推理资源消耗（MU/GPU）与单位Token成本 |
| **输入格式** | 已注册的 `model_id`（如 `qwen3-8b`、`qwen3.5-flash-2026-02-23`）；支持官方模型、DTU自定义模型、微调产出模型、压缩产出模型 | 训练数据集（JSONL / ZIP含data.jsonl+媒体文件）、源模型ID、超参配置；数据需符合格式规范（如DPO需`chosen/rejected`对） | 已成功完成的**微调模型实例**（状态为 `SUCCEEDED`）；仅支持百炼平台内训练产出 |
| **输出格式** | 可调用的 HTTPS endpoint（`https://<region>.api.bailian.aliyuncs.com/v1/models/<model_id>:predict`），返回标准OpenAI兼容响应 | 新的模型实例（`model_id` 自动分配，如 `ft-qwen3-8b-20260415-abc123`），可直接用于部署或进一步压缩 | 新的量化模型实例（`model_id` 为 `<源模型名>-<后缀>`，如 `qwen3.5-flash-2026-02-23-awqmu8`），独立可部署 |
| **支持模型** | 全量支持：<br>• 百炼官方模型（Qwen系列、万相、CosyVoice等）<br>• DTU部署的Hugging Face模型（需镜像导入）<br>• 微调产出模型<br>• 压缩产出模型 | 严格受限：<br>• 文本生成：Qwen3/Qwen2.5/Plus等数十个模型（SFT/CPT/DPO/RL）<br>• 视觉理解：Qwen-VL（仅SFT）<br>• 图像/视频生成：万相、Qwen-Image（仅SFT-LoRA）<br>• 语音合成：CosyVoice（仅efficient_sft）<br>• 决策模型：`decision-model-preview-*`（仅API） | 极度受限：<br>• **仅华北2（北京）地域**<br>• **仅百炼平台内完成的微调模型**（非基础模型、非OSS导入、非跨平台模型）<br>• 当前仅支持PTQ（后训练量化），不支持剪枝/蒸馏 |
| **API 端点** | `POST /v1/deployments`（创建）<br>`GET /v1/deployments/{id}`（查询）<br>`DELETE /v1/deployments/{id}`（下线）<br>调用：`POST {endpoint_url}`（OpenAI兼容） | `POST /api/v1/files`（上传数据）<br>`POST /api/v1/fine-tunes`（提交训练）<br>`GET /api/v1/fine-tunes/{id}`（轮询状态） | 无独立API；**仅控制台操作**（路径：左侧导航栏 → 模型压缩 → 创建压缩任务） |
| **计费方式** | 按部署类型差异化计费：<br>• `dedicated`：按实例时长（小时）计费<br>• `ptu`：预购PTU包 + 超额Token按量<br>• `dtu`：按GPU卡数×时长计费<br>• `token`：纯按Token数计费<br>• `routing`：按被路由到的实际部署类型计费 | 多模式可选（控制台）：<br>• 按Token计费（最常用）<br>• 预付费训练单元（适合批量任务）<br>• 后付费（按实际资源消耗结算）<br>**API方式仅支持Token计费** | **压缩任务本身限时免费**（以控制台公告为准）；<br>**压缩后模型的部署费用按MU规格单独计费**（与压缩免费期无关） |
| **典型场景** | • 客服对话机器人（低延迟要求 → `dedicated`）<br>• 内容审核API（高并发+长文本 → `ptu`）<br>• 私有化AI助手（需CUDA定制 → `dtu`）<br>• A/B测试验证（低成本试跑 → `token`）<br>• 多版本灰度发布（自动调度 → `routing`） | • 金融合同摘要（SFT对齐行业术语）<br>• 用户评论情感分级（决策模型微调）<br>• 企业知识库问答（CPT注入私域知识）<br>• 生成式UI组件（DPO对齐设计偏好）<br>• 语音播报定制（CosyVoice多发音人SFT） | • 已微调的Qwen3-8b模型需部署至边缘设备（压缩至MU8规格）<br>• 在线客服场景需将微调后模型成本降低40%+（AWQ量化）<br>• 快速验证多个量化模板对业务指标的影响（利用免费期并行压测） |
| **地域限制** | **全地域支持**（但endpoint仅限创建Region内访问） | **绝大多数功能仅华北2（北京）**；新加坡仅部分VL模型支持SFT | **仅华北2（北京）** |
| **启动耗时** | `token`/`routing`：秒级就绪<br>`ptu`：秒级就绪<br>`dedicated`/`dtu`：5–15分钟 | SFT（LoRA）：约30–120分钟<br>CPT/RL/OPD：数小时至数天（取决于数据量与模型规模） | 通常10–60分钟（取决于模型大小与量化模板复杂度） |
| **是否可逆** | 可随时下线实例（`DELETE`），零残留 | 可重新提交新训练任务（不影响原模型）；但训练过程不可中断修改 | **不可逆**：压缩后模型不支持继续微调、不支持二次压缩、不支持还原为全精度 |

## 各方案适用场景建议

### ✅ 推荐选择「模型部署」当：
- 您已有**可用模型**（官方模型、微调模型或压缩模型），只需快速上线服务；
- 业务对**延迟、稳定性、隔离性或定制化运行环境**（如CUDA版本、自定义镜像）有明确要求；
- 流量特征清晰（如稳定高并发、突发流量、长上下文为主），可匹配 `ptu`/`dtu`/`token` 等策略；
- 需要**多版本管理、灰度发布、故障熔断**等生产治理能力 → 优先选用 `routing` 类型。

### ✅ 推荐选择「模型微调」当：
- 官方模型在您的**垂直领域（如医疗、法律、制造）或具体任务（如工单分类、报告生成）上表现不足**；
- 您拥有**高质量标注数据或偏好数据**（如人工标注的问答对、`chosen/rejected` 对、多发音人录音）；
- 业务需要**深度语义对齐**（如品牌话术、合规表述、专业术语）或**行为一致性**（如决策模型输出封闭集合标签）；
- 您能接受**数小时至数天的训练周期**，并具备数据准备与评估能力；
- ⚠️ 注意：务必确认您的**地域（首选北京）和模型类型**是否在支持列表中。

### ✅ 推荐选择「模型压缩」当：
- 您已完成微调，且该模型**已验证有效**，但**推理成本过高**（如MU16部署费用超出预算）；
- 您的目标部署环境**资源受限**（如边缘服务器、轻量级容器），需更低MU规格（如MU4/MU8）；
- 您愿意投入少量时间进行**量化模板对比实验**（利用免费期并行压测多个模板）；
- 您接受**精度轻微下降**（建议使用真实业务测试集验证BLEU/ROUGE/准确率等核心指标）；
- ⚠️ 重要前提：必须是**百炼平台内完成的微调模型**，且位于**华北2（北京）**。

## 技术选型参考指南（给开发者的行动清单）

| 场景 | 推荐路径 | 关键检查项 | 风险提示 |
|------|----------|------------|----------|
| **首次上线一个客服问答API** | 1. 选用 `qwen3-8b` 官方模型 → 2. `token` 部署快速验证 → 3. 根据压测结果升级为 `ptu` 或 `dedicated` | • 确认Region与endpoint可达性<br>• 设置合理的 `max_tokens` 与 `temperature` | `token` 类型有32k token请求上限；高并发下可能触发限流 |
| **将内部产品文档训练成专属知识模型** | 1. 准备JSONL格式SFT数据 → 2. 控制台提交 `qwen3-8b` SFT任务（北京地域）→ 3. 部署微调后模型 → 4. （可选）对微调模型执行压缩 | • 数据需脱敏、去重、格式校验<br>• SFT推荐使用LoRA（`efficient_sft`）降低成本<br>• 压缩前务必保留原始微调模型 | DPO/CPT需北京地域；CosyVoice等语音模型仅支持API方式 |
| **已上线的微调模型因成本过高需优化** | 1. 进入「模型压缩」控制台 → 2. 选择该微调模型 → 3. 并行尝试 `awqmu4`/`awqmu8` 模板 → 4. 用线上流量镜像验证各模板效果与延迟 | • 确保模型状态为 `SUCCEEDED`<br>• 下载日志检查量化校准是否成功<br>• 对比压缩前后相同请求的Token数与首字延迟 | 压缩后模型不可再微调；若效果不达标，需回退至上游微调模型重试 |
| **需同时支持多语言、多版本、A/B测试** | 1. 分别部署各版本模型（`dedicated` 或 `ptu`）→ 2. 创建 `routing` 实例 → 3. 配置 `version_weighted` 策略分发流量 | • 所有被路由模型须在同一Region<br>• routing实例本身不产生推理费用，仅按实际调用计费 | 不支持跨地域路由；策略变更需重新发布 |

> 💡 **最佳实践提示**：  
> - **不要跳过验证环节**：无论部署、微调还是压缩，均应使用**真实业务请求样本**进行端到端测试（非仅Hello World）。  
> - **善用免费资源**：微调任务的预付费训练单元、压缩任务的限时免费期，是低成本探索最优配置的关键窗口。  
> - **关注地域一致性**：北京地域是微调与压缩的唯一可靠选择；部署虽全地域支持，但若依赖微调/压缩产物，请确保部署Region与训练Region一致（避免跨Region调用失败）。  
> - **版本即资产**：所有产出（部署实例ID、微调任务ID、压缩任务ID）均应纳入CI/CD流程管理，确保可追溯、可复现。
