# 模型部署、微调与压缩方案对比

为帮助开发者在百炼平台上高效完成模型全生命周期管理（从效果优化到生产落地），本文系统对比三大核心能力：**模型部署（Model Deployment）**、**模型微调（Fine Tuning）** 和 **模型压缩（Model Compression）**。三者定位不同、能力互补：微调聚焦「效果提升」，部署保障「服务交付」，压缩解决「成本与性能平衡」。本对比基于当前（2024年Q3）平台最新能力与文档规范，面向技术选型提供客观、可操作的决策依据。

---

## 关键维度对比表

| 维度 | 模型部署（Deployment 1） | 模型微调（Fine Tuning） | 模型压缩（Compression） |
|------|---------------------------|--------------------------|--------------------------|
| **核心目标** | 将模型（基础/微调）转化为高可用、可计量的在线推理服务 | 通过数据驱动方式提升模型在特定任务/领域的效果、稳定性与对齐性 | 在可控精度损失下降低微调模型的推理资源消耗与部署成本 |
| **输入格式** | 已注册模型 `code`（如 `qwen3.7-plus-2026-05-26`）、LoRA 权重包（OSS ZIP）、或智能路由配置列表 | 训练数据集（JSONL 格式为主；CosyVoice 需 `.wav` + `data.jsonl`；图像/视频需符合分辨率/尺寸约束） | 已成功完成的微调模型（状态为 `SUCCEEDED` 的自定义模型） |
| **输出格式** | 可调用的部署服务 `code`（如 `my-qwen-ft-ptu-100`）、API 端点、实时监控指标 | 微调后的新模型 `code`（如 `my-qwen-ft-20240526`），含完整权重与推理配置 | 量化后的压缩模型 `code`（如 `my-qwen-ft-awq4`），仅支持部署，不可再训练或压缩 |
| **支持模型** | ✅ 平台预置大模型（Qwen/GLM/DeepSeek/Kimi 等）<br>✅ LoRA 微调模型（导入后部署）<br>✅ 全参微调模型（白名单开通）<br>❌ 第三方/OSS 直接加载模型（未导入） | ✅ 文本生成（Qwen3/Qwen2.5/千问-Plus-Character）<br>✅ 视觉理解（Qwen-VL）<br>✅ 图像/视频生成（万相、千问图像/视频）<br>✅ 语音合成（CosyVoice-v3-flash）<br>❌ 基础模型（无训练数据时无法启动） | ✅ 仅限百炼平台内完成的微调模型（SFT/CPT/DPO/RL 产出）<br>❌ 基础模型、LoRA 导入模型、OSS 外部模型、第三方训练模型 |
| **API 端点** | `POST /api/v1/deployments`（创建）<br>`GET /api/v1/deployments/{id}`（查询）<br>调用端点：`/v1/chat/completions`（兼容 OpenAI） | `POST /api/v1/fine-tunes`（提交）<br>`GET /api/v1/fine-tunes/{id}`（轮询）<br>CosyVoice 必须使用 API（控制台不支持） | `POST /api/v1/model-compressions`（创建）<br>`GET /api/v1/model-compressions/{id}`（查询）<br>无独立调用端点（压缩模型需通过部署服务调用） |
| **计费方式** | • PTU：按预置吞吐量（TPM）月度订阅<br>• DTU/MU：按独占 GPU 单元（MU1/MU2…）小时计费<br>• Token 按量：按实际输入/输出 Token 计费（仅 LoRA）<br>• 智能路由：按实际执行模型计费 | • SFT/CPT/DPO：按训练时长 × MTU 规格计费<br>• RL：按 `n_rollouts × batch_size × steps` 与 MTU 资源综合计费<br>• CosyVoice：按 `(lm_max_epoch + fm_max_epoch) × 25 × 总音频秒数` 计费 | • 压缩任务本身：限时免费（以控制台公告为准）<br>• 压缩后模型部署：按 MU 规格单独计费（如 `MU1` vs `MU8`） |
| **典型场景** | • 高并发客服问答（PTU 保障低延迟）<br>• 金融合规审核（DTU 启用 Thinking 模式+长上下文）<br>• A/B 效果验证（Token 按量低成本试跑）<br>• 多模型动态降级（智能路由） | • 客服话术风格定制（SFT）<br>• 法律条款精准解析（DPO 对齐偏好）<br>• 医疗报告生成（CPT 增强领域知识）<br>• 音色克隆（CosyVoice SFT）<br>• 图生图质量优化（万相 LoRA） | • 微调模型上线后发现 MU 成本过高<br>• 边缘/轻量级服务需降低显存占用（如 `MU1` 替代 `MU4`）<br>• 批量部署多个微调模型时统一降本 |
| **地域支持** | 北京（cn-beijing）为主；智能路由强制使用 `maas.aliyuncs.com` 域名 | 仅华北2（北京）全域支持（SFT/DPO/CPT/RL/图像/视频/语音） | 仅华北2（北京）支持 |
| **关键限制** | • 部署后计费模式不可变更<br>• Token 按量仅支持 LoRA，闲置 30 天自动释放<br>• 智能路由不支持多模态/Embedding/Batch | • 控制台不支持 CosyVoice 微调（必须 API）<br>• 数据格式强校验（JSONL 结构、`.wav` 采样率等）<br>• 所有类型均仅限北京地域 | • 不可逆：压缩后模型不可微调、不可二次压缩、不可还原全精度<br>• 仅支持百炼原生微调模型<br>• 校准数据需提前在数据管理中发布 |

## 适用场景建议（面向开发者的技术选型指南）

### ✅ 优先选择「模型部署」当：
- 您已拥有**效果达标的模型**（无论是平台预置模型、LoRA 微调模型或全参微调模型），目标是快速上线服务；
- 业务对**SLA、延迟、吞吐有明确要求**（如 TP99 < 800ms，TPM ≥ 5000），需 PTU 或 DTU 提供确定性保障；
- 需要**灵活的成本弹性**：短期验证用 Token 按量，长期稳定用 PTU，高隔离需求用 DTU；
- 面临**多模型协同场景**（如主模型降级至备选模型），需智能路由实现策略化调度。

> ⚠️ 注意：若尚未完成模型效果优化，请勿直接部署基础模型——应先进行微调。

---

### ✅ 优先选择「模型微调」当：
- Prompt 工程、RAG 等轻量方法**无法解决幻觉、事实错误、风格不符、领域知识缺失等问题**；
- 您拥有**高质量、结构化的小规模标注数据**（≥100 条有效对话/样本），且数据符合平台格式规范；
- 业务场景具有**强领域属性**（如保险条款解读、芯片设计文档生成、医疗影像报告）；
- 需要**深度对齐价值观或安全策略**（DPO/RL 可显式建模偏好与风险）；
- 支持多模态任务（图像理解、文生图、图生视频、语音克隆）。

> ⚠️ 注意：微调是效果前置环节，非部署替代方案；CosyVoice 等特殊模型务必规划 API 接入路径。

---

### ✅ 优先选择「模型压缩」当：
- 您已完成微调并获得满意效果，但**部署成本超出预算**（如 `MU4` 推理费用过高）；
- 您希望**在保持业务效果前提下，将部署规格降至更低档位**（如从 `MU4` 压缩至 `MU1`）；
- 需要**批量部署多个微调模型**，通过统一量化降低整体算力开销；
- 您已准备好**语义相关校准数据**（如 100–500 条真实业务 query），用于提升 INT4 量化鲁棒性。

> ⚠️ 注意：压缩是部署前的**可选优化步骤**，不可用于“挽救效果差的微调模型”；务必在免费期内完成多模板对比与业务测试集验证。

## 技术选型决策流程图（简明版）

```
您的目标是上线一个高性能、低成本、效果可靠的模型服务？
│
├─ 否 → 先明确业务需求与数据现状（是否已有标注数据？是否多模态？）
│
└─ 是 → 按顺序检查：
     │
     ├─ 效果是否达标？  
     │   ├─ 否 → 进入【模型微调】：选择 SFT/DPO/RL 等方式优化  
     │   └─ 是 → 进入下一步  
     │
     ├─ 是否需极致成本控制或轻量部署？  
     │   ├─ 是 → 进入【模型压缩】：对已达标微调模型尝试 INT4/INT8 量化  
     │   └─ 否 → 进入下一步  
     │
     └─ 是否需高 SLA、低延迟、长上下文或物理隔离？  
         ├─ 是 → 【模型部署】选择 DTU/PTU 模式  
         └─ 否 → 【模型部署】选择 Token 按量（验证）或 MU（通用）  
```

> 💡 提示：三者非互斥，而是典型组合链路：**微调 → （可选）压缩 → 部署**。百炼平台支持该全链路无缝衔接，所有产出模型均统一纳管于「模型中心」，一键触发后续环节。
