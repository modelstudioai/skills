# 多模态生成 API 对比：图像、视频与 3D 生成

为帮助开发者快速理解百炼平台在多模态内容生成领域的技术能力边界与工程适配要点，本文系统对比图像生成、视频生成与 3D 生成三类核心 API。对比聚焦实际开发中高频关注的接口规范、模型生态、调用范式与生产约束，旨在支撑技术选型决策——避免因地域错配、路径误用、参数越界或异步逻辑缺失导致集成失败。

---

## 关键维度对比

| 维度 | 图像生成（`/v1/images/generations`） | 视频生成（`/api/v1/services/aigc/video-generation/video-synthesis` 等） | 3D 生成（`/v1/3d/generation`） |
|------|-------------------------------------|---------------------------------------------------------------|------------------------------|
| **输入格式** | 同步 JSON：支持 `prompt`（文本）、`image_url` 或 `image`（Base64）；图生图需显式传入参考图 | 异步 JSON：`input` 对象结构动态适配任务类型（文生/图生/参考生/编辑），所有媒体资源必须为公网 HTTP(S) URL 或带鉴权的 OSS URL | 异步 JSON：仅支持 `prompt`（必填，≤200 字符） + 可选 `image_url`（JPEG/PNG，建议 ≥512×512） |
| **输出格式** | 同步响应：`data[]` 数组，每项含 `url`（CDN 临时链接，有效期 1 小时）和 `revised_prompt` | 异步轮询：`GET /api/v1/tasks/{task_id}` 返回 `output.video_url`（OSS 直链，有效期 24 小时） | 异步轮询：`GET /v1/3d/generation/{task_id}` 返回 `model_url`（`.glb` 文件直链，有效期 24 小时） |
| **支持模型** | 千问（Qwen-VL/Qwen2-VL）、万相（WanXiang）、Z-Image、可灵（Kling）、Vidu、创意工具（后处理） | HappyHorse、万相（WanX v2.7/v3.0）、爱诗（PixVerse）、可灵（Kling v3/v4）、Vidu | Tripo（唯一支持模型） |
| **API 端点** | 统一同步端点：<br>`POST /v1/images/generations` | **多端点强绑定**：<br>- 通用能力：`/api/v1/services/aigc/video-generation/video-synthesis`<br>- 专用能力（如万相2.2-animate-move）：`/api/v1/services/aigc/image2video/video-synthesis`<br>⚠️ 必须匹配模型文档指定路径 | 统一异步端点：<br>`POST /v1/3d/generation`<br>`GET /v1/3d/generation/{task_id}` |
| **调用范式** | **同步阻塞**：请求即返回结果（含错误），无任务 ID 概念 | **强制异步**：必须两步（创建任务 → 轮询状态），`task_id` 有效期 24 小时，禁止重复提交 | **强制异步**：必须两步（创建任务 → 轮询状态），`task_id` 有效期 24 小时，支持可选 `callback_url` 回调 |
| **地域与鉴权** | 无显式地域约束，API Key 全局有效（但部分模型内部调度依赖地域） | **强地域绑定**：Endpoint 域名（如 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com`）、API Key、模型部署地域三者必须严格一致 | 无显式地域字段，但 WorkspaceId 隐含地域上下文；API Key 需与业务空间所属地域匹配 |
| **计费方式** | 按**成功请求数**计费（无论生成 1 张或 4 张，单次请求计 1 次）；失败请求不计费 | 按**成功完成的任务数**计费（`status=SUCCESS` 才计费）；轮询请求不计费 | 按**成功完成的任务数**计费（`status=success` 才计费）；轮询请求不计费 |
| **典型场景** | - 快速原型草图（Z-Image）<br>- 高保真营销图（万相）<br>- 图文混合理解生成（千问）<br>- 动态构图预演（Vidu/Kling） | - 文生短视频（HappyHorse/PixVerse）<br>- 首帧延展动画（Kling/WanX）<br>- 口型驱动/动作迁移（PixVerse）<br>- 视频超清增强（PixVerse/HappyHorse） | - 游戏低多边形资产生成（Tripo）<br>- 电商产品 3D 展示建模<br>- AR 应用轻量级模型快速构建 |
| **关键限制** | - `prompt` ≤1000 字符（超长静默截断）<br>- 图像 URL 有效期 1 小时<br>- 敏感内容自动过滤（`content_filter` 错误） | - 输入文件必须公网可访问或 OSS URL<br>- 单任务耗时 1–10 分钟，需设计合理轮询间隔（≥5 秒）<br>- 严禁跨地域调用（硬性失败） | - `prompt` ≤200 字符（超长报错）<br>- 不支持骨骼动画、PBR 材质贴图、物理碰撞体<br>- 生成超时阈值 300 秒（超时置 `failed`） |

## 各方案适用场景建议

| 场景需求 | 推荐方案 | 理由说明 |
|----------|----------|----------|
| **需要毫秒级响应、前端实时渲染的轻量图像生成**（如设计工具中的风格预览、A/B 测试图生成） | ✅ 图像生成（Z-Image 或万相） | 同步 API 无轮询开销，Z-Image 专为低延迟优化；万相支持高分辨率与多比例，适合交付级输出。 |
| **需生成带时间连续性与运动语义的内容**（如广告短视频、教育动画、虚拟人播报） | ✅ 视频生成（Kling v4 或 PixVerse） | Kling v4 支持首/中/尾关键帧控制，保障构图一致性；PixVerse 全栈覆盖对口型与动作模仿，适合人像类应用。 |
| **需将 2D 设计稿快速转化为可交互 3D 模型**（如独立游戏开发、AR 商品展示） | ✅ 3D 生成（Tripo） | Tripo 是当前唯一支持图文混合输入的 3D 模型 API，能较好保持参考图几何特征；`.glb` 格式开箱即用，兼容 Three.js / Babylon.js 等主流引擎。 |
| **需对已有图像进行增强、扩图、主体提取等后处理** | ✅ 图像生成（创意工具系列） | 创意工具提供标准化后处理能力，且与前序生成任务通过 `request_id` 关联，确保上下文一致性。 |
| **需构建端到端多模态流水线**（如：文生图 → 图生视频 → 视频抽帧 → 3D 重建） | ⚠️ 组合使用，但需注意： | - 图像 URL 1 小时过期，需立即下载并转存为持久化 URL 供后续视频/3D 调用<br>- 视频/3D 任务均需公网可访问输入，本地文件必须先上传至 OSS 并构造合规 URL<br>- 所有环节的地域必须统一（推荐华北2（北京）作为默认生产环境） |

## 技术选型参考（面向开发者）

- **优先验证同步 vs 异步架构**：  
  若业务无法容忍异步轮询（如实时聊天机器人需即时返回），**仅图像生成可用**；视频与 3D 必须接受任务队列模型，需在客户端实现健壮的轮询或回调处理逻辑。

- **严格校验地域与 Endpoint 匹配**：  
  视频生成是地域敏感性最高的模块。务必在初始化阶段校验：① API Key 所属地域；② WorkspaceId 解析出的域名；③ 模型文档中标注的部署地域。三者不一致将返回 `403 Forbidden` 或 `ModelNotAvailable`，**无降级重试机制**。

- **输入 URL 是最大共性陷阱**：  
  三类 API 均**不接受本地文件路径或相对路径**。图像生成虽支持 Base64，但视频与 3D 仅接受公网 URL。建议统一使用阿里云 OSS 临时上传 + 签名 URL 方案，避免 CDN 缓存或防盗链问题。

- **参数容错性差异显著**：  
  图像生成对 `size` 等参数宽松（如万相支持 `"768x768"`，可灵仅支持 `"1024x1024"`），但会静默忽略不支持值；视频/3D 生成对参数更严格（如 `aspect_ratio` 错误直接报 `InvalidParameter`）。**务必以目标模型文档为准，勿跨模型复用参数配置**。

- **计费粒度决定架构设计**：  
  图像生成按“请求”计费，适合批量生成（`n=4`）；视频/3D 按“成功任务”计费，适合失败重试（如网络抖动导致轮询中断，可凭 `task_id` 继续查询）。避免为节省费用而合并请求——视频不支持批量任务，3D 不支持多模型并发。

- **安全策略需前置适配**：  
  三类 API 均启用内容安全过滤，但触发阈值不同：图像对人脸/商标敏感，视频对暴力动作敏感，3D 对武器/违禁品建模敏感。建议在 `prompt` 中主动规避高风险词，并在生产环境捕获 `content_filter` 错误码，引导用户修改提示词。
