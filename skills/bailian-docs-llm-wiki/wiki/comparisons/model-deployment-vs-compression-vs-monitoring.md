# 模型部署、压缩与监控方案对比

为帮助开发者在百炼平台上高效构建、交付与运维大模型服务，本文系统对比三大核心能力模块：**模型部署**（含多种计费与调度模式）、**模型压缩**（轻量化推理支持）与**模型监控**（全链路可观测性）。对比聚焦实际工程落地中的关键决策维度——包括输入/输出约束、模型兼容性、集成方式、成本结构与运维边界，旨在为不同阶段（效果验证 → 生产上线 → 规模化运营）的技术选型提供清晰、可操作的参考依据。

---

## 关键维度对比表

| 维度 | 模型部署（PTU / DTU/MU / Token / 智能路由） | 模型压缩（INT4 量化） | 模型监控（全链路可观测） |
|------|---------------------------------------------|--------------------------|----------------------------|
| **输入格式** | • PTU/DTU/MU：原始模型 ID 或已导入 LoRA 模型 code<br>• Token 按量：仅限已训练完成的 LoRA 模型<br>• 智能路由：OpenAI 兼容请求体（`messages`, `model="auto-model-xxx"`） | • 原始 FP16 模型版本 ID + 版本号<br>• 可选校准数据集（JSONL，含 `text` 字段）<br>• 必填 `compression_type`（`"w4a16"` 或 `"awq"`） | • 无显式“输入”；自动采集所有已部署模型的调用流量<br>• 审计日志：自动记录 Request ID、状态码、Token 数、延迟等元信息<br>• 推理日志：需手动开启，采集完整 Prompt/Response（截断上限 128K） |
| **输出格式** | • 统一 DashScope/OpenAI 兼容响应（含 `id`, `choices`, `usage`）<br>• 智能路由额外返回 `x-dashscope-resolved-model` 响应头 | • 新生成的压缩后模型版本 ID（格式如 `qwen2-7b-int4-awq-v123`）<br>• 输出为平台专有 `.bml` 格式，**不支持 ONNX 导出** | • 控制台可视化图表（分钟级粒度）<br>• 审计日志：结构化 JSON（SLS 投递）<br>• 推理日志：带上下文的完整请求/响应 JSON（SLS 投递）<br>• 告警通知：邮件/钉钉等渠道文本消息 |
| **支持模型** | • PTU：千问、DeepSeek、GLM、千问VL 等主流文本/多模态模型<br>• DTU/MU：基础模型、LoRA 微调模型、用户导入 LoRA 模型<br>• Token 按量：**仅 LoRA 微调模型**<br>• 智能路由：备选模型池中支持 OpenAI 协议的文本模型（如 Qwen、GLM） | • **仅 Qwen 系列（Qwen1.5/Qwen2/Qwen2.5/Qwen-VL）FP16 版本**<br>• 明确**不支持 Llama、Phi、Mixtral 等第三方架构** | • 所有在「模型列表」中可见的模型（含 LoRA 微调模型）<br>• **不支持**语音/图片/视频生成类、三方直连类模型（控制台无监控入口） |
| **API 端点** | • 部署：`POST /api/v1/deployments`（PTU/DTU/MU/Token）<br>• 调用：`POST /api/v1/services/{model_code}/chat/completions`（DashScope）或 `POST /v1/chat/completions`（OpenAI 兼容）<br>• 智能路由：仅支持 OpenAI 兼容端点（`maas.aliyuncs.com`） | • 压缩触发：`POST /v1/models/{model_id}/versions/{version_id}/compress`<br>• 查询任务：`GET /v1/jobs/{job_id}` | • 监控数据查询：通过控制台交互实现，**无直接 REST API 拉取指标**<br>• 日志投递：依赖云监控（Prometheus）、SLS SDK 或控制台配置<br>• 告警规则：`POST /v1/alert-rules`（需先完成云监控角色授权） |
| **计费方式** | • PTU：按预置吞吐额度（input/output TPM）月度包年包月<br>• DTU：按输入/输出 TPM 实时计费（新模型）<br>• MU：按模型单元数量（MU1/MU2…）月度计费（已有模型）<br>• Token 按量：按实际消耗 Token 数实时计费<br>• 智能路由：按**实际路由到的模型单价**结算 | • **不单独计费**；压缩本身免费<br>• 压缩后模型部署仍按所选部署模式（PTU/DTU/MU/Token）计费<br>• 校准过程占用 GPU 资源，计入空间配额，但不产生额外费用 | • 监控数据存储与计算在百炼平台侧**免费**<br>• **数据投递产生费用**：<br> – 云监控（Prometheus）按实例+指标数计费<br> – SLS 按日志写入量+存储时长计费<br> – 钉钉/邮件告警通道免费 |
| **典型场景** | • PTU：高并发客服、实时摘要、搜索增强等低延迟稳态服务<br>• DTU/MU：新模型灰度发布、私有化部署、长上下文推理（1M token）<br>• Token 按量：A/B 测试、微调效果快速验证、小流量试运行<br>• 智能路由：多模型能力兜底、自动降级、成本敏感型泛化任务 | • 边缘设备部署（如车载、IoT 网关）<br>• 高并发 API 服务（降低单请求 GPU 显存占用与首 Token 延迟）<br>• 私有化交付中对体积与启动速度有强约束的场景 | • 生产环境稳定性巡检（失败率突增、延迟毛刺）<br>• 成本归因分析（某模型 Token 消耗异常飙升）<br>• [Prompt 工程](../concepts/prompt-engineering.md)调试（通过推理日志回溯 bad case）<br>• 合规审计（请求内容留痕） |

## 各方案适用场景建议

### ✅ 模型部署 —— 按阶段选择计费与调度模式
- **效果验证期（0→1）**：首选 **Token 按量**。零预置成本、按调用付费，适合快速验证 LoRA 微调效果；但注意其**不支持自助扩缩容**，需人工审核扩容，不适合突发流量。
- **灰度上线期（1→10）**：推荐 **DTU（新模型）或 MU（成熟模型）**。独占算力保障 SLA，支持自定义推理模式（`enable_thinking`）、上下文长度调节（`max_context_length`）及 PD 分离，便于性能压测与参数调优。
- **生产稳态期（10→∞）**：优先 **PTU**。适用于流量可预测、需长期稳定服务的场景（如企业知识库问答），享受前缀缓存折扣与长输入支持；若需极致弹性，可搭配自动伸缩策略。
- **多模型智能调度**：选用 **智能路由**。当业务需自动匹配最优模型（如按延迟/成本/能力兜底），且接受 OpenAI 协议约束（仅北京/新加坡地域、`maas.aliyuncs.com` 域名），此方案可显著降低运维复杂度。

### ✅ 模型压缩 —— 按硬件与性能需求启用
- **必须启用**：目标部署环境为边缘设备（GPU 显存 < 16GB）、或线上服务 P99 首 Token 延迟 > 800ms 且无法扩容资源。
- **谨慎启用**：业务对生成质量极度敏感（如法律文书生成），且未使用高质量校准数据集（建议 ≥128 条代表性样本）；此时应优先测试 `w4a16` 与 `awq` 在真实业务请求下的效果衰减。
- **不可启用**：模型非 Qwen 系列（如 Llama3、Phi-3）、或需后续继续微调——压缩后模型**仅支持推理，不可再训练**。

### ✅ 模型监控 —— 按运维成熟度分层配置
- **基础运维（必开）**：**审计日志 + 分钟级监控图表**。无需额外配置，自动生效，用于实时查看失败率、首 Token 延时、TPM/RPM 趋势，是故障定位第一入口。
- **深度运维（推荐）**：**开启推理日志投递至 SLS**。用于精准复现 bad case、分析 Prompt 效果、支撑日志回流训练；注意需**先开启审计日志投递**，且关闭后历史日志不可恢复。
- **成本治理（进阶）**：**配置 TotalToken 数告警 + 关联用量分析**。当某模型 Token 消耗环比增长 >50% 时自动告警，结合[模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)页面进行小时级成本归因。
- **告警策略（注意边界）**：仅对 `失败率`、`首 Token 延时`、`TotalToken 数` 等预置指标支持告警；`RPM`、`非首 Token 延时` 等诊断指标**无法配置告警**，需通过图表人工巡检。

## 开发者技术选型 checklist

请在实施前逐项确认：

- [ ] **部署模式是否可变更？** → ❌ 不可变！创建后需下线重建。首次部署务必根据流量预期与预算慎重选择 PTU/DTU/MU/Token。
- [ ] **模型是否满足压缩前提？** → 仅 Qwen FP16 版本；LoRA 模型需先部署为 MU/DTU 模式，再对其版本发起压缩。
- [ ] **监控是否覆盖目标模型？** → 语音/图片/视频类模型在控制台无「查看详情」入口，不支持任何监控能力。
- [ ] **智能路由是否符合协议限制？** → 必须使用 OpenAI SDK、`maas.aliyuncs.com` 域名、且地域限定为 `cn-beijing` 或 `ap-southeast-1`。
- [ ] **日志投递是否已授权？** → 开启推理日志前，必须完成云监控服务角色授权（否则按钮置灰）；SLS 日志库需提前创建并授权。
- [ ] **校准数据集是否就绪？** → 压缩时若未指定 `calibration_dataset`，系统将回退至默认集，可能导致长文本生成质量下降，建议显式上传业务相关样本。

> **最后提醒**：所有方案均通过百炼统一控制台或标准 API 管理，底层 GPU 资源由平台全托管。开发者应聚焦业务逻辑与模型效果，将基础设施运维交由平台保障。
