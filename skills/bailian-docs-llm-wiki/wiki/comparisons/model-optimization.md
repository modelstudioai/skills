# 模型微调与模型压缩对比

模型微调（Fine-Tuning）和模型压缩（Model Compression）是百炼平台提供的两种模型优化手段，分别面向"提升模型能力"和"降低部署成本"两个不同目标。开发者在完成基础模型选型后，往往需要根据业务需求在二者之间做出选择或组合使用。本文从多个维度对比两种方案，帮助技术选型。

## 核心定位对比

| 维度 | 模型微调（Fine-Tuning） | 模型压缩（Model Compression） |
|------|------------------------|------------------------------|
| 核心目标 | 提升模型在特定任务/领域的表现 | 降低显存占用、缩小部署规格、降本增效 |
| 作用对象 | 基础模型（平台支持列表内） | 微调后产出的自定义全精度模型 |
| 技术原理 | 通过训练数据更新模型参数 | 通过量化算法将全精度转为低精度 |
| 产出物 | 自定义微调模型 | 量化后的低精度模型 |
| 对模型能力的影响 | 增强特定场景能力 | 能力基本保持，可能有轻微精度损失 |
| 对部署成本的影响 | 不变（与原模型同规格部署） | 显著降低（部署规格缩小） |

## 使用方式对比

| 维度 | 模型微调 | 模型压缩 |
|------|---------|---------|
| 控制台入口 | 模型训练 > 模型调优 | 模型训练 > 模型压缩 |
| API 支持 | DashScope API（/api/v1/fine-tunes） | OpenAPI |
| 操作流程 | 上传数据 → 创建任务 → 训练 → 发布 → 部署 | 选择源模型 → 选择量化模板 → 创建任务 → 部署 |
| 是否需要训练数据 | 是（JSONL/ZIP 格式，按调优方法不同要求不同） | 可选（校准数据，视量化模板要求） |
| 数据量要求 | CPT ≥ 1000万 Token；SFT ≥ 1000 条；DPO ≥ 100 组 | 校准数据无明确最小量要求 |
| 任务耗时 | 较长（取决于数据量和模型大小） | 相对较短 |

## 支持模型范围对比

| 维度 | 模型微调 | 模型压缩 |
|------|---------|---------|
| 支持的模型类型 | 文本生成、视觉理解、语音合成、视频生成、图像生成 | 仅文本生成（当前） |
| 代表性模型 | Qwen3/2.5 系列、CosyVoice、万相等 | qwen3.5-flash-2026-02-23 等（以控制台为准） |
| 输入要求 | 基础模型（平台支持列表内） | 必须是微调产出的自定义模型 |
| 是否支持迭代 | 支持多轮调优 | 不支持二次压缩或继续训练 |

## 计费方式对比

| 维度 | 模型微调 | 模型压缩 |
|------|---------|---------|
| 任务费用 | 按训练 Token 数 × 循环次数 × 单价计费 | 限时免费（以控制台公告为准） |
| 部署费用 | 按模型单元使用时长计费 | 按压缩后规格的模型单元计费（规格更小） |
| 成本示例 | Qwen3-8B: 0.006 元/千 Token | 如 MU1×2（108元/时）→ MU8×1（47元/时） |

## 流程依赖关系

模型微调和模型压缩并非互斥，而是可以串联使用：

1. 先通过**模型微调**提升模型在目标场景的表现
2. 再通过**模型压缩**对微调产出的模型进行量化，降低部署成本

即典型路径为：基础模型 → 微调 → 全精度自定义模型 → 压缩 → 量化模型 → 部署。

## 适用场景建议

**选择模型微调的场景：**

- 模型在目标任务上的表现不满足业务要求
- 需要模型学习特定领域知识或遵循特定指令风格
- 有充足的高质量标注数据
- 需要对视觉、语音、视频等多模态模型进行定制

**选择模型压缩的场景：**

- 微调模型效果已满足要求，但部署成本过高
- 希望在不显著损失精度的前提下降低推理资源消耗
- 需要提升推理吞吐量

**组合使用的场景：**

- 既需要提升模型能力，又需要控制部署成本
- 适合先调优到满意效果，再压缩以优化部署规格

## 限制与注意事项

| 维度 | 模型微调 | 模型压缩 |
|------|---------|---------|
| 不可逆性 | 可反复迭代调优 | 压缩后不可继续训练或二次压缩 |
| 前置条件 | 需准备符合格式的训练数据 | 需先有微调产出的自定义模型 |
| 任务管理 | 可随时创建新任务 | 仅排队中/运行中可取消 |
| 效果评估 | 平台提供评测功能，不额外收费 | 需部署后实际验证推理效果 |
