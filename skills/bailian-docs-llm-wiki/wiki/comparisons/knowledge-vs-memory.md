# 知识库与记忆库对比

百炼平台同时提供**知识库**和**记忆库**两种数据增强方案，分别面向不同的信息管理需求。知识库基于 RAG 技术为大模型补充结构化与非结构化的领域知识，而记忆库则专注于从对话中自动提取并持久化用户级长期记忆。两者在数据来源、存储粒度、检索方式和典型场景上差异显著，开发者在技术选型时需根据业务特征做出选择。

## 关键维度对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **核心定位** | 基于 RAG 为大模型补充私有领域知识 | 为智能体提供跨会话的长期记忆能力 |
| **数据来源** | 主动上传文件（PDF、Word、Markdown、图片、Excel、音视频等） | 自动从对话中提取，或通过 API 写入自定义内容 |
| **数据类型** | 非结构化文档、结构化表格、图片、音视频 | 记忆片段（事件/信息）、用户画像（结构化属性） |
| **存储粒度** | 文档级，自动切分为切片（单切片上限 6000 Token） | 记忆条目级，按 user_id 隔离 |
| **索引方式** | 向量化（text-embedding-v4 等）+ 可选 Rerank 排序 | 语义检索（内置向量化，排序模型 gte-rerank-v2） |
| **检索方式** | 语义相似度召回切片，送入大模型生成答案 | 按 user_id + 语义匹配召回记忆，注入 Prompt |
| **知识库类型** | 文档搜索、数据查询（NL2SQL）、图片问答、音视频搜索 | 统一类型，区分记忆片段规则与用户画像规则 |
| **支持模型** | 与应用所选模型协同（千问系列、DeepSeek、Llama 等） | 不绑定特定推理模型，通过 API 独立调用 |
| **集成方式** | 智能体应用挂载、工作流节点、SDK/API 调用 | API 直接调用、插件集成（如 OpenClaw 生命周期钩子） |
| **API 端点** | 百炼 SDK（ApplyFileUploadLease → AddFile → SubmitIndexJob → Retrieve） | REST API（AddMemory、SearchMemory、ListMemory 等） |
| **更新机制** | 文档类支持 OSS + FC 自动更新；数据类支持 RDS 自动同步 | 每轮对话后自动提取，支持自动更新与去重 |
| **配置复杂度** | 高（向量模型、切片方式、排序模型、Meta 抽取等，创建后多数不可改） | 低（记忆规则、过期时间、画像模板即可） |
| **计费方式** | 向量存储 + Rerank 调用 + 模型推理，标准版/旗舰版分档计费 | 目前限时免费 |
| **检索延迟** | 取决于切片数量与排序模型配置 | SearchMemory 200–500ms，AddMemory 500–1000ms |
| **速率限制** | 取决于应用和模型配额 | AddMemory 120 次/分钟，SearchMemory 300 次/分钟，合计 3000 次/分钟 |

## 适用场景

### 适合使用知识库的场景

- **领域知识问答**：企业内部文档、产品手册、技术文档等需要精准检索和回答的场景。
- **多模态数据检索**：需要对图片、音视频、结构化表格进行语义检索的场景。
- **数据查询（NL2SQL）**：用户通过自然语言查询结构化数据（Excel、RDS 表）。
- **合规与审计**：需要基于权威文档提供可溯源答案的场景。

### 适合使用记忆库的场景

- **个性化助手**：需要记住用户偏好、习惯和历史交互的长期陪伴类应用。
- **跨会话上下文延续**：客服、健康管理等需要在多次会话间保持连续性的场景。
- **用户画像积累**：需要从多轮对话中逐步提取用户属性（年龄、职业、兴趣等）的场景。
- **多应用共享记忆**：多个智能体需要访问同一份用户记忆数据的场景。

### 两者结合使用

在复杂的智能体应用中，知识库和记忆库可以协同工作：知识库提供领域专业知识的检索能力，记忆库提供用户个性化的上下文。例如，一个健康咨询助手可以用知识库检索医学文档，同时用记忆库记住用户的健康状况和用药历史，实现既专业又个性化的服务。

## 技术选型建议

| 决策因素 | 选知识库 | 选记忆库 |
|----------|----------|----------|
| 数据是否需要预先准备 | 是，需主动上传和索引 | 否，从对话自动提取 |
| 数据是否与特定用户关联 | 通常不关联，面向全局 | 强关联，按 user_id 隔离 |
| 是否需要精细的检索调优 | 是（切片方式、排序模型、阈值等） | 通常不需要，开箱即用 |
| 信息时效性 | 取决于文档更新频率 | 实时（每轮对话后即可写入） |
| 初始接入成本 | 较高（文档准备、参数调优、效果评测） | 较低（调用 API 即可开始积累记忆） |
