# 知识库与记忆库对比

百炼平台同时提供**知识库**和**记忆库**两种数据增强方案，分别解决不同维度的信息补充需求。知识库基于 RAG 技术为大模型注入结构化/非结构化的领域知识，侧重"通用知识检索"；记忆库则专注于从对话中自动提取并持久化用户级信息，侧重"个性化长期记忆"。本文从技术架构、数据模型、API 设计、适用场景等维度进行系统对比，帮助开发者根据业务需求选择合适的方案或组合使用。

## 核心维度对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **定位** | 为大模型补充私有领域知识与最新信息 | 为智能体提供跨会话的用户级长期记忆 |
| **底层技术** | RAG（[检索增强生成](../concepts/rag.md)）：文档解析 → 切分 → 向量化 → 向量库检索 | 对话记忆自动提取 + 语义检索 |
| **数据来源** | PDF、Word、Markdown、图片、Excel、RDS、音视频等外部文件/数据源 | 用户与智能体的对话内容，或通过 `custom_content` 直接写入 |
| **数据粒度** | 文档切片（单切片上限 6000 Token） | 记忆片段（自动提取的关键事件/信息）和用户画像（结构化属性） |
| **存储模型** | 向量库（内置免费 / ADB-PG 自购） | 平台托管存储，账号级别资源 |
| **向量模型** | `text-embedding-v4`（推荐）/ `text-embedding-v3`（512 维）；图片场景用 `multimodal-embedding-v1`（1024 维）；视觉理解用 `qwen3-vl-embedding` | 平台内置，用户无需选择 |
| **排序/重排** | 支持 Rerank 模型（推荐 `qwen3-rerank(hybrid)`），可选问答/相似/自定义模式 | 支持 `enable_rerank` 开关（内置 `gte-rerank-v2`） |
| **知识库类型** | 文档搜索、数据查询（NL2SQL）、图片问答、音视频搜索，创建后不可更改 | 单一类型，按记忆片段规则和用户画像规则区分 |
| **创建数量** | 多个知识库，可挂载到不同应用 | 每账号一个默认记忆库（不可删除），可创建额外记忆库 |

## API 与集成对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **API Base URL** | 百炼 SDK（阿里云 OpenAPI 风格） | `https://dashscope.aliyuncs.com/api/v2/apps/memory/` |
| **核心写入接口** | `ApplyFileUploadLease` → `AddFile` → `SubmitIndexJob` | `AddMemory`（POST `/add`） |
| **核心检索接口** | `Retrieve` | `SearchMemory`（POST `/memory_nodes/search`） |
| **接口总数** | 文件上传 + 索引 + 检索 + 管理等多步流程 | 11 个接口（记忆片段 5 个 + 画像模板 5 个 + 用户画像 1 个） |
| **SDK** | 百炼 SDK（Java、Python、Go 等） | `agentscope-runtime`（Python，≥ 1.1.5） |
| **认证方式** | 阿里云 AccessKey + WorkspaceID | DashScope API Key（Bearer Token） |
| **智能体集成** | 应用编辑页添加"文档知识库"，支持权重与阈值覆盖 | 通过 API 在对话前后分别调用 SearchMemory/AddMemory |
| **工作流集成** | 拖入"知识库"节点，支持固定/动态引入 | 无原生工作流节点，需通过代码节点调用 API |
| **第三方框架** | — | 支持插件集成（如 OpenClaw 长期记忆插件，autoCapture/autoRecall） |

## 性能与配额对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **检索延迟** | 取决于切片数量、Rerank 配置，通常秒级 | SearchMemory 200–500ms |
| **写入延迟** | 索引构建为[异步任务](../concepts/async-task.md)，分钟级到小时级 | AddMemory 500–1000ms |
| **召回参数** | 最大召回数量上限 20，相似度阈值可调 | `top_k` 范围 1–100（默认 10），`min_score` 范围 0–1（默认 0.3） |
| **速率限制** | 按百炼 SDK 标准限流 | AddMemory 120 次/分钟，SearchMemory 300 次/分钟，合计 3000 次/分钟 |
| **版本/规格** | 标准版与旗舰版，旗舰版可调 RCU（每日限变配 1 次） | 单一版本，限时免费 |
| **计费** | 向量模型 + Rerank + 存储（内置免费 / ADB-PG 自购）+ 大模型推理 | 目前限时免费 |

## 数据更新与维护对比

| 维度 | 知识库 | 记忆库 |
|------|--------|--------|
| **自动更新** | 文档搜索类支持 OSS + FC 自动更新；数据查询类支持 RDS/MySQL 自动同步 | 对话时自动提取，支持自动更新开关 |
| **手动更新** | 修改文件需先删再传（不支持原地覆盖）；切片可单独编辑/新增/删除 | 通过 UpdateMemory 更新指定片段（`custom_content` 最大 512 字符） |
| **过期机制** | 无自动过期，需手动管理 | 可配置 7 天 / 30 天 / 180 天 / 永不过期 |
| **删除约束** | 需先解除与已发布应用的关联 | 通过 DeleteMemory 直接删除指定片段 |
| **规则配置** | 切片方式、排序模式、Meta 信息抽取等（创建后多数不可改） | 每库最多 50 条记忆片段规则 + 50 条用户画像规则 |

## 适用场景建议

**选择知识库的场景：**

- 需要让大模型回答基于企业内部文档（产品手册、技术文档、FAQ 等）的问题
- 数据以文件形式存在（PDF、Word、Excel、音视频等），需要结构化检索
- 需要 NL2SQL 能力，用自然语言查询数据库
- 对召回精度有较高要求，需要精细调优向量模型、Rerank 策略和切片方式
- 知识面向所有用户共享，无需区分个体差异

**选择记忆库的场景：**

- 需要智能体记住每位用户的个人偏好、历史行为和特定需求
- 应用场景强调个性化交互（如私人助理、健康管理、教育辅导等）
- 需要跨会话保持上下文连贯性，避免用户重复提供信息
- 需要构建用户画像，按模板持久化存储结构化属性

**组合使用：**

在实际业务中，知识库与记忆库可以互补使用。例如，一个客服智能体可以通过知识库检索产品文档来回答通用问题，同时通过记忆库记住每位客户的历史工单、偏好设置和沟通风格，从而提供既专业又个性化的服务。开发者只需在对话流程中先调用 SearchMemory 获取用户记忆，再将记忆与知识库召回结果一并注入 Prompt 即可。
