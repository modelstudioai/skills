# 模型监控与应用监控对比

阿里云百炼平台提供两套独立的监控体系：**模型监控**面向模型调用层，追踪 Token 消耗、调用性能和费用；**应用监控（应用观测）**面向应用编排层，追踪应用内部调用链路和节点级行为。两者关注的粒度和目标不同，开发者需要根据运维场景选择合适的监控手段，或将二者配合使用以实现端到端可观测性。

## 核心维度对比

| 维度 | 模型监控 | 应用监控（应用观测） |
|------|---------|-------------------|
| **监控对象** | 单个模型的调用行为（API 级别） | 应用的完整调用链路（含多节点编排） |
| **支持的目标类型** | 模型列表中的所有模型及调优后的自定义模型 | 智能体应用、工作流应用、高代码应用 |
| **核心指标** | Token 消耗、调用时长、首 Token 延时、RPM、TPM、失败率、限流错误 | 调用次数、失败率、Token 总量（输入/输出）、平均首 Token 耗时、平均调用时长 |
| **链路追踪** | 不支持（仅单模型粒度） | 支持完整调用链路（CHAIN → AGENT → LLM → RETRIEVER 等多层 Span） |
| **日志能力** | 推理日志（需开通，仅限部分模型和北京/新加坡地域） | 自动追踪所有 Prompt 输入及响应，支持按 Request ID / Trace ID / Span ID 检索 |
| **告警机制** | 费用告警 + 模型指标告警（需开启高级监控），支持短信、邮件、电话、钉钉、企业微信、Webhook | 无内置告警（依赖外部可观测链路服务） |
| **数据导出** | 通过 Prometheus HTTP API 接入 Grafana 等外部系统 | 支持导出 JSONL 或 EXCEL 格式的 Trace 数据 |
| **数据标注** | 不支持 | 支持对 Span 添加自定义标签（布尔值、分类、数字、文本） |
| **评测集集成** | 不支持 | 支持将 Span 数据批量添加到评测集 |
| **计费** | 高级监控使用私有 Prometheus 实例，需支付对应存储费用 | 功能本身免费，数据存储依赖可观测链路 OpenTelemetry 服务的存储费用 |
| **地域限制** | 高级监控限北京、新加坡、弗吉尼亚；告警限北京、新加坡；日志限北京、新加坡 | 需开通可观测链路 OpenTelemetry 服务（无特定地域限制说明） |
| **API 支持** | 高级监控开启后支持标准 Prometheus HTTP API | 暂无 API |
| **底层技术栈** | 私有 Prometheus 实例 | 可观测链路 OpenTelemetry 服务 |

## 功能侧重对比

| 能力 | 模型监控 | 应用监控 |
|------|---------|---------|
| Token 用量统计 | 按[业务空间](../concepts/workspace.md)维度汇总，支持按模型类型和推理类型筛选 | 按应用维度统计，区分输入/输出 Token |
| 免费额度管理 | 支持"用完即停"开关，防止超额消费 | 不涉及 |
| 内容安全监控 | 提供内容安全错误次数指标 | 通过 GUARDRAIL 节点观测内容安全检测过程 |
| 成本优化参考 | 提供平均单次请求调用量、费用告警 | 提供平均单次请求 Token 量，可辅助分析 |
| 模型思考过程查看 | 不支持 | 支持查看模型响应的思考过程 |
| 检索过程观测 | 不涉及 | 支持观测 RETRIEVER / EMBEDDING / RERANKER 节点 |

## 适用场景建议

**优先使用模型监控的场景：**

- 需要追踪特定模型的 Token 消耗趋势和费用，进行成本管控
- 需要对模型调用性能（首 Token 延时、RPM、TPM）设置阈值告警
- 需要管理免费额度、防止超额消费
- 需要将监控数据接入 Grafana 等外部可视化系统做长期运维
- 直接通过 API 调用模型，不经过百炼应用层

**优先使用应用监控的场景：**

- 需要排查智能体或工作流应用中某个环节的异常（如检索质量差、插件调用失败）
- 需要查看完整调用链路，定位端到端延时瓶颈
- 需要将线上真实数据标注后导入评测集，构建持续优化闭环
- 需要审计应用级别的输入输出内容
- 使用高代码应用并需要观测自定义上报的 Tracing 信息

**配合使用的场景：**

- 生产环境中同时运行多个应用和模型，需要从应用链路层和模型调用层两个维度交叉分析问题
- 应用监控定位到某个 LLM Span 异常后，切换到模型监控查看该模型的全局指标趋势和告警历史
- 通过模型监控发现某模型失败率上升，再通过应用监控定位受影响的具体应用和调用链路
