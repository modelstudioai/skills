# 模型监控与模型数据概览对比

本文旨在帮助开发者清晰区分百炼平台中 **模型监控（Model Monitoring）** 与 **模型数据概览（Model Data Overview）** 两大核心能力模块。二者名称相近、入口偶有交叠（如日志回流功能同时涉及两者），但设计目标、技术定位与适用阶段存在本质差异：  
- **模型监控** 是面向 *生产环境模型服务* 的可观测性系统，聚焦调用链路的实时性、稳定性与成本归因；  
- **模型数据概览** 是面向 *模型研发与迭代闭环* 的数据基础设施，支撑训练、评测、数据治理等离线/半在线场景。  

正确理解二者边界，可避免误用（如用监控数据替代训练集做微调）、规避权限或地域限制导致的配置失败，并为技术选型提供明确依据。

## 关键维度对比

| 维度 | 模型监控（Model Monitoring） | 模型数据概览（Model Data Overview） |
|------|-----------------------------|-------------------------------------|
| **核心目标** | 保障线上模型服务的可用性、性能与成本可视性；支持故障定位与运维响应 | 构建高质量、可版本化、可复用的训练/评测数据资产，支撑模型持续优化与效果评估 |
| **输入格式** | 原始 API 调用请求与响应（自动采集）；审计日志含 Request ID、状态码、[Token](../concepts/token.md) 数等；推理日志含完整 Prompt/Response（需手动开启） | 用户主动导入的结构化数据文件：`JSONL`（必选 ChatML 格式用于处理）、`Excel`；或通过日志回流从 SLS 自动提取的 JSONL 日志流 |
| **输出格式** | - 用量统计：聚合报表（按模型 Code/API-Key/时间维度的 [Token](../concepts/token.md)/张/秒等计费单位）<br>- 实时监控：时序图表（调用次数、失败率、首 [Token](../concepts/token.md) 延时等 15+ 指标）<br>- 告警：云监控通知（短信/邮件/钉钉/Webhook）<br>- 日志：结构化审计日志（SLS）、原始推理日志（OSS/SLS） | - 数据集元信息（名称、类型、场景、版本号、创建时间）<br>- 结构化数据内容（JSONL 行式记录）<br>- 处理后数据集（新版本 JSONL 文件）<br>- 下游调用凭证（`training_file_ids` 字符串列表） |
| **支持模型** | - **用量统计**：所有公开模型（LLM/视觉/语音/向量/全模态）<br>- **实时监控 & 告警**：仅限控制台「模型监控」页可选模型（排除语音/图片/视频生成、三方直连等部分模型）<br>- **日志**：审计日志全模型支持；推理日志需手动开启，且仅北京/新加坡地域可用 | 不直接关联具体模型实例，而是关联**模型能力类型与训练方法**：<br>- 训练集：支持 `文本生成` / `视觉理解` / `图生视频（首帧/首尾帧）` 场景，对应 SFT/DPO/CPT 方法<br>- 评测集：仅支持 `文本生成` 场景<br>- **不绑定模型 Code**，但下游调优任务需指定兼容模型 |
| **API 端点** | - 用量查询：`GET /api/v1/usage/statistics`（需 `bailian:Usage:GetStatistics` 权限）<br>- 监控指标：`GET /api/v1/telemetry/metrics`（需 `bailian:Telemetry:GetMetrics`）<br>- 告警管理：对接阿里云云监控 OpenAPI（`alibabacloud-cloudmonitor20190101`） | - 数据集管理：`POST /api/v1/datasets`（创建）、`GET /api/v1/datasets/{id}/versions`（获取版本）<br>- 日志回流：`POST /api/v1/log-backflow/jobs`（启动回流任务）<br>- 数据处理：`POST /api/v1/dataflows/{id}/tasks`（触发清洗/增强） |
| **计费方式** | **完全免费**（不含底层依赖服务费用）：<br>- 监控指标采集、告警规则、审计日志投递均不产生额外费用<br>- **注意**：监控中的 `TotalToken` 等指标**不作为计费依据**，对账请以费用中心账单为准 | **功能本身免费**，但关联资源独立计费：<br>- 平台 OSS 存储：按存储量 + 请求次数计费<br>- 云存储挂载（OSS Bucket）：按 OSS 标准计费<br>- SLS 日志服务：按日志写入量 + 查询分析量计费<br>- 推理日志投递若启用，计入 SLS 写入费用 |
| **典型场景** | - 运维值班：发现某模型失败率突增至 15%，结合 429 错误数判断是否遭遇限流<br>- 成本分析：按 API-Key 统计过去 7 天 `qwen-max` 的总 Token 消耗，识别高用量调用方<br>- 故障排查：通过 Request ID 定位某次超时请求的完整 Prompt 与 Response（需已开启推理日志） | - 数据准备：将线上用户问答日志（SLS）回流生成 SFT 训练集，用于模型微调<br>- 质量提升：对已有 ChatML 格式训练集执行敏感信息打码 + Few-Shot 增强<br>- 效果验证：构建标准评测集，批量测试多个模型在相同 prompt 下的回复质量一致性 |
| **数据延迟** | - 用量统计：约 **1 小时** 延迟<br>- 实时监控：**分钟级**（通常 < 2 分钟）<br>- 告警触发：取决于「告警检查周期」参数（最小 60 秒） | - 日志回流：SLS 日志写入后 **5–10 分钟** 可见于数据集<br>- 数据处理任务：取决于数据量，通常 **数分钟至数十分钟**<br>- 数据集发布：即时生效（元信息更新） |
| **数据保留周期** | - 用量数据：**30 天**（超期需导出费用中心账单）<br>- 监控指标：默认保留 **30 天**（云监控策略）<br>- 审计日志：SLS 默认保留 **30 天**（可配置）<br>- 推理日志：OSS/SLS 中按用户配置保留 | - 数据集版本：**永久保留**（除非手动删除）<br>- 日志回流原始日志：依赖 SLS Logstore 保留策略（默认 30 天）<br>- 处理任务历史：**永久保留**（任务元信息） |

## 各方案的适用场景建议

### ✅ 选择 **模型监控** 当您需要：
- **保障线上服务 SLA**：实时跟踪关键模型的 P95 首 Token 延时、错误率、RPM，设置阈值告警；
- **精细化成本治理**：按业务线/API-Key/模型 Code 拆分用量，识别异常调用或配额瓶颈；
- **快速根因分析**：通过 Request ID 关联审计日志与推理日志，还原失败请求上下文；
- **合规审计**：留存调用行为记录（时间、身份、结果），满足安全审计要求。

> ⚠️ 注意：若您关注的是“模型为什么效果变差”，模型监控无法回答——它不提供模型输出质量、语义合理性等评估维度。

### ✅ 选择 **模型数据概览** 当您需要：
- **构建训练闭环**：将线上真实用户反馈（SLS 日志）沉淀为高质量 SFT/DPO 训练数据；
- **提升数据质量**：对原始数据集执行标准化清洗（去重、脱敏）、结构化增强（Few-Shot 注入）；
- **统一评测基准**：创建跨模型、跨版本可复现的文本生成评测集，量化效果演进；
- **管理数据资产**：为不同项目、不同模型版本建立带版本号、描述、标签的数据集仓库。

> ⚠️ 注意：若您尚未开启审计日志投递，则无法使用日志回流功能——这是模型数据概览与模型监控的关键协同点。

## 面向开发者的选型参考

| 您的问题 | 推荐方案 | 关键依据 |
|----------|-----------|-----------|
| “我的 `qwen-plus` 模型最近 1 小时失败率飙升，是网络问题还是模型异常？” | **模型监控** | 实时失败率图表 + 429 错误数趋势 + 对应 Request ID 的审计日志可立即定位 |
| “如何把过去一周用户提问和助手回答的日志，变成可用于微调的新训练集？” | **模型数据概览**（配合日志回流） | 日志回流功能专为此设计，自动生成符合 ChatML 格式的 JSONL 数据集 |
| “我们有 5 个业务方共用一个 API Key，想分别统计他们各自消耗了多少 Token？” | **模型监控** | 用量统计支持按 API-Key 维度聚合，精度可达分钟级 |
| “新上线的视觉理解模型在测试集上准确率达标，但线上用户反馈图片识别经常错，怎么改进？” | **模型数据概览** | 通过日志回流收集线上真实 case，清洗后构建针对性评测集或补充训练集 |
| “能否对已发布的训练集进行编辑（比如修改某条样本）？” | ❌ 两者均不支持 | 模型监控无数据编辑能力；模型数据概览中**已发布数据集不可编辑**，需创建新版本 |
| “我需要在新加坡地域对语音模型做实时性能监控” | **模型监控**（仅用量统计 & 基础监控） | 新加坡支持模型监控（含用量与指标），但语音模型**不支持告警**；推理日志也支持新加坡 |
| “能否用模型监控里的 Token 数直接作为训练数据量统计？” | ❌ 不可替代 | 监控 Token 数是调用侧计量，非训练数据格式/质量/分布的反映；训练数据量需通过模型数据概览中数据集的行数/Token 数（需自行解析）评估 |

> 💡 **最佳实践提示**：  
> - **监控与数据联动**：开启审计日志是启用日志回流的前提，二者是“可观测性 → 数据资产化”的天然流水线；  
> - **权限前置检查**：配置告警前务必完成云监控服务角色授权；使用日志回流前需完成 SLS + OSS（如挂载）多角色授权；  
> - **地域约束优先确认**：DPO/CPT 训练、数据处理仅限北京；日志回流扩展至新加坡，但处理能力仍限北京——新加坡用户需将回流数据同步至北京再处理；  
> - **计费隔离原则**：监控不计费，数据功能不计费，但其依赖的 OSS/SLS/云监控服务均独立计费，请在控制台预估成本。
