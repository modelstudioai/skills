# 实时 API、沙箱 API 与托管智能体 API 对比

本对比旨在帮助开发者在百炼平台中快速识别三类核心 API 的定位差异、能力边界与适用阶段，避免因技术选型偏差导致开发返工、架构冗余或体验降级。随着百炼平台能力分层日益清晰——从**毫秒级多模态交互**（实时 API）、到**隔离式代码/浏览器执行环境**（沙箱 API）、再到**具备记忆与规划能力的长期运行智能体**（托管智能体 API）——明确三者的技术坐标，是构建高可用 AI 应用的前提。

以下表格从 7 个关键维度进行横向对比，所有信息均基于当前（2024 年 Q3）正式发布版本的接口规范与行为事实，已排除文档陈旧描述与未上线特性。

| 维度 | 实时 API（Omni Realtime） | 沙箱 API（Sandbox） | 托管智能体 API（Managed Agents） |
|------|---------------------------|----------------------|-----------------------------------|
| **核心定位** | 低延迟、双向流式多模态人机交互管道 | 隔离、可控、可复现的运行时环境托管服务 | 具备[长期记忆](../concepts/memory.md)、工具调用与多步推理能力的 AI Agent 全生命周期管理 |
| **输入格式** | 多模态流式输入：PCM/WAV 音频帧（支持双/四通道）、视频帧（仅 Qwen3.8-Omni-Flash-Realtime）、文本；支持 `input_audio_buffer.append` / `.commit` 等事件驱动方式 | 结构化 JSON 请求体（如 `POST /sandboxes`），含 `templateID`、资源规格、网络策略等；**不接收用户原始数据流** | 结构化 JSON 输入：`{ "text": "..." }` 或 `{ "files": [...] }`（需预上传）；**不支持音频/视频原始流输入** |
| **输出格式** | 双向事件流（WebSocket/WebRTC/AOQ）：`response.text.delta`（文本流）、`response.audio.delta`（音频流）、`conversation.item.created`（含工具调用结果）、`speech_started/stopped`（VAD 事件） | RESTful JSON 响应：返回沙箱实例 ID、连接域名（`domain`）、访问令牌（`envdAccessToken`）、状态（`running`/`paused`）等元数据；**无模型推理结果输出** | RESTful JSON 或 SSE 流式响应：含 `output.text`、`steps` 执行轨迹、`tool_calls`、`memory_references`；支持 Webhook 异步事件回调（如 `agent.step_completed`） |
| **支持模型** | 专属实时系列模型：<br>• `qwen3.8-omni-flash-realtime`（最强，支持空间音频、视频、MCP）<br>• `qwen3.5-omni-plus-realtime` / `qwen3.5-omni-flash-realtime`<br>• `qwen3-omni-flash-realtime` / `qwen-omni-turbo-realtime`（参数受限） | **不提供模型推理能力**；依赖沙箱内自行部署的模型（如通过 `code-interpreter-v1` 模板运行本地 Llama.cpp）或调用外部 API | 仅支持百炼托管模型：<br>• `qwen-max`（强推理）<br>• `qwen-plus`（均衡）<br>• `qwen-turbo`（高吞吐）<br>**不支持自定义模型或外部模型接入** |
| **API 端点协议** | WebSocket（主推）、WebRTC、AOQ（均为长连接、事件驱动） | RESTful HTTP/HTTPS（兼容 E2B 协议语义，但非完全兼容） | RESTful HTTP/HTTPS + 可选 SSE（`stream=true`）+ Webhook（事件通知） |
| **计费方式** | 按**实际消耗 [Token](../concepts/token.md) 数 + 音频处理时长（秒）** 计费：<br>• 输入音频按声道数加权折算 [Token](../concepts/token.md)<br>• 输出音频按采样率与时长计费<br>• 支持用量配额与用量告警 | 按**沙箱实例运行时长（秒） + 资源规格（CPU/内存）** 计费：<br>• 实例创建即开始计费，暂停期间仍计费（除非配置 `autoPause`）<br>• 模版构建过程不计费 | 按**Agent 执行次数 + 消耗 [Token](../concepts/token.md) 数 + Memory Store 调用量** 计费：<br>• 单次 `chat` 调用为一次执行（无论内部多少 step）<br>• Memory Store 向量检索、写入单独计费 |
| **典型场景** | • 实时语音客服（端到端 <800ms 延迟）<br>• 多语种会议实时转录与翻译<br>• 空间音频交互助手（如 AR 场景语音导航）<br>• 视频内容实时理解与语音反馈（Qwen3.8） | • 安全沙箱中的代码解释与执行（如用户上传 Python 脚本自动分析）<br>• 浏览器自动化测试（如爬取动态渲染页面）<br>• 敏感数据脱敏处理（在隔离环境中解析并清洗）<br>• 模型微调后验证（在定制镜像中运行评估脚本） | • 客户服务智能体（记住历史对话、调用 CRM 工具查订单）<br>• 企业知识助理（结合 Memory Store 检索内部文档，多步推理生成报告）<br>• 自动化工作流 Agent（如“审批报销单 → 查询余额 → 发起打款 → 同步邮件”） |

## 各方案适用场景建议

### ✅ 选择 **实时 API** 当：
- 你的应用对**端到端延迟极度敏感**（要求 <1s），且涉及**语音、视频等实时流媒体输入/输出**；
- 需要原生支持 VAD（语音活动检测）、空间音频合成、多通道音频处理；
- 交互模式是**短时、高频、事件驱动**（如用户说一句、模型立刻回应一句）；
- 不需要长期上下文记忆或跨会话状态保持（Session 生命周期由客户端控制）。

> ⚠️ 注意：若业务只需文本问答，无需语音/视频能力，请勿选用实时 API——成本显著高于其他方案。

### ✅ 选择 **沙箱 API** 当：
- 你需要**安全、隔离、可销毁的运行环境**来执行不可信代码、浏览器操作或数据处理；
- 任务本质是**一次性、有明确输入输出的计算任务**（如“运行这段 SQL 查数据库”、“打开这个网页截图”）；
- 你已有成熟脚本/工具链，只需一个“容器化执行引擎”，而非 AI 推理能力；
- 对环境一致性、网络策略、资源配额有强管控需求（如金融合规场景）。

> ⚠️ 注意：沙箱本身**不提供大模型能力**；若需在沙箱中调用大模型，必须自行集成（如通过 SDK 调用百炼其他 API）。

### ✅ 选择 **托管智能体 API** 当：
- 你的应用需要**多轮、有状态、带记忆的智能交互**（如客服 Agent 记住用户上月投诉记录）；
- 业务逻辑涉及**多步骤自主规划与工具协同**（如“先查天气 → 再订车 → 最后发提醒”）；
- 你希望**免运维地使用 Memory Store 进行向量检索**，或通过 Vault 安全管理 API Key/数据库密码；
- 开发目标是构建**可复用、可编排、可监控的 AI Agent 服务**，而非单点功能。

> ⚠️ 注意：托管智能体**不支持实时音视频流**；若需语音交互，需前端将语音转文本后调用此 API，再将文本结果合成为语音（即“实时 API + 托管智能体 API”组合架构）。

## 技术选型参考（面向开发者）

| 你的问题 | 推荐方案 | 理由简述 |
|----------|-----------|-----------|
| “如何让 App 用户对着手机说话，立刻听到自然语音回答？” | ✅ 实时 API | 唯一支持端到端语音流式输入/输出与低延迟合成的方案 |
| “用户上传一份 Excel，我要在服务器上安全运行 Python 脚本分析它，并返回图表” | ✅ 沙箱 API | 提供隔离环境、文件挂载、资源限制，天然适配此类计算任务 |
| “我们想做一个销售助手，能查 CRM、读合同 PDF、生成报价单，并记住客户偏好” | ✅ 托管智能体 API | 内置 Memory Store（PDF 向量化）、Skill 工具链（CRM 插件）、长期 Session 状态管理 |
| “我需要一个能调用多个 API、做决策、重试失败步骤的自动化机器人” | ✅ 托管智能体 API | `max_steps` 控制推理深度，Webhook 支持失败重试编排，Skills 支持任意 HTTP 工具注册 |
| “我想在浏览器里跑一个 Llama.cpp 模型做本地推理，但不想暴露用户设备” | ✅ 沙箱 API + 自定义模板 | 构建含 Llama.cpp 的镜像，在沙箱中加载 GGUF 模型，通过 API 调用 |
| “我们的客服系统已有 TTS/ASR，只需一个‘大脑’做语义理解与业务决策” | ✅ 托管智能体 API（或实时 API 的 `text-only` 模式） | 若已有音视频链路，托管智能体更专注决策；若需统一音视频栈，选实时 API 并禁用音频输出 |
| “如何低成本验证一个新模型在真实用户请求下的表现？” | ⚠️ 组合方案：实时 API（前端接入） + 托管智能体（A/B 测试路由） | 利用实时 API 获取真实语音流，经 ASR 后路由至不同 Agent 进行效果对比 |

> 💡 **最佳实践提示**：  
> - **不要试图用单一 API 解决所有问题**。生产级 AI 应用常采用分层架构：  
>   `前端（实时 API）→ 中台（托管智能体）→ 后端（沙箱执行高危操作）`  
> - 所有 API 均支持细粒度权限控制（RAM Policy），请按最小权限原则分配 `AliyunBaiLianFullAccess` 或自定义策略。  
> - 建议优先使用官方 SDK（Python/Java），它们已封装重连、鉴权、事件解析、错误退避等通用逻辑，显著降低集成复杂度。
