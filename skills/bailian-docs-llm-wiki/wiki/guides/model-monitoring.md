# model monitoring

百炼平台的 model monitoring 是面向生产环境的模型可观测性能力，提供分钟级延迟的调用统计、性能指标、审计日志及告警配置，帮助开发者实时掌握模型健康度、排查异常并控制成本。监控数据按业务空间隔离，不作为计费依据；用量与费用核对请以[模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)和账单为准。核心能力覆盖调用规模、失败分析、延迟诊断、安全拦截与限流追踪等场景。

## 支持的模型/功能

- **支持范围**：全部百炼平台内置模型（含文本生成、深度思考、视觉理解、图像/视频生成、语音合成与识别、全模态、向量模型等）均支持基础监控指标（如调用次数、失败率、调用时长、首 Token 延时）；但语音、图片、视频生成及三方直连等部分模型**不支持全部指标或告警配置**，具体以控制台实际可选为准（详见[监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)文档说明）。
- **核心功能模块**：
  - **监控概览与详情**：按业务空间聚合展示整体调用规模、健康度卡片及单模型多维图表；
  - **审计日志**：默认开启，记录 Request ID、时间、模型、Token 用量、状态码、延迟等元信息，**不包含 Prompt/Response**；
  - **推理日志**：需手动开启并完成日志投递配置，记录完整 Prompt/Response 与中间步骤（长度上限 128K），仅支持北京、新加坡地域；
  - **告警管理**：支持基于预置或自定义模板为关键指标配置规则，触发后通过邮件等渠道通知；
  - **数据投递**：可将监控指标投递至云监控 Prometheus 实例，或将审计/推理日志投递至 SLS 日志库（需授权并开通对应云服务）。

> **注意**：文档 1 中“失败次数、失败率、限流错误次数和内容安全拦截次数已移至[模型监控](../../raw/model-user-guide/model-monitoring/model-telemetry.md)页面”与文档 2 的实际功能划分一致；但文档 1 提到“批量离线推理和批量在线推理不展示调用次数”，而文档 2 的监控详情页明确支持按“推理类型”（含 Batch File / Batch Chat）筛选，且指标表中“调用次数”列为可配置告警项——此处存在表述矛盾。**实际以文档 2 为准：批量推理调用次数可被监控和告警，但模型用量页面（文档 1）因统计口径差异暂不展示其调用次数卡片**。

## 关键参数

以下指标在模型监控详情页图表中直接展示，其中带 ✅ 标记的指标支持告警配置（基于预置模板或自定义规则）：

| 指标名称 | 含义 | 是否支持告警 | 说明 |
|----------|------|----------------|------|
| 调用次数 | 模型被调用的总次数 | ✅ | 包含在线推理、Batch File、Batch Chat 等全部成功/失败请求 |
| 失败次数 | 调用失败次数（状态码非 200） | ✅ | 排查突增需结合失败率、限流错误次数综合分析 |
| 失败率 | 失败次数 / 总调用次数 | ✅ | 关键可用性指标，推荐配置阈值告警（如 >1%） |
| 调用时长 | 请求到响应的总耗时（ms） | ✅ | 反映端到端延迟，含网络、排队、模型推理全流程 |
| 首 Token 延时 | 请求发起到返回首个 Token 的耗时（ms） | ✅ | 衡量模型“启动”性能，对流式体验至关重要 |
| 限流错误次数 | HTTP 429 触发次数 | ✅ | 直接反映配额或吞吐瓶颈，需关联 RPM/TPM 分析 |
| 模型消耗 TotalToken 数 | 按模型维度统计的 Token 消耗总量 | ✅ | **控制 Token 成本的核心告警指标**，推荐配置环比突增告警 |
| 内容安全错误次数 | 内容安全拦截次数 | ❌ | 仅展示，不可配置告警（见[监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)说明） |
| 非首 Token 延时 | 首 Token 后每 Token 平均生成耗时 | ❌ | 用于评估模型持续输出效率，不支持告警 |

## 使用方式

1. **访问入口**：登录百炼控制台 → 左侧导航栏 **运维管理 > 模型监控**（[直达链接](https://bailian.console.aliyun.com/cn-beijing/model/telemetry)）；
2. **查看概览**：在概览页筛选时间范围、推理类型、API Key，快速查看业务空间整体调用次数、失败率、平均调用时长等卡片；
3. **深入单模型**：在模型列表点击目标模型的 **查看详情**，进入监控详情页，查看调用统计（调用次数、失败次数、Token 用量）与性能（首 Token 延时、调用时长）双组图表；
4. **配置告警**：
   - 在详情页图表中点击支持告警指标旁的 **蓝色/灰色告警铃铛**，快速打开规则配置侧边面板；
   - 或前往 [模型告警页面](https://bailian.console.aliyun.com/cn-beijing/model/alert) → **告警规则** 页签，点击 **创建告警规则**，选择预置模板（如“模型调用失败占比1分钟总和大于1%”）、指定模型、设置持续时间与通知对象；
   - **首次使用前必须完成云监控服务角色授权**（见[监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)中“告警规则管理”说明）；
5. **查看日志**：
   - 审计日志：概览页点击模型列表的 **查看日志**，默认开启，支持按 Request ID、状态码（200/4XX/5XX）、时间范围（最长30天）筛选；
   - 推理日志：需先在日志页面完成 **日志投递配置**（授权 SLS 角色 + 创建日志库），再开启推理日志开关；开启后可在同一日志页面查看含 Prompt/Response 的完整记录；
6. **数据投递**：
   - 监控数据投递：在监控概览页左上方点击 **模型监控投递**，完成云监控角色授权、开通 Prometheus 实例；
   - 日志投递：在日志页面右上角点击 **日志投递配置**，完成 SLS 角色授权、开通日志服务、创建日志库。

## 限制和注意事项

- **数据时效性**：监控数据延迟约 **1–2 分钟**，不作为计费依据；用量与费用核对请参考[模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)及账单中心；
- **地域限制**：推理日志仅支持 **北京、新加坡** 地域，其他地域开启后显示“不支持”；
- **权限与依赖**：
  - 告警规则创建前**必须授权云监控服务角色**，否则按钮置灰（见[监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)）；
  - 推理日志开启前**必须先开启审计日志投递**；关闭审计日志投递将**自动关闭推理日志投递**；
- **投递风险**：
  - 关闭监控/日志投递后，**关闭期间产生的数据不会补录**，SLS 中不可恢复；
  - SLS 侧**禁止删除百炼创建的日志库**或**修改索引配置**，否则导致投递失败；
- **模型兼容性**：语音、图片、视频生成及三方直连模型的部分指标（如首 Token 延时、缓存命中率）可能不支持或数值为空，需以控制台实际展示为准；
- **用量统计差异**：模型用量页面（文档 1）与监控页面（文档 2）统计目的不同——前者用于**费用核对**（如 Token 用量延迟约 10 分钟），后者用于**实时运维**（分钟级延迟），二者数值在短期内可能存在微小差异，属正常设计。
