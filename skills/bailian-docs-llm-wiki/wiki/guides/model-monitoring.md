# model monitoring

阿里云百炼平台提供模型监控与用量管理功能，帮助开发者实时掌握模型调用状态、追踪 Token 消耗、监控性能指标并配置异常告警。通过模型监控和模型用量两个核心模块，开发者可以从成本、性能、安全和稳定性等维度全面管理生产环境中的模型服务。

## 功能概览

百炼平台的监控与用量管理分为两个互补模块：

- **模型用量**：按[业务空间](../concepts/workspace.md)维度统计各模型的调用量和费用，支持免费额度管理和费用告警。详见 [模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)。
- **模型监控**：提供调用记录查看、性能指标监控（Token 延时、调用时长、RPM、TPM、失败率）及主动告警能力。详见 [模型监控](../../raw/model-user-guide/model-monitoring/model-telemetry.md)。

## 支持的模型

- **用量统计**：模型列表中的所有模型均支持查看用量，包括基于它们调优后的自定义模型。
- **普通监控**：支持模型列表中的所有模型及其调优后的自定义模型。
- **高级监控**：支持北京、新加坡、弗吉尼亚地域下的所有模型。
- **告警功能**：支持北京、新加坡地域下的所有模型。
- **日志功能**：目前仅支持部分模型（如 qwen3-max、qwen-plus、deepseek-v3 系列等），且仅限北京和新加坡地域。

## 用量统计单位

不同类型模型的用量统计口径不同：

| 模型类型 | 统计单位 | 说明 |
|---------|---------|------|
| 大语言模型（文本生成、深度思考、视觉理解） | Token | 按输入/输出 Token 数计费 |
| 图像生成 | 张 | 按成功生成的图像张数计费 |
| 视频生成 | 秒 | 按成功生成的视频秒数计费 |
| 语音模型 | 秒/字符/Token | 视具体模型而定 |
| 全模态模型 | Token | 文本按 Token 数，其他模态按对应 Token 数计费 |
| 向量模型 | Token | 按输入文本的 Token 数计费 |

> **注意**：Token 与字符的换算关系为经验值——平均 1 个汉字约对应 1.5-2 个 Token，1 个英文单词约对应 1.3 个 Token。

## 查看模型用量

在控制台的模型用量页面，可按[业务空间](../concepts/workspace.md)维度查看各模型的用量数据：

1. 选择模型类型页签（如大语言模型），按需选择统计时间范围。
2. 在搜索框输入模型名称（如 `qwen-plus`）筛选对应数据。
3. 大语言模型页签支持按推理类型（实时推理或批量推理）筛选。

> **注意**：用量数据延迟约 1 小时，且不支持查看 30 天以前的统计数据。更早的用量信息需通过阿里云费用与成本页面查询。用量按[业务空间](../concepts/workspace.md)维度统计，不支持按阿里云账号维度直接统计。如需查看账号总用量，可在账单详情页面导出账单查看。

## 免费额度管理

在控制台的免费额度页面，可查看各模型的免费额度使用情况，并管理"免费额度用完即停"开关：

- **开启即停**：免费额度用尽时服务自动停止（返回 403 错误 `AllocationQuota.FreeTierOnly`），避免产生额外费用。
- **关闭即停**：免费额度用尽后继续使用模型服务，按实际用量付费。

> **注意**：只能在账户内仍有未消耗的免费额度时开启此功能；开启后需在免费额度完全消耗后才能关闭。

## 监控指标

模型监控提供四类核心指标，详见 [模型监控](../../raw/model-user-guide/model-monitoring/model-telemetry.md)：

- **安全**：识别对话中的违规内容，如内容安全错误次数。
- **成本**：评估模型成本效益，如平均单次请求调用量。
- **性能**：观察模型性能变化，如调用时长、首 Token 延时、RPM、TPM。
- **错误**：判断模型稳定性，如失败次数、失败率、限流错误次数。

### Token 消耗追踪

模型监控提供三个层次的成本管理能力：

- **汇总**：按[业务空间](../concepts/workspace.md)维度汇总模型的历史 Token 消耗，支持按时间范围和 API Key 筛选。
- **追踪**：记录每一次模型调用的 Token 消耗（需开通推理日志，仅限部分模型）。
- **告警**：设置 Token 消耗阈值，异常消耗时立即通知。

## 模型日志

> **注意**：该功能目前仅适用于华北2（北京）地域的部分模型。

开通推理日志后，可查看模型的每一次对话记录，包括输入、输出及耗时，适用于故障排查和内容审计。开通步骤：

1. 使用主账号登录，在模型监控页面点击"模型监控配置"。
2. 按指引依次开通审计日志和推理日志。
3. 开通后，在模型监控列表中点击目标模型的"日志"查看调用记录。

> **注意**：从调用发生到日志记录存在分钟级延迟。

## 告警配置

百炼提供两种告警机制：

- **费用告警**：在费用概览页面设置，当费用异常时通知。详见 [模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)。
- **模型指标告警**：需先开启高级监控，然后在模型告警页面创建告警规则，支持对调用统计和性能指标设置阈值告警。

告警通知方式包括短信、邮件、电话、钉钉群机器人、企业微信机器人及 Webhook。告警等级分为：

| 等级 | 通知渠道 |
|------|---------|
| 紧急（CRITICAL） | 电话、短信、邮件 |
| 错误（ERROR） | 短信、邮件 |
| 警告（WARNING） | 短信、邮件 |
| 普通（INFO） | 邮件 |

## 接入外部监控系统

开启高级监控后，监控指标数据存储在私有 Prometheus 实例中，支持标准 Prometheus HTTP API。可接入 Grafana 或自建应用进行可视化分析。

核心监控指标包括：

| 指标名称 | 描述 |
|---------|------|
| `model_call_count` | 模型调用次数 |
| `model_call_duration` | 模型调用时长均值 |
| `model_first_token_duration` | 首包时长均值 |
| `model_usage` | 模型用量总和 |

支持的过滤条件（LabelKey）包括 `user_id`、`apikey_id`、`workspace_id`、`model`、`protocol`、`status_code`、`error_code`、`usage_type` 等。

## 生产环境最佳实践

- **控制输出长度**：合理设置 `max_tokens` 参数和思考长度限制，控制单次生成的最大长度。
- **按任务选模型**：简单任务（分类、摘要）优先选择轻量级模型，降低成本。
- **监控与告警**：通过模型监控追踪用量趋势，配置异常告警及时发现问题。
- **优化 Prompt**：简洁清晰的 Prompt 既能提升输出质量，也能减少输入 Token 消耗。
- **使用批量推理**：非实时、大批量处理任务使用批量推理，通常更具成本优势。
