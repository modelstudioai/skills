# model monitoring

百炼平台提供面向模型调用全链路的可观测能力，包括分钟级延迟的监控指标、多维度告警配置、审计日志与可选的推理日志。该能力按业务空间隔离，数据默认存储于平台侧，支持投递至云监控（Prometheus）和日志服务（SLS）进行长期留存与自有系统集成。监控数据不作为计费依据，对账请以费用中心账单为准 [监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)。

## 支持的模型与功能

- **支持范围**：所有在模型列表中可见的模型（含调优后模型）均支持基础监控与用量统计；但语音、图片、视频生成及三方直连等部分模型**不支持监控与告警**，具体以控制台实际展示为准 [监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)。  
- **核心功能**：
  - **监控指标**：调用次数、失败次数、失败率、调用时长、首 Token 延时、限流错误次数（429）、模型消耗 TotalToken 数等（详见下表）；
  - **告警**：支持基于预置或自定义模板为指定指标配置阈值告警，覆盖失败率突增、Token 消耗异常、首包延时超标等典型场景；
  - **日志**：审计日志默认开启（含 Request ID、状态码、Token 用量、延迟等，不含 Prompt/Response）；推理日志需手动开启并依赖日志投递，记录完整 Prompt/Response（截断上限 128K）；
  - **用量统计**：按业务空间聚合，延迟约 1 小时，支持分钟/小时/天精度，可按模型、API-Key、推理类型（仅大语言模型支持批量/实时筛选）过滤 [模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)。

> **注意**：文档 2 中称“模型列表中的所有模型均支持查看用量”，而文档 1 明确指出“语音、图片、视频生成及三方直连等部分模型不支持监控与告警”。二者口径不同——用量统计（如 Token/张/秒）普遍可用，但**监控图表、告警配置、首 Token 延时等深度性能指标并非全部模型都支持**。实际使用请以控制台模型详情页的「查看详情」按钮是否可点击为准。

## 关键参数与指标

| 指标名称             | 含义                         | 是否支持告警 | 说明                                                                 |
|----------------------|------------------------------|--------------|----------------------------------------------------------------------|
| 调用次数             | 模型被调用总次数              | ✅            | 随业务波动，可用于容量规划                                           |
| 失败次数 / 失败率    | 调用失败次数及占比            | ✅            | 排查可用性问题的首要指标；失败率告警建议阈值 ≥1% [监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md) |
| 限流错误次数（429）  | 触发限流的请求次数            | ✅            | 直接反映配额瓶颈，需结合 API-Key 筛查定位                           |
| 调用时长             | 请求到响应总耗时              | ✅            | 端到端延迟，含网络与模型推理时间                                     |
| 首 Token 延时        | 请求发起至首个 Token 返回耗时 | ✅            | 衡量模型“冷启动”与首响体验的关键指标                                 |
| 模型消耗 TotalToken 数 | 按模型维度统计的 Token 总量   | ✅            | **推荐配置环比突增告警**，用于控制 Token 成本 [监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md) |
| 非首 Token 延时      | 首 Token 后每 Token 平均耗时  | ❌            | 不在预置告警模板中，无法配置告警                                     |
| RPM / TPM / TPS      | 每分钟请求数 / Token 数 / 输出速度 | ❌         | 仅用于观察，不支持告警                                               |
| 内容安全错误次数     | 内容安全拦截次数              | ❌            | 不展示告警铃铛，无法配置告警                                         |

## 使用方式

1. **访问入口**：登录百炼控制台 → 左侧导航栏 **运维管理 > 模型监控**（概览页）[监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)。  
2. **查看监控**：
   - 概览页：查看整体调用规模（总量、失败次数、平均调用时长等）；
   - 模型列表：点击目标模型的 **查看详情** 进入监控详情页（含图表与告警铃铛），或 **查看日志** 进入审计日志页签；
   - 筛选：支持按时间（快捷/自定义）、推理类型、API-Key（当前空间内已存在者）过滤。  
3. **配置告警**：
   - **快速配置**：在监控详情页图表中点击支持告警的指标旁的蓝色/红色铃铛图标，打开侧边面板设置规则；
   - **完整管理**：前往 **运维管理 > 模型告警** 页面，在「告警规则」页签创建/编辑规则，需**先完成云监控服务角色授权**（否则按钮禁用）[监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)；
   - **模板复用**：优先选用预置模板（如“模型调用失败占比1分钟总和大于1%”），亦可自建复合条件模板。  
4. **开启日志投递（可选）**：
   - **审计日志投递**：在日志页面右上角点击 **日志投递配置**，授权日志服务角色并创建 SLS 日志库；
   - **推理日志**：必须先开启审计日志投递，再在推理日志页签点击 **开始配置**；投递后日志写入 SLS，可用于调试与回流训练 [监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)。  
5. **用量查询**：进入 **费用与成本 > 模型用量** 页面，选择模型类型页签与时间范围，支持按模型名、API-Key 筛选；关键用量卡片（如 Token 总量）支持本周期/上周期对比 [模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)。

## 限制和注意事项

- **数据延迟与保留**：监控数据分钟级可见；审计日志最多查询 **30 天**；用量统计数据延迟约 **1 小时**，且不支持查询 **30 天以前** 的数据 [模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)。  
- **权限与隔离**：所有监控、日志、用量数据严格按**业务空间**隔离，不可跨空间查看。  
- **投递依赖与费用**：
  - 开启监控数据投递需授权云监控服务角色，将自动开通云监控、SLS 及 Prometheus 服务，**告警规则免费，但底层云产品按量计费**；
  - 开启推理日志投递会产生 SLS 存储与读写费用；**关闭投递后，关闭期间日志无法补录** [监控告警](../../raw/model-user-guide/model-monitoring/model-telemetry.md)。  
- **模型兼容性**：语音、图像、视频生成类模型可能缺失首 Token 延时、非首 Token 延时等指标，其监控详情页图表区域可能显示为空或仅含基础调用统计。  
- **免费额度联动**：用量监控与免费额度管理独立；若开启「免费额度用完即停」，服务将在额度耗尽时返回 `403 AllocationQuota.FreeTierOnly`，此时监控中失败率会骤升，需结合免费额度页面排查 [模型用量](../../raw/model-user-guide/model-monitoring/model-usage-statistics.md)。
