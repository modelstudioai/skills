# model compression

模型压缩是百炼平台提供的量化能力，用于将全精度微调模型转换为低精度版本，在可控精度损失前提下显著降低推理部署所需的 MU 规格与成本。该功能属于模型生产链路中的可选环节，必须在完成[模型调优](raw/model-user-guide/fine-tuning.md)后对产出的自定义微调模型执行，且压缩结果不可逆。详细背景和设计目标请参见 [模型压缩](../../raw/model-user-guide/model-compression/model-compression-introduction.md)。

## 支持的模型与功能

- **支持范围**：仅限通过百炼平台完成微调训练的**自定义模型**（即“微调产出模型”），不支持基础模型、第三方模型或未完成微调的中间状态模型。
- **地域限制**：当前仅华北2（北京）地域可用；新加坡等其他地域暂未开放，控制台中对应区域表格为空（参见 [模型压缩](../../raw/model-user-guide/model-compression/model-compression-introduction.md) 中“支持压缩的模型”章节）。
- **技术范畴**：当前仅支持**量化（Quantization）**，不包含结构剪枝、知识蒸馏等其他压缩技术。该限定在 [模型压缩](../../raw/model-user-guide/model-compression/model-compression-introduction.md) 的“功能概述”中明确说明。

> **注意**：原始文档中“支持压缩的模型”表格内新加坡区域全部为“-”，但未说明是否为临时空缺或长期不支持。建议以控制台实时展示为准，避免依赖静态表格判断地域可用性。

## 关键参数

创建压缩任务时需配置以下核心参数：

| 参数 | 是否必填 | 说明 |
|------|----------|------|
| **任务名称** | 是 | ≤50 字符，建议含模型简称、量化方式、版本号，便于追踪管理。 |
| **选择源模型** | 是 | 仅显示当前工作空间中状态为“成功”的微调模型；切换源模型会自动清空已选量化模板。 |
| **量化产出模型名后缀** | 是 | 仅支持小写字母+数字，≤8 位；将拼接至源模型名后形成压缩后模型唯一标识（如 `qwen35-flash-ft-v1-int4`）。 |
| **量化模板** | 是 | 卡片式选择，模板名中 MU 编号越大，部署规格越小、成本越低，但潜在精度损失可能增加。须先选定源模型才可加载对应模板列表。 |
| **校准数据** | 条件选填 | 仅当所选模板要求校准时出现；最多选 5 个已发布数据集（不支持 OSS 挂载），建议语义贴近目标推理场景（如客服问答场景选用对话数据集）。 |

## 使用方式

1. **前提条件**：确保工作空间中存在状态为“成功”的微调模型（参见 [模型调优](raw/model-user-guide/fine-tuning.md)）。
2. **入口路径**：百炼控制台 → 左侧导航栏 → **模型压缩** → **创建压缩任务**。
3. **配置与提交**：按上述关键参数完成配置，确认无误后单击**开始压缩**（按钮仅在所有必填项合法时启用）。
4. **监控进度**：在任务列表页点击任务名称进入详情页，通过**详情**页签查看状态与配置，通过**日志**页签实时跟踪运行过程（支持 ERROR 级别高亮、全量日志下载等）。
5. **结果使用**：任务状态变为 `SUCCEEDED` 后，压缩后模型将出现在模型中心，可直接用于[模型部署](raw/model-user-guide/model-high-speed-inference/model-deployment-index.md)。

## 限制和注意事项

- **不可逆性**：压缩操作不可撤销。压缩后的模型**不支持继续微调**，也**不支持二次压缩**（详见 [模型压缩](../../raw/model-user-guide/model-compression/model-compression-introduction.md) “重要”提示）。
- **任务管理限制**：
  - PENDING / RUNNING 状态任务可手动停止，但停止后不可恢复；
  - 仅终态（SUCCEEDED / FAILED / CANCELED）任务可删除；QUEUING 状态不可删除。
- **计费说明**：压缩任务本身限时免费（截止时间以控制台公告为准）；压缩后模型的部署费用按 MU 规格单独计费，与压缩免费期无关。
- **精度验证建议**：量化可能导致精度下降。强烈建议在免费期内对同一源模型尝试多个量化模板，并使用业务测试集进行部署后验证，再择优上线（该实践建议出自 [模型压缩](../../raw/model-user-guide/model-compression/model-compression-introduction.md) “常见问题”章节）。
