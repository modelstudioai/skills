# model evaluation introduction

模型评测是百炼平台用于量化评估文本生成类模型能力的核心功能，支持通过自定义维度对模型输出进行自动或人工评分，并生成可对比的指标报告。它既可用于模型选型、调优效果验证等业务场景，也提供开箱即用的基线评测能力。评测流程围绕“数据集 → 评测维度 → 评测任务 → 结果分析”四步展开，所有环节均面向开发者提供细粒度控制。

## 支持的模型/功能

- **支持模型类型**：当前仅支持文本生成类模型（如 Qwen 系列），不支持多模态、语音或结构化输出模型。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet）或已有的推理结果集，结合自定义创建的[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)进行评分。
  - **基线评测**：内置 5 大类、13 个公开标准 Benchmark（如 GSM8K、HumanEval、MMLU-Pro），仅在北京地域可用，无需准备数据或配置维度，系统自动完成全量评测与评分。
- **评分范式**：覆盖三大类共五种评测维度类型，详见[评测维度概述](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)：
  - 大模型评估（分类型 / 数值型）：由裁判模型（如千问-Max）执行语义级评判；
  - 规则评估（字符串匹配 / 文本相似度）：基于确定性算法（BLEU/ROUGE/Cosine/Fuzzy Match 等）计算分数；
  - 人工评估-分类型：由人工逐条标注 Pass/Fail 标签。

> **注意**：文档 2 中称“基线评测不使用自定义评测维度，系统使用预设标准自动评分”，而文档 1 的“评测维度概述”未提及基线评测，二者无冲突；但文档 2 明确指出基线评测“仅北京地域可用”，而文档 1 未说明地域限制，该信息以文档 2 为准。

## 关键参数

| 参数类别 | 参数名 | 说明 | 是否必填 | 取值约束 |
|----------|--------|------|-----------|------------|
| **通用** | 维度名称 | 评测维度模板标识符 | 是 | ≤ 20 字符 |
| | 描述 | 补充说明评判目标 | 否 | ≤ 100 字符 |
| **大模型评估专用** | 裁判模型 | 执行评判的 LLM（如 `qwen-max`） | 是（仅大模型评估） | 从控制台下拉列表选择 |
| | 评分器 Prompt | 指导裁判模型打分的提示词 | 是（仅大模型评估） | 必须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量；≤ 50000 字符 |
| | 评分范围（数值型） | 最小值与最大值 | 是（仅数值型） | 整数，最小值 ≥ 0，最大值 ≥ 1，默认 `0~5` |
| | 通过阈值 | 判定为 Pass 的最低分值或相似度 | 是（数值型/相似度型） | 数值型：步长 0.1；相似度型：范围 `0~1`，步长 `0.01` |
| **规则评估专用** | 比较操作符（字符串匹配） | 相等 / 不相等 / 包含 | 是（仅字符串匹配） | — |
| | 评估指标（文本相似度） | BLEU / ROUGE-1 / ROUGE-2 / ROUGE-L / Cosine / Fuzzy Match / Accuracy | 是（仅文本相似度） | — |
| **人工评估专用** | Pass 标签 / Fail 标签 | 人工评审时选择的分类标签 | 是（仅人工评估） | 互斥、不重复，各 ≤ 20 字符 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或复用已有推理结果集（含 `Prompt`、`Completion`、`Output`）。
2. **创建评测维度**：进入[评测维度页面](https://bailian.console.aliyun.com/cn-beijing/model/evaluate/dimension_template)，按需选择类型并配置参数。推荐从小样本（50–100 条）+ 预置模板（如“综合评测”）起步，验证效果后再迭代 Prompt 或切换为自定义逻辑。
3. **创建评测任务**：
   - 自定义评测：选择模型、指定数据来源（评测数据集 or 推理结果集）、关联至少一个已创建的维度；
   - 基线评测：仅限北京地域，选择模型后勾选 Benchmark 即可启动。
4. **查看结果**：任务完成后，在详情页的 **指标统计** 查看综合得分、通过率与分布图；在 **数据明细** 查看每条样本的原始输入、模型输出、参考答案及各维度评分。

> **注意**：文档 1 强调“评分器类型创建后不可更改”，文档 2 在“创建评测维度”小节中重复该说明并补充“已关联该维度的评测任务不受影响”，二者一致，无矛盾。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用；其他地域控制台不显示该选项，属正常行为。
- **维度不可变性**：评测维度的**类型**（如“大模型评估-数值型”）创建后不可修改，选错需删除重建；若已被排行榜绑定，则必须先解除绑定才能删除。
- **费用归属明确**：
  - 使用**评测数据集**作为数据来源 → 产生被评测模型推理费用；
  - 使用**推理结果集** → 无推理费用；
  - **大模型评估**维度 → 产生裁判模型评分费用；
  - **规则评估**与**人工评估** → 无裁判模型费用；
  - 详细计费规则见[计费说明](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **人工评估特殊性**：任务状态变为“评测完成”需**全部数据人工标注完毕**；不支持 Case 下钻查看裁判依据（此为大模型评估特有）。
- **命名与设计建议**：维度名称建议采用“评估方面 + 评估方式”格式（如“回答准确性-LLM评分”）；Pass/Fail 标签应互斥且穷尽，避免歧义；评分范围建议 ≤10（文档 1 建议默认 0~5），以保障 LLM 评分一致性。
