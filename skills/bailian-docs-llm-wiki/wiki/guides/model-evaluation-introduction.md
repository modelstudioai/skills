# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化流程对文本生成类模型进行量化打分与横向对比。它提供自定义评测（基于用户数据与自定义维度）和基线评测（基于公开标准数据集）两种范式，覆盖从快速选型、调优验证到持续质量监控的全场景需求。该功能面向开发者设计，强调可复用性、可解释性与成本可控性。

## 支持的模型/功能

- **支持模型类型**：仅限文本生成类模型（Text Generation），包括百炼预置模型（如千问系列）及用户调优后的模型；不支持多模态、语音、向量等非文本生成模型 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评测方式**：
  - **自定义评测**：完全由用户控制，支持上传评测数据集（含 Prompt + Completion）或直接导入推理结果集（含 Output），并关联一个或多个已创建的评测维度。
  - **基线评测**：内置 5 大类、13 个公开 Benchmark（如 MMLU-Pro、GSM8K、HumanEval、LongBench-v2、FinanceQA），自动加载数据与评分逻辑，无需准备数据或配置维度；**仅在北京地域（华北2）可用** [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评分器类型（即评测维度）**：共 5 种，按评估范式分为三类：
  - *大模型评估*（需裁判模型）：数值型（0–5 整数分）、分类型（Pass/Fail 标签）；
  - *规则评估*（无裁判模型）：字符串匹配（相等/不相等/包含）、文本相似度（ROUGE/BLEU/Cosine 等 7 种算法）；
  - *人工评估*（无裁判模型）：分类型（人工标注 Pass/Fail） [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

> **注意**：文档 1 称“当前仅支持文本生成类模型评测”，而文档 2 未明确限定模型类型，但其所有示例与参数说明（如 `${prompt}/${output}/${completion}` 变量、Function Calling/NL2SQL 场景）均严格对应文本生成任务。因此以文档 1 的明确声明为准，该限制为硬性约束。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 备注 |
|----------|--------|------|--------|------|
| **通用** | 维度名称 | 模板标识符，≤20 字符 | 是 | 建议采用“评估方面+方式”命名，如 `回答准确性-LLM评分` |
| | 描述 | 补充说明，≤100 字符 | 否 | — |
| **大模型评估专用** | 裁判模型 | 执行评分的 LLM（如千问-Max） | 是（仅大模型评估） | 影响费用与延迟；推荐千问-Max 用于高精度场景 |
| | 评分器 Prompt | 指导裁判模型评分的提示词 | 是（仅大模型评估） | 必须含至少一个变量：`${prompt}` / `${output}` / `${completion}` [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 评分范围（数值型） | 整数区间，如 `0–5` | 是（仅数值型） | 默认 `0–5`；范围过大（>10）易降低 LLM 评分一致性 |
| | 通过阈值（数值型/相似度型） | 判定 Pass 的最低分/相似度 | 是（数值型/相似度型） | 步长 0.1（数值型）或 0.01（相似度型）；默认 3.0 |
| | Pass/Fail 标签（分类型） | 分类标签集合 | 是（仅分类型） | Pass 与 Fail 标签不可重复，且应互斥穷尽 |

## 使用方式

1. **前置准备**  
   - 开通百炼账号，进入北京地域控制台（`cn-beijing`）；  
   - 在**数据管理**模块上传评测数据集（类型为 `EvaluationSet`，含 `Prompt` 和 `Completion` 两列）或准备推理结果集（含 `Prompt`/`Output`/`Completion`）。

2. **创建评测维度**  
   - 进入**模型评测 → 评测维度**页签 → **创建评测维度**；  
   - 选择类型（如 `大模型评估-数值型`），配置裁判模型、评分器 Prompt（可选预置模板）、评分范围与通过阈值；  
   - 保存后该维度可被多个评测任务复用。

3. **创建评测任务**  
   - 进入**模型评测 → 评测任务**页签 → **创建评测任务**；  
   - 选择方式（自定义 or 基线）→ 选择被评测模型 → 配置数据来源（评测数据集 or 推理结果集）→ 关联已创建的维度 → （可选）开启排行榜参与 → **开始评测**。

4. **查看与分析结果**  
   - 任务状态变为“评测完成”后，点击任务名进入详情页；  
   - **指标统计**页查看综合得分、通过率、分数分布；  
   - **数据明细**页逐条查看 Prompt/Output/Completion 及各维度评分；  
   - 基线评测额外提供“基线评分明细”“Case 分析”“多任务对比”页签 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 限制和注意事项

- **地域限制**：基线评测功能**仅在北京地域（华北2）可用**；其他地域控制台不显示该选项，属正常行为。自定义评测全地域可用。
- **模型限制**：仅支持文本生成类模型；不支持图像生成、语音合成、嵌入模型等非文本生成任务。
- **维度不可变**：评测维度的**类型创建后不可修改**，选错需删除重建；若已被排行榜绑定，需先解除绑定再删除。
- **费用关键点**：
  - 使用**评测数据集**时，产生被评测模型的推理费用；
  - 使用**大模型评估维度**时，产生裁判模型的评分费用；
  - 规则评估与人工评估**无裁判模型费用**；
  - 使用**推理结果集**作为数据源时，**不产生被评测模型推理费用**。
- **结果解读建议**：  
  - 综合得分是各维度平均分，可能掩盖维度间差异，**务必结合分数分布图与维度明细分析短板**；  
  - 1–3% 的分数差异通常属于评测噪声，不建议据此决策；  
  - 人工评估任务需**全部标注完成后**才标记为“评测完成”。
