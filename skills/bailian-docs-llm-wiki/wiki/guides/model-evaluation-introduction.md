# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化或自定义方式对文本生成类模型的推理结果进行量化打分与横向对比。它服务于模型选型、调优效果验证、能力基线建立和持续质量监控等关键研发场景。评测结果以综合得分、通过率及明细数据形式输出，支撑数据驱动的模型决策。

## 支持的模型/功能

- **支持模型类型**：仅限文本生成类模型（Text Generation），包括百炼预置模型（如千问系列）及用户调优后的模型；不支持多模态、语音、向量等非文本生成模型。详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有的推理结果集，结合自定义创建的评测维度进行评分；
  - **基线评测**：直接调用平台内置的 13 个公开标准 Benchmark（覆盖通用知识、数学、代码、上下文推理、领域专项五大类），无需准备数据或配置维度，但**仅在北京地域可用**（其他地域控制台不显示该选项）[原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评分器类型**：共 5 种，分为三大范式：
  - *大模型评估*（数值型/分类型）：依赖裁判模型（如千问-Max）进行语义级评判，适用于问答质量、内容安全等场景；
  - *规则评估*（字符串匹配/文本相似度）：基于算法（如 ROUGE、BLEU、Cosine、精确匹配）自动计算，零裁判模型费用，适用于翻译、摘要、Function Calling 等有确定性标准的场景；
  - *人工评估*（分类型）：由人工逐条标注 Pass/Fail，适用于创意写作、专业合规审核等主观性强的场景。各类型能力边界与选型建议详见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

> **注意**：文档 1 中“基线评测仅北京地域可用”与文档 2 未提地域限制，但文档 1 多次明确强调且附有控制台行为说明（“其他地域不显示此选项”），应以文档 1 为准；文档 2 作为维度专项文档，聚焦通用能力，未覆盖地域约束信息，不构成矛盾。

## 关键参数

- **评测维度参数**：
  - `裁判模型`：仅大模型评估类型必填，影响评分质量与费用；
  - `评分器 Prompt`：必须包含至少一个变量 `${prompt}`、`${output}` 或 `${completion}`，用于指导裁判模型评判逻辑；
  - `评分范围`（数值型）：整数区间，默认 `0–5`，最大值不建议超过 10（避免 LLM 评分一致性下降）；
  - `通过阈值`：数值型/相似度型必填，步长 0.1（数值）或 0.01（相似度），默认 3.0；
  - `Pass/Fail 标签`：分类型维度必填，标签间须互斥且穷尽。
- **评测任务参数**：
  - `数据来源`：二选一——**评测数据集**（触发被测模型推理，产生推理费用）或**推理结果集**（跳过推理，仅评分，无推理费）；
  - `System Prompt`：作用于被测模型，用于设定角色或行为规范，多数场景可留空；
  - `排行参与`：开启后需绑定已有排行榜，确保维度一致方可提交。

## 使用方式

1. **前置准备**：
   - 开通百炼账号并进入北京地域控制台（`cn-beijing`）；
   - 在**数据管理**模块上传评测数据集（类型为 `EvaluationSet`，含 `Prompt` 和 `Completion` 列）或准备推理结果集文件；
2. **创建评测维度**（必选）：
   - 进入**模型评测 → 评测维度**页签，单击**创建评测维度**；
   - 选择类型（如“大模型评估-数值型”），配置裁判模型、评分器模板（推荐先用预置模板）、评分范围与通过阈值；
   - 保存后该维度可被多个任务复用；
3. **创建评测任务**：
   - 进入**模型评测 → 评测任务**页签，单击**创建评测任务**；
   - 选择评测方式（自定义/基线），指定被测模型、数据来源（数据集或结果集）、关联已创建的维度；
   - 配置推理参数（Temperature/TopP 等，默认继承模型设置），确认后单击**开始评测**；
4. **查看结果**：
   - 任务状态变为“评测完成”后，点击任务名进入详情页；
   - **指标统计**页查看综合得分、通过率、分数分布；
   - **数据明细**页查看每条样本的 Prompt、Output、Completion 及各维度评分；
   - 基线评测额外提供“Case 分析”与“多任务对比”页签。

## 限制和注意事项

- **模型限制**：当前**仅支持文本生成类模型**，不支持图像生成、语音合成、嵌入模型等；调优模型评测不额外计费（推理费用已含在部署算力中），但裁判模型评分仍按 [Token](../concepts/token.md) 计费 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **地域限制**：基线评测功能**仅在北京地域（华北2）可用**，其他地域控制台不展示该选项，属正常设计，非故障。
- **维度不可变**：评测维度的类型创建后不可修改，选错需删除重建；若已被排行榜绑定，需先解除绑定才能删除。
- **费用说明**：
  - 费用 = 被测模型推理费（仅当使用评测数据集时产生） + 裁判模型评分费（仅大模型评估类型产生）；
  - 规则评估与人工评估无裁判模型费用；
  - 推理结果集模式下，无被测模型推理费。
- **结果解读建议**：
  - 综合得分是各维度平均值，可能掩盖维度间差异，**务必结合分数分布图与明细分析短板**；
  - 1–3% 的分差通常属评测噪声，不建议作为模型选型唯一依据；
  - 人工评估任务需全部标注完成后才标记为“评测完成”，此前状态恒为“进行中”。
