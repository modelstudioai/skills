# model evaluation introduction

百炼平台的模型评测功能是一套模型质量验证工具，用于客观、量化地评估大语言模型在特定业务场景下的表现。通过准备测试数据集、定义评分标准（评测维度）、执行自动或人工评测，最终生成包含综合得分、通过率和数据明细的评测报告。该功能适用于模型选型决策、调优效果验证、能力量化评估和持续监控等场景。

## 评测模式

百炼提供两种评测模式，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)：

- **自定义评测**：面向具体业务场景，需要自行创建评测维度和准备测试数据。支持预置模型（千问-QwQ/Max/Plus/Turbo/Coder/Math、千问开源版、通义法睿、第三方文本生成模型等）及其调优后的模型。灵活度高，可完全自定义评分标准。
- **基线评测**：使用行业标准数据集（C-Eval、MMLU、ARC、GSM8K、HellaSwag、BBH）评估模型通用能力。仅支持调优后的模型，不支持预置模型。无需准备数据，可快速验证调优效果并与业界模型横向对比。

首次使用或业务场景评测建议选择自定义评测；调优后验证通用能力建议使用基线评测；最佳实践是两者结合。

## 评测维度

评测维度定义了评分标准，是自定义评测的核心配置。百炼支持 5 种评测维度类型，如[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)所述：

| 类型 | 评分方式 | 适用场景 | 成本 |
| --- | --- | --- | --- |
| 大模型评估-数值型 | AI 裁判打分（数值范围，如 0-5） | 问答质量、内容生成质量 | 中 |
| 大模型评估-分类型 | AI 裁判分类（Pass/Fail） | 内容安全、正确性判断 | 中 |
| 规则评估-文本相似度 | 算法计算相似度（BLEU、ROUGE-L、Cosine 等） | 翻译、摘要、改写 | 低 |
| 规则评估-字符串匹配 | 精确字符串匹配（相等、包含等） | Function Calling、NL2SQL | 极低 |
| 人工评估-分类型 | 人工打标签 | 创意性、专业判断 | 高 |

一个评测任务可组合多个评测维度。大模型评估类型需要配置评分器 Prompt 和裁判模型；规则评估类型通过算法自动判定；人工评估需要标注人员手动标注。

## 评测数据

自定义评测支持两种数据来源：

- **评测数据集**：包含问题（Prompt）和参考答案（Completion），系统调用被评测模型实时推理生成 Output 后再评分。适合首次评测和多模型对比。
- **推理结果集**：已包含模型输出（Output），系统直接读取进行评分，不再推理。适合降低推理成本或用作对照基准。

数据格式为 Excel，建议数据量：小规模验证 50-100 条，正式评测 200-500 条，全面评估 500+ 条。

> **注意**：模型评测只能使用评测集类型的数据集，不支持训练集。

## 评测流程

整个评测流程分为四个阶段：

1. **准备工作**：创建评测维度（定义评分标准）+ 准备测试数据（上传评测数据集）
2. **创建评测任务**：选择被评测模型、数据集、评测维度，可选配置 System Prompt 和排行榜
3. **执行评测**：自动评测由系统完成，人工评测需要标注人员手动标注
4. **查看结果**：查看综合得分、通过率、数据明细，分析高分和低分样本

## 核心变量与 Prompt 配置

大模型评估类型中，裁判模型接收三个核心变量：

- `${prompt}`：用户的原始问题或指令
- `${output}`：被评测模型生成的回答
- `${completion}`：参考答案（有标准答案时使用）

评测中涉及两种 Prompt，容易混淆：

- **System Prompt**：配置在评测任务上，作用于被评测模型，设定其角色定位（如"你是客服人员"）。非必填，大多数情况留空。
- **评分器 Prompt**：配置在评测维度上，作用于裁判模型，定义评分标准。仅大模型评估类型需要配置。可选择预置模板（综合评测、语义相似度等）或自定义编写。

## 排行榜

排行榜用于对比多个模型在同一评测维度上的表现，支持可视化排名展示。每个排行榜最多支持 50 个评测任务，创建后评测维度不可修改。可通过创建新任务或选择已有任务加入排行榜。

## 基线评测数据集

基线评测提供以下预置标准数据集，如[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)中详细说明：

| 分类 | 数据集 | 说明 |
| --- | --- | --- |
| 学科 | C-Eval | 52 个学科，13,000+ 道中文测试题 |
| 学科 | MMLU | 57 个学科，57,000+ 道测试题 |
| 学科 | ARC | 7,900+ 道深度推理测试题 |
| 数学 | GSM8K | 8,000+ 个小学数学问题 |
| 推理 | HellaSwag | 70,000+ 道常识推理测试题 |
| 推理 | BBH | 23 个挑战性推理任务 |

基线评测结果包含分学科得分明细、能力雷达图和行业对比。

## 计费说明

评测费用由两部分组成：

- **被评测模型推理费用**：预置模型按 Token 消耗计费，独立部署的调优模型不额外计费。
- **裁判模型评分费用**：仅大模型评估类型涉及，当前限时免费。

规则评估和人工评估不产生裁判模型费用。具体价格以百炼控制台显示为准。

## 使用建议

- 评分标准要具体化，为每个分数档提供清晰的判定条件
- 先用小规模数据集（50-100 条）验证配置正确，再扩大到正式规模
- 对于频繁评测的基准模型，将输出保存为推理结果集以降低成本
- 定期人工抽查高分和低分样本，验证评测准确性
- 建立定期评测机制，追踪模型表现趋势
- 如果模型输出频繁与参考答案无关或部分相关，考虑引入知识库补充背景知识
