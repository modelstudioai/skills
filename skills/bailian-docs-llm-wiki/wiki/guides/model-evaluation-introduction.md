# model evaluation introduction

模型[评测](../concepts/evaluation.md)是百炼平台提供的模型质量验证工具，用于基于数据集对大语言模型进行多维度量化评估。它支持自动[评测](../concepts/evaluation.md)和人工[评测](../concepts/evaluation.md)两种模式，最终生成综合得分、通过率和分数分布等评测报告，帮助开发者在[模型选型](../concepts/model-selection.md)、调优验证、能力量化与持续监控等场景中以数据驱动决策。详细介绍可参考[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 支持的评测类型

模型评测分为两类，开发者应根据评测目的选择合适的方式。

### 自定义评测

适用于业务场景评测与自定义评分标准。需要先创建评测维度，再准备评测数据（Excel 格式）。具体说明见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

- **评测维度类型（5 种）**：
  - **大模型评估-数值型**：AI 裁判按 1–5 分打分，适合问答质量、内容生成质量评估，推荐度最高。
  - **规则评估-文本相似度**：算法计算相似度，适合翻译、摘要、改写，成本较低。
  - **大模型评估-分类型**：AI 裁判做 Pass/Fail 分类，适合内容安全、正确性判断。
  - **规则评估-字符串匹配**：精确字符串匹配，适合 Function Calling、NL2SQL，成本极低。
  - **人工评估-分类型**：人工打标签，适合创意性、专业判断，成本较高。

一个评测任务可以组合多个评测维度。

### 基线评测

适用于验证模型通用能力（学科、数学、推理），使用系统预置的标准榜单数据集，无需自备评测数据，也无需创建评测维度。

> **注意**：基线评测**仅支持调优后的模型**，不支持预置模型（如千问-Max）。若创建任务时模型列表为空，需先完成模型调优与部署。

基线评测提供预置数据集，包括：

- **学科类**：C-Eval（52 个学科、13,000+ 题）、MMLU（57 个学科、57,000+ 题）、ARC（7,900+ 题）。
- **数学类**：GSM8K（8,000+ 小学数学问题）。
- **推理类**：HellaSwag（70,000+ 推理题）、BBH（23 个高难度推理题）。

## 关键参数

### 评分器 Prompt 中的核心变量

仅适用于**大模型评估-数值型**和**大模型评估-分类型**评测维度，裁判模型会接收以下三个变量：

| 变量名 | 说明 | 使用场景 |
| --- | --- | --- |
| `${prompt}` | 原始输入（用户问题或指令） | 所有场景必填 |
| `${output}` | 模型输出（参评模型生成的回答） | 所有场景必填 |
| `${completion}` | 参考答案（标准答案或期望输出） | 有标准答案时使用 |

### System Prompt 与评分器 Prompt 的区别

| Prompt 类型 | 配置位置 | 作用对象 | 是否必填 | 费用归属 |
| --- | --- | --- | --- | --- |
| System Prompt | 创建**评测任务**时 | 被评测模型 | 否 | 被评测模型推理费用 |
| 评分器 Prompt | 创建**大模型评估**评测维度时 | 裁判模型 | 是 | 裁判模型评分费用 |

形象比喻：System Prompt 告诉"学生"（被评测模型）以什么身份答题；评分器 Prompt 告诉"阅卷老师"（裁判模型）如何批改试卷。

### 评分器模板

系统预置三种模板（创建评测维度时选择）：

- **综合评测**（默认）：从相关性、文化敏感性、信息丰富性、清晰性、用户参与度 5 个维度评分，适合通用对话、客服场景。
- **语义相似度**：评估输出与参考答案的语义接近程度，适合问答系统、知识检索。
- **自定义评测**：自行编写 Prompt，适合特定业务场景。

## 使用方式

### 评测流程

整体分为四个阶段：

1. **准备工作**：定义评测维度（评分标准）→ 准备测试数据（问题和答案）。
2. **创建评测任务**：选择模型 → 选择数据 → 选择维度 → 决定是否参与排行榜。
3. **执行评测**：自动评测（系统自动完成）或人工评测（需手动标注）。
4. **查看结果**：得分报告 → 通过率统计 → 详细明细。

### 自定义评测数据

自定义评测支持两种数据来源类型：

- **评测数据集**：包含 Prompt 和 Completion 两列，系统调用模型实时推理生成 Output 再评分，适用于首次评测、对比多个模型、模型尚未生成结果的场景。
- **推理结果集**：已包含 Output 列，系统直接读取 Output 评分（不推理），适用于模型已生成结果、降低推理成本、作为对照组基准模型的场景。

数据格式为 Excel，数据量建议：小规模验证 50–100 条，正式评测 200–500 条，全面评估 500+ 条。

> **注意**：模型评测只能使用**评测集**类型的数据集，不支持训练集。

### 任务状态

评测任务状态包括：**待执行**（高峰时段排队）、**进行中**（系统正在评测）、**评测完成**（可查看结果）、**评测失败**、**评测终止**（人工手动终止）。

### 结果查看

任务完成后进入详情页：

- **数据明细** Tab：查看每条数据的 Prompt、Completion、Output 及对应评测维度的评分。
- **指标统计** Tab：查看综合得分（评测维度的平均分）、通过率（达到阈值的样本占比）、评测集总量、已完成量、未完成量。

基线评测的结果报告还提供分学科得分明细、能力雷达图和与业界标准模型的行业对比。

## 限制和注意事项

- **模型支持范围**：自定义评测支持千问系列（QwQ/Max/Plus/Turbo/Coder/Math）、千问开源版（Qwen3/Qwen2.5/Qwen2/Qwen1.5）、通义法睿及部分第三方文本生成模型；列表可能随时变化，以创建任务页面显示为准，灰色且无"申请"按钮的模型暂不支持评测。完整说明见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **基线评测仅支持调优模型**：不支持预置模型，需先完成模型调优与部署。
- **数据集类型限制**：自定义评测仅支持评测集，不支持训练集。
- **评分器 Prompt 适用范围**：仅大模型评估类型（数值型、分类型）需要配置，规则评估和人工评估类型不涉及。
- **费用归属**：System Prompt 产生被评测模型推理费用，评分器 Prompt 产生裁判模型评分费用，使用时需关注成本。
- **排行榜使用**：用于对比多个模型在同一评测维度上的表现，需在创建任务时选择参与。
