# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化或自定义方式对文本生成类模型的推理结果进行量化打分与横向对比。它服务于模型选型、调优验证、能力基线建立和持续质量监控等关键研发场景，提供从数据准备、维度定义、任务执行到结果分析的端到端闭环。当前功能仅面向文本生成类模型，不支持多模态或语音类模型。

## 支持的模型与功能

- **支持模型类型**：预置模型（如千问系列）及用户调优后的文本生成模型（详见[预置模型列表](raw/model-user-guide/model-high-speed-inference/model-deployment-index/model-deployment-introduction.md)），**不支持非文本生成类模型**。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（`EvaluationSet` 类型）或已有的推理结果集，配合自定义创建的评测维度进行评分。支持大模型评估、规则评估、人工评估三类共五种评分器（见下文“关键参数”）。
  - **基线评测**：内置覆盖通用知识、数学、代码、上下文推理、领域专项 5 大类共 13 个公开标准 Benchmark（如 MMLU-Pro、GSM8K、HumanEval），自动完成评测并生成基准分数。> **注意**：基线评测**仅在北京地域（华北2）可用**，其他地域控制台不显示该选项，属正常限制，详见[创建基线评测任务](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **核心功能模块**：评测维度（可复用的评分模板）、评测任务（执行单元）、排行榜（跨任务横向对比）、人工标注（针对人工评估维度）。

## 关键参数

评测维度是配置的核心，其类型决定评分逻辑与费用模型：

| 维度类型 | 评分方式 | 是否需参考答案 | 自动化程度 | 裁判模型费用 | 典型适用场景 |
|----------|----------|----------------|------------|----------------|----------------|
| 大模型评估-数值型 | 裁判模型输出整数分（如 0–5） | 否 | 全自动 | 是 | 问答质量、生成完整性等需精细量化的场景 |
| 大模型评估-分类型 | 裁判模型输出 Pass/Fail 等标签 | 否 | 全自动 | 是 | 内容安全、事实正确性等二元/多类判定 |
| 规则评估-字符串匹配 | 程序化判断相等/包含/不相等 | 是 | 全自动 | 否 | Function Calling、NL2SQL 等确定性输出场景 |
| 规则评估-文本相似度 | ROUGE/BLEU/Cosine 等算法计算相似度 | 是 | 全自动 | 否 | 翻译、摘要、改写等开放式回答场景 |
| 人工评估-分类型 | 人工逐条标注 Pass/Fail | 否 | 人工 | 否 | 创意写作、语气风格、专业合规审核等主观场景 |

> **注意**：所有维度类型创建后**不可修改**；选错类型必须删除重建。已关联该维度的评测任务不受影响，但排行榜若绑定该维度后被删除，则会阻止新任务创建——此行为在[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)文档中有明确说明。

关键配置项包括：
- **裁判模型**（仅大模型评估类型必填）：推荐 `qwen-max`，影响评分质量与费用。
- **评分器 Prompt**（仅大模型评估类型）：必须包含至少一个变量 `${prompt}`、`${output}` 或 `${completion}`，用于动态注入评测数据。
- **评分范围与通过阈值**（数值型/相似度型必填）：数值型默认 `0–5`，阈值默认 `3.0`（步长 0.1）；相似度型阈值范围 `0–1`（步长 0.01）。
- **Pass/Fail 标签**（分类型必填）：标签间须互斥且无重复，否则提交失败。

## 使用方式

标准流程为四步闭环（以自定义评测为例）：
1. **创建评测维度**：在控制台「模型评测 → 评测维度」页签，选择类型并完成配置（如选「大模型评估-数值型」，裁判模型选 `qwen-max`，评分范围 `0–5`，通过阈值 `3.0`）。详细指引见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。
2. **准备数据集**：在「数据管理」模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 两列），或准备已含 `Output` 的推理结果集。
3. **创建评测任务**：在「模型评测 → 评测任务」页签，选择「自定义评测」，指定目标模型、数据来源（评测数据集或推理结果集）、关联上一步创建的维度。System Prompt 可留空，多数场景无需配置。
4. **查看与分析结果**：任务状态变为「评测完成」后，进入详情页查看「指标统计」（综合得分、通过率、分布图）和「数据明细」（每条样本的 Prompt/Output/Completion/各维度评分）。支持下载 CSV 进行离线分析。

基线评测流程更简化：跳过维度与数据集准备，直接在创建任务时选择「基线评测」，勾选所需 Benchmark（如 `MATH-500`、`HumanEval`），系统自动运行并返回雷达图与多任务对比报告。

## 限制和注意事项

- **地域限制**：基线评测功能**仅在北京地域可用**，其他地域无法创建或查看基线评测任务。
- **模型限制**：当前**仅支持文本生成类模型**，不支持图像生成、语音合成等多模态模型。
- **数据要求**：
  - 评测数据集必须为 `EvaluationSet` 类型且已发布版本；
  - 推理结果集需严格按模板格式上传（含 `Prompt`、`Output` 字段，`Completion` 可选）；
  - 建议小规模验证用 50–100 条，正式评测用 200–500 条，全面评估建议 ≥500 条。
- **费用说明**：
  - 使用「评测数据集」会产生**被评测模型的推理费用**；
  - 「大模型评估」维度会产生**裁判模型评分费用**（按 [Token](../concepts/token.md) 计费）；
  - 「规则评估」与「人工评估」维度无裁判模型费用；
  - 「推理结果集」作为数据来源时，**不产生被评测模型推理费用**。
- **结果解读**：综合得分是各维度平均分，可能掩盖维度间差异；建议结合分数分布图与 Bad Case 分析定位短板。1–3% 的分差通常属评测噪声，不宜作为决策依据。
- **人工评估特殊性**：任务状态需**全部数据人工标注完成后**才变为「评测完成」；未标注完前始终为「进行中」，且不可下载结果。
