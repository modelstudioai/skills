# model evaluation introduction

模型评测是百炼平台用于量化评估文本生成类模型能力的核心功能，支持通过自定义维度对模型输出进行自动化或人工打分，并生成可对比的指标报告。它覆盖模型选型、调优验证、能力基线比对和持续质量监控等关键研发场景。评测逻辑围绕“数据集 + 维度 + 任务”三层结构展开，其中评测维度定义评分标准，是复用性与准确性的核心载体。

## 支持的模型/功能

- **支持模型类型**：当前仅支持文本生成类模型（如 Qwen 系列），不支持多模态、语音或嵌入模型。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet）或已有的推理结果集，关联自定义评测维度执行评分；
  - **基线评测**：调用平台预置的 5 大类、13 个公开标准 Benchmark（如 GSM8K、HumanEval、MMLU-Pro），自动完成评测并返回基准分数；该功能[仅北京地域可用](raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评分范式**：统一支持三大类共五种评测维度类型，详见[评测维度](raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)：
  - 大模型评估（分类型 / 数值型）：由裁判模型（如千问-Max）进行语义级评判；
  - 规则评估（字符串匹配 / 文本相似度）：基于程序化算法（如 ROUGE、BLEU、余弦相似度、精确匹配）计算得分；
  - 人工评估-分类型：由人工逐条标注 Pass/Fail 标签。

> **注意**：文档 2 中称“基线评测不使用自定义评测维度，系统使用预设标准自动评分”，而文档 1 未提及基线评测的维度机制。该差异属功能层级划分不同，无实质矛盾——基线评测的“预设标准”本质是平台固化的一组规则/大模型评估维度，用户不可见、不可编辑，因此不纳入维度模板管理范畴。

## 关键参数

| 参数类别 | 参数名 | 说明 | 是否必填 | 约束 |
|----------|--------|------|-----------|------|
| **公共参数** | 维度名称 | 模板标识符 | 是 | ≤20 字符，建议采用“评估方面+评估方式”命名（如`回答准确性-LLM评分`） |
| | 描述 | 补充说明 | 否 | ≤100 字符 |
| **大模型评估专用** | 裁判模型 | 执行评判的 LLM | 是（大模型评估类型） | 从控制台下拉列表选择，如 `qwen-max` |
| | 评分器 Prompt | 指导裁判模型评判的提示词 | 是 | 必须含至少一个变量：`${prompt}`、`${output}` 或 `${completion}`；≤50000 字符 |
| | 评分范围（数值型） | 最小值与最大值 | 是（数值型） | 均为整数，最小值 ≥ 0，最大值 ≥ 1，默认 `0~5` |
| | 通过阈值 | 判定 Pass 的最低分值（数值型）或相似度（规则型） | 是（数值型/相似度型） | 数值型步长 0.1；相似度型范围 `0~1`，步长 0.01 |
| | Pass/Fail 标签（分类型） | 分类判定标签 | 是（分类型） | 各标签 ≤20 字符，Pass 与 Fail 标签互斥且不可重复 |
| **规则评估专用** | 比较操作符（字符串匹配） | 相等 / 不相等 / 包含 | 是 | 决定匹配逻辑 |
| | 评估指标（文本相似度） | BLEU / ROUGE-1/2/L / Cosine / Fuzzy Match / Accuracy | 是 | 按场景选择：翻译用 BLEU，摘要用 ROUGE-L，语义相关用 Cosine |

## 使用方式

1. **准备数据**：在数据管理模块上传类型为 `EvaluationSet` 的评测数据集（含 `Prompt` 和 `Completion` 列），或准备已含 `Output` 的推理结果集；
2. **创建维度**：进入[评测维度页面](https://bailian.console.aliyun.com/cn-beijing/model/evaluate/dimension_template)，按需选择类型并配置参数（如大模型评估-数值型需指定裁判模型、评分范围、通过阈值）；完整流程参见[评测维度](raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)；
3. **创建任务**：
   - 自定义评测：在评测任务页选择“自定义”，指定被测模型、数据来源（评测数据集或推理结果集）、关联已创建的维度；
   - 基线评测：选择“基线评测”，勾选目标 Benchmark（如 `GSM8K`、`HumanEval`），仅限北京地域；
4. **查看结果**：任务完成后，在详情页的**指标统计**页查看综合得分、通过率及分布图，在**数据明细**页查看每条样本的逐维评分。

## 限制和注意事项

- **维度类型不可变**：评测维度创建后，其类型（如“大模型评估-数值型”）不可修改，选错需删除重建；若该维度已被排行榜绑定，则需先解除绑定方可删除；
- **地域限制**：基线评测功能[仅在北京地域可用](raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)，其他地域控制台不显示该选项；
- **费用归属明确**：
  - 使用**评测数据集**时：产生被评测模型推理费用 + （大模型评估维度）裁判模型评分费用；
  - 使用**推理结果集**时：仅产生（大模型评估维度）裁判模型评分费用；
  - **规则评估**与**人工评估**维度不产生裁判模型费用；
- **人工评估特殊性**：任务状态变为“评测完成”需所有样本人工标注完毕；不支持基线评测任务进入人工标注流程；
- **成本优化建议**：优先用规则评估（零裁判模型费用）；小规模（50–100 条）验证配置后再全量运行；保存推理结果集复用以避免重复推理；
- **命名与标签规范**：Pass/Fail 标签应互斥穷尽；评分范围建议不超过 10（如 `0~5`），过大易降低 LLM 评分一致性。
