# model evaluation introduction

模型评测是百炼平台提供的模型质量验证工具，用于客观、量化地评估大语言模型在特定业务场景下的表现。通过构建评测数据集、选择评测维度和裁判模型，系统自动或人工对模型输出打分并生成评测报告。该功能适用于模型选型、调优验证、能力量化和持续监控等场景，帮助开发者用数据驱动决策。

## 典型使用场景

模型评测覆盖模型全生命周期中的关键决策节点，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)：

- **模型选型**：用相同的测试数据评测多个候选模型（千问、GPT、Claude 等），对比得分和通过率，选出最适合业务的模型。
- **调优验证**：分别评测调优前后的模型，量化调优效果（如 75 分 → 85 分），判断调优方向是否正确。
- **能力量化**：生成包含综合得分、通过率、分数分布和典型案例的评测报告，为团队汇报提供数据支撑。
- **持续监控**：建立定期评测机制，追踪模型表现趋势，及时发现性能下降。

## 评测类型

百炼平台提供两种评测模式，适用于不同需求：

### 自定义评测

自定义评测允许开发者定义评分标准和测试数据，灵活度高，适用于业务场景评测。

**支持的模型**包括千问系列（QwQ/Max/Plus/Turbo/Coder/Math）、千问开源版（Qwen3、Qwen2.5 等）、通义法睿以及部分第三方文本生成模型。基于这些预置模型调优后的模型同样支持评测。具体可用模型以[创建评测任务](https://bailian.console.aliyun.com/?tab=model#/efm/model_evaluate/task/creation)页面中的列表为准。

**评测维度**（即评分标准）支持 5 种类型：

| 类型 | 评分方式 | 适用场景 | 成本 |
|------|----------|----------|------|
| 大模型评估-数值型 | AI 裁判打分（1-5 分） | 问答质量、内容生成 | 中 |
| 规则评估-文本相似度 | 算法计算相似度 | 翻译、摘要、改写 | 低 |
| 大模型评估-分类型 | AI 裁判分类（Pass/Fail） | 内容安全、正确性判断 | 中 |
| 规则评估-字符串匹配 | 精确字符串匹配 | Function Calling、NL2SQL | 极低 |
| 人工评估-分类型 | 人工打标签 | 创意性、专业判断 | 高 |

一个评测任务可以组合多个评测维度。

**评测数据**支持两种来源，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)中的说明：

- **评测数据集**：包含 [prompt](prompt.md) 和 completion（参考答案），系统调用模型实时推理后评分。适合首次评测和多模型对比。
- **推理结果集**：已包含 output（模型输出），系统直接评分不推理。适合降低推理成本或作为基准对照。

数据格式为 Excel，建议小规模验证 50-100 条，正式评测 200-500 条，全面评估 500 条以上。

> **注意**：模型评测只能使用**评测集**类型的数据集，不支持训练集。

### 基线评测

基线评测使用预置的行业标准数据集，快速验证模型通用能力，无需准备评测数据。

> **注意**：基线评测仅支持调优后的模型，不支持预置模型（如千问-Max）。如果在创建任务时模型列表为空，需先完成模型调优和部署。

基线评测提供三类标准数据集：

| 分类 | 数据集 | 评测能力 |
|------|--------|----------|
| 学科 | C-Eval、MMLU、ARC | 中文学科知识、广泛领域知识、深度推理 |
| 数学 | GSM8K | 基础数学问题求解 |
| 推理 | HellaSwag、BBH | 常识推理、多步复杂推理 |

基线评测的结果报告包含分学科得分明细、能力雷达图和行业对比，可将调优模型与业界标准模型横向比较。

### 如何选择

- **首次使用或业务场景评测**：选择自定义评测（更灵活）
- **调优后验证通用能力**：选择基线评测（快速对比）
- **最佳实践**：两者结合使用

## 评测流程

整体流程分为四个阶段：

1. **准备工作**：定义评测维度（评分标准）、准备测试数据（问题和参考答案）
2. **创建评测任务**：选择模型 → 选择数据 → 选择维度 → 决定是否参与排行榜
3. **执行评测**：系统自动评测或分配人工标注
4. **查看结果**：查看综合得分、通过率、分数分布和数据明细

## 核心变量

在大模型评估类型的评测维度中，裁判模型的评分器 Prompt 使用三个变量：

| 变量 | 含义 | 说明 |
|------|------|------|
| `${prompt}` | 用户的原始问题或指令 | 所有场景必需 |
| `${output}` | 被评测模型生成的回答 | 所有场景必需 |
| `${completion}` | 参考答案/期望输出 | 有标准答案时使用 |

## System Prompt 与评分器 Prompt 的区别

这两种 Prompt 在评测中作用于不同环节，容易混淆。根据[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)的说明：

| 维度 | System Prompt | 评分器 Prompt |
|------|---------------|---------------|
| 配置位置 | 创建评测任务时 | 创建评测维度时 |
| 作用对象 | 被评测模型 | 裁判模型 |
| 作用阶段 | 模型生成答案时 | 裁判模型打分时 |
| 是否必填 | 否（大多数情况可留空） | 是（大模型评估类型必须配置） |

简单理解：System Prompt 告诉"学生"以什么身份答题，评分器 Prompt 告诉"阅卷老师"如何批改。

## 排行榜

排行榜用于对比多个模型在同一评测维度上的表现，支持可视化展示和多任务横向对比。当需要在团队内分享模型对比结果、或需要从多个候选模型中选型时，可在创建评测任务时选择参与排行。

## 评测结果说明

评测完成后可在任务详情页查看：

- **指标统计**：综合得分（平均分）、通过率（达到阈值的样本占比）、评测集总量和完成量
- **数据明细**：每条样本的原始问题（Prompt）、参考答案（Completion）、模型输出（Output）和各维度评分

任务状态包括待执行、进行中、评测完成、评测失败和评测终止五种。

## 注意事项

- 评测数据集建议覆盖各种边界情况，避免样本分布过于集中
- 大模型评估类型的裁判模型推理会产生额外费用，需区分被评测模型推理费用和裁判模型评分费用
- 评分标准应具体化，为每个分数档提供清晰描述，并定期人工抽查高分和低分样本
- 评测数据集与训练数据集不应重叠，以确保评测结果的客观性
- 支持的模型列表可能随时变化，请以控制台创建评测任务页面中实际显示的列表为准
