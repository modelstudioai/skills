# model evaluation introduction

模型评测是百炼平台提供的模型质量验证工具，用于基于数据集对大语言模型进行客观、量化的多维度评估。它支持自定义评测和基线评测两种模式，覆盖从业务场景验证、调优效果对比，到通用能力量化和持续监控的完整链路，最终输出综合得分、通过率和详细明细的结果报告。

## 适用场景

按使用目的，评测主要服务于四类场景，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)：

- **模型选型决策**：用相同测试集对多个候选模型（千问、GPT、Claude 等）进行横向对比，用数据替代主观判断。
- **调优效果验证**：分别评测调优前后的模型，量化得分提升幅度（例如 75 → 85 分）。
- **能力量化汇报**：用综合得分、通过率、分数分布等指标向团队或管理层汇报模型表现。
- **持续监控**：建立定期评测机制（如每月一次），追踪模型在固定数据集上的表现趋势，及时发现下降。

## 两种评测模式

百炼平台将评测分为「自定义评测」与「基线评测」两类，使用前请先按业务诉求做选择，详细对比见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

| 对比维度 | 自定义评测 | 基线评测 |
| --- | --- | --- |
| 适用场景 | 业务场景评测、自定义标准 | 模型通用能力验证（学科、数学、推理） |
| 评测标准 | 自定义评测维度（5 种类型） | 使用预置评测规则 |
| 是否需要创建评测维度 | 必须创建 | 不需要 |
| 数据来源 | 自备评测数据集或推理结果集（Excel） | 系统预置标准数据集 |
| 灵活性 | 高 | 低，使用行业标准 |
| 支持的模型 | 千问 QwQ/Max/Plus/Turbo/Coder/Math、Qwen 开源版、通义法睿、第三方文本生成模型及其调优版本 | **仅支持调优后的模型**，不支持预置模型 |

选择建议：

- **首次使用 / 业务场景评测**：选自定义评测。
- **调优后验证通用能力**：选基线评测，配合 C-Eval / MMLU / ARC / GSM8K / HellaSwag / BBH 等公开榜单。
- **最佳实践**：两者结合使用。

> **注意**：基线评测对模型的可选范围严格依赖「是否完成模型调优和部署」，在「创建评测任务」页面如果下拉为空，需先完成调优流程；自定义评测中显示为灰色且无「申请」按钮的模型同样不支持评测。

## 评测维度（自定义评测专属）

评测维度即评分标准，决定如何给模型打分。一个评测任务可组合多个评测维度。

| 类型 | 评分方式 | 适用场景 | 成本 | 推荐度 |
| --- | --- | --- | --- | --- |
| 大模型评估-数值型 | AI 裁判打分（1-5 分） | 问答质量、内容生成质量 | 中 | ⭐⭐⭐⭐⭐ |
| 规则评估-文本相似度 | 算法计算相似度 | 翻译、摘要、改写 | 低 | ⭐⭐⭐⭐ |
| 大模型评估-分类型 | AI 裁判分类（Pass/Fail） | 内容安全、正确性判断 | 中 | ⭐⭐⭐ |
| 规则评估-字符串匹配 | 精确字符串匹配 | Function Calling、NL2SQL | 极低 | ⭐⭐⭐ |
| 人工评估-分类型 | 人工打标签 | 创意性、专业判断 | 高 | ⭐⭐ |

创建「大模型评估-数值型」或「大模型评估-分类型」维度时，需要选择 **裁判模型**（如千问-Max）、**评分器模板**（综合评测 / 语义相似度 / 自定义）、**评分范围**（默认 0~5）与 **通过阈值**（如 3.0）。

## 关键参数与变量

「大模型评估-数值型 / 分类型」维度下，裁判模型的 Prompt 可使用三个内置变量：

| 变量 | 含义 | 使用建议 |
| --- | --- | --- |
| `${prompt}` | 原始输入：用户问题或指令 | 所有场景必填 |
| `${output}` | 模型输出：参评模型生成的回答 | 所有场景必填 |
| `${completion}` | 参考答案：标准答案或期望输出 | 有标准答案时使用 |

百炼平台还区分两种容易混淆的 Prompt 配置，必须在合适的环节填写：

| Prompt 类型 | 配置位置 | 作用对象 | 是否必填 | 费用归属 |
| --- | --- | --- | --- | --- |
| System Prompt | 创建评测任务时 | 被评测模型（生成答案） | 否 | 被评测模型推理费用 |
| 评分器 Prompt | 创建评测维度时 | 裁判模型（打分） | 是（仅大模型评估类） | 裁判模型评分费用 |

形象比喻：System Prompt 告诉「学生」以什么身份答题；评分器 Prompt 告诉「阅卷老师」如何批改试卷。

## 评测数据准备

自定义评测的数据格式为 Excel，需要根据数据来源类型组织列：

- **评测数据集**（最常用）：包含 `Prompt`（问题）与 `Completion`（参考答案）两列，系统会调用模型实时推理生成 Output 后再打分。
- **推理结果集**：包含 `Prompt`、`Completion`、`Output` 三列，系统直接读取 Output 进行打分，可以省去推理费用，适合作为对照基准或模型已落地的回放评测。

> **注意**：模型评测只能使用 **评测集** 类型的数据集，不支持训练集；数据集需通过「数据管理」页面新建。

数据量建议：

| 阶段 | 建议条数 | 说明 |
| --- | --- | --- |
| 小规模验证 | 50 ~ 100 条 | 验证配置是否正确 |
| 正式评测 | 200 ~ 500 条 | 获得可靠统计结果 |
| 全面评估 | 500 条以上 | 覆盖各种边界情况 |

基线评测无需准备数据，可直接选用 C-Eval、MMLU、ARC（学科）、GSM8K（数学）、HellaSwag、BBH（推理）等开源榜单；评测集、评测逻辑、评测脚本均与社区数据保持一致并定期更新。

## 使用流程

参考[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)中的快速体验示例，完整流程分为四个阶段：

1. **准备工作**：创建评测维度（定义评分标准）→ 准备测试数据（Prompt / Completion 等）。
2. **创建评测任务**：在「模型评测 → 评测任务」页面选择评测对象、裁判模型、评分器模板、评测维度，可选择是否参与排行榜。
3. **执行评测**：分为自动评测（系统执行）和人工评测（邀请评分员手动标注）两种方式；任务状态包含「待执行 / 进行中 / 评测完成 / 评测失败 / 评测终止」。
4. **查看结果**：
   - **数据明细** Tab：每条样本的 Prompt / Completion / Output / 评测维度得分。
   - **指标统计** Tab：综合得分（评测维度平均分）、通过率（≥ 阈值样本占比）、评测集总量、已完成量、未完成量等。
   - **基线评测特有内容**：分学科得分明细、能力雷达图、与业界模型（GPT-4、Claude 等）的对比。

如果需要可视化对比多个模型、在团队内分享结论，可在创建评测任务时勾选「参与排行榜」。

## 限制与注意事项

- 评测数据集类型仅支持 **评测集**，不支持训练集；数据来源类型选择「推理结果集」时必须包含 `Output` 列。
- 大模型评估类维度对 **裁判模型** 有费用消耗，按裁判模型 token 计费；System Prompt 与被评测模型的推理费用分开归属。
- 基线评测支持的模型严格限定为 **调优后的模型**，未完成调优部署的账户在选择模型时会看到空列表。
- 自定义评测中评分标准应具体化（为每个分数档提供清晰描述），并定期人工抽查高分和低分样本以校准；避免所有样本集中在同一分数段。
- 「评测任务」页面显示的支持模型列表会随时更新，灰色字体且无「申请」按钮的条目暂时不可用，请以[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)中提示的实际列表为准。
