# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化流程对文本生成类模型进行量化打分与横向对比。它提供自定义评测（基于用户数据与自定义维度）和基线评测（基于公开标准数据集）两种范式，覆盖从快速选型、调优验证到持续质量监控的全场景需求。该功能面向开发者设计，强调可复用性、可解释性与成本可控性。

## 支持的模型/功能

- **支持模型类型**：仅支持文本生成类（text-generation）模型，包括预置模型（如千问系列）及用户调优后的模型；不支持多模态、语音、向量等非文本生成模型。详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评测方式**：
  - **自定义评测**：完全由用户控制数据集、评分维度与评分逻辑，支持大模型评估、规则评估、人工评估三类共五种维度类型；
  - **基线评测**：内置 5 大类、13 个公开 Benchmark（如 MMLU-Pro、GSM8K、HumanEval），自动执行、无需配置维度或数据集，**仅在北京地域可用**（其他地域控制台不显示该选项）。
- **核心能力模块**：
  - 评测维度（模板化评分规则，可跨任务复用）；
  - 评测任务（绑定模型、数据源与维度，触发执行）；
  - 排行榜（同维度下多模型横向对比）；
  - 人工标注（针对人工评估维度的交互式标注界面）。

> **注意**：文档 1 中称“基线评测仅北京地域可用”，文档 2 未提及地域限制，但其引用的控制台路径 `https://bailian.console.aliyun.com/cn-beijing/...` 及文档 1 的明确声明均指向地域强约束。实际使用中若在非北京地域未见基线评测入口，属正常行为，**以文档 1 的说明为准**。

## 关键参数

| 参数类别 | 参数名 | 说明 | 约束与建议 |
|----------|--------|------|------------|
| **维度级** | 维度类型 | 必填，创建后不可修改：大模型评估-数值型/分类型、规则评估-字符串匹配/文本相似度、人工评估-分类型 | 选错需删除重建；详见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 裁判模型 | 仅大模型评估类型必填，推荐 `qwen-max`（推理能力强） | 影响评分质量与费用 |
| | 评分器 Prompt | 含 `${prompt}`、`${output}`、`${completion}` 变量，至少使用一个 | 长度 ≤ 50,000 字符；自定义时需明确定义评判逻辑与输出格式 |
| | 评分范围 / 通过阈值 | 数值型：整数区间（默认 0–5），阈值步长 0.1；文本相似度：0–1 区间，阈值步长 0.01 | 建议数值型范围 ≤ 10；阈值按业务容忍度设定（如 3.0 为常用基准） |
| **任务级** | 数据来源 | 二选一：<br>• **评测数据集**：含 `Prompt`+`Completion`，系统调用被测模型推理（产生推理费）<br>• **推理结果集**：已含 `Output`，仅评分（无推理费） | 小规模验证建议用 50–100 条；正式评测建议 200–500 条 |
| | System Prompt | 作用于被测模型，设定角色或行为规范；多数场景可留空 | 与评分器 Prompt（作用于裁判模型）严格区分，二者费用归属不同 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或准备已含 `Output` 的推理结果集。
2. **创建维度**：在**评测维度**页签创建至少一个维度模板。例如：  
   - 快速启动：选“大模型评估-数值型”，裁判模型 `qwen-max`，模板“综合评测”，范围 `0–5`，阈值 `3.0`；  
   - 成本敏感：选“规则评估-字符串匹配”，操作符“相等”，用于 Function Calling 验证。
3. **创建任务**：在**评测任务**页签，选择评测方式（自定义/基线）、目标模型、数据来源、关联维度；开启“参与排行”可加入排行榜。
4. **查看结果**：任务状态为“评测完成”后，进入详情页：  
   - **数据明细页签**：逐条查看 `Prompt`/`Output`/`Completion` 及各维度评分；  
   - **指标统计页签**：查看综合得分（维度平均分）、通过率（≥阈值样本占比）、分数分布图；  
   - **基线评测特有**：支持“多任务对比”雷达图与优劣势分析。

完整操作路径与最小配置示例见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 限制和注意事项

- **模型限制**：仅支持文本生成类模型；多模态、Embedding、Speech 模型暂不支持评测。
- **地域限制**：基线评测**仅限北京地域（cn-beijing）**；自定义评测全地域可用。
- **维度不可变性**：维度类型创建后不可修改，错误配置需删除重建；若已被排行榜绑定，需先移除绑定再删除。
- **费用关键点**：
  - 被测模型推理费：使用“评测数据集”时产生，按 [Token](../concepts/token.md) 计费；“推理结果集”方式无此费用；
  - 裁判模型评分费：仅大模型评估维度产生（按 [Token](../concepts/token.md) 计费）；规则评估与人工评估无此费用；
  - 人工评估无模型费用，但需人力投入且耗时长。
- **结果解读提醒**：
  - 综合得分是各维度平均值，可能掩盖维度间差异，**务必结合分数分布与明细分析短板**；
  - 1–3% 的分数差异通常属评测噪声，不建议作为决策唯一依据；
  - 人工评估任务需**全部标注完成后**才变为“评测完成”状态。
- **成本优化建议**：  
  - 先用 50–100 条数据小规模验证配置；  
  - 保存首次评测的推理结果集，后续复用以规避重复推理；  
  - 有确定性标准答案时，优先选用规则评估（零裁判模型费用）。
