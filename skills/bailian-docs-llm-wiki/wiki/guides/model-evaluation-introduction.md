# model evaluation introduction

[模型评测](../concepts/model-evaluation.md)是百炼平台提供的核心模型能力评估功能，支持通过标准化流程对文本生成类模型进行量化打分与横向对比。它提供自定义评测（基于用户数据与定制维度）和基线评测（基于公开标准数据集）两种模式，覆盖从模型选型、调优验证到持续质量监控的全生命周期场景。该功能面向开发者设计，强调可复用性、可解释性与成本可控性。

## 支持的模型/功能

- **支持模型类型**：仅限文本生成类模型（Text Generation），包括百炼预置模型（如千问系列）及用户调优后的模型；不支持[多模态](../concepts/multi-modal.md)、语音、向量等非文本生成模型 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **核心评测方式**：
  - **自定义评测**：支持用户上传评测数据集（EvaluationSet 类型，含 `Prompt` 和 `Completion` 字段）或导入已有推理结果集；支持五种评测维度类型复用（大模型评估-数值型/分类型、规则评估-字符串匹配/文本相似度、人工评估-分类型）。
  - **基线评测**：内置 5 大类、13 个公开 Benchmark（如 MMLU-Pro、GSM8K、HumanEval、LongBench-v2、FinanceQA），自动执行、无需配置数据与维度；但**仅在北京地域（华北2）可用**，其他地域控制台不显示该选项 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **扩展能力**：支持排行榜（跨任务同维度对比）、人工标注（仅限人工评估维度）、Case 分析与多任务雷达对比（基线评测专属）。

> **注意**：文档 1 称“基线评测仅北京地域可用”，文档 2 未提地域限制，但其内容聚焦于维度定义本身，不涉及地域逻辑。以文档 1 的明确声明为准，实际使用中非北京地域无法创建基线评测任务。

## 关键参数

| 参数类别 | 参数名 | 说明 | 约束与建议 |
|----------|--------|------|------------|
| **评测维度** | 维度类型 | 必填，5 种之一：`大模型评估-数值型`/`-分类型`/`规则评估-字符串匹配`/`-文本相似度`/`人工评估-分类型`；**创建后不可修改** | 选错需删除重建；已关联任务不受影响 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 裁判模型 | 仅大模型评估类型必填；推荐千问-Max（推理能力强） | 影响评分一致性与费用 |
| | 评分器 Prompt | 仅大模型评估类型必填；须含至少一个变量 `${prompt}` / `${output}` / `${completion}` | 长度 ≤ 50,000 字符；自定义时需明确定义评判逻辑与输出格式 |
| | 评分范围 & 通过阈值 | 数值型：整数区间（默认 0–5），阈值步长 0.1；相似度型：0–1 区间，阈值步长 0.01 | 建议数值型范围 ≤ 10；阈值按业务容忍度设定（如 3.0 为常用基准） |
| **评测任务** | 数据来源 | `评测数据集`（触发被测模型推理，产生推理费）或 `推理结果集`（仅评分，无推理费） | 小规模验证建议先用 50–100 条数据集；已有输出可复用结果集降本 |
| | System Prompt | 可选，作用于被测模型（非裁判模型），用于角色设定；多数场景可留空 | 与评分器 Prompt 严格区分：前者影响被测模型行为，后者指导裁判模型打分 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或整理好含 `Prompt`/`Output`/`Completion` 的推理结果集 CSV 文件。
2. **创建维度**：进入「评测维度」页签 → 「创建评测维度」→ 选择类型并完成配置（如大模型评估需选裁判模型、填 Prompt、设阈值）[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。
3. **创建任务**：
   - *自定义评测*：选「评测任务」→ 「创建评测任务」→ 选模型 + 数据来源 + 关联维度 → 提交；
   - *基线评测*：同上路径，但评测方式选「基线评测」→ 选模型 + 勾选 Benchmark（支持多选与子维度筛选）→ 提交。
4. **查看结果**：
   - 自定义任务：详情页含「数据明细」（逐条评分）与「指标统计」（综合得分、通过率、分布图）；
   - 基线任务：含「任务总览」（雷达图）、「基线评分明细」、「Case 分析」、「多任务对比」。

## 限制和注意事项

- **地域限制**：基线评测功能仅在北京地域（华北2）可用，其他地域控制台不展示该选项，属正常现象 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **模型限制**：当前**仅支持文本生成类模型**，不支持图像生成、语音合成、嵌入模型等；[多模态](../concepts/multi-modal.md)模型暂未开放评测能力。
- **维度约束**：维度类型创建后不可修改；删除维度前需确保无排行榜绑定（否则阻止删除），且已关联的评测任务不受影响。
- **费用说明**：费用由两部分构成——被测模型推理费（使用评测数据集时产生）与裁判模型评分费（仅大模型评估维度产生）；规则评估与人工评估无裁判模型费用 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **结果解读**：综合得分是各维度平均分，可能掩盖维度间差异；建议结合分数分布图与 Bad Case 分析定位短板；1–3% 的分差通常属评测噪声，不宜作为决策依据。
