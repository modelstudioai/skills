# model evaluation introduction

模型评测是百炼平台用于量化评估文本生成类模型能力的核心功能，支持通过自定义维度对模型输出进行自动化或人工评分，并生成可对比的指标报告。它既可用于业务场景下的效果验证（如模型选型、调优效果归因），也可用于通用能力的基线 benchmark 测评。评测结果依赖于评测维度的准确定义与合理配置，是模型迭代闭环中关键的质量度量环节。

## 支持的模型/功能

- **支持模型类型**：当前仅支持文本生成类模型（Text Generation），包括预置模型（如千问系列）及用户调优后的模型；不支持多模态、语音、向量模型等其他模态模型。
- **评测方式**：提供**自定义评测**与**基线评测**两类入口：
  - 自定义评测：使用用户上传的评测数据集（EvaluationSet）或已有的推理结果集，结合自定义创建的评测维度进行评分；
  - 基线评测：直接调用平台内置的 5 大类、13 个公开标准 benchmark（如 MMLU-Pro、GSM8K、HumanEval），无需准备数据或配置维度，但**仅北京地域可用** [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评分范式**：覆盖三大评估范式，对应五种评测维度类型（详见下文“关键参数”），均支持在评测任务中多选复用。

> **注意**：文档 1 中称“评测维度模板的创建和管理本身不收费”，而文档 2 的[计费说明](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)明确指出：大模型评估类型在评测任务执行时会产生裁判模型推理费用；规则评估与人工评估无裁判模型费用。二者无矛盾——前者强调“模板创建”零成本，后者强调“评测执行”按实际调用计费，符合平台实际计费逻辑。

## 关键参数

评测维度是评分逻辑的载体，其核心参数按类型分组如下：

| 维度类型 | 必填参数 | 说明 | 是否可修改 |
|----------|-----------|------|-------------|
| **大模型评估-分类型** | 裁判模型、评分器 Prompt、Pass/Fail 标签 | Prompt 中须至少含 `${prompt}`、`${output}` 或 `${completion}` 变量；标签互斥且不可重复 | 创建后仅 Prompt/标签可改，**类型不可更改** |
| **大模型评估-数值型** | 裁判模型、评分器 Prompt、评分范围（整数区间）、通过阈值（步长 0.1） | 默认范围 0~5，阈值默认 3.0；范围过大会降低 LLM 评分一致性，建议 ≤10 | 同上 |
| **规则评估-字符串匹配** | 评测输入（参考文本）、比较操作符（相等/不相等/包含）、模型输出（待匹配文本） | 至少一侧需含变量（如 `${completion}`）；Function Calling 场景推荐“包含” | 同上 |
| **规则评估-文本相似度** | 评测输入、评估指标（BLEU/ROUGE-L/Cosine 等 7 种）、模型输出、通过阈值（0~1，步长 0.01） | 算法选择需匹配场景：翻译用 BLEU，摘要用 ROUGE-L，语义相关用 Cosine | 同上 |
| **人工评估-分类型** | Pass 标签、Fail 标签 | 标签需简洁明确、覆盖所有可能结果；不涉及裁判模型，无费用 | 同上 |

所有维度均需配置**维度名称**（≤20 字符）和**描述**（≤100 字符），命名建议采用“评估方面+评估方式”模式，例如 `回答准确性-LLM评分` [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。

## 使用方式

完整流程为四步闭环：  
1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或准备已含 `Output` 的推理结果集；  
2. **创建维度**：在控制台 **模型评测 → 评测维度** 页签单击“创建评测维度”，按需选择并配置上述五种类型之一；  
3. **创建任务**：在 **模型评测 → 评测任务** 页签选择“自定义评测”，指定被测模型、数据来源（评测数据集/推理结果集）、关联已创建的维度；  
4. **查看结果**：任务状态变为“评测完成”后，在详情页的 **指标统计** 查看综合得分、通过率与分布图，在 **数据明细** 查看每条样本的逐维评分 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

> **注意**：文档 1 与文档 2 均强调“维度类型创建后不可更改”，且删除维度前需解除其与评测任务及排行榜的关联，否则操作被阻止。该限制为强约束，开发者应优先使用预置模板快速验证，再迭代至自定义配置。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用；其他地域控制台不显示该选项，属正常行为 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
- **模型限制**：仅支持文本生成类模型；不支持图像生成、语音合成等非文本任务。  
- **费用敏感点**：  
  - 大模型评估类型（分类型/数值型）同时产生**被测模型推理费**与**裁判模型评分费**；  
  - 规则评估与人工评估**无裁判模型费用**，成本更低；  
  - 使用“推理结果集”作为数据来源可规避被测模型重复推理费用。  
- **配置风险**：  
  - Prompt 中缺失 `${prompt}`/`${output}`/`${completion}` 变量将导致提交失败；  
  - Pass/Fail 标签重复、评分范围非整数、阈值超限等均会触发前端校验拦截；  
  - 切换预置模板会**覆盖当前自定义 Prompt 内容**，重要逻辑请提前备份。  
- **结果解读**：综合得分是各维度平均分，易掩盖维度间差异；务必结合**分数分布图**与**数据明细**定位短板，1–3% 的分差通常属评测噪声，不宜作为决策依据 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
