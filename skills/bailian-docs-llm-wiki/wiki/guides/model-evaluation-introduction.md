# model evaluation introduction

模型评测是百炼平台提供的模型能力评估功能，支持自定义评测和基线评测两种方式，通过评测维度对模型推理结果进行打分和对比，帮助开发者进行模型选型、调优验证和持续质量监控。当前仅支持文本生成类模型的评测。

## 评测方式

百炼提供两种评测方式，适用于不同场景。详细说明参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

### 自定义评测

使用自有数据集和自定义维度进行评测，支持三种评分方式：

- **大模型评估（AI 自动评测）**：由裁判模型（推荐千问-Max）对被评测模型的回答打分。数值型维度输出评分区间内的整数分，分类型维度输出 Pass/Fail 标签。适用于问答质量、内容安全等需要语义理解的场景。
- **规则评估（自动化指标）**：使用算法直接计算评分，无需裁判模型。支持字符串匹配（相等/不相等/包含）和文本相似度（ROUGE-1/2/L、BLEU、Cosine、Fuzzy Match、Accuracy）。适用于翻译、摘要、Function Calling 等有确定性标准的场景。
- **人工评估（人工标注）**：由人工逐条查看模型推理结果并标注 Pass/Fail 标签。适用于创意性写作、专业领域判断等机器难以准确评价的场景。

### 基线评测

使用公开标准数据集（C-Eval、MMLU、ARC、GSM8K、BBH、HellaSwag）快速评测模型基础能力，无需自行准备数据集或配置评测维度。

> **注意**：基线评测仅北京地域可用，其他地域不显示此选项。基线评测不支持下载评测结果，也不可进入人工标注页面。

## 评测维度

评测维度定义模型的评分标准，使用前须至少创建一个。维度类型创建后不可修改，选错需删除重建。百炼支持 5 种维度类型：

| 维度类型 | 评分方式 | 适用场景 | 裁判模型费用 |
|---------|---------|---------|------------|
| 大模型评估-数值型 | 裁判模型打分（整数，如 0-5） | 问答质量、内容生成 | 有 |
| 大模型评估-分类型 | 裁判模型标签（Pass/Fail） | 内容安全、正确性判断 | 有 |
| 规则评估-文本相似度 | ROUGE/BLEU/Cosine 等算法 | 翻译、摘要 | 无 |
| 规则评估-字符串匹配 | 相等/不相等/包含 | Function Calling、NL2SQL | 无 |
| 人工评估-分类型 | 人工标注 Pass/Fail | 创意性写作、专业判断 | 无 |

大模型评估维度的自定义评分器 Prompt 支持变量：`${prompt}`（用户问题）、`${output}`（模型回答）、`${completion}`（参考答案），须至少包含一个变量。

## 评测流程

完整的评测流程分为四个阶段，具体操作步骤参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)中的快速入门部分：

1. **准备数据集**：在数据管理模块上传评测集（EvaluationSet）类型的数据，包含 Prompt（用户问题）和 Completion（参考答案）两列。
2. **创建评测维度**：定义评分标准和方式，选择维度类型、裁判模型、评分范围和通过阈值。
3. **创建评测任务**：选择被评测模型，配置数据来源（评测数据集或推理结果集），关联评测维度。
4. **查看评测结果**：分析综合得分、通过率和分数分布，可选加入排行榜对比。

### 数据来源配置

| 对比项 | 评测数据集 | 推理结果集 |
|-------|-----------|-----------|
| 数据内容 | 包含 Prompt 和 Completion | 已包含模型 Output |
| 推理调用 | 系统调用被评测模型推理 | 不调用模型推理 |
| 推理费用 | 产生 | 不产生 |
| 适用场景 | 首次评测、标准流程 | 已有模型输出，降低成本 |

数据量建议：小规模验证 50-100 条，正式评测 200-500 条，全面评估 500 条以上。

### 关键参数说明

- **评分范围**：定义裁判模型的打分区间（整数，如 0-5），决定评分粒度。
- **通过阈值**：判定 Pass/Fail 的分界线（支持小数，步长 0.1，如 3.0），用于统计通过率。
- **System Prompt**：配置于评测任务，为被评测模型设定角色定位，大多数场景可留空。
- **评分器 Prompt**：配置于评测维度，指导裁判模型如何打分，两者作用对象和费用归属不同。

## 评测结果分析

评测任务完成后，结果包含两部分：

- **指标统计**：综合得分（各维度平均分）、通过率（达到通过阈值的样本占比）、分数分布图。
- **数据明细**：逐样本展示 Prompt、模型 Output、参考 Completion 及各维度评分。

> **注意**：综合得分可能掩盖维度间的显著差异，建议逐维度分析。1-3% 的分数差异通常为评测噪声，不建议仅凭微小分差做决策。

## 排行榜

排行榜用于在相同评测维度下横向对比多个模型的表现。排行榜得分范围为 0-100，基于关联评测维度的综合评分计算。创建时须绑定评测维度（创建后不可修改），可关联使用相同维度的已完成任务。为确保公平性，建议排行榜内所有评测任务使用相同的评测数据集。

## 计费说明

模型评测费用由被评测模型推理费用和裁判模型评分费用两部分构成，按 [Token](../concepts/token.md) 消耗计费。计算公式：输入 [Token](../concepts/token.md) 数 / 1M × 输入单价 + 输出 [Token](../concepts/token.md) 数 / 1M × 输出单价。详细定价参见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)中的计费说明。

成本优化策略：

- 先用 50-100 条数据小规模验证配置正确性，再扩大规模。
- 首次评测后保存推理结果集复用，避免重复推理费用。
- 翻译、摘要等有确定性标准的场景优先选用规则评估（无裁判模型费用）。
- 已部署的调优模型评测不额外计费，推理费用包含在部署算力费用中。

## 限制与注意事项

- 当前仅支持文本生成类模型评测。
- 基线评测仅北京地域可用。
- 维度类型创建后不可修改，选错需删除重建。
- 评测任务提交后不可更换被评测模型，需删除重建（已消耗 Token 费用不可追回）。
- 模型评测当前仅支持控制台操作，不提供公开 API/SDK。如需编程化评测能力，可参考 PAI Judge Model API 作为替代方案。
- LLM 评分器存在位置偏差和自我偏好偏差，建议定期人工抽查校准。
