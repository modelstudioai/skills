# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化或自定义方式对文本生成类模型进行量化打分与横向对比。它覆盖模型选型、调优验证、能力基线建立和持续质量监控等关键场景，提供从数据准备、维度定义、任务执行到结果分析的端到端闭环。当前功能仅面向文本生成类模型，不支持多模态或语音类模型。

## 支持的模型/功能

- **支持的模型类型**：预置模型（如千问系列商业及开源模型）和用户调优后的文本生成模型（详见[预置模型列表](raw/model-user-guide/model-deployment-index/model-deployment-introduction.md)）。  
- **评测方式**：  
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有的推理结果集，配合自定义评测维度进行评分；支持大模型评估（AI 自动评分）、规则评估（ROUGE/BLEU/Cosine/字符串匹配）和人工评估三种范式。  
  - **基线评测**：内置 5 大类、13 个公开标准 Benchmark（如 MMLU-Pro、GSM8K、HumanEval、LongBench-v2、FinanceQA），自动完成评测并生成基准分数；**仅北京地域可用**，其他地域不显示该选项 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。  
- **复用能力**：评测维度以模板形式创建后，可被多个评测任务复用；排行榜支持在统一维度下横向对比多个模型表现。

## 关键参数

| 参数类别 | 关键字段 | 说明 | 约束 |
|----------|----------|------|------|
| **评测维度** | 维度类型 | 必填，5 种之一：大模型评估-数值型/分类型、规则评估-字符串匹配/文本相似度、人工评估-分类型；**创建后不可修改** | 选错需删除重建 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |
| | 裁判模型 | 仅大模型评估类型必填；推荐千问-Max（推理能力强） | 不同裁判模型影响费用与一致性 |
| | 评分器 Prompt | 仅大模型评估类型必填；须含至少一个变量 `${prompt}` / `${output}` / `${completion}` | 长度 ≤ 50,000 字符 |
| | 评分范围 & 通过阈值 | 数值型维度必填：默认 `0–5` 整数区间，阈值步长 `0.1`；相似度维度阈值范围 `0–1` | 阈值需结合业务容忍度设定 |
| | Pass/Fail 标签 | 分类型维度必填；标签互斥且不可重复 | 同一标签不得同时出现在 Pass 和 Fail 中 |
| **评测任务** | 数据来源 | 二选一：<br>• 评测数据集：触发被测模型推理，产生推理费用<br>• 推理结果集：仅评分，无推理费用 | 数据集须为 EvaluationSet 类型且已发布版本 |
| | System Prompt | 可选；作用于被测模型，用于角色设定或行为约束 | 与评分器 Prompt（作用于裁判模型）严格区分，二者费用归属不同 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) |

> **注意**：文档 1 中“评测流程与核心术语”明确指出 `System Prompt` 配置于评测任务、作用于被测模型，而 `评分器 Prompt` 配置于评测维度、作用于裁判模型；但文档 2 的“配置评分器Prompt”章节未强调此区分，易引发混淆。请以文档 1 定义为准。

## 使用方式

1. **准备数据**：在数据管理模块上传评测集（含 `Prompt` 和 `Completion` 两列），类型为 EvaluationSet 并发布版本；或准备已含 `Output` 的推理结果集。  
2. **创建维度**：进入**评测维度**页签 → **创建评测维度** → 按业务选择类型并完成配置（如大模型评估需选裁判模型+Prompt；规则评估需选算法+阈值）→ 保存为模板。  
3. **创建任务**：进入**评测任务**页签 → **创建评测任务** →  
   - 选择方式（自定义 or 基线）；  
   - 选择被测模型；  
   - 配置数据来源（评测数据集 or 推理结果集）；  
   - 关联已创建的维度（基线评测无需此步）；  
   - 设置排行参与（可选）→ **开始评测**。  
4. **查看结果**：任务状态为“评测完成”后，点击任务名称进入详情页：  
   - **数据明细页签**：逐条查看 `Prompt`/`Output`/`Completion` 及各维度评分；  
   - **指标统计页签**：查看综合得分、通过率、分数分布图；  
   - 基线评测额外提供“基线评分明细”“Case 分析”“多任务对比”页签 [原文标题](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用；控制台地域切换会影响可用功能。  
- **模型限制**：当前**仅支持文本生成类模型**，不支持图像、语音、多模态等其他模态模型。  
- **维度不可变**：评测维度类型创建后不可修改，错误选择需删除重建；若已被排行榜绑定，删除前须先解除绑定。  
- **费用说明**：  
  - 使用评测数据集时，产生被测模型推理费用（按 [Token](../concepts/token.md) 计费）；  
  - 大模型评估维度产生裁判模型评分费用（按 [Token](../concepts/token.md) 计费）；  
  - 规则评估与人工评估无裁判模型费用；  
  - 使用推理结果集可规避被测模型推理费用。  
- **结果解读建议**：  
  - 综合得分是各维度平均分，可能掩盖维度间差异，**务必结合分数分布与维度明细分析短板**；  
  - 1–3% 的分数差异通常属评测噪声，不建议作为决策依据；  
  - 人工评估任务需全部标注完成后才变为“评测完成”状态。
