# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化或自定义方式对文本生成类模型进行量化打分与横向对比。它服务于模型选型、调优验证、能力归因和持续监控等关键研发环节，提供从数据准备、维度定义、任务执行到结果分析的端到端闭环。当前功能仅面向文本生成类模型，不支持多模态或语音模型。

## 支持的模型/功能

- **支持模型类型**：预置模型（如千问系列）及用户调优后的文本生成模型（详见[预置模型列表](raw/model-user-guide/model-deployment-1/model-deployment-introduction.md)），**不支持非文本生成类模型**。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有的推理结果集，配合自定义创建的评测维度（含大模型评估、规则评估、人工评估三类共五种类型）进行评分。
  - **基线评测**：内置覆盖通用知识、数学、代码、上下文推理、领域专项 5 大类共 13 个公开标准 Benchmark（如 MMLU-Pro、GSM8K、HumanEval），**仅在北京地域可用**，详见[创建基线评测任务](https://help.aliyun.com/zh/model-studio/model-evaluation-overview#6a6d224tod900)。
- **核心功能模块**：评测维度管理、自定义/基线评测任务创建、人工标注流程、排行榜构建与多模型对比、结果下载与离线分析。

> **注意**：文档 1 中称“基线评测仅北京地域可用”，而文档 2 未提及地域限制；该限制以文档 1 的明确声明为准，属平台基础设施约束，非文档过时。

## 关键参数

| 参数类别 | 参数名 | 说明 | 约束/默认值 |
|----------|--------|------|-------------|
| **评测维度** | 维度类型 | 必填，决定评分逻辑：`大模型评估-数值型`/`-分类型`、`规则评估-字符串匹配`/`-文本相似度`、`人工评估-分类型` | 创建后不可修改，选错需删除重建 |
| | 裁判模型 | 仅大模型评估类型必填，用于自动评分 | 推荐千问-Max；费用按 Token 计费 |
| | 评分器 Prompt | 仅大模型评估类型必填，含 `${prompt}`、`${output}`、`${completion}` 变量 | 至少含一个变量，长度 ≤ 50,000 字符 |
| | 评分范围 / 通过阈值 | 数值型：整数区间（默认 `0–5`）；相似度型：`0.00–1.00`；所有类型均需设通过阈值 | 阈值步长：数值型 `0.1`，相似度型 `0.01` |
| **评测任务** | 数据来源 | `评测数据集`（触发被测模型推理，产生费用）或 `推理结果集`（仅评分，无推理费） | 数据集须为 EvaluationSet 类型且已发布 |
| | System Prompt | 配置于任务级，作用于被测模型，非裁判模型 | 多数场景可留空 |
| | 排行榜参与 | 开启后需绑定已创建的排行榜（绑定维度不可为空） | 用于多模型公平对比 |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或准备含 `Prompt`/`Output`/`Completion` 的推理结果集文件。
2. **创建维度**：在**评测维度**页签创建至少一个维度模板。推荐初学者选用预置模板（如“综合评测”或“标准匹配”），再根据小样本验证结果迭代优化 Prompt。详细配置请参见[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。
3. **创建任务**：
   - *自定义评测*：选择模型、数据来源、关联维度，配置推理参数（Temperature/TopP 等可选），点击**开始评测**。
   - *基线评测*：选择模型、勾选目标 Benchmark（如 `MATH-500` 或 `HumanEval`），可选开启数据采样，点击**开始评测**。操作路径详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
4. **查看结果**：
   - 自定义任务：在详情页的**指标统计**查看综合得分、通过率、分数分布；在**数据明细**查看每条样本的逐项评分。
   - 基线任务：在**基线评分明细**页下钻各 Benchmark 得分，在**Case 分析**页查看 LLM 判官依据。
5. **进阶分析**：将多个同维度任务加入**排行榜**，生成雷达图与优劣势分析；对人工评估任务，需在**人工标注**页完成全部 Pass/Fail 标注后状态才变为“评测完成”。

## 限制和注意事项

- **模型限制**：仅支持文本生成类模型（Text Generation），不支持图像、语音、多模态等其他模态模型。
- **地域限制**：基线评测功能**仅在北京地域（华北2）可用**，其他地域控制台不显示该选项，属正常部署策略。
- **维度不可变性**：评测维度的类型创建后不可修改，错误选择需删除重建；若该维度已被排行榜绑定，删除前须先解除绑定。
- **费用说明**：
  - 使用 `评测数据集` 作为数据来源时，产生**被测模型推理费用**（按输入/输出 Token 计费）；
  - 使用 `大模型评估` 类型维度时，产生**裁判模型评分费用**（按 Token 计费）；
  - `规则评估` 与 `人工评估` 维度无裁判模型费用；`推理结果集` 来源无被测模型推理费用。
- **结果解读**：综合得分是各维度平均分，易掩盖维度间差异；建议结合**分数分布图**与**Bad Case 分析**定位具体短板。1–3% 的分差通常属评测噪声，不宜作为决策依据。
- **配置验证**：强烈建议先用 50–100 条数据做小规模验证，确认维度配置（尤其是 Prompt 和标签）合理后再全量运行，避免无效消耗。
