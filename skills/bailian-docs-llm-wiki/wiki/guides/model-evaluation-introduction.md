# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化流程对文本生成类模型进行量化打分与横向对比。它提供自定义评测（基于用户数据与自定义维度）和基线评测（基于公开标准数据集）两种模式，覆盖从模型选型、调优验证到持续质量监控的全生命周期场景。该功能面向开发者设计，强调可复用性、可解释性与成本可控性。

## 支持的模型/功能

- **支持模型类型**：仅限文本生成类模型（Text Generation），包括百炼预置模型（如千问系列）及用户调优后的模型；不支持多模态、语音、向量等非文本生成模型 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **评测方式**：
  - **自定义评测**：完全由用户控制——上传评测数据集（EvaluationSet 类型）、创建评测维度、配置评分逻辑，支持大模型评估、规则评估、人工评估三类共五种评分器 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。
  - **基线评测**：内置 5 大类、13 个公开 Benchmark（如 MMLU-Pro、GSM8K、HumanEval、LongBench-v2、FinanceQA），自动加载数据与评分标准，**仅在北京地域（华北2）可用**；不支持自定义维度或推理结果集输入 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **关键辅助功能**：排行榜（同维度下多模型横向对比）、人工标注工作台（仅限人工评估维度）、Case 分析与多任务对比（基线评测专属）。

> **注意**：文档1称基线评测“仅北京地域可用”，而文档2未提地域限制，但文档2明确引用文档1作为任务创建入口，且其上下文均基于同一控制台路径（`cn-beijing`），因此以文档1为准。其他地域用户无法看到基线评测选项，属正常行为。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 约束条件 |
|----------|--------|------|--------|-----------|
| **通用** | 维度名称 | 维度模板标识符 | 是 | ≤20 字符 |
| | 描述 | 补充说明 | 否 | ≤100 字符 |
| **大模型评估** | 裁判模型 | 执行评分的 LLM（如千问-Max） | 是（仅大模型评估） | 从控制台下拉列表选择 |
| | 评分器 Prompt | 指导裁判模型打分的提示词 | 是（仅大模型评估） | 必须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量；≤50,000 字符 |
| | 评分范围（数值型） | 整数区间，如 `0-5` | 是（仅数值型） | 最小值 ≥ 0，最大值 ≥ 1 |
| | 通过阈值 | 判定 Pass 的最低分（数值型）或相似度（规则型） | 是（数值型/相似度型） | 步长 0.1（数值型）或 0.01（相似度型） |
| | Pass/Fail 标签（分类型） | 分类标签定义 | 是（仅分类型） | Pass 与 Fail 标签互斥、无重复 |
| **规则评估** | 比较操作符（字符串匹配） | 相等 / 不相等 / 包含 | 是（仅字符串匹配） | — |
| | 评估指标（文本相似度） | ROUGE-1/2/L、BLEU、Cosine、Fuzzy Match、Accuracy | 是（仅文本相似度） | — |

## 使用方式

1. **准备数据**：在数据管理模块上传 `EvaluationSet` 类型数据集（含 `Prompt` 和 `Completion` 列），或准备已含 `Output` 的推理结果集文件。
2. **创建维度**：进入「评测维度」页签 → 「创建评测维度」→ 选择类型 → 配置参数（如裁判模型、Prompt、标签、阈值等）。**类型创建后不可修改**，选错需删除重建 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。
3. **创建任务**：
   - *自定义评测*：选择「评测任务」→ 「创建评测任务」→ 选「自定义」→ 关联模型、数据源（评测数据集/推理结果集）、维度 → 提交。
   - *基线评测*：同上路径 → 选「基线评测」→ 选模型 → 勾选 Benchmark（支持子维度筛选与数据采样）→ 提交。
4. **查看结果**：
   - 自定义评测：任务完成后查看「指标统计」（综合得分、通过率、分布图）与「数据明细」（逐条 Prompt/Output/Completion/评分）。
   - 基线评测：查看「任务总览」（雷达图）、「基线评分明细」、「Case 分析」、「多任务对比」。

## 限制和注意事项

- **模型限制**：仅支持文本生成类模型；基线评测不支持推理结果集输入，必须由平台调用被测模型推理 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **地域限制**：基线评测功能**仅在北京地域（华北2）可用**；其他地域控制台不显示该选项。
- **维度约束**：评测维度类型创建后不可更改；已被排行榜绑定的维度删除后，将导致排行榜无法新建任务（绑定维度为空）。
- **费用说明**：
  - 被评测模型推理费：使用「评测数据集」时产生；使用「推理结果集」时不产生。
  - 裁判模型评分费：仅「大模型评估」维度产生；「规则评估」与「人工评估」无此费用。
  - 人工评估无模型费用，但需人力投入且耗时长，任务状态需全部标注完成后才变为「评测完成」。
- **结果解读建议**：避免仅依赖综合得分；应结合分数分布、Bad Case 分析与维度明细定位短板；1–3% 的分差通常属评测噪声，不宜作为决策依据。
