# model evaluation introduction

模型评测是百炼平台用于量化评估文本生成类模型能力的核心功能，支持通过自定义维度对模型输出进行自动或人工评分，并生成可对比的评测报告。它覆盖从快速基线验证到精细化业务效果评估的全场景，是模型选型、调优验证与持续质量监控的关键基础设施。评测逻辑解耦为「数据集」、「评测维度」和「评测任务」三层，确保标准统一、配置复用、结果可追溯。

## 支持的模型/功能

- **支持模型类型**：当前仅支持文本生成类模型（如 Qwen 系列、调优后的 LLM），不支持多模态或语音模型 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **两大评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet）或已有的推理结果集，关联自定义创建的评测维度，支持大模型评估、规则评估、人工评估三类评分方式；
  - **基线评测**：内置 5 大类、13 个公开标准 Benchmark（如 MMLU-Pro、GSM8K、HumanEval），仅在北京地域可用，无需准备数据或配置维度 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。
- **五大评测维度类型**（均在[评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)中定义）：
  - 大模型评估-分类型（Pass/Fail 标签）
  - 大模型评估-数值型（0~5 等整数分）
  - 规则评估-字符串匹配（相等/不相等/包含）
  - 规则评估-文本相似度（BLEU/ROUGE/余弦等 7 种算法）
  - 人工评估-分类型（人工标注 Pass/Fail）

> **注意**：文档 1 称“人工评估-分类型”适用于“语气风格、合规性审核”，而文档 2 在“适用场景”中明确其更适用于“创意性写作、专业领域判断”。二者侧重点不同，但无本质矛盾；实际使用应以业务判断复杂度为准——若需领域专家介入（如医学合规），优先人工；若仅需基础风格识别（如口语化程度），可尝试大模型评估。

## 关键参数

| 参数类别 | 参数名 | 说明 | 是否必填 | 约束条件 |
|----------|--------|------|-----------|------------|
| **通用** | 维度名称 | 评测维度模板标识符 | 是 | ≤ 20 字符 |
| | 描述 | 补充说明评判目标 | 否 | ≤ 100 字符 |
| | 类型 | 5 种评分器类型之一，创建后不可更改 | 是 | — |
| **大模型评估专用** | 裁判模型 | 执行评判的 LLM（如千问-Max） | 是（该类型下） | 从控制台下拉列表选择 |
| | 评分器 Prompt | 指导裁判模型评判的提示词 | 是（该类型下） | 必须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量；≤ 50000 字符 |
| | 评分范围（数值型） | 最小值与最大值 | 是（数值型） | 整数，最小值 ≥ 0，最大值 ≥ 1，默认 0~5 |
| | 通过阈值 | 判定 Pass 的最低分值或相似度 | 是（数值型/相似度型） | 数值型：步长 0.1；相似度型：0~1，步长 0.01 |
| | Pass/Fail 标签（分类型） | 分类标签定义 | 是（分类型） | 各标签 ≤ 20 字符，互斥且不可重复 |

## 使用方式

1. **准备数据集**：在数据管理模块上传 `EvaluationSet` 类型数据（含 `Prompt` 和 `Completion` 两列），或复用已有 `InferenceResultSet`（含 `Prompt`、`Output`、`Completion`）；
2. **创建评测维度**：进入「模型评测 → 评测维度」，按需选择类型并配置参数（如裁判模型、Prompt、阈值等）；
3. **创建评测任务**：
   - 自定义评测：选择「评测模型」+「数据来源」（评测数据集 or 推理结果集）+「关联维度」；
   - 基线评测：仅北京地域可用，选择模型 + 基线 Benchmark（如 GSM8K、HumanEval）；
4. **查看结果**：任务完成后，在「指标统计」页查看综合得分、通过率、分数分布；在「数据明细」页逐条核验评分依据。

> **注意**：文档 1 强调“评分器类型创建后不可更改，选错只能删除重建”，而文档 2 在同一位置表述为“已关联该维度的评测任务不受影响”。二者一致——维度类型不可改，但已绑定的任务仍可正常运行，不影响历史结果。

## 限制和注意事项

- **地域限制**：基线评测仅在北京地域可用，其他地域控制台不显示该选项 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)；
- **模型限制**：仅支持文本生成类模型，暂不支持图像、音频等多模态模型；
- **维度类型锁定**：评测维度创建时选定的类型不可修改，误选需删除后重建；若该维度已被排行榜绑定，则需先解除绑定才能删除；
- **费用相关**：
  - 大模型评估维度会产生裁判模型推理费用（按 Token 计费）；
  - 规则评估与人工评估无裁判模型费用；
  - 使用「评测数据集」会触发被测模型推理并产生费用；使用「推理结果集」则无此费用；
- **成本优化建议**：
  - 先用 50~100 条数据小规模验证维度配置合理性；
  - 首次评测后下载推理结果集，后续复用以避免重复推理；
  - 有确定答案的场景优先选用规则评估（零裁判模型费用）；
- **命名与设计规范**：维度名称建议采用“评估方面 + 评估方式”格式（如 `回答准确性-LLM评分`），便于团队协作识别 [评测维度](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)。
