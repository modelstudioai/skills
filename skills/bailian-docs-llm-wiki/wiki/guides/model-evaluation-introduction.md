# model evaluation introduction

模型评测是百炼平台提供的模型能力评估功能，支持自定义评测和基线评测两种方式，通过评测维度对模型推理结果进行打分和对比，帮助开发者选择最优模型或验证调优效果。当前仅支持文本生成类模型的评测，评测结果以报告和排行榜形式呈现。

## 使用场景

- **模型选型对比**：使用相同的评测数据集和维度评测多个候选模型，通过排行榜横向对比综合得分和通过率，用数据驱动选型决策。
- **调优效果验证**：对模型调优前后分别执行评测，对比评分变化，量化调优带来的能力提升。
- **能力量化评估**：生成包含综合得分、通过率和分数分布的评测报告，为团队协作提供客观数据支撑。
- **持续质量监控**：建立定期评测机制，使用相同评测条件追踪模型表现趋势，及时发现能力下降。

## 自定义评测与基线评测

百炼平台提供两种评测方式，详见[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

### 自定义评测

使用开发者自有数据集和自定义维度进行评测，支持三种评分方式：

| 评分方式 | 说明 | 适用场景 | 裁判模型费用 |
|---------|------|---------|------------|
| 大模型评估（AI 自动评测） | 由裁判模型（推荐千问-Max）对回答进行评分。数值型输出整数分，分类型输出 Pass/Fail | 问答质量、内容安全等需语义理解的场景 | 有 |
| 规则评估（自动化指标） | 使用 ROUGE、BLEU、Cosine 等算法或字符串匹配直接计算 | 翻译、摘要、Function Calling 等有确定性标准的场景 | 无 |
| 人工评估（人工标注） | 人工逐条查看推理结果并标注 Pass/Fail | 创意性写作、专业领域判断等机器难以准确评价的场景 | 无 |

### 基线评测

使用公开标准数据集（C-Eval、MMLU、ARC、GSM8K、BBH、HellaSwag）快速评测模型基础能力，无需自行准备数据集或配置维度。

> **注意**：基线评测仅北京地域可用。其他地域控制台不显示此选项，属正常行为。基线评测不支持结果下载，也不支持推理结果集数据来源。

## 评测流程

端到端流程分为四个阶段：

1. **准备数据集**：在数据管理模块上传评测集（EvaluationSet）类型的数据，包含 Prompt（用户问题）和 Completion（参考答案）两列。
2. **创建评测维度**：定义评分标准和方式，从 5 种维度类型中选择（大模型评估-数值型/分类型、规则评估-文本相似度/字符串匹配、人工评估-分类型）。维度类型创建后不可修改。
3. **创建评测任务**：选择被评测模型、关联数据集和维度，可选参与排行榜。
4. **查看结果**：在指标统计 Tab 查看综合得分和通过率，在数据明细 Tab 查看逐条评分。

需注意区分两个核心概念：**评分器 Prompt** 配置于评测维度，指导裁判模型如何打分；**System Prompt** 配置于评测任务，为被评测模型设定角色定位，通常可留空。

## 评测维度配置

根据[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)文档，支持以下 5 种维度类型：

| 维度类型 | 评分方式 | 适用场景 |
|---------|---------|---------|
| 大模型评估-数值型 | 裁判模型打分（整数，如 0-5） | 问答质量、内容生成 |
| 大模型评估-分类型 | 裁判模型标签（Pass/Fail） | 内容安全、正确性判断 |
| 规则评估-文本相似度 | ROUGE/BLEU/Cosine 等 7 种算法 | 翻译、摘要 |
| 规则评估-字符串匹配 | 相等/不相等/包含 | Function Calling、NL2SQL |
| 人工评估-分类型 | 人工标注 Pass/Fail | 创意性写作、专业判断 |

### 大模型评估维度关键参数

- **裁判模型**：推荐千问-Max，推理能力强。
- **评分器模板**：数值型可选综合评测、语义相似度、自定义评测；分类型可选标准匹配判断、情感分析、自定义评分器。
- **评分范围**：仅数值型，默认 0-5 整数。
- **通过阈值**：默认 3.0，步长 0.1，评分达到此值判定为 Pass。
- **自定义 Prompt 变量**：`${prompt}`（用户问题）、`${output}`（模型回答）、`${completion}`（参考答案），须至少包含一个变量。

### 规则评估算法选择

文本相似度支持 7 种算法：ROUGE-1、ROUGE-2、ROUGE-L（文本摘要）、BLEU（翻译）、Cosine（语义理解和开放问答）、Fuzzy Match（OCR 和语音识别）、Accuracy（精确匹配）。字符串匹配支持相等、不相等、包含三种方式。

## 数据来源配置

创建评测任务时可选择两种数据来源：

| 对比项 | 评测数据集 | 推理结果集 |
|-------|-----------|-----------|
| 数据内容 | 包含 Prompt 和 Completion | 已包含模型 Output |
| 推理调用 | 系统调用被评测模型推理 | 不调用模型推理 |
| 推理费用 | 产生 | 不产生 |
| 适用场景 | 首次评测、标准流程 | 已有模型输出，降低成本 |

数据量建议：小规模验证 50-100 条，正式评测 200-500 条，全面评估 500 条以上。

## 排行榜

排行榜用于在相同评测维度下横向对比多个模型。创建时须选择评测维度（创建后不可修改），得分范围为 0-100（基于关联维度综合评分计算，与维度本身评分范围不同）。为确保公平性，建议所有任务使用相同数据集。

## 评测结果分析

据[模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)文档的建议：

- 关注**分数分布**而非仅看综合得分。综合得分是各维度平均分，可能掩盖维度间差异。
- **1-3% 的分数差异**通常为评测噪声，不建议仅凭微小分差做决策。
- 使用人工评估维度的任务须全部数据标注完成后才变为评测完成状态。
- 评测结果支持下载（待执行状态和基线评测任务除外）。

## 计费说明

评测费用由两部分构成：

| 维度类型 | 被评测模型推理费 | 裁判模型评分费 |
|---------|----------------|--------------|
| 大模型评估（数值型/分类型） | 按 Token 计费 | 按 Token 计费 |
| 规则评估（字符串匹配/文本相似度） | 按 Token 计费 | 无 |
| 人工评估（分类型） | 按 Token 计费 | 无 |
| 使用推理结果集时 | 无 | 按维度类型决定 |

推理费用计算公式：输入 Token 数 / 1M x 输入单价 + 输出 Token 数 / 1M x 输出单价。已部署的调优模型评测不额外计费（推理费用已含在部署算力费用中）。

### 成本优化策略

1. **先小规模验证**：使用 50-100 条数据验证配置正确性，确认无误后再扩大规模。
2. **保存推理结果集复用**：首次评测后下载含模型 Output 的结果，后续评测使用推理结果集方式避免重复推理。
3. **优先选规则评估**：无裁判模型费用，适用于翻译、摘要、Function Calling 等有确定性标准的场景。

## 限制与注意事项

- 当前仅支持文本生成类模型评测。
- 维度类型创建后不可修改，选错需删除重建。
- 评测任务提交后不可更换目标模型，选错需删除重建（已消耗 Token 费用不可追回）。
- 基线评测仅北京地域可用。
- 模型评测当前仅支持控制台操作，不提供公开 API/SDK。如需编程化评测，可参考 PAI Judge Model API 作为替代方案。
- 排行榜绑定的评测维度删除后，会阻止在该排行榜下创建新任务。
- LLM 评分器存在位置偏差和自我偏好偏差，建议定期人工抽查校准。

## 常见问题

**评测任务提交后状态失败**：检查数据集是否为评测集（EvaluationSet）类型并已发布版本，模型是否可选（灰色表示暂不支持），数据格式是否包含 Prompt 和 Completion 列。

**评分结果区分度低**：检查评分器 Prompt 是否有明确评分标准和正确变量引用，为每个分数档提供清晰判定条件，并确认裁判模型推理能力足够（推荐千问-Max）。

**评分范围与通过阈值混淆**：评分范围定义打分区间（整数，如 0-5），通过阈值是判定 Pass/Fail 的分界线（支持小数，如 3.0）。前者决定"能得几分"，后者决定"几分算及格"。
