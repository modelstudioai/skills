# model evaluation introduction

模型评测是百炼平台提供的核心模型能力评估功能，支持通过标准化或自定义方式对文本生成类模型的输出质量进行量化打分与横向对比。它服务于模型选型、调优效果验证、能力基线建立和持续质量监控等关键研发场景，覆盖从快速基线测试到精细化业务效果评估的完整闭环。当前功能仅面向文本生成类模型，不支持多模态或语音类模型。

## 支持的模型与功能

- **支持的模型类型**：仅支持文本生成类（text-generation）模型，包括百炼预置模型（如千问系列）及用户调优后的文本生成模型；[模型评测产品概览](../../raw/model-user-guide/model-evaluation-introduction.md)明确指出“当前仅支持文本生成类模型评测”。
- **评测方式**：
  - **自定义评测**：使用用户上传的评测数据集（EvaluationSet 类型）或已有的推理结果集，配合自定义创建的评测维度（含大模型评估、规则评估、人工评估三类共五种类型），实现业务场景驱动的精准评估。
  - **基线评测**：内置通用知识、数学、代码、上下文推理、领域专项五大类共13个公开标准 benchmark（如 MMLU-Pro、GSM8K、HumanEval），全自动执行、无需准备数据或配置维度；但需注意，[模型评测 (raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) 明确说明“基线评测仅北京地域可用”，其他地域控制台不显示该选项。
- **核心功能模块**：评测维度（可复用的评分模板）、评测任务（执行单元）、排行榜（跨任务模型对比）、人工标注（针对人工评估维度）、基线报告（含多任务雷达对比）。

> **注意**：文档1中“基线评测”章节称其“仅北京地域可用”，而文档2未提及地域限制，但文档2作为《评测维度》专项文档，聚焦维度定义本身，不涉及基线评测部署范围。因此以文档1为准，此为平台实际运行约束，非矛盾信息。

## 关键参数

| 参数类别 | 参数名 | 说明 | 必填性 | 备注 |
|----------|--------|------|--------|------|
| **通用** | 维度名称 | 维度模板标识，≤20字符 | 是 | 命名建议采用“评估方面+评估方式”，如`回答准确性-LLM评分` |
| | 描述 | 补充说明，≤100字符 | 否 | — |
| **大模型评估** | 裁判模型 | 执行评判的LLM（如千问-Max） | 是（仅大模型评估类型） | 影响评分质量与费用 |
| | 评分器模板 | 预置Prompt模板（如综合评测、标准匹配）或自定义 | 是（仅大模型评估类型） | 切换将覆盖当前Prompt |
| | 评分范围（数值型） | 整数区间，如`0-5` | 是（仅数值型） | 默认`0-5`，最小值≥0，最大值≥1 |
| | 通过阈值（数值型/相似度型） | 判定Pass的最低分/相似度值 | 是（数值型/相似度型） | 步长0.1（数值型）或0.01（相似度型） |
| | Pass/Fail标签（分类型） | 分类标签，各≤20字符且互斥 | 是（分类型） | 标签不可重复，须穷尽所有可能输出 |
| **规则评估** | 比较操作符（字符串匹配） | 相等/不相等/包含 | 是（字符串匹配） | — |
| | 评估指标（文本相似度） | ROUGE-1/ROUGE-2/ROUGE-L/BLEU/Cosine/Fuzzy Match/Accuracy | 是（文本相似度） | 按场景选择：翻译用BLEU，摘要用ROUGE-L，语义相关用Cosine |
| **所有类型** | Prompt变量 | `${prompt}`、`${output}`、`${completion}` | 是（大模型评估Prompt中） | 至少包含一个，否则提交失败；详见[评测维度 (raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md)](../../raw/model-user-guide/model-evaluation-introduction/evaluation-metrics.md) |

## 使用方式

1. **准备数据**：在数据管理模块上传评测集（EvaluationSet 类型），至少包含 `Prompt`（问题）和 `Completion`（参考答案）两列；若使用推理结果集，则需预先包含 `Output` 字段。
2. **创建评测维度**：进入**评测维度**页签 → **创建评测维度** → 选择类型 → 配置参数（如裁判模型、评分范围、标签、算法等）→ 保存。维度创建后类型不可修改。
3. **创建评测任务**：
   - **自定义评测**：选择**评测任务** → **创建评测任务** → 选“自定义” → 选择被测模型 → 选择数据来源（评测数据集或推理结果集） → 关联已创建的维度 → （可选）开启排行 → **开始评测**。
   - **基线评测**：同上，但评测方式选“基线评测”，选择目标模型与benchmark（如MATH-500），可选数据采样百分比。
4. **查看结果**：
   - 自定义任务：在任务详情页的**指标统计**页签查看综合得分、通过率、分数分布；在**数据明细**页签查看每条样本的逐项评分。
   - 基线任务：在**任务总览**看雷达图与整体得分，在**基线评分明细**下钻各benchmark，在**Case分析**查看具体输入/输出/评判依据。
5. **管理与迭代**：通过排行榜横向对比多模型；下载结果用于离线分析；根据小规模验证（50–100条）结果优化Prompt或维度配置，再扩大评测规模。

## 限制和注意事项

- **地域限制**：基线评测功能仅在北京地域（华北2）可用，其他地域控制台不提供该选项，属平台部署策略，非配置错误。
- **模型限制**：仅支持文本生成类模型；多模态、语音、embedding等模型暂不支持评测。
- **维度约束**：评测维度类型创建后不可修改，选错需删除重建；已被排行榜绑定的维度删除后，该排行榜将无法创建新任务（绑定维度为空）。
- **费用说明**：费用由两部分构成——被评测模型的推理费（使用评测数据集时产生）和裁判模型的评分费（仅大模型评估维度产生）；规则评估与人工评估无裁判模型费用；使用推理结果集可避免被测模型推理费。
- **结果解读**：综合得分是各维度平均分，易掩盖维度间差异；应结合**分数分布图**与**逐维度分析**定位短板；1–3%的分数差异通常属评测噪声，不宜作为决策唯一依据。
- **人工评估特殊性**：任务状态在全部人工标注完成前始终为“进行中”，不可下载结果；标签设计须简洁明确、互斥穷尽，避免歧义。
