# 函数调用

函数调用（Function Calling）是大模型根据用户输入和工具描述，自主判断是否调用外部函数并生成结构化参数的能力。在百炼平台中，函数调用是连接大模型与外部工具（插件、MCP 服务、自定义 API）的核心机制。

## 工作原理

函数调用的基本流程为：

1. 开发者向模型注册可用工具的名称、描述和参数结构
2. 用户发送请求时，模型根据上下文判断是否需要调用工具
3. 模型输出结构化的函数名和参数（而非自然语言）
4. 应用侧执行实际函数调用并将结果返回模型
5. 模型根据返回结果生成最终回复

单次任务中支持组合调用多个工具（最多 10 个），模型会根据输入自动选择调用一个或多个。

## 在百炼平台的使用场景

### 智能体应用

- **Agent 2.0（推荐）**：将知识库、MCP 服务统一为工具，由智能体自主规划调用顺序，支持完整的"规划-执行-反思"链路。可配置 ReAct 最大轮次（1-50）限制单次会话中工具调用的最大次数。
- **Agent 1.0**：知识库检索先行，再决策是否调用其他工具，适用于流程固定的简单任务。

### 工作流应用

将工具作为工作流节点，按预定义编排执行，而非由大模型主动规划。需通过大模型节点做自然语言与参数的转换。

### API 直接调用

通过 OpenAI 兼容的 Chat Completions 接口（`/v1/chat/completions`）的 `tools` 参数传递工具定义。Assistant API 中通过 `tools` 参数指定工具 ID 进行调用。

### 意图路由

使用专用的意图理解模型 `tongyi-intent-detect-v3` 可在百毫秒级内解析用户意图并选择工具，常用于路由层，替代"先让通用大模型识别意图"的高成本方案。

## 关键参数和配置

### 工具定义

| 参数 | 说明 |
|------|------|
| `tools` | 工具列表，包含每个工具的名称、描述和参数 schema |
| `tool_choice` | 控制模型是否强制调用工具（auto/none/指定工具） |

### 插件调用参数

| 参数 | 说明 |
|------|------|
| 工具 ID | 在插件详情页获取，通过 `tools` 参数传递 |
| `biz_params` | 传递业务透传参数或用户级鉴权信息 |
| 输入参数传参方式 | "大模型识别"（从用户输入提取）或"业务透传"（外部主动传入） |

### 智能体配置

| 参数 | 说明 |
|------|------|
| ReAct 最大轮次 | 1-50，限制工具调用链的最大长度 |
| enable_thinking | 开启思考模式，提升智能体反思与规划效果 |
| 插件超时 | 自定义插件超时限制为 5 秒 |

## 支持函数调用的模型

- **通用对话模型**：千问-Max、千问-Plus、千问-Turbo（推荐使用具备强工具调用能力的模型）
- **视觉理解模型**：千问VL-Max、千问VL-Plus
- **专用意图模型**：`tongyi-intent-detect-v3`（上下文 8,192 Token，百毫秒级响应）

## 工具接入方式

百炼平台提供三种工具接入途径，均基于函数调用机制：

- **插件**：官方插件直接使用，自定义插件需配置 API 路径、鉴权和参数结构
- **MCP 服务**：通过标准化协议接入，支持云部署和自定义部署，智能体最多同时添加 5 个 MCP 服务
- **[OpenAI 兼容接口](openai-compatible-api.md)**：通过 `tools` 参数定义函数，适用于代码直接集成场景

## 注意事项

- 函数调用会增加 Token 消耗：工具描述和返回结果均计入上下文
- 效果依赖提示词质量：需在提示词中明确工具名称和能力描述
- MCP 服务不能在直接调用千问 API 时接入，必须集成在智能体或工作流应用中
- 自定义插件的工具必须处于"已发布"状态才能在应用中被调用
