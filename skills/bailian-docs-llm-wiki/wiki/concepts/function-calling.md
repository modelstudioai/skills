# 函数调用与工具使用

函数调用（Function Calling）与工具使用（Tool Use）是大模型与外部系统交互的核心机制。在百炼平台中，大模型根据用户输入、工具名称和工具描述自主判断是否需要调用外部工具，从而弥补模型在实时信息获取、精确计算、代码执行等方面的不足。

## 调用机制

百炼平台的函数调用遵循"判断 — 调用 — 整合"三步流程：

1. **判断**：大模型根据用户输入内容和已注册工具的名称、描述，决定是否需要调用工具
2. **调用**：若需要调用，模型选择合适的工具并生成调用参数，平台内部完成实际调用
3. **整合**：工具返回结果与用户内容合并后再次输入大模型，生成最终回复

若模型判断无需调用工具，则直接生成回复输出。

## 工具接入方式

百炼平台提供多种工具接入途径，适用于不同应用类型和开发场景：

### 插件（Plugin）

插件是百炼最早期的工具扩展机制，分为官方插件（如 Python 代码解释器、夸克搜索、计算器等）、三方插件和自定义插件。每个智能体应用最多支持添加 10 个工具。自定义插件需配置插件 URL、工具路径、输入输出参数和鉴权信息。自定义插件在旧版智能体中的超时限制为 5 秒。

### MCP 协议

模型上下文协议（MCP）是新版智能体（Agent 2.0）推荐的工具接入方式，提供标准化的工具连接协议。支持官方预部署的 MCP 服务和自定义部署（npx/uvx/http），每个智能体应用最多同时添加 5 个 MCP 服务。自定义插件也支持一键发布为 MCP 服务。

### [OpenAI 兼容接口](openai-compatible-api.md)

通过 Responses API（`/v1/responses`）可使用百炼提供的内置工具，包括联网搜索、网页抓取、代码解释器、文搜图、图搜图等，无需额外配置即可使用。

### 意图理解模型

百炼提供专用的意图理解模型 `tongyi-intent-detect-v3`，可在百毫秒级内解析用户意图并选择工具，常用于路由层替代通用大模型做意图识别，降低成本和延迟。

## 在不同应用类型中的使用

| 应用类型 | 工具调用方式 | 特点 |
|---------|------------|------|
| 智能体 Agent 2.0 | MCP 协议 | 模型自主规划调用顺序，支持"规划-执行-反思"链路 |
| 智能体 Agent 1.0 | 插件 | 知识库检索先行，再决策是否调用工具 |
| 工作流应用 | 插件节点 / MCP 节点 | 按编排顺序执行，非模型自主规划 |
| API 直接调用 | Chat Completions / Responses | 通过 tools 参数定义可用函数 |

## 关键参数与配置

### 工具定义参数

| 参数 | 说明 |
|------|------|
| 工具名称 | 具有语义的名称，帮助模型理解工具功能 |
| 工具描述 | 功能和使用场景的简要说明，直接影响模型的调用判断 |
| 输入参数 | 分为"大模型识别"（从用户输入中提取）和"业务透传"（外部主动传入）两种方式 |
| 输出参数 | 定义 API 返回结果的筛选和重组规则 |

### 运行时参数

| 参数 | 说明 |
|------|------|
| ReAct 最大轮次 | 限制单次会话中工具调用的最大次数（1-50），超出后自动退出调用链路 |
| enable_thinking | 开启思考模式有助于提升智能体的工具调用反思效果 |
| temperature | 较低值有利于工具调用的稳定性 |

### 鉴权配置

自定义插件和 MCP 服务均需配置鉴权：
- 插件支持服务级和用户级鉴权，Token 类型支持 basic / bearer / appcode
- MCP 服务通过请求头中的百炼 API Key 进行鉴权

## 支持的模型

函数调用能力要求模型具备工具理解和参数生成能力，推荐使用以下模型：

- **千问-Max 系列**：工具调用能力最强，推荐用于新版智能体的多步规划
- **千问-Plus / 千问-Turbo**：适用于一般工具调用场景
- **千问3 系列**：推理能力更强，适合复杂工具编排
- **tongyi-intent-detect-v3**：专用意图理解模型，适合路由层快速决策

## 框架集成

主流开发框架均支持百炼的函数调用能力：
- **LlamaIndex**（Python）：通过 DashScope 集成，支持 RAG 与工具调用
- **Spring AI Alibaba**（Java）：通过 `DashScopeAgent` 调用智能体应用，支持[流式输出](streaming.md)和思考过程展示
- **Qwen Agent**：支持 MCP SDK 编码调用，适合自定义工具编排

## 限制与注意事项

- 工具名称和描述的质量直接影响模型的调用准确性，建议使用语义清晰的命名
- MCP 服务不能在直接调用千问 API 时接入，必须集成在智能体或工作流应用中
- 调用工具会增加 Token 消耗：工具返回的内容作为上下文传入模型，增加输入 Token
- 工作流中插件按编排方式执行，而非由大模型主动规划调用
- GET 请求方法下的输入参数不支持 Object 类型
