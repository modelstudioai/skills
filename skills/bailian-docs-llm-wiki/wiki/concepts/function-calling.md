# 函数调用与工具使用

函数调用（Function Calling）是大语言模型与外部工具交互的核心机制，允许模型在对话过程中识别用户意图并自动调用预定义的函数或工具来完成特定任务。在百炼平台中，函数调用贯穿于模型推理、智能体应用、工作流编排和实时多模态交互等多个场景，是构建具备实际行动能力的 AI 应用的基础。

## 基本原理

函数调用的工作流程分为三步：

1. **声明工具**：开发者在请求中通过 `tools` 参数描述可用函数的名称、功能说明和参数结构（JSON Schema）。
2. **模型决策**：模型根据用户输入和工具描述，自主判断是否需要调用工具，并生成结构化的调用参数。
3. **执行与回传**：客户端执行实际的函数调用，将结果回传给模型，模型据此生成最终回复。

模型本身不直接执行函数，而是输出调用意图和参数，由客户端负责实际执行。

## 在百炼平台中的使用场景

### 模型推理（API 直接调用）

百炼的文本生成模型（Qwen 系列）通过 [OpenAI 兼容接口](openai-compatible-api.md)、Anthropic 兼容接口或 DashScope 原生接口均支持 Function Calling。开发者在请求中传入 `tools` 数组定义可用工具，模型在需要时返回 `tool_calls` 响应。

主要支持的模型包括：

| 模型 | Function Calling | 内置工具 |
|------|-----------------|---------|
| qwen3.7-max | 支持 | 支持 |
| qwen3.7-plus | 支持 | 支持 |
| qwen3.6-flash | 支持 | 支持 |
| deepseek-v4-pro | 支持 | 不支持 |

除了自定义函数调用外，部分模型还支持**内置工具**（联网搜索、代码解释器等），无需开发者自行实现执行逻辑。

### 插件系统

插件是百炼平台对 Function Calling 的产品化封装。每个插件包含一个或多个工具，平台提供三类插件：

- **官方插件**：如 Python 代码解释器（`code_interpreter`）、夸克搜索（`quark_search`）、图片生成（`text_to_image`）等，开箱即用。
- **第三方插件**：来自合作伙伴的商业服务插件，开通后即可调用。
- **自定义插件**：开发者将自有 API 封装为插件，需配置插件 URL、工具路径、鉴权方式、输入/输出参数等。

单次任务中最多可组合调用 10 个工具，模型根据输入自动选择调用其中一个或多个。

### MCP 协议集成

模型上下文协议（MCP）是百炼平台连接大模型与外部工具的标准化协议。通过 MCP，开发者可以将工具以标准化方式接入智能体或工作流应用，而无需为每个工具编写定制接口。MCP 服务支持官方预部署服务和自定义部署（npx/uvx/http）两种方式。

需要注意的是，MCP 服务不能在直接调用千问 API 时使用，必须集成在智能体或工作流应用中。

### 智能体应用

在智能体应用中，Function Calling 是模型自主规划和执行的基础：

- **新版智能体（Agent 2.0）**：将知识库、MCP、插件统一为工具，由模型自主规划调用顺序，支持完整的"规划-执行-反思"链路。可通过 `ReAct 最大轮次`（1-50）限制单次会话的工具调用次数。
- **旧版智能体（Agent 1.0）**：采用"先检索知识库、再决策是否调用其他工具"的固定流程。
- **Assistant API**：通过 `tools` 参数指定工具 ID 进行调用，若插件存在业务透传参数或用户级鉴权，需通过 `biz_params` 传递。

### 工作流应用

在工作流中，工具调用以节点形式编排。每个 MCP 节点手动指定一个工具，通过大模型节点完成自然语言与参数之间的转换，按预定义流程串联执行。

### 实时多模态交互

Qwen-Omni-Realtime API 支持在实时语音对话中进行工具调用。模型在语音交互过程中识别调用需求，通过 `conversation.item.create` 事件回传工具调用结果，再由 `response.create` 触发后续响应。目前仅 Qwen3.5-Omni-Realtime 系列支持实时工具调用。

## 关键参数与配置

### tools 参数

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "获取指定城市的天气信息",
        "parameters": {
          "type": "object",
          "properties": {
            "city": {
              "type": "string",
              "description": "城市名称"
            }
          },
          "required": ["city"]
        }
      }
    }
  ]
}
```

### 常用配置项

| 参数 | 说明 | 适用场景 |
|------|------|---------|
| `tools` | 工具定义数组，描述函数名称、说明和参数结构 | API 调用、Assistant API |
| `tool_choice` | 控制模型是否调用工具（`auto`/`none`/指定函数） | API 调用 |
| `enable_thinking` | 开启思考模式，提升复杂工具选择的准确性 | Qwen3 及以上模型 |
| `biz_params` | 传递业务透传参数或用户级鉴权信息 | 自定义插件调用 |

### 自定义插件核心配置

创建自定义插件时需关注以下要素：

- **插件 URL**：API 的访问域名（同一插件下的工具共享域名）
- **工具路径**：相对于插件 URL 的路径，如 `/query`
- **鉴权配置**：支持服务级鉴权和用户级鉴权，Token 可放在 Header 或 Query 中
- **输入参数传参方式**："大模型识别"（从用户输入提取）或"业务透传"（外部主动传入）
- **输出参数**：定义 API 返回的数据结构，模型据此筛选和组合结果

## 最佳实践

1. **工具描述要清晰准确**：模型根据工具的 `description` 和参数说明决定是否调用，描述越精确命中率越高。
2. **合理控制工具数量**：单次请求中工具过多会增加 Token 消耗和决策复杂度，建议按场景精简。
3. **优先选用强推理模型**：复杂的多工具选择场景推荐使用千问-Max 或千问-Plus 系列，效果更稳定。
4. **结合思考模式使用**：对于多步工具调用链路，开启 `enable_thinking` 可提升规划准确性。
5. **注意 Token 消耗**：工具定义和调用结果都会计入上下文 Token，需关注成本。
