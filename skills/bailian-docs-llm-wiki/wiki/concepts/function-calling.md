# 函数调用

函数调用（Function Calling）是指大模型在对话过程中，根据用户输入自主判断需要调用某个外部工具或接口，并由平台执行后将结果回传给模型、再由模型整合成最终回复的机制。它是让大模型从"只会生成文本"扩展到"能操作系统、查询数据、执行动作"的核心能力。

## 在百炼平台中的实现形式

百炼平台围绕函数调用提供了三层递进的能力：插件、MCP 服务、以及作为函数调用路由专用通道的意图理解模型。

### 1. 插件机制

插件是函数调用最传统的承载方式。每个插件下挂若干"工具"，工具对外暴露名称、描述、输入输出参数。模型在对话中读取这些元信息，决定是否调用、传什么参。

调用入口有三种：

| 调用方式 | 适用场景 | 触发方 |
| --- | --- | --- |
| 智能体应用 | 零代码对话场景 | 模型根据用户输入与工具描述自动判断 |
| 工作流应用 | 固定流程编排 | 作为节点按编排执行，不由模型主动规划 |
| Assistant API | 代码集成 | 通过 `tools` 参数显式指定工具 ID |

可选工具包括官方插件（代码解释器、计算器、夸克搜索等）、第三方插件、以及开发者通过 OpenAPI 规范接入的自定义插件。单个任务最多组合调用 10 个工具。

### 2. MCP（Model Context Protocol）

MCP 是插件机制的升级形态，基于 Anthropic 开源的标准化协议，统一了工具的接入与调用方式。相比插件，MCP 的优势在于：

- 工具生态更广（社区 MCP 服务可直接接入）
- 支持外部调用（Cherry Studio、Cursor、Qwen Agent 等客户端可通过 Streamable HTTP 协议直接调用百炼托管的 MCP 服务）
- 智能体与工作流应用内均可使用

在智能体 2.0 中，知识库、MCP 工具被统一视为"工具"，由模型自主规划调用顺序；智能体最多可同时挂载 5 个 MCP 服务。

### 3. 意图理解模型（专用路由）

对于希望在调用大模型前先做一层"快速意图分流"的场景，百炼提供专用意图模型 `tongyi-intent-detect-v3`。它可在百毫秒级内判断用户意图并选择对应的下游工具或 Agent，常用于函数调用的前置路由层，避免让通用大模型承担意图识别的成本。

## 关键参数与配置

### 工具描述质量

函数调用效果高度依赖工具的元信息。无论插件还是 MCP，都需关注：

- **工具名称**：语义清晰，避免模糊命名
- **工具描述**：用自然语言准确描述功能，模型据此判断是否调用
- **输入参数说明**：明确每个参数的类型、是否必填、取值范围
- **传参方式**：自定义插件可设为"大模型识别"（由模型从用户输入抽取）或"业务透传"（外部系统主动注入）

### 模型选型

函数调用对模型的推理与工具使用能力有要求。推荐选用：

- 千问-Max 系列（通用场景下工具调用能力最强）
- 千问 3 系列（新一代推理模型，工具调用效果更佳）
- `tongyi-intent-detect-v3`（仅用于意图路由，不生成回复）

若函数调用效果不理想，优先更换更强的推理模型，其次优化提示词中对工具使用场景的描述。

### 智能体侧配置

在智能体应用中启用函数调用相关能力时，可调整：

| 参数 | 作用 |
| --- | --- |
| ReAct 最大轮次 | 1–50，限制单次会话内工具调用的最大次数，超出后强制模型输出最终回复 |
| enable_thinking | 开启思考模式，有助于模型在工具调用后反思结果是否正确（仅部分模型支持） |
| temperature | 控制生成随机性；工具调用场景通常建议使用较低值以提升确定性 |

### MCP 服务接入要点

通过 API 接入百炼 MCP 服务时，需要注意：

- 端点格式：`https://dashscope.aliyuncs.com/api/v1/mcps/<service-name>/mcp`
- 鉴权：请求头携带 `Authorization: Bearer <api-key>`
- 协议：已从旧版 SSE 升级为 Streamable HTTP，老用户需重新开通以完成升级
- Token 成本：MCP 返回内容会作为上下文送入模型，会增加输入 Token；必要时精简返回字段

## 自定义工具开发要点

当官方工具无法满足需求时，可通过以下方式扩展函数调用能力：

1. **自定义插件**：在百炼控制台配置 API 路径、鉴权、输入输出参数，调试通过后发布。只有"已发布"状态的工具才能被模型调用。
2. **自定义 MCP 服务**：支持 npx（Node.js）、uvx（Python）、http（远程服务器）三种部署方式，仅限部署者主账号及授权 RAM 用户使用。

自定义插件的超时限制为 5 秒，设计工具接口时需注意响应时间。

## 常见陷阱

- **工具描述模糊**：模型无法准确判断何时调用，出现该调不调或不该调乱调
- **参数传参方式选错**：需要用户输入中提取的参数被设成"业务透传"，导致工具拿不到值
- **MCP 返回内容过大**：占满上下文窗口，挤压模型推理空间，同时推高 Token 成本
- **在 API 直调中接入 MCP**：MCP 必须通过智能体或工作流应用承载，不能直接在千问 API 请求里挂载
