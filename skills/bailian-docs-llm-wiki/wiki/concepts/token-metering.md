# Token 计量与计费

Token 是百炼平台衡量模型输入与输出文本量的基本单位，平台以 Token 数量为核心维度进行用量统计和费用结算。理解 Token 计量机制是控制成本、优化调用策略的前提。

## Token 的含义与计算

在大语言模型中，Token 并非等同于字符或词语——中文通常 1 个汉字约对应 1～2 个 Token，英文单词约对应 1～4 个 Token，具体取决于模型使用的分词器。百炼平台按**输入 Token**（用户发送给模型的内容）和**输出 Token**（模型生成的内容）分别计量，两者通常采用不同单价。

不同模型类型的计量单位有所差异：

| 模型类型 | 计量单位 |
|----------|----------|
| 大语言模型（文本生成/深度思考/视觉理解） | Token |
| 图像生成 | 张 |
| 视频生成 | 秒 |
| 语音模型 | 秒、字符或 Token（视模型而定） |
| 全模态模型 | Token（各模态均折算） |
| 向量模型 | Token |

## 计费模式

百炼平台的 Token 计费覆盖三大场景：

### 模型推理调用

按输入/输出 Token 数量计费，部分模型实行**阶梯计费**——单价取决于单次请求的输入 Token 总量，所有 Token 统一按命中的阶梯单价结算，不做分段。以千问系列为例：

| 模型 | 输入单价（每百万 Token） | 输出单价（每百万 Token） |
|------|------------------------|------------------------|
| qwen3.7-max | 12 元 | 36 元 |
| qwen3-max (0~32K) | 2.5 元 | 10 元 |
| qwen-plus (0~128K) | 0.8 元 | 非思考 2 元 / 思考 8 元 |

Batch 调用可享半价，上下文缓存可获折扣，但两者不能同时生效。

### 模型训练

按训练 Token 计费，公式为：`(训练数据 Token + 混合训练数据 Token) × 循环次数 × 单价`。图像和视频生成模型的训练 Token 计算方式有所不同。

### 模型部署

提供三种计费方式：

- **预置吞吐（PTU）**：按使用时长和购买的 TPM 量计费，超出部分自动降级为按量付费。
- **模型单元（MU）**：按使用时长与单元数量计费，资源独占。
- **按 Token 用量**：仅适用于部分 LoRA 调优后模型，按实际输入/输出 Token 结算。

## Token Plan 订阅制

除按量付费外，百炼还提供订阅制方案：

- **Token Plan 团队版**：按 Credits 计量（Credits 由输入/缓存/输出 Token 抵扣），面向团队，覆盖文本与图像模型，无频次限制。
- **Coding Plan**：按模型调用次数计量，面向个人开发者，仅文本模型，有每 5 小时/每周/每月限额。

两者使用各自独立的 API Key 和 Base URL，不可混用。

## 免费额度

首次开通百炼的用户自动获得各模型的免费推理额度（有效期 30～90 天，仅限中国内地版模型）。免费额度仅抵扣实时推理费用，不支持 Batch 调用、模型调优与部署。建议开启**免费额度用完即停**功能，避免额度耗尽后自动扣费。

抵扣优先级为：免费额度 > 资源包 > 其他模型节省计划 > AI 通用型节省计划 > 按量付费。

## 成本优化

百炼提供三种成本优化工具，推荐优先级：AI 通用型节省计划 > 其他模型节省计划 > 资源包。

- **AI 通用型节省计划**：承诺月消费金额换取阶梯折扣（最高 5.3 折），覆盖阿里直供全部模型的调用费用。
- **其他模型节省计划**：针对特定模型系列，如千问语音模型（最高 8 折）、向量模型（最高 7 折）。
- **资源包**：预购固定 Token 数量，抵扣特定模型用量。

## 限流机制（RPM/TPM）

限流按主账号维度聚合，每个模型同时受 RPM（每分钟请求数）与 TPM（每分钟 Token 数）双重限制。超出任一阈值即触发限流，常见错误包括 `Requests rate limit exceeded`（RPM 超限）和 `Allocated quota exceeded`（TPM 超限）。

应对策略：降低调用频率、缩短输入、限制 `max_tokens` 输出长度、采用指数退避重试。

## 用量监控与账单

### 用量统计

在控制台「模型用量」页面可查看各模型的 Token 消耗情况，数据按业务空间维度统计，延迟约 1 小时。近 30 天以外的数据需通过阿里云「费用与成本」页面导出。

### 应用观测

应用观测功能可追踪每次调用的 Token 总量、输入/输出 Token 分布，支持按 Token 量过滤 Span，并提供平均单次请求 Token 量等聚合指标。

### 模型监控

高级监控支持分钟级的 Token 消耗数据采集（指标 `model_usage`），可接入 Grafana 等工具进行自定义可视化，并配置告警规则及时发现用量异常。

### 出账时间

大模型推理分钟级出账（通常 2～10 分钟），批量推理和模型训练为小时级出账。

## 开发者最佳实践

- 通过 `max_tokens` 参数控制单次生成长度，防止输出失控。
- 简单任务优先选用轻量级模型（如 qwen-flash），降低单次 Token 成本。
- 精简 Prompt，减少不必要的上下文输入。
- 非实时大批量任务使用 Batch 调用，可享半价优惠。
- 配置模型监控告警，设定 Token 消耗阈值，及时发现异常。
