# 模型评测

模型评测是百炼平台面向文本生成类大模型提供的标准化、可复用的量化评估能力，用于客观衡量模型在指定任务上的输出质量，并支持跨模型、跨版本、跨维度的横向对比与持续监控。

## 在百炼平台的不同场景中，这个概念如何使用

- **模型选型阶段**：通过基线评测（如 MMLU-Pro、GSM8K、HumanEval 等 13 个公开 Benchmark）快速比对多个预置模型（如 Qwen3.7-Max、DeepSeek-v4-pro）在通用能力上的表现，无需准备数据或配置维度，**仅限北京地域（华北2）可用**。  
- **调优验证阶段**：使用自定义评测，上传业务专属的 `EvaluationSet` 数据集（含 `Prompt` 和 `Completion` 字段），结合定制化评测维度（如“客服响应合规性”“金融术语准确性”），验证微调/蒸馏后模型的效果提升。  
- **上线后质量监控**：将线上 SLS 推理日志回流为结构化评测集，定期执行相同维度的评测任务，追踪模型在真实流量下的稳定性与退化趋势；支持通过“排行榜”功能长期跟踪多版本模型在同一维度下的得分变化。  
- **成本优化实践**：复用已有推理结果集（而非重新调用被测模型）进行纯评分，规避重复推理费用；对规则类维度（字符串匹配、文本相似度）优先选用，避免裁判模型调用开销。

> ⚠️ 注意：模型评测**仅支持文本生成类模型**（Text Generation），不适用于[多模态](multi-modal.md)、语音、向量嵌入等模型类型；所有评测任务均需在控制台「模型评测」模块中创建，与训练集、RAG 等模块解耦。

## 关键参数和配置

| 类别 | 参数 | 说明 | 实用建议 |
|------|------|------|----------|
| **评测维度** | 维度类型 | 必填，5 种之一：<br>• `大模型评估-数值型` / `-分类型`<br>• `规则评估-字符串匹配` / `-文本相似度`<br>• `人工评估-分类型`<br>**创建后不可修改** | 优先尝试规则评估（零成本、高确定性）；复杂语义判断再启用大模型评估。 |
| | 裁判模型（仅大模型评估） | 必填，推荐 `qwen-max` 或 `qwen3.7-max` | 避免使用小模型作裁判，易引入评分偏差；注意该模型调用单独计费。 |
| | 评分器 Prompt（仅大模型评估） | 必填，须含 `${prompt}` / `${output}` / `${completion}` 至少一个变量 | 示例：`请基于以下prompt和模型输出，判断回答是否包含准确的年份信息（2020–2025）。仅输出数字：1（是）或 0（否）。prompt: ${prompt}\noutput: ${output}` |
| | 评分范围 & 通过阈值 | 数值型：整数区间（默认 `0–5`）；相似度型：`0–1` 区间 | 阈值建议设为业务可接受下限（如客服场景设 `3.0`，代码生成设 `4.0`）；避免设过严导致误判。 |
| **评测任务** | 数据来源 | 二选一：<br>• `评测数据集` → 触发被测模型推理（产生推理费）<br>• `推理结果集` → 仅调用裁判模型评分（无推理费） | 小规模验证用 50–100 条数据集；批量回归测试优先复用历史结果集。 |
| | System Prompt | 可选，作用于**被测模型**（非裁判模型），用于角色设定（如“你是一名资深医生”） | 与评分器 Prompt 严格区分：前者影响模型行为，后者指导裁判逻辑。 |

## 面向开发者的小贴士

- ✅ **起步最快路径**：北京地域用户 → 创建基线评测任务 → 勾选 `GSM8K` + `HumanEval` → 选 `qwen3.7-max` → 查看雷达图与 Case 分析，10 分钟完成首评。  
- ✅ **低成本验证技巧**：先用规则评估（如关键词存在性、JSON 格式校验）快速过滤硬伤；再对通过规则的样本启用大模型评估，节省 60%+ 裁判费用。  
- ✅ **Bad Case 定位法**：在「数据明细」页按分数排序，导出低分样本 → 检查 `prompt` 是否模糊、`completion` 是否偏离 `completion` 标准答案 → 反哺数据清洗或 Prompt 优化。  
- ❌ **避坑提醒**：  
  - 非北京地域无法看到「基线评测」选项，属正常限制，勿反复刷新；  
  - 维度类型一旦创建不可改，命名时加后缀如 `_v2_numerical` 便于迭代；  
  - 综合得分是各维度平均值，若某维度得分骤降（如从 4.2→2.1），应优先排查该维度配置而非整体模型。
