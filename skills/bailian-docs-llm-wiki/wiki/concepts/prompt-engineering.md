# Prompt 工程

Prompt 工程是指通过系统化地设计、优化和管理提示词（Prompt），最大化大语言模型输出质量的方法论与实践。在阿里云百炼平台中，Prompt 工程贯穿应用构建、模型调优和效果评测的全流程，是开发者有效利用大模型能力的核心技能。

## 核心概念

Prompt 是用户向大模型发送的指令或输入文本，模型的输出质量高度依赖于 Prompt 的设计质量。Prompt 工程的目标是通过结构化的方法，使模型输出更准确、更符合预期。

关键设计原则：

- **清晰具体**：任务描述越清晰、无歧义，模型表现越能符合预期
- **结构化组织**：按"背景 + 目的 + 风格 + 语气 + 受众 + 输出"等要素组织 Prompt
- **Few-shot 示例**：提供少量示例让模型理解期望的输出格式和风格
- **链式思考（CoT）**：引导模型逐步推理，在复杂逻辑任务中显著提升表现

## Prompt 工程框架

百炼平台内置三种 Prompt 工程框架，适用于不同复杂度的任务：

| 框架 | 组成要素 | 适用场景 |
| --- | --- | --- |
| **ICIO** | 指令 + 背景信息 + 补充数据 + 输出格式 | 简单明确的任务（数据分析、内容生成、文本摘要） |
| **CRISPE** | 角色与能力 + 背景信息 + 任务 + 输出风格 + 输出范围 | 需要 AI 扮演特定角色的交互（客服、创意写作） |
| **RASCEF** | 角色 + 行动 + 步骤 + 上下文 + 示例 + 格式 | 多步骤复杂业务流程（项目规划、战略分析） |

在控制台创建自定义 Prompt 模板时，可选择"基于 Prompt 工程创建"模式，直接使用这些框架进行结构化设计。

## 在百炼平台中的应用场景

### Prompt 模板管理

百炼提供 Prompt 模板功能，将固定结构与动态变量分离，实现 Prompt 的复用与团队协作：

- **预置模板**：涵盖营销文案、摘要抽取、文案润色等通用场景，开箱即用
- **自定义模板**：支持文本生成和图片生成两种类型，可通过控制台、API 或 SDK 使用

通过 API 管理 Prompt 的核心优势在于：逻辑与内容分离（无需重部署即可更新 Prompt）、集中管理便于团队协作、跨服务版本一致性保障。

### Prompt 优化

百炼提供两种 Prompt 优化方式：

- **自动优化**：大模型对原始 Prompt 进行结构重组、角色引导、指令增强和安全边界注入，不计费
- **反馈优化**：引入用户提供的样例数据和评测数据，通过多轮自动化评估、反思和优化生成更精准的 Prompt。建议提供 5~10 条样例数据和至少 20 条评测数据

### 多模态 Prompt 设计

Prompt 工程不仅适用于文本生成，百炼在多模态场景中同样提供了 Prompt 设计指南：

- **文生图**：通过 `prompt`（正向提示词）和 `negative_prompt`（反向提示词）控制生成内容。基础公式为"主体 + 场景 + 风格"，进阶公式增加镜头语言、氛围词和细节修饰
- **文生视频/图生视频**：基础公式为"主体 + 场景 + 运动"，支持声音描述和多镜头分镜

### 智能体应用中的系统提示词

在智能体应用中，系统提示词（System Prompt）用于定义角色、行为指令与能力边界。新版智能体（Agent 2.0）支持配置 temperature、enable_thinking（思考模式）等参数，与 Prompt 设计配合使用可精细控制模型行为。

### 评测中的 Prompt

Prompt 工程与模型评测紧密关联：

- **System Prompt**：在评测任务中设定被评测模型的角色定位（如"你是客服人员"），大多数情况下可留空
- **评分器 Prompt**：在评测维度中定义裁判模型的评分标准和打分规则，是评测质量的关键
- **评测驱动优化**：调整 Prompt 后建议触发评测，通过数据验证优化效果

## 关键参数与配置

| 参数 | 说明 | 典型值 |
| --- | --- | --- |
| 模板变量上限 | 单个变量最大字符数 | 6144 字符 |
| temperature | 控制输出随机性，值越低越确定 | 0~2，推荐 0.7 |
| enable_thinking | 启用思考模式，展示推理过程 | true/false |
| ReAct 最大轮次 | 智能体单次会话最大工具调用次数 | 1~50 |
| [prompt](../guides/prompt.md)_extend | 文生图 V2 大模型智能改写 | 默认开启 |

## 最佳实践

1. **从框架出发**：根据任务复杂度选择合适的 Prompt 框架（ICIO/CRISPE/RASCEF），避免从零编写
2. **善用自动优化**：先手写初版 Prompt，再用平台的自动优化功能进行结构化增强
3. **数据驱动迭代**：利用反馈优化功能，基于真实业务样例持续提升 Prompt 质量
4. **分离管理**：通过 API 管理 Prompt 模板，使业务逻辑与 Prompt 内容解耦，支持独立更新
5. **评测验证**：每次调整 Prompt 后触发评测任务，用量化数据验证优化效果
