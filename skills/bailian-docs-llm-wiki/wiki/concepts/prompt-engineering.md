# Prompt 工程

Prompt 工程是指通过系统化地设计、优化和管理输入给大语言模型的提示词（Prompt），以引导模型产出高质量、符合预期结果的技术实践。在百炼平台中，Prompt 工程贯穿文本生成、图像生成、视频生成、智能体应用构建和模型评测等多个核心场景。

## 核心原则

设计有效的 Prompt 需要遵循以下基本原则：

- **清晰具体**：任务描述越明确、无歧义，模型表现越好。
- **结构化组织**：按"背景 → 目的 → 风格 → 语气 → 受众 → 输出"六要素构建 Prompt。
- **少样本示例（Few-shot）**：在 Prompt 中提供输入-输出示例，引导模型理解任务格式和期望输出。
- **思维链（Chain-of-Thought）**：对复杂推理任务，引导模型逐步思考再给出结论。
- **限制输出格式**：明确指定 JSON、列表、表格等输出形式，减少格式偏差。

## 百炼平台的 Prompt 工具链

百炼围绕 Prompt 提供了一整套从设计、复用到自动优化的工具链：

### Prompt 模板

百炼提供预置模板和自定义模板两类：

- **预置模板**：阿里云已调优的场景化模板，覆盖营销标题、摘要抽取、文案润色等通用场景，开箱即用。
- **自定义模板**：通过控制台或 `CreatePromptTemplate` API 创建，适合对格式（如 JSON、列表）有严格要求的业务场景。支持变量占位（`${name}`），可通过 `GetPromptTemplate` 接口动态拉取。

使用模板的推荐做法：通过 API 获取模板而非在代码中硬编码，便于在控制台修改 Prompt 而无需重新部署应用。

### Prompt 自动优化

控制台提供一键优化功能，利用大模型对输入 Prompt 进行结构重组、角色引导、指令具体化和格式注入。入口位于「应用开发 → 组件管理 → 提示词 → 自动优化」。

### Prompt 样例库（Few-shot 召回）

通过预定义高质量问答对，在请求时检索 Top-K 注入到大模型上下文。典型用途包括智能客服、特定领域问答和格式化输出。样例库支持手动输入和批量导入，召回片段数默认 5 条、最多 10 条。

> 官方推荐将样例库数据迁移到 RAG 表格库，新项目优先考虑反馈优化或 RAG 方案。

### Prompt 反馈优化

基于样例和评测集进行多轮迭代，自动生成更优的 Prompt。适合需要持续改进 Prompt 质量的场景。

## Prompt 框架

百炼在自定义模板创建流程中内置了三种 Prompt 框架，帮助开发者按结构化方式编写高质量 Prompt：

| 框架 | 全称 | 适用场景 |
|------|------|----------|
| ICIO | Instruction / Context / Input Data / Output Indicator | 数据分析、内容生成、摘要等明确任务 |
| CRISPE | Capacity & Role / Insight / Statement / Personality / Experiment | 需要 AI 扮演特定角色的交互（客服、面试模拟） |
| RASCEF | Role / Action / Script / Content / Example / Format | 多步骤复杂业务（项目规划、上市策略） |

## 不同模态的 Prompt 策略

### 文生文

遵循六要素结构化原则，善用少样本示例和思维链。百炼控制台提供一键优化工具辅助改进。

### 文生图

关键参数包括 `prompt`（正向提示词）、`negative_prompt`（反向提示词）和 `prompt_extend`（智能改写开关）。

- **基础公式**：主体 + 场景 + 风格
- **进阶公式**：主体描述 + 场景描述 + 定义风格 + 镜头语言 + 氛围词 + 细节修饰

可组合景别、视角、拍摄类型和光线效果来精细控制画面。

### 文生视频 / 图生视频

- **基础公式**：主体 + 场景 + 运动
- **进阶公式**：主体描述 + 场景描述 + 运动描述 + 美学控制 + 风格化
- **图生视频公式**：运动 + 运镜（图像已确定主体和风格，重点描述动态过程）

wan2.5 及以上版本还支持声音描述，可通过 `prompt_extend_with_audio` 参数开启音频提示词的智能改写。

## 与模型调优的关系

Prompt 工程与模型微调（Fine-tuning）是提升模型表现的两条互补路径：

- **优先尝试 Prompt 工程**：通过优化提示词、使用少样本示例、利用平台自动优化等手段提升效果，成本低、迭代快。
- **Prompt 不足时再考虑调优**：当 Prompt 工程无法满足特定行业或业务场景需求时，可通过 SFT、DPO 等方式微调模型。

## 在模型评测中的角色

模型评测中涉及两种不同用途的 Prompt：

| 类型 | 作用对象 | 用途 |
|------|----------|------|
| System Prompt | 被评测模型 | 定义模型答题时的角色和行为 |
| 评分器 Prompt | 裁判模型 | 定义评分标准和批改规则 |

在评测维度配置中，评分器 Prompt 使用 `${prompt}`、`${output}`、`${completion}` 三个核心变量分别引用原始问题、模型输出和参考答案。

## 最佳实践

1. **从模板开始**：优先使用预置模板或基于框架创建自定义模板，避免从零开始。
2. **利用自动优化**：对初版 Prompt 使用平台一键优化功能进行结构改进。
3. **通过 API 管理**：使用 `GetPromptTemplate` 接口动态获取模板，实现 Prompt 与代码解耦。
4. **数据驱动迭代**：结合模型评测的量化结果持续优化 Prompt，形成闭环。
5. **注意模板输入上限**：模板提示词输入框上限为 6144 字符，超长 Prompt 需精简。
