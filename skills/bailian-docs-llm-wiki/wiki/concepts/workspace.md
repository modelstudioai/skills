# 业务空间

业务空间（Workspace）是阿里云百炼平台进行精细化权限管理、资源隔离和账单分账的最小管理单元。每个业务空间归属于特定地域，单个业务空间不能跨地域存在，各地域的默认业务空间也是相互独立的空间。

## 核心定位

业务空间将平台资源划分为可独立管理的逻辑单元，承担以下职责：

- **权限边界**：控制哪些用户可以访问空间内的模型、应用和数据，以及可以执行哪些操作。
- **资源隔离**：不同业务空间的模型调用权限、限流配额、[API Key](api-key.md)、数据集和应用互不干扰。
- **成本核算**：用量数据按业务空间维度统计，便于按业务线或环境进行费用分摊。

## 角色与权限体系

业务空间围绕三种角色组织权限，权限范围自上而下递减：

| 角色 | 权限范围 |
| --- | --- |
| 超级管理员 | 阿里云主账号或拥有 `AliyunBailianFullAccess` 策略的 RAM 用户，可跨空间统一管理用户、模型授权、限流和 [API Key](api-key.md) |
| 业务空间管理员 | 负责特定业务空间内的用户权限和资源管理，拥有该空间所有页面的访问权限 |
| 普通用户 | 根据分配的权限使用被授权的空间、页面和资源 |

## 模型与资源管控

在非默认业务空间中，可对以下维度进行精细化管控（默认业务空间无法设置这些限制）：

- **模型调用**：控制某个模型是否可在该空间内调用（控制台和 API），并设置请求数限流和 [Token](token.md) 限流。
- **模型训练**：控制某个模型是否可在该空间内进行调优及调优后部署。
- **模型部署**：控制某个模型是否可在该空间内直接部署。
- **用户控制台权限**：管理 RAM 用户对该空间控制台功能页面的访问权限。

## [API Key](api-key.md) 与业务空间的关系

单个 API Key 只能归属一个地域内的一个业务空间和一个用户，且不能转移。API Key 可调用的功能和模型限流与其归属业务空间的权限保持一致，不受用户控制台权限的影响。将 RAM 账号移出业务空间会使其 API Key 失效（重新加入后恢复），在 RAM 控制台删除账号则会使 API Key 永久失效。

## 子业务空间的模型调用

在需要按业务线隔离权限或分账的场景下，可使用子业务空间进行模型调用：

- 必须使用子业务空间自身的 API Key。
- 调用标准模型前，需为该空间设置模型调用权限。
- 通过 API 调用子业务空间内的应用时，必须在请求中额外提供 Workspace ID。

## 监控与数据统计

- **用量统计**：模型用量数据按业务空间维度聚合，不支持按阿里云账号维度统计。如需账号级汇总，需通过费用与成本页面导出账单。
- **模型监控**：监控表格按「模型 + 业务空间」维度列出调用数据。默认业务空间成员可查看所有空间的监控数据，子业务空间成员仅能查看当前空间。
- **应用观测**：应用观测的范围限定在当前业务空间，只能观测属于该空间的已发布应用。
- **数据管理**：训练集和评测集统一管理在业务空间下，数据处理操作在控制台完成。

## API 调用中的 Workspace ID

所有应用组件 API 接口均需传入 `WorkspaceId` 参数。在以下场景中，API 调用必须显式提供 Workspace ID：

- 调用子业务空间下的应用。
- 调用特定地域（德国、华北2、新加坡、日本）的模型。

Workspace ID 可通过百炼控制台右上角图标查看，目前不支持通过 API 或 CLI 查询。

## 生产环境最佳实践

- **空间规划**：推荐按环境（dev / test / prod）划分业务空间实现隔离，或按业务线划分便于权限与成本管理。
- **限流分配**：将主账号总配额按比例分配给各业务空间并预留缓冲。例如总配额 1000 QPM，可分配 prod 600 / test 200 / dev 100，预留 100。
- **安全建议**：生产环境使用 RAM 用户而非主账号的 AccessKey，通过业务空间的模型授权功能实现最小权限原则。
