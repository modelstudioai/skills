# 检索增强生成（RAG）

检索增强生成（Retrieval-Augmented Generation，RAG）是一种将信息检索与大语言模型生成能力结合的技术范式。它在模型生成回答前，先从外部知识库召回与用户查询语义相关的文本切片，作为上下文注入提示词，从而让模型能够基于私有数据和最新信息给出准确、可溯源的回答，有效缓解大模型的"幻觉"问题。

## 在百炼平台中的定位

百炼提供托管式 RAG 能力，核心载体是**知识库**。平台负责完整的"文件解析 → 切片 → 向量化 → 存储 → 检索 → 重排 → 注入生成"流水线，开发者只需关注数据准备和应用集成，无需自行维护向量数据库或检索服务。

RAG 在百炼的三种应用类型中均可使用：

- **智能体应用**：知识库作为工具挂载，Agent 2.0 由智能体自主规划何时调用，Agent 1.0 则先检索再决策是否调用其他工具。
- **工作流应用**：通过「知识库」节点显式编排，输入变量绑定查询，输出变量注入下游大模型节点的提示词。
- **高代码应用**：通过百炼 SDK 调用知识库检索接口，适合需要完全控制检索与生成逻辑的场景。

## 核心流程

1. **文件上传与解析**：通过控制台或 `ApplyFileUploadLease → AddFile → SubmitIndexJob` API 流程将文档入库。支持 PDF、Word、Markdown、图片、音视频等多种格式。
2. **切片与向量化**：平台按配置的切片方式对文档进行切分，并使用向量模型将每个切片转为向量，存入向量库。
3. **语义检索**：应用调用时，将用户查询向量化，按语义相似度从知识库中召回 Top-K 切片。
4. **重排（Rerank）**：可选启用排序模型对召回结果做二次精排，提升送入大模型的切片质量。
5. **生成回答**：将召回的文本切片拼入提示词上下文，由大模型基于这些证据生成最终回答。

## 关键参数与配置

以下参数在创建知识库时配置，大部分创建后不可修改：

| 参数 | 说明 | 推荐值 |
| --- | --- | --- |
| 向量模型 | 文本场景推荐 `text-embedding-v4`（512 维）；图片问答场景使用 `multimodal-embedding-v1`（1024 维）；视觉理解场景自动使用 `qwen3-vl-embedding` | `text-embedding-v4` |
| 切片方式 | 支持智能切分（语义自适应）、按长度、按页、按标题、按正则、按符号；单切片上限 6000 Token | 智能切分 |
| 排序模型 | 外部 Rerank，推荐 `qwen3-rerank（hybrid）`，综合语义与 BM25 | hybrid |
| 排序模式 | 问答模式（默认）/ 相似模式 / 自定义高级（≤200 字自然语言指令） | 问答模式 |
| 相似度阈值 | 仅高于此值的切片被召回，可在应用侧覆盖 | 按场景调优 |
| 最大召回数量 | 排序后送入大模型的切片数 K，上限 20 | 按场景调优 |
| 向量存储 | 内置（免费）或 ADB-PG（自购计费） | 内置 |
| 多轮对话改写 | 用轻量模型基于历史对话补全当前查询 | 按需开启 |

> **注意**：排序模型不支持图片问答类知识库；视觉理解和极速问答场景不支持排序模式配置。

## 知识库类型与适用场景

根据数据形态选择知识库类型，创建后不可更改：

- **文档搜索**：面向 PDF、Word、Markdown、图片等非结构化数据。细分为基础文档问答、图文并茂回复、视觉理解（富文本文档）、极速问答（低延迟，适合 FAQ 和参数表）四种场景。
- **数据查询**：面向结构化 Excel / RDS 表，按列控制是否参与检索与模型回复，要求多文件表头完全一致。
- **图片问答**：数据表中需包含 `image_url` 字段（公网可访问，单图 ≤ 3 MB）。
- **音视频搜索**：MP3、WAV、MP4、MOV 等格式，按时间轴对齐语音识别、视频帧提取与剧情解析。

## 框架集成

百炼支持通过主流框架快速构建 RAG 应用：

**LlamaIndex（Python）**：通过 `DashScopeParse`（文件解析）、`DashScopeCloudIndex`（云端建库）、`DashScopeRerank`（语义重排）三个核心组件，完成从本地文件到云端 RAG 应用的完整搭建。关键参数包括 `similarity_top_k`（检索返回数）、`similarity_cutoff`（最低相似度阈值）和 `top_n`（重排后返回数）。

**Spring AI Alibaba（Java）**：通过 `DashScopeDocumentRetriever` 检索知识库切片，结合 `DocumentRetrievalAdvisor` 自动将检索结果注入大模型上下文。需在 `application.yml` 中配置 API Key 和知识库名称。

## 效果优化要点

- **命中测试**：在不调用大模型的前提下模拟提问，验证召回质量并调优相似度阈值。不同排序模式下同一查询的分数差异显著，调优时应以实际排序模式的分数为准。
- **Rerank 配置优先级**：旧版智能体在应用页面配置（优先级高于知识库）；Agent 2.0 以知识库自身配置为准；OpenAPI 调用时 API 参数优先级最高。配置错误可能产生非预期费用。
- **切片与召回策略**：召回的切片会占用模型上下文窗口并增加输入 Token，需在召回充分性和成本之间取得平衡。
