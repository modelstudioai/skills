# 检索增强生成（RAG）

检索增强生成（Retrieval-Augmented Generation，RAG）是一种将信息检索与大模型文本生成相结合的技术范式。大模型在生成回答前，先从外部知识库中检索与用户问题相关的内容片段，再将这些片段作为上下文输入模型，从而生成更准确、更具时效性的回答。

## 核心原理

RAG 的工作流程分为三个阶段：

1. **索引（Indexing）**：将文档切分为片段（切片），通过向量模型将每个片段转换为向量表示并存储到向量数据库中。
2. **检索（Retrieval）**：用户提问时，将问题同样转换为向量，在向量数据库中搜索语义最相似的片段。
3. **生成（Generation）**：将检索到的片段与用户问题一并送入大模型，由模型综合上下文生成最终回答。

## 在百炼平台中的使用方式

### 知识库驱动的 RAG

百炼知识库是平台原生的 RAG 实现。开发者上传文档后，平台自动完成切片、向量化和索引构建，应用调用时自动执行检索与生成。知识库支持多种类型：

| 知识库类型 | 适用场景 |
|-----------|---------|
| 文档搜索 — 基础文档问答 | 纯文本文档的语义检索 |
| 文档搜索 — 图文并茂回复 | 需要返回图文混排内容 |
| 文档搜索 — 视觉理解 | 含复杂排版、图表、公式的 PDF/图片 |
| 文档搜索 — 极速问答 | 高度结构化或简单文档，低延时优化 |
| 数据查询 | 结构化数据（单个 Excel/CSV） |
| 图片问答 | 图片类数据 |
| 音视频搜索 | 音视频文件 |

### 智能体应用中的 RAG

在智能体应用中，知识库可作为工具接入。新版智能体（Agent 2.0）由模型自主规划是否调用知识库，旧版智能体则采用知识库检索先行的固定模式。两种方式均支持通过标签限定查询范围。

### 工作流中的 RAG

在工作流应用中，可将知识库节点拖入画布，配置输入变量和 TopK 参数，实现 RAG 检索作为流程的一个确定性步骤。

### 文件问答中的 RAG

智能体支持用户上传文件后以"切片检索"模式进行问答。系统将文件切分为片段并检索最相关内容，适合长文档问答和精确信息定位。

### API 调用

通过百炼 SDK 可直接调用知识库的检索能力，将 RAG 集成到自有应用中。调用前需配置 `ALIBABA_CLOUD_ACCESS_KEY_ID`、`ALIBABA_CLOUD_ACCESS_KEY_SECRET` 和 `WORKSPACE_ID` 环境变量。

## 第三方框架集成

百炼的 RAG 能力可通过以下框架快速接入：

| 框架 | 语言 | 集成方式 |
|-----|------|---------|
| LlamaIndex | Python | 通过 `DashScopeCloudIndex` 构建云端知识库并检索 |
| Spring AI Alibaba | Java | 通过 `DashScopeDocumentRetriever` 检索已有知识库 |

LlamaIndex 方案支持从本地文件构建云端知识库，并可配置相似度阈值、TopK、重排模型等参数。Spring AI Alibaba 方案侧重检索已有知识库并结合 `ChatClient` 生成回答。

## 关键参数与配置

### 索引阶段

| 参数 | 说明 | 建议 |
|-----|------|-----|
| 切片方式 | 智能切分 / 按长度切分 | 推荐智能切分，基于语义自适应切分 |
| 向量模型 | text-embedding-v4 / v3（512 维）、multimodal-embedding-v1（1024 维） | 文档类使用 text-embedding-v4 |
| Meta 信息抽取 | 为切片附加元数据键值对 | 创建知识库时配置，创建后不可修改 |

### 检索阶段

| 参数 | 说明 | 建议 |
|-----|------|-----|
| 相似度阈值（similarity_cutoff） | 过滤低于该阈值的检索结果 | 通过命中测试反复调试，避免过高 |
| 召回片段数（TopK / similarity_top_k） | 返回的最相似片段数量 | 列举/比较类问题适当增大（如 K=20） |
| 重排模型（Rerank） | 对初步检索结果重新排序 | 可使用 gte-rerank 模型 |

### 生成阶段

| 参数 | 说明 | 建议 |
|-----|------|-----|
| 模型选择 | 生成回答使用的大模型 | 简单查询用千问 Turbo，复杂推理用千问 Max/QwQ |
| 提示词 | 控制模型输出格式与行为 | 使用 `${documents}` 变量注入检索结果，且只出现一次 |
| 多轮对话改写 | 根据历史对话自动补全用户查询 | 建议开启，解决指代不清问题 |

## RAG 效果优化

当 RAG 效果不理想时，可从以下方向排查和优化：

**检索未命中（未找到相关知识）**：补充缺失知识、优化源文件排版（推荐 Markdown 格式）、统一实体表述、开启多轮对话改写。

**检索不相关（召回内容偏离）**：使用标签过滤缩小检索范围、通过元数据提取实现结构化前置过滤。

**切片质量问题**：避免切片过短（语义缺失）或过长（主题干扰），优先使用智能切分，必要时人工检查和修正切片。

**召回参数调整**：调整相似度阈值和 TopK 值，对总结/比较类问题增大召回数量，或选择"按拼装长度"策略。

**提示词优化**：在提示词中明确限定输出格式、使用 Few-Shot 示例、将检索结果与指令明确分隔。

## 配额与限制

| 项目 | 限制 |
|------|------|
| 每账号知识库数量（RDS 数据源） | 100 个 |
| 标准版存储 | 100 GB |
| 旗舰版存储 | 9,999 GB |
| 单文本切片最大长度 | 6,000 Token |
| 单次召回切片数 | 最多 20 个 |
| 标准版检索并发 | 1 QPS |
| 旗舰版检索并发 | 50 - 10,000 QPS |

## 本地 RAG 方案

对于需要自定义切分策略或使用本地嵌入模型的场景，百炼也支持本地 RAG 方案：检索在本地执行（支持 GTE 系列嵌入模型），生成调用百炼云端 API（qwen-max / qwen-plus / qwen-turbo），无需本地 GPU。可调参数包括模型温度、最大回复长度、召回片段数和相似度阈值。
