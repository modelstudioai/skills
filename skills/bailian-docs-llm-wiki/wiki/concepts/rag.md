# 检索增强生成

检索增强生成（Retrieval-Augmented Generation，RAG）是一种将大语言模型（LLM）与外部知识源动态结合的技术范式：在模型生成响应前，先从私有或结构化知识库中检索相关片段，并将其作为上下文注入提示词，从而提升回答的准确性、时效性与可溯源性。它不依赖模型参数微调，而是通过“检索→融合→生成”三步链路，解决大模型幻觉、知识陈旧和领域适配难等核心问题。

## 在百炼平台的不同场景中，这个概念如何使用

在百炼平台，RAG 不是单一功能模块，而是贯穿多个能力层的横切架构能力，开发者可根据应用复杂度选择适配路径：

- **轻量级问答集成**：直接调用 `/v1/knowledge` API（RAG API），传入 `knowledge_base_id` 和 `query`，平台自动完成检索+生成闭环，适用于客服问答、文档摘要等标准场景；
- **低代码工作流编排**：在「工作流」画布中拖拽「知识库节点」与「大模型节点」串联，显式控制检索参数（如 `top_k`）、结果过滤逻辑及生成模板，适合需多步骤处理（如先查政策再生成合同条款）的业务；
- **智能体（Agent 2.0）深度协同**：将知识库注册为 Agent 的内置工具（`search_knowledge`），由模型自主判断何时检索、检索什么、如何整合结果，支持多跳推理与反思优化，适用于复杂决策场景（如技术故障根因分析）；
- **高代码服务定制**：在 Rich Code 应用中，通过 `fastmcp.Client` 调用知识库 MCP 接口获取检索结果，再手动拼接 prompt 或构建自定义 Rerank + Prompt 工程逻辑，满足强可控性需求（如金融合规问答中的证据链强制校验）；
- **多模态 RAG 延伸**：结合 `qwen3-vl-rerank` 等多模态重排模型，对图文混排文档进行跨模态检索，再交由 `qwen3.6-plus` 生成带图注释的报告，突破纯文本边界。

> ✅ 关键共识：所有路径均复用同一套知识库基础设施（向量化、切片、索引），仅在“触发时机”和“融合方式”上分层抽象，无需重复构建知识底座。

## 关键参数和配置

RAG 效果高度依赖以下可调参数，需按场景协同配置：

| 参数 | 作用域 | 取值范围 | 推荐值 | 说明 |
|------|--------|----------|--------|------|
| `top_k` | RAG API / 工作流 / 应用用例 | 1–10（API 默认3）；知识库底层召回支持1–100 | 3–5 | 控制检索返回的切片数量；值过大会引入噪声，过小易漏关键信息；注意：API 的 `top_k` 是最终生成所用切片数，知识库后台可能先召回更多再经 Rerank 截断 |
| `enable_citation` | RAG API | `true`/`false`（默认 `false`） | `true`（调试期）、`false`（生产精简输出） | 开启后响应中包含 `citations: [{document_id, chunk_position}]`，用于审计与溯源 |
| 最大分段长度 | 知识库创建时设定 | 10–6000 token（默认600） | 300–800 | 影响单切片信息密度与上下文连贯性；技术文档建议400–600，法律条文建议300以内以保精确性 |
| 相似度阈值 | 知识库检索配置 | 0.01–1.0（默认0.3） | 0.25–0.4 | 过滤低置信度切片；设过高可能导致无结果，设过低则引入无关噪声；建议从0.3开始A/B测试 |
| Rerank 模型 | 知识库服务配置 | `qwen3-rerank`（文本）、`qwen3-vl-rerank`（多模态） | 按数据类型选配 | 替代简单向量相似度排序，显著提升相关性；启用后 `top_k` 实际生效值受其最大返回数（≤20）约束 |

> ⚠️ 注意：`retrieval_config` 是应用用例中启用 RAG 的统一参数对象，必须包含 `knowledge_id`（非 `knowledge_base_id`）且对应知识库状态为 `active`；未激活的知识库将静默返回空检索结果。

## 面向开发者，简洁实用

- **快速验证**：用控制台 Playground → 选择知识库 → 切换“知识问答”模式，5秒内看到检索高亮+生成答案，无需写一行代码；
- **调试黄金法则**：开启 `enable_citation` + 查看 SLS 日志中的 `retrieved_chunks` 字段，确认检索是否命中预期文档及切片内容；
- **性能优化重点**：  
  - 若响应延迟高，优先检查知识库 RCU 规格是否足够（1 RCU ≈ 50 QPS），而非调大 `top_k`；  
  - 若答案不准确，先调低相似度阈值（如0.25），再优化切片策略（如改用“按标题切分”替代“按长度”）；  
  - 避免在单次请求中混合多个知识库——百炼当前不支持跨库联合检索，需自行聚合；
- **生产必备**：所有 RAG 请求必须设置超时（建议 ≥15s）并实现指数退避重试（`429 Too Many Requests` 常见于突发流量）；
- **安全底线**：RAG 输出默认经过百炼内容安全过滤，但检索到的原始切片内容不受此保护——敏感数据须在上传前脱敏，或通过知识库元数据标签+查询过滤实现权限隔离。
